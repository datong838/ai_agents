# 第一部分 · Palantir 全链路总览图（宏观视角）

> **文档性质**：PRD 第一章素材  
> **版本**：v1.0 · 2026-07-13

---

## 1. 一句话：Palantir 卖的是什么？

> Palantir 卖的不是某个 SaaS 功能，而是一套 **「企业级 AI 操作系统（AOS）」**——把杂乱数据变成可执行的业务世界，让人类和 AI 在同一个本体世界里协同决策。

## 2. 总链路图（PRD 必插图）

### 2.1 竖向价值链

```text
┌─────────────────────────────────────────────────────────────┐
│           最终形态：人类 + AI 协同决策                         │
│     Workshop 看板 · AIP Agent · 数字孪生 · 可执行 Action       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│  【顶层大脑】Palantir AIP                                     │
│  生成式 AI · Agent Studio · k-LLM 调度 · Evals 门控           │
│  → 为什么独立：LLM 不能直写库，需要 Ontology 世界边界           │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│  【中台核心】Palantir Foundry                                 │
│  数据接入 → Pipeline → Ontology 本体 → 低代码应用              │

└─────────────────────────────────────────────────────────────┘
```

### 2.2 横向数据流（给架构师）

```text
Excel/PDF/ERP/IoT/日志
        │
        ▼  Foundry：Connectors + Pipeline Builder
   Backing Dataset (Iceberg/Parquet)  ← 物理层不动
        │
        ▼  Funnel 映射
   Object / Link / Property / Action   ← Ontology 语义层
        │
        ├──────────────────┬──────────────────┐
        ▼                  ▼                  ▼
   Workshop 应用      AIP Agent/K-LLM    Gotham 图谱分析
        │                  │                  │
        └──────────────────┴──────────────────┘
                           │
                           ▼  Action 写回 / 决策闭环
                    真实业务世界变化
                           │
                           ▼  Apollo 保证全球任意环境稳定运行
```

### 2.3 三大商业化平台 + Gotham（四大金刚）


| 平台          | 层位    | 一句话                | 商业化权重      |
| ----------- | ----- | ------------------ | ---------- |
| **Apollo**  | 底层基石  | 让系统在全球任何环境「活着」     | 交付/OS      |
| **Foundry** | 中台核心  | 让数据变成「可执行的业务世界」    | **营收核心**   |
| **AIP**     | 顶层大脑  | 让 AI 在本体世界里安全行动    | 2023+ 增长引擎 |
| **Gotham**  | 平行情报线 | 关系网络 + 地理空间 + 战术决策 | 政府/军工同源能力  |


> **PRD 写法提示：** 「三大平台构成 AOS」；对技术讲「四大金刚」，Gotham 的能力（Link Analysis）已下沉到 Foundry Ontology。

## 3. 为什么是这个顺序？（记为什么，不记功能清单）


| 层级             | 如果没有它会怎样            | Palantir 的解法                       |
| -------------- | ------------------- | ---------------------------------- |
| **无 Apollo**   | 每个客户环境一套手工运维，版本碎片化  | Hub-Spoke 约束求解，气隙也能升级              |
| **无 Foundry**  | 数据孤岛，BI 只能看数字不能行动   | 数据湖 + Pipeline + 统一治理              |
| **无 Ontology** | 表没有业务语义，没有「动作」和「权限」 | Object/Link/Action 可执行世界模型         |
| **无 AIP**      | 大模型直连数据库，幻觉写库       | K-LLM 路由 + Logic 编排 + HITL + Evals |
| **无 Workshop** | 只有数据科学家能用，业务人员够不着   | 低代码绑定 Ontology 对象，不是表格             |

## 4. 价值链：Land-and-Expand

```text
Pilot（$1-5M）
    → 部门扩展（$10-25M/年）
        → 企业基础设施（$50-100M+/年）
            → NRR > 118%（持续加购数据源/用户/Ontology类型/AIP Token）
```

**Palantir 卖的不是席位，是「决策能力」+ 极高切换成本。**

## 5. 与谛听架构的映射（废弃）

> Gotham：客户问「你们有没有 Gotham？」→ **关系分析 / Link Analysis 能力已下沉到 Foundry Ontology + Workshop 图谱**；企业侧按场景用 Ontology Link，不必单独采购「Gotham 产品名」。


| Palantir 链路              | 谛听 / AOS 对标                | 策略                     |
| ------------------------ | -------------------------- | ---------------------- |
| Foundry Data Integration | **L1 数据集成**（05）            | 复用思想 · 文件 P0 + 连接器尽量多做 |
| Foundry Ontology         | **L2 语义本体**（06/06b）        | OKF + Wiki 双向绑定        |
| AIP (K-LLM)              | **AIP 人工智能平台**（07 · 左引擎主路） | 并列拥抱最佳实践               |
| 自研 PPR+ANN+EGB           | **可选快路径 / 右引擎**（04 · M7-6） | 高并发补位；目标态技术方案可分期       |
| Workshop + Apollo        | **L3 工作台 + 交付底座**（08/09）   | 复用范式 · Lite Spoke 降准入  |
