## 1. Palantir Foundry（企业数据操作系统）

> **定位：** Palantir 商业化最核心的平台。核心任务：把企业散落的数据变成一个 **「可执行的业务世界」**。

### 模块 1.1 · 数据集成与管道（Pipeline Builder）


| 维度        | 内容                                                        |
| --------- | --------------------------------------------------------- |
| **功能描述**  | 把 Excel、PDF、ERP、IoT、日志等异构数据源接入，清洗、转换、编排                   |
| **核心价值**  | 批流一体；可「联」外部数据库，**不必物理搬迁**源数据                              |
| **关键能力**  | 200+ Connectors · 可视化算子 DAG · 数据血缘追踪 · Iceberg/Parquet 落地 |
| **界面示意**  | 左：数据源目录树 · 中：拖拽算子画布 · 右：实时预览 + 血缘图                        |
| **为什么要有** | 企业不会推倒 ERP，只能叠加集成层                                        |


**PRD 功能点清单：**

- 数据源注册与凭证管理
- 批/流/增量同步策略
- 转换算子库（Join/Filter/Aggregate/UDF）
- 调度与失败重试
- 血缘与影响分析
- 输出到 Backing Dataset（不可变层）

---

### 模块 1.2 · Ontology（本体层 — 绝对核心）


| 维度        | 内容                                                                      |
| --------- | ----------------------------------------------------------------------- |
| **功能描述**  | 把底层表（Table）映射成现实世界的 **对象（Object）**：客户、订单、工厂、SKU                         |
| **核心价值**  | 赋予数据 **业务语义 + 行为逻辑 + 权限治理**                                             |
| **三区并列**  | Semantic（名词）/ Kinetic（动词）/ Governance（治理）— 运行时原子裁决                      |
| **核心元素**  | Object Type · Property · Link Type · Action Type · Function · Interface |
| **界面示意**  | **Ontology Manager**：画布设计器，定义 Object 属性、Link 关系、Action 动作               |
| **为什么要有** | 表没有「动作」；AI 不能直读 Dataset，只能走 Action/Function                             |


**PRD 功能点清单：**

- Object Type 建模（属性/主键/接口）
- Link Type 建模（一对多/多对多/时序）
- Action Type 定义（参数/副作用/权限）
- Function 注册（确定性计算）
- Funnel 映射（Dataset 列 → Object 属性）
- OSv2 索引（Funnel + CDC 增量）
- Markings / RBAC 行列权限

---

### 模块 1.3 · 分析与建模（Code Workbooks / Notebooks）


| 维度       | 内容                                          |
| -------- | ------------------------------------------- |
| **功能描述** | 内置 Jupyter、R、SQL 环境，数据科学家在统一平台分析、训练 ML      |
| **核心价值** | 分析结果可回写 Ontology 或 Dataset，不脱离企业治理          |
| **关联产品** | Contour（BI 探索）· Quiver（时序分析）· Vertex（ML 实验） |
| **界面示意** | Notebook 单元格 + 左侧 Ontology 对象浏览器            |


---

### 模块 1.4 · 低代码应用构建（Workshop / Slate / Quiver）


| 维度        | 内容                                              |
| --------- | ----------------------------------------------- |
| **功能描述**  | 基于 Ontology 快速搭建业务应用，无需从零写前端                    |
| **核心价值**  | 前端展示 **「对象卡片」** 而不是「数据表格」                       |
| **界面示意**  | 左：Widget 组件库（图表/地图/列表）· 中：画布 · 右：绑定 Ontology 对象 |
| **为什么要有** | 让业务人员直接操作对象世界，降低 FDE 依赖                         |


**PRD 功能点清单：**

- Widget 组件库（Table/Chart/Map/Object Card）
- Ontology 对象/链接绑定
- Action 按钮（触发写回）
- 权限裁剪后的视图
- 嵌入 AIP Assist Copilot

## 2. Palantir AIP（人工智能平台）

> **定位：** 2023 年推出，相当于给 Foundry 装上 **「通用人工智能大脑」**。全部锚定 Ontology。

### 模块 2.1 · k-LLM（核心调度与路由）


| 维度        | 内容                               |
| --------- | -------------------------------- |
| **功能描述**  | 像管家一样，按任务敏感度、复杂度路由到合适的大模型        |
| **路由策略**  | 敏感数据 → 私有模型；通用问题 → GPT-4 等；多模型合议 |
| **安全护栏**  | 权限裁剪后的对象进 Prompt；禁止直写 Dataset    |
| **为什么要有** | 单一模型无法满足企业安全/成本/能力三角             |


**PRD 功能点清单：**

- 模型注册与路由策略
- 敏感级分类与模型映射
- Token 计量与成本管控
- Prompt 模板与 Ontology 上下文注入

---

### 模块 2.2 · AIP Logic（编排引擎）


| 维度       | 内容                               |
| -------- | -------------------------------- |
| **功能描述** | Block 链式编排：检索 → 推理 → 工具调用 → 条件分支 |
| **核心价值** | LLM **只提议**，系统 **确定性执行** Action  |
| **关联**   | Agent Studio 的可视化底层              |


---

### 模块 2.3 · AIP Agent Studio（Agent 开发工坊）


| 维度       | 内容                                      |
| -------- | --------------------------------------- |
| **功能描述** | 低代码/无代码构建企业专属 AI 代理                     |
| **界面示意** | 拖拽 LLM 节点 · RAG/知识库节点 · 工具调用节点 · 编排业务逻辑 |
| **关键约束** | World Definition = Ontology 子集 + 工具白名单  |
| **HITL** | Draft Action 默认暂存，人工审批后执行               |


**PRD 功能点清单：**

- Agent 画布编辑器
- Ontology Tool 绑定
- 外部 API / Function 工具注册
- Evals 评测门控
- Decision Lineage 全审计

---

### 模块 2.4 · AIP Assist（智能助手）


| 维度        | 内容                                |
| --------- | --------------------------------- |
| **功能描述**  | 嵌入各业务界面的"副驾驶"，自然语言查数据、生成报告        |
| **界面示意**  | Workshop 右侧浮层 · 对话式查询 Ontology 对象 |
| **为什么要有** | 降低 Ontology 使用门槛，业务人员零代码交互        |


---

### 模块 2.5 · AIP Evals（质量门控）


| 维度       | 内容                      |
| -------- | ----------------------- |
| **功能描述** | Agent 上线前的评测集、回归测试、质量阈值 |
| **核心价值** | 非确定性 LLM 输出必须门控才能进生产    |

## 3. Palantir Apollo（持续交付与底层运维）

> **定位：** 自主部署操作系统 — **不是 Jenkins**。详见 [Apollo 深度解析](../ref/Palantir-Apollo-深度解析.md)


| 维度          | 内容                                   |
| ----------- | ------------------------------------ |
| **功能描述**    | 管理跨云、私有云、气隙边缘环境，每日成千上万次零停机升级         |
| **架构**      | Hub-Spoke · 约束求解 · Spoke 出站拉取        |
| **编排对象**    | 产品级（Foundry/Gotham/AIP 300+ 微服务 DAG） |
| **价值**      | 军工级/金融级环境下 AIP+Foundry 稳定运行          |
| **与 Rubix** | **Apollo = 编排层**（跨环境产品级 Plan / Channel / Ferry）；**Rubix = 加固 K8s 运行时**（单集群容器执行面）。Apollo 不替代 K8s，Rubix 不替代 Apollo |


**PRD 功能点清单：**

- Product Catalog 与 Release Channel
- 环境订阅（产品+通道，非固定版本号）
- 约束求解 Plan 生成与执行
- 气隙 Artifact Bundle 签名验证
- 舰队级健康 Probe 与自动 Rollback

## 4. Palantir Gotham（国防级情报分析引擎）

> **定位：** 主要面向政府/军方，但核心能力已赋能大型企业场景。


| 维度            | 内容                                            |
| ------------- | --------------------------------------------- |
| **功能描述**      | 关系网络分析（Link Analysis）+ 地理空间分析 + 战术决策          |
| **核心界面**      | 动态关系图谱：人、事、物、事件连成一张活图                         |
| **企业场景**      | 供应链风控 · 反欺诈 · 合规调查 · 复杂关系溯源                   |
| **企业落地路径** | ① Ontology 建「实体-关系」对象；② Workshop Graph/Map 做调查台；③ Action 闭环处置；④ 不必单独卖 Gotham 品牌给纯企业客户 |


**PRD 功能点清单：**

- 多跳关系图谱可视化
- 地理空间图层叠加
- 时间轴事件回放
- 假设推演（What-if）
- 权限裁剪后的子图探索
