## 0. 一句话结论

| 问题 | 结论 |
| --- | --- |
| 企业客户 0.1 交付什么？ | **本地桌面 AI 工作站（试用版）**：Tauri 客户端 + 本机 OpenOcta + 本机 Dify（Docker），**不挂**钉钉/企微/飞书；**须可在 Windows / macOS / Linux 部署安装** |
| 与 Palantir 叙事对齐点 | **数据主权 / Local-First Client**（对标 Foundry Client 体验切片）；不是群聊机器人 |
| 能否迭代到 01～09？ | **能方向对齐**，须显式替换：Dify≠Ontology；桌面壳≠工作台 Module 工厂；见 §5 |
| 是否还做 IM 通道？ | **0.1 Out of Scope**；合同二期可选，不得堵 Local-First 主路径 |
| **代码改在哪？** | **新起/用好自有目录开发，不要在 Dify（及 OpenOcta 上游）里大改**；详见下节「开发组织方式」 |
| **安装平台** | **Windows · macOS · Linux 三端均可安装运行**（打包物形态可不同，能力与配置一致）；详见 §0.2 |
| **页面风格** | **与目标版 `foundry/html` 同视觉语言**（深色 AOS 壳）；详见 §0.3 |

产品对外名建议：**AOS 本地工作站**（工程目录 `mybuddy-v01`）。合同可换客户品牌皮，**方案与能力描述保持行业无关的通用 AOS 表述**。  
**版本含义：** **v0.1 = 第一阶段试用版**（知识智能体可装可用）；不是「仅售前走秀」。

## 0.1 开发组织方式（强制）

> **一句话：自有目录写产品；上游当引擎；claudeskills 当工具箱。禁止把 Dify 源码仓当成主开发仓库大改。**

| 位置 | 角色 | 允许 | 禁止 |
| --- | --- | --- | --- |
| `mybuddy-v01/desktop/` | ★ 主开发（Tauri UI） | 三栏界面、打包、本机调用 | 业务逻辑写进 Dify 源码树 |
| `mybuddy-v01/openocta-overlay/` | ★ 可提交配置/Skill | `SearchKnowledgeDoc` 等模板 | 把覆盖层逻辑只改在上游工作区且无法同步回 overlay |
| `mybuddy-v01/adapter/` | 可选契约层 | `/v1/buddy/ask` | 膨胀成第二套业务平台 |
| `mybuddy-v01/docs/` | 金牌集、语料、导出 DSL | 全部可提交 | — |
| `mybuddy-v01/dify/` | **上游只读依赖**（gitignore） | Docker 起服、控制台配知识库/Prompt/Workflow、API Key、导出 DSL | **内核大改、业务 Ontology 堆进源码、无记录的 fork 漂移** |
| `mybuddy-v01/openocta/` | **上游只读依赖**（gitignore） | 本机运行、加载 overlay Skill | 上游主干堆永久业务、接 IM 为主路径 |
| `claudeskills/` | 工程工具（平级，不进交付包） | 按需跑评测/Prompt/安全 Skill | 整库拷贝进产品伪装能力层 |

**「捞取」含义（允许）：** 调 Dify/OpenOcta **HTTP API**；复用官方配置与 DSL 导出；参考 claudeskills 脚本做切分/评测。  
**「捞取」不含：** 以修改 `dify/api` 主体为日常开发方式。

**上游极小 patch 例外：** 仅本机私有化/端口等不得不改时，须记入变更说明并可回灌官方 tag；默认路径仍是 **配置 + overlay + 自有目录**。

工程细则见 [10a §0.1 / §1](10a-v0.1开工编码规格.md)。

## 0.2 跨平台部署与安装（强制）

> **要求：我们自有交付物（桌面客户端 + 启动/探测脚本 + 配置约定）必须在 Windows、macOS、Linux 均可部署安装；业务能力一致，禁止「只做 Windows」。**

| 平台 | 桌面客户端形态 | 依赖运行时 | 说明 |
| --- | --- | --- | --- |
| **Windows** | `.msi` / `.exe` 安装包或便携目录 | Docker Desktop 或兼容引擎；OpenOcta 二进制 | 企业现场常首选 |
| **macOS** | `.dmg` / `.app`（Apple Silicon + Intel 需分别说明构建目标） | Docker Desktop；OpenOcta 二进制 | 公证/签名可二期加固，**安装运行不可缺** |
| **Linux** | `.AppImage` / `.deb` / 解压目录（选 1～2 种写进交付清单） | Docker Engine + Compose；OpenOcta 二进制 | 服务器桌面或开发机场景 |

**一致的能力底线（三端都要过）：**

1. 安装或解压后能启动 **AOS 本地工作站** UI（Tauri）。  
2. 能按文档起 **本机 Dify（Compose）** 与 **OpenOcta**，默认 `127.0.0.1`。  
3. 三栏问答 + 引用溯源 + 健康检测在三端行为一致。  
4. 配置项（环境变量、知识库、API Key）跨平台同名同义；路径差异用相对路径/`$HOME` 约定消化。

**实现约束（写入研发）：**

- UI 与业务逻辑写在 **Tauri + Web 前端**，用官方多目标打包（`tauri build` 分平台 CI），**禁止**桌面逻辑用 Windows-only API。  
- 安装器/启动脚本按 OS 分目录交付：`scripts/win` · `scripts/mac` · `scripts/linux`，共用同一套探测逻辑说明。  
- Dify / OpenOcta 仍是上游引擎：各 OS 使用对应官方或社区支持的安装方式，我们提供**统一检查单**，而不是改内核。  
- CI 至少：**每平台能产出产物**；若暂无三台物理机，用矩阵构建 + 一台真机抽测，但发布清单必须列齐三端包。

**资源底线（写入交付检查单，三端通用）：** ≥16GB RAM 推荐 · 已装可用 Docker · 磁盘 ≥30GB · 本机端口未被占用。

**试用版验收（摘要）：** 客户指定电脑安装后，业务用户能对已入库文档完成 ≥10 条金牌问答且带引用；连续使用不依赖「剧本走秀」。

## 0.3 UI 视觉规范（强制 · 与目标版一致）

> **要求：v0.1「AOS 本地工作站」页面风格必须与目标版 `docs/palantier/foundry/html/`（当前约 v1.5.x）保持同一套视觉语言。**  
> 能力可以少（试用切片），**观感不能另起一套浅色/通用后台皮**。

**权威参照（设计源）：**

| 资源 | 路径 |
| --- | --- |
| 总览与壳 | `foundry/html/index.html` |
| 工作台/Buddy 页 | `foundry/html/workshop*.html`（尤其 `workshop-aip-chat.html`） |
| 共享样式 / 导航 | `foundry/html/assets/demo.css` · `demo.js` |

**必须对齐的视觉要素：**

| 维度 | 目标版约定 | v0.1 桌面要求 |
| --- | --- | --- |
| 主题 | 深色底 `slate-950` / 面板 `slate-900` | **默认 Dark**；禁止默认白底 Admin 风 |
| 分割与边框 | `border-white/[0.08]` | 同透明度细边框 |
| 主文字 | 标题 `gray-100` · 正文 `gray-400` · 弱化 `gray-500` | 同级灰阶 |
| 强调色 | **cyan / sky**（数据/入口）；**violet**（本体区）；**amber**（AIP/Buddy 提示） | 三栏与健康态跟色系，勿紫霓虹乱配 |
| 圆角与卡片 | `rounded-lg` / `rounded-xl` + 轻阴影 | 列表、消息气泡、引用卡片同制式 |
| 顶栏 | 高约 56px · 底边框 · 可模糊 | 产品名 + 健康灯放顶栏 |
| 交互 | hover 边框提亮（如 `cyan-400/30`） | 选中对象、发送按钮同逻辑 |
| 品牌位 | 「AI操作系统 / AOS…」信息架构 | 对外可用合同品牌，**壳与色板仍跟 AOS 目标版** |

**布局关系（能力切片，风格不切片）：**

```text
目标版工作台壳：左侧导航 + 顶栏 + 主区模块卡片
v0.1 试用壳：    左对象列表 | 中 Chat | 右溯源
→ 允许信息架构更窄，但颜色、边框、字号层级、卡片语法必须同源。
```

**落地约束：**

1. `desktop/` 前端优先复用或抽取 `foundry/html` 的 CSS Token（可拷贝 `demo.css` 中变量进 Tauri 工程，禁止各写一套）。  
2. 评审验收增加一项：**并排截图对比**（目标版 `workshop-aip-chat` vs 试用版三栏），风格不一致视为未通过。  
3. 新建控件先对照 HTML 目标版已有组件，再扩展。

## 1. 01～09 目标态 vs 0.1 试用态

```text
目标态（01～09 / AOS）
  L1 数据集成 · Connectors / Pipeline / Dataset/MediaSet
  L2 Ontology · Object/Link/Action/Function · OKF · Wiki
  AIP · k-LLM · Logic / Chatbot · Draft · Lineage · HITL
  L3 工作台 · Module/Widget · Selection · 知识图谱 · Buddy
  Apollo · Hub-Spoke · Ferry · OPS-001~009

0.1 试用态（企业客户 · Local-First · 可交付）
  L1′  本机上传企业文档 PDF/手册（≈ MediaSet 代用品）
  L2′  本机 Dify Dataset RAG（≠ Ontology；左侧「业务对象列表」可为静态/假数据先占位）
  AIP′ OpenOcta Agent + Skill 调 Dify；无 Draft 写回
  L3′  Tauri 桌面三栏 UI（左对象列表 · 中 Chat · 右引用溯源）≈ UI-002 试用壳
  OPS′ 本机 Docker Compose + 单二进制 OpenOcta；**不做 Apollo**
```

| 对客户可以说 | 对内真实是 | 不可对外说成 |
| --- | --- | --- |
| 数据留在本机 / 不出厂 | Dify+向量库+语料在客户指定电脑 | 「已建成气隙 Apollo 舰队」 |
| 本地工作站 · 可追溯问答 | Tauri + OpenOcta + Dify RAG | 「已建成 Ontology / OKF」 |
| 引用来源浮现 | Dify citations 映射到右侧面板 | 「Decision Lineage」 |
| 后续演进 AOS 全栈 | 见 §5 替换阶梯 | 「当前即 Workshop 运营台」 |

售前愿景仍可用 `foundry/html`（全链路蓝图）；**可运行产品是 v0.1 试用版本机工作站**。讲解可分两段：① HTML 目标蓝图 → ② 安装并试用本地助手。

## 3. 收敛后的 v0.1 架构（唯一主路径）

```text
┌─────────────── 客户触点（本机）──────────────┐
│  AOS 本地工作站（Tauri · Win/macOS/Linux）  │
│  左：业务对象列表 · 中：Chat · 右：溯源引用   │
└───────────────────────┬──────────────────────┘
                        │ HTTP / local bridge
          ┌─────────────▼─────────────┐
          │ OpenOcta（本机单二进制）     │  Agent + Skill
          │ SearchKnowledgeDoc → Dify API │
          └─────────────┬─────────────┘
                        │ HTTP localhost
          ┌─────────────▼─────────────┐
          │ Dify（本机 Docker）         │  Knowledge + Chat/Workflow
          │ · 企业知识库 · Citations  │
          └─────────────┬─────────────┘
                        │
          ┌─────────────▼─────────────┐
          │ 模型 API 或客户私有化端点    │  Key 可走客户账号
          │ 向量库 / PG（Compose 卷）   │  物理在本机磁盘
          └───────────────────────────┘
```

**铁律：**

1. 默认绑定 `127.0.0.1`；不开放公网入站。  
2. **禁止改 Dify 内核**；OpenOcta 仅 Skill/配置级二开。  
3. 对内仍保留统一契约 `POST /v1/buddy/ask`（可由 OpenOcta Skill 内实现，或极薄本地 adapter），便于日后换自研 AIP。

### 3.1 三类必交资产

1. **问答契约**（应答含 `citations[]` + `trace_id`）  
2. **金牌评测集** ≥10 题  
3. **对象雏形表**（左栏后续接真 Object 的样本字段）

## 4. 三周实施路径

| 周 | 目标 | 完成定义 |
| --- | --- | --- |
| **W1** | 本机知识底座 | Compose 起 Dify；上传先 **10～20** 份业务文档（勿迷信 50）；Web 预览答对 ≥5 金牌题且有引用 |

## 6. 风险（Local-First 专项）

| ID | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| R1 | 夸大 Ontology/Workshop | 高 | 话术表 §1 |
| R2 | 本机 Docker 起不来 / 杀软拦截 | **高** | 交付清单预检；提供「修复脚本」；试用机我们预装 |
| R3 | 8GB 内存 OOM | 高 | 建议 16GB；可关 Dify 不用的 worker |
| R4 | 语料幻觉 | 高 | 金牌集 + 拒答；试用验收跑金牌题 |
| R5 | OpenOcta GPL-3 | 中 | 交付二进制；法务扫 |
| R6 | Tauri 多平台打包 / 签名 / 杀软误报 | 中 | 三端先出可运行包；签名与公证按平台分期加固 |
| R7 | 无替换表锁死缝合怪 | 高 | §5 + 契约 API |
