# v0.1 开发计划与自测（含单元测试）

> **文档性质**：排期 + 测试门禁；编码前照此执行  
> **版本**：v1.0 · 2026-07-15  
> **承接**：[10 技术方案](10-v0.1技术方案.md) · [10a 开工编码规格](10a-v0.1开工编码规格.md)  
> **原则**：自有目录开发；最小改动上游；每阶段单测绿 + 自测清单勾完再进下一阶段

## 0. 总览

| 项 | 约定 |
| --- | --- |
| 周期 | **3 周**（可压缩为 15 个工作日） |
| 主战场 | `mybuddy-v01/desktop` · `openocta-overlay` · `adapter` · `docs` |
| 上游 | `dify` / `openocta` 仅起服与配置 |
| 测试分层 | **单测 → 契约/集成自测 → 金牌 UI 自测 → 三端抽测** |
| 总验收 | 桌面三栏可问可引用 + 金牌 ≥10 + Win/macOS/Linux 至少各一种可装包 |

```text
W0 准备(0.5d) → W1 知识底座 → W2 Agent+契约 → W3 桌面+打包
         │              │              │              │
      环境自测       A 单测/Web金牌  B 单测+curl     C 前端单测+UI金牌
```

## 1. 测试策略（强制）

### 1.1 分层

| 层 | 范围 | 工具建议 | 何时跑 |
| --- | --- | --- | --- |
| **L0 环境自测** | Docker / 端口 / 健康灯前置 | 脚本 + 手工 | 每日开工 / 换机 |
| **L1 单元测试** | 纯逻辑：契约解析、citations 映射、status 判定、UI store/helpers | pytest（adapter）· vitest/jest（desktop） | 每次提交前；CI 必绿 |
| **L2 契约/集成自测** | `POST /v1/buddy/ask`；Skill→Dify（可 mock） | httpx/pytest · curl 脚本 | Epic B/C 合并前 |
| **L3 金牌自测** | `docs/golden-qa.yaml` 全量 | 桌面手工勾选 + 可选 CLI runner | W3 验收门禁 |
| **L4 打包抽测** | 三端安装起 UI | 手工检查单 | 发版前 |

### 1.2 单元测试必须覆盖（DoD）

| 模块 | 目录 | 必测点 | 最低条数（建议） |
| --- | --- | --- | --- |
| **adapter**（若启用） | `adapter/tests/` | request 校验；Dify 响应 → `citations[]`/`status` 映射；`ok`/`no_hit`/`error`；超时包装；`trace_id` 生成 | ≥12 |
| **overlay Skill 逻辑** | `openocta-overlay/.../tests/` 或抽纯函数到可测模块 | 入参拼接（含 object_id）；citations 规范化（缺字段兜底）；拒答文案 | ≥8 |
| **desktop** | `desktop/src/**/*.test.ts(x)` | 健康态聚合；消息列表追加；citations 渲染数据变换；选中对象写入 meta | ≥10 |
| **scripts**（可选） | 轻量 | 端口探测真/假 | ≥2 |

**不做单测：** Dify/OpenOcta **上游源码**；Docker 镜像本身。

**Mock 原则：** L1 禁止依赖真 Dify；L2 可对 Dify 打桩或用录制 fixture；L3 必须打真本机链路。

### 1.3 自测脚本入口（交付物）

```text
mybuddy-v01/
├── scripts/
│   ├── win|mac|linux/healthcheck.*     # L0
│   └── selftest/
│       ├── run-unit.(ps1|sh)           # L1：adapter + desktop
│       ├── run-contract.(ps1|sh)       # L2：curl/httpx 打 /v1/buddy/ask
│       └── run-golden-checklist.md     # L3：人工勾选表（可后补 CLI）
```

**每次阶段结束：** 执行对应层脚本，结果记入 `docs/selftest-log.md`（日期 · 谁 · 过/不过 · 备注）。

## 2. 阶段计划（按工作日）

### Phase 0 · 开工闸门（0.5 天）

| # | 任务 | 产出 | 自测 |

### Phase 1 · Epic A 本机知识底座（约 4～5 天）

| ID | 任务 | 代码/配置落点 | 单测 | 自测 DoD |
| --- | --- | --- | --- | --- |
| A1 | Compose 起 Dify；三端起服说明 | `dify/docker` 配置 + `scripts/*/README` | — | 浏览器开控制台；`healthcheck` 绿 |
| A2 | 配模型 + Embedding；空聊 | Dify 控制台 | — | 空聊返回非空 |

| A4 | 写 `golden-qa.yaml` ≥10 | `docs/golden-qa.yaml` | **YAML schema 校验单测**（字段齐全） | 人工过首 5 题并勾选 |
| A5 | 导出 DSL | `docs/dify-export/` | — | 导出文件可再导入 |

**阶段门禁：** A1～A4 自测全过；`run-unit` 中 **golden schema** 绿。  
**风险：** Docker/内存（R2/R3）→ 卡住则先修环境，不进 Phase 2。

---

### Phase 2 · Epic B Agent + 契约（约 3～4 天）

| ID | 任务 | 落点 | 单测 | 自测 DoD |
| --- | --- | --- | --- | --- |
| B1 | 本机起 OpenOcta | 上游二进制 + 说明 | — | Control UI / 健康探针可达 |
| B2 | 实现 `SearchKnowledgeDoc`（调 Dify） | `openocta-overlay/skills/...` | citations 映射 · status · 缺字段 | fixture 输入 → 期望 JSON |
| B3 | （推荐）`adapter` 暴露 `/v1/buddy/ask` | `adapter/` | request/response · timeout · no_hit | `run-contract`：ok / no_hit / error 各 ≥1 |
| B4 | 错误与超时话术 | overlay + adapter | 分支覆盖 | 关 Dify 得 `status=error` 且 UI 可消费文案 |

**阶段门禁：** L1 全绿；`curl`/`run-contract` 三种 status 通过；契约字段与 10a §4 **字节级一致**。

**单测用例清单（adapter 示例）：**

| Case | 输入要点 | 期望 |
| --- | --- | --- |
| U-ASK-01 | 合法 question | 200 + `status=ok` + citations 数组 |
| U-ASK-02 | 空 question | 4xx 或契约 error |
| U-ASK-03 | Dify 返回无引用/拒答 | `status=no_hit` |
| U-ASK-04 | Dify 超时 mock | `status=error` + refuse/reason |
| U-ASK-05 | 残缺 citation 字段 | 规范化后仍可序列化 |
| U-ASK-06 | meta.object_id 透传 | 请求体或 Skill 入参包含 |

## 4. 日常开发节奏（每人/每日）

```text
1. healthcheck（L0）
2. 写功能（仅自有目录）
3. 补/改对应单测（红→绿）
4. run-unit（L1）
5. 触及契约则 run-contract（L2）
6. 记 selftest-log 一行（可选）
```

**合码前硬规则：** L1 不过禁止合；改契约必须先改 10a + 单测再改实现。
