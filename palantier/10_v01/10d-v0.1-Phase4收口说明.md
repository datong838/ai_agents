## 启动 / 关闭命令行（强制写入交付）

> 工作目录一律先进入：`cd c:\work\projects\wchat\mybuddy-v01`（或本机等价路径）。

### Windows（主推）

**一键启动（Docker + Dify + adapter）：**

```powershell
cd c:\work\projects\wchat\mybuddy-v01
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\win\start-all.ps1
```

未设 `DIFY_API_KEY` 时自动 `BUDDY_DEMO_MODE=1`。正式试用：编辑 **`mybuddy-v01/.env`**（勿提交 Git）：

```env
DIFY_API_KEY=app-从Dify访问API复制的密钥
BUDDY_DEMO_MODE=0
DIFY_BASE_URL=http://127.0.0.1
```

模板：`.env.example`。`start-all.ps1` / `start-adapter.ps1` 会自动加载 `.env`，无需再手敲 `$env:...`。

```powershell
cd c:\work\projects\wchat\mybuddy-v01
# 先改好 .env 里的 DIFY_API_KEY
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\win\start-all.ps1
```

**启动桌面（二选一）：**

```powershell
# 安装包 / 便携
.\dist\windows\AOS-Local-Workstation.exe

# 开发态
cd .\desktop
npm run tauri dev
```

**一键关闭（adapter + Dify；默认不停 dockerd）：**

```powershell
cd c:\work\projects\wchat\mybuddy-v01
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\win\stop-all.ps1
```

**分项命令：**

| 动作 | 命令 |
| --- | --- |
| 仅起 Docker | `.\scripts\win\start-dockerd.ps1` |
| 仅起 Dify | `.\scripts\win\start-dify.ps1` |
| 仅起 adapter | `.\scripts\win\start-adapter.ps1` |
| 健康检查 | `.\scripts\win\healthcheck.ps1` |
| 仅停 adapter | `.\scripts\win\stop-adapter.ps1` |
| 仅停 Dify | `.\scripts\win\stop-dify.ps1` |
| 停 dockerd（可选） | `.\scripts\win\stop-dockerd.ps1` |

**入口：** Dify `http://127.0.0.1/install` · Adapter `http://127.0.0.1:8090/healthz`

### macOS

## 备忘 · 鉴权抽象（未做 · 二期）

> **记录日期：** 2026-07-16  
> **结论（产品约定）：** 当前对外仍直接暴露 / 依赖 `DIFY_API_KEY`、`BUDDY_DEMO_MODE` 等；`DIFY_API_KEY` 必须是本机 Dify 控制台签发的 `app-…`，不可随意自造。

**目标态：** 在自有层（建议落在 `adapter/` 或独立 auth 网关）做一层：

```text
对外：我们自己的鉴权 + 自定义配置项名（如 AOS_*）
    ↓
对内：持有并调用本机 Dify（Bearer app-Key / 等价凭证）
```

**何时才算「对外可完全自定义配置名与鉴权方式」：** 上述抽象层落地之后；在此之前，正式问答路径仍绑定 Dify 签发的 Key。  
**不做范围（本备忘）：** 不改 v0.1 已交付契约；不替代 Demo 模式；不把 Dify 源码改成自有鉴权中心。
