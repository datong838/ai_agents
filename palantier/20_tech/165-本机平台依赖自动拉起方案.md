## 2. 行为

| 步骤 | 行为 |
| --- | --- |
| 进入本机平台 / 重新检测 | ① 探活 aos-api ② `GET /v1/ops/local/deps` ③ **`GET /v1/ops/local/hub`（主动探活 Docker Hub）** |
| 依赖未齐 | 自动 `POST /v1/ops/local/deps/ensure` → `docker compose up -d` 核心依赖 |
| 成功 | 状态点绿；列出 PG/MinIO 可达 |
| 失败 | 状态点红；展示失败原因（docker 缺失 / compose 失败 / 端口未就绪） |
| Hub 可达 | 绿点；提示可用 `start-local.sh` |
| Hub 不可达 | 红点；提示改用 `start-local-native.sh`（细则见 [72](72-系统启停与健康检查手册.md) §1.3.1） |

核心服务：`aos-dev-pg` · `aos-dev-minio` · `aos-dev-minio-init`（探活端口 **5433** / **9000**）。

### 2.1 Docker Hub 主动探活（v1.1）

| 项 | 已决 |
| --- | --- |
| 探测目标 | `https://registry-1.docker.io/v2/`（短超时，如 8s） |
| 可达判定 | HTTP 响应（含 **401**）= 可达；超时/连接失败 = 不可达 |
| 非目标 | 不在本页执行 `docker pull`；不替代 compose ensure |
| UI | 本机平台第三行「Docker Hub（镜像拉取）」 |

## 3. 门禁

- 仅 Local-First / Dev：`AOS_AUTH_ALLOW_DEV=1` **或** `AOS_LOCAL_DEPS_ENSURE=1`
- 生产关 Dev 时 ensure 返回 403（探活 GET 仍可读，不启动）
- Hub GET **不**要求 ensure 门禁（只读探活）

## 4. 落点
