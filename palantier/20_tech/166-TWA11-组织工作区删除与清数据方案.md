> **点名**：用户 — 组织创建者 / 工作区创建者（管理员）可删组织与工作区；**前提区内无业务数据**；管理员可先清理区内数据

## 使用的 Rules

| Rule | 应用 |
| --- | --- |
| 先方案后编码 | 本文 |
| 最小更改 | 复用 membership / catalog；新增 `tenant_data` 汇总与清理 |
| 不破坏既有 | 创建、切换、邀请、申请、成员管理保持 |
| 诚实 | 「数据」= 本刀可枚举的业务资源；成员/审计不算阻挡数据，删除时一并摘除 |

---

## 0. 一句话

| 能力 | 规则 |
| --- | --- |
| 清数据 | 工作区 **owner/admin**（组织级则组织管理员）可清空区内业务数据 |
| 删工作区 | 同上；**仅当** `data.total == 0`，否则 409 |
| 删组织 | 组织管理员；**仅当** 组织下所有工作区业务数据合计为 0，否则 409；通过后级联摘除工作区/成员/邀请 |

---

## 1. 「区内有数据」定义（MVP）

计入 `total`（任一 >0 → 不可删）：

| 资源 | 来源 |
| --- | --- |
| workspaceItems | 内存隔离探针 |
| pluginConfigs | 按区插件配置 |
| modules | PG `meta_module`（库不可用则计 0 并记 warning） |
| drafts | PG `draft_dataset` |
| wikiPages | PG `wiki_page` |

**不计入**阻挡：成员关系、审计日志、待审申请、邀请 token（删除时清理）。

清数据 = 删除上表业务资源；**不**默认移除成员（清完仍可继续协作；删实体时再摘成员）。

---

## 2. 权限

| 动作 | 权限 |
| --- | --- |
| `…/data` 摘要 · `…/data/clear` · `DELETE` 工作区 | 该工作区 owner/admin，或组织管理员 |
| 组织级摘要 / 清数据 / `DELETE` 组织 | `can_manage_org`（任一工作区 owner/admin） |

---

## 3. API

| Method | Path | 说明 |
| --- | --- | --- |
| `GET` | `/v1/workspaces/{id}/data` | `{ empty, total, counts }` |
| `POST` | `/v1/workspaces/{id}/data/clear` | 清业务数据；返回新摘要 |
| `DELETE` | `/v1/workspaces/{id}` | 非空 → 409 `NOT_EMPTY`；成功摘目录+成员 |
| `GET` | `/v1/orgs/{id}/data` | 各工作区汇总 + `empty` |
| `POST` | `/v1/orgs/{id}/data/clear` | 清组织下全部工作区业务数据 |
| `DELETE` | `/v1/orgs/{id}` | 非空 → 409；成功级联删除 |

审计：`workspace.data_clear` · `workspace.delete` · `org.data_clear` · `org.delete`。

## 4. Web

在 **组织与加入** 页增加「当前组织 / 当前工作区」管理区：

- 显示数据摘要（各类计数）
- **清理区内数据**（二次确认）
- **删除当前工作区** / **删除当前组织**（非空时按钮可用但提交后提示先清理；或禁用并说明）

顶栏切换器不放危险删除（避免误触）；管理集中在组织页。
