> **点名**：用户 — 邮箱/手机识别；**用户可维护自己的信息（如本机开发者）**

## 使用的 Rules

| Rule | 应用 |
| --- | --- |
| 先方案后编码 | 本文 |
| 诚实 | **既有方案没有**「用手机号/邮箱加人」的产品能力；20a 仅有 IdP `sub` |
| 最小 | 规范化标识 → 稳定 `subject`；**验证码 / OTP 本刀不做** |
| 不破坏 | 既有 `alice` / `user:dev` / OIDC `sub` 成员继续有效 |

## 1. 现状（诚实）

| 层 | 现状 |
| --- | --- |
| 20a | User = IdP **`sub`**；Membership = `(user, project, role)` |
| TWA.7 UI | 输入框是任意 **subject 字符串**（如 `carol`），不是手机/邮箱 |
| IdP | 生产邮箱/手机通常在 IdP 侧；AOS 成员页未对接「按联系方式邀请」 |

**结论：** 方案里 **有身份主体（sub）**，**没有**「管理员用手机号/邮箱识别并加人」的完整产品路径。本刀补上。

## 2. 已决模型

```text
联系方式（email | phone）
        │ normalize
        ▼
canonical subject（稳定键）
  email:user@example.com
  phone:+8613812345678
        │
        ▼
Membership(org, project, subject, role)
```

| 字段 | 规则 |
| --- | --- |
| email | 小写 · trim；subject = `email:{addr}` |
| phone | 去空格；国内 11 位可补 `+86`；subject = `phone:{e164}` |
| 兼容 | 仍接受裸 `subject`（历史/OIDC sub） |
| 展示 | 列表优先显示 email/phone；无则显示 subject |
| **验证码** | **延期**：不发短信/邮件；本刀只做识别与入库键 |

可选目录 `_PERSONS[subject] = { email?, phone?, displayName? }`，加人时写入，便于列表展示。

## 3. API

| 变更 | 说明 |
| --- | --- |
| `POST …/members` | body 增 `email?` · `phone?`（与 `subject` 三选一优先：email > phone > subject） |
| `GET …/members` | 每项可带 `email` · `phone` · `displayLabel` |
| 校验 | email/phone 格式非法 → 400 |

邀请链接 / 申请加入后续可同样填 email/phone（本刀先打通成员页）。

## 8. 本人资料维护（v1.1）

| 项 | 已决 |
| --- | --- |
| 谁 | 当前登录用户维护 **自己的** 资料 |
| 可改 | `displayName` · `email` · `phone` · `title` |
| 不可改 | 登录 **subject**（如 `user:dev`）— 改联系方式只更新档案，不改 Membership 键 |
| API | `GET /v1/me` 带 profile；`PATCH /v1/me/profile` |
| UI | 侧栏「我的资料」`/settings/profile`；**不展示**「当前登录标识 …」开发腔说明 |
| 输入框视觉 | 必须用蓝图暗色输入（`aos-input` / 同系 CSS），**禁止**浏览器默认白底；对齐 [80](80-蓝图按钮体系与复杂交互页层次规范.md) 与成员页 `aos-members-form` |

验证码绑定邮箱/手机仍后置。
