## 0. 一句话结论


| 问题             | 结论                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| AOS 是不是只能私有化？  | **主路径 = 私有化**；**商业上允许**对小客户做 **SaaS（包月/包年）**。同一套产品与契约，换的是「云落在谁机房」                                                |
| 端云怎么分？         | **端 = 人用的 Client**（**桌面端必选产品位** + Web 端）；**云 = 控制面 + 数据面**（aos-api / Ontology / AIP / L1 / IdP…），部署在客户机房或我方多租户机房 |
| 为什么必须有桌面端？     | AOS 自称 **操作系统**：桌面安装带来 **「本地 OS 私有主权获得」**；Web 是协作与轻量入口，**不能替代**桌面产品位                                             |
| 和 20a 工作区什么关系？ | 工作区隔离发生在 **云侧会话与数据**；端只持有登录态 + 当前工作区上下文，**不**在端上另造租户库                                                            |
| 大客户 vs 小客户差在哪？ | **同一端、同一 API**；差在云的部署权属、Org 数量、运维责任与计费，不差「另一套前端」                                                                 |
| **端上哪些菜单、运维哪些菜单？** | **三层 UI（§5）**：① 业务座舱 + ② 工作区/组织管理 = **端**；③ Apollo/集群/开通台 = **运维控制台**；审批人仅环境**只读**；配模型不碰 Vault |

## 1. 端云定义（产品语言）



### 1.1 两端一云（逻辑）

```text
┌─────────────────────────────────────┐
│  端 · Client Plane（人操作的地方）      │
│  · 桌面端（Tauri 等）★ 产品必选位        │
│  · Web 端（浏览器）                    │
│  · （可选）移动 / 嵌入 — 本期非目标       │
└─────────────────┬───────────────────┘
                  │ 仅 HTTPS → aos-api（+ IdP）
                  │ Bearer · 工作区会话 · 禁止直连引擎
┌─────────────────▼───────────────────┐
│  云 · Cloud / DC Plane（算力与数据）    │
│  · 控制面：aos-api · 身份 · 授权 · 发布 │
│  · 数据面：PG/图/湖/对象存储/向量 …      │
│  · 边车：LLM 网关 · OCR · 分析 runtime │
│  落点：客户机房 或 我方 SaaS 机房         │
└─────────────────────────────────────┘
```


| 平面    | 产品 UI 说法    | 技术落点                            | 不做什么                                   |
| ----- | ----------- | ------------------------------- | -------------------------------------- |
| **端** | 桌面端 / 网页端   | `apps/desktop` · `apps/web`     | 不直连 LiteLLM / Vault / OpenFGA / 厂商 LLM |
| **云** | 平台服务 / 机房服务 | `services/`* · `deploy/*` · IdP | 不把业务状态只存在浏览器 localStorage 当真源          |




### 1.2 「云」不一定是公有云


| 说法              | 含义                                           |
| --------------- | -------------------------------------------- |
| **云（本方案）**      | 相对「端」而言的 **服务端聚合**：控制面 + 数据面                 |
| **私有化机房**       | 云部署在 **客户** DC / VPC —— 仍叫端云分离               |
| **SaaS 机房**     | 云部署在 **我方** 多租户环境 —— 端仍是同一套 Client           |
| **Local-First** | 云进程跑在 **本机**（桌面旁路拉起 compose/边车）—— 端云同机，契约仍分离 |


**已决：** 话术上可说「端云分离」；销售上区分 **专有云/私有化** 与 **SaaS**，避免客户以为必须上公有云。

## 2. 与既有部署四形态的对齐（20 §2.3）


| 20 形态               | 云落点                         | 端怎么连                     | 20a Org/工作区                    | 典型商务            |
| ------------------- | --------------------------- | ------------------------ | ------------------------------ | --------------- |
| **Local-First 工作站** | 本机服务                        | 桌面为主；Web 可指 localhost    | 常 1 Org · 可隐藏工作区切换             | 试用 / PoC        |
| **单机房私有化**          | 客户机房（Compose/K8s · 单 Spoke） | **桌面 + Web** 指向客户入口域名    | **1 Org · 多工作区**（20a P0）       | **标准企业 · 全套部署** |
| **Hub + 多 Spoke**   | Hub 控制面 + 多地数据 Spoke        | 端连 Hub 控制面；数据面按 Spoke 策略 | 多 Org / 工作区；数据不跨 Spoke 串读      | 集团 / 强付费        |
| **气隙 / Ferry**      | 隔离网内云                       | 端仅内网；升级靠 Bundle          | 同私有化                           | 高安全             |
| **（商业补充）SaaS**      | **我方**多租户机房                 | 桌面 + Web 指向 SaaS 域名      | **多 Org**（每客户一 Org）；工作区模型同 20a | **小公司 · 包月/包年** |


> SaaS **不是**推翻私有化主路径，而是同一产品的 **托管交付 SKU**。代码路径不删 `org_id`（20a / T-CROSS）。

## 3. 商务 SKU 与技术映射（自洽）



### 3.1 两类主卖法


| SKU             | 谁买            | 云谁运维               | 端发给谁                     | 计费直觉        |
| --------------- | ------------- | ------------------ | ------------------------ | ----------- |
| **A · 企业全套私有化** | 付费能力强 · 要数据主权 | **客户**（我方可交付实施/维保） | 全员装 **桌面端** + 浏览器书签/门户   | 项目制 / 年维保   |
| **B · SaaS 订阅** | 小公司 / 快速上线    | **我方**             | 同一桌面端（改服务器地址或内置渠道包）+ Web | **包月 / 包年** |




### 3.2 同一产品钉死（禁止因 SKU 分叉）


| 钉                       | 说明                                                               |
| ----------------------- | ---------------------------------------------------------------- |
| **同一** `aos-api` **契约** | Web / Desktop 只依赖 T-API；无「SaaS 专用 API」旁路                         |
| **同一工作区模型**             | [20a](20a-多用户与工作区整站隔离方案.md)：Org · 工作区 · Membership · 插件目录共用/配置按区 |
| **同一 UI 语言**            | foundry/html → ui-kit；桌面内容区与 Web **同构路由**（T-UI S3）               |
| **同一禁演示壳**              | R-PROD-*：无演示临时页；案例用正式工作区（如微信商城案例）                                |
| **桌面必选产品位**             | 两个 SKU **都提供桌面安装包**；SaaS 不「只给网页」                                 |




### 3.3 SKU 差异（允许不同）


| 维度            | SKU A 私有化                | SKU B SaaS      |
| ------------- | ------------------------ | --------------- |
| 默认 Org 数      | 1（可扩）                    | N（每租户一 Org）     |
| IdP           | 客户 Keycloak / 企业 IdP（24） | 我方托管 IdP 或社交/账密 |
| 数据驻留          | 客户机房                     | 我方区域约定          |
| 升级            | Apollo Channel / Ferry   | 我方滚动发布          |
| 桌面默认 API Base | 客户域名（可 MDM 下发）           | SaaS 域名（渠道包预置）  |
| 测试工作区         | 客户可有；开发种子可删              | 租户内可选；平台级测试区隔离  |

## 4. 端侧方案（桌面 ★ + Web）



### 4.1 产品定位


| 端         | 产品 UI 名                        | 定位                                | 获得感              |
| --------- | ------------------------------ | --------------------------------- | ---------------- |
| **桌面端**   | **AOS 桌面**（安装器/关于页可用「AOS 工作站」） | **主座舱**：日常办公默认入口；托盘、本地缓存、深链 OS 集成 | **「给我装了本地操作系统」** |
| **Web 端** | **AOS 网页版**                    | 轻量协作、临时机器、IT 门户嵌入                 | 不替代桌面叙事          |


**已决：** 对外宣传与报价清单中，**桌面端为标准配置项**，不得标成「仅企业版才有」；SaaS 客户同样下载桌面端。

### 4.2 桌面端能力分层


| 层               | 能力                                      | 说明                                 |
| --------------- | --------------------------------------- | ---------------------------------- |
| **壳**           | 窗口 · 托盘 · 自动更新 · 深链协议 `aos://`          | 自 v0.1 Tauri 演化（20 / T-UI）；壳保留、页替换 |
| **连接**          | 可配置 **平台地址**（API Base / IdP）；企业 MDM 可锁定 | 私有化与 SaaS 只换地址与证书钉扎                |
| **会话**          | Refresh 由桌面安全管理；Access → aos-api        | 对齐 T-CROSS                         |
| **工作区**         | 与 Web 同一切换器语义（20a）                      | 切区清缓存                              |
| **离线**          | 只读快照缓存；写路径排队待同步（T08 §4.5）               | **禁止**离线直写生产                       |
| **Local-First** | 可选「**本机平台**」模式：拉起/探活本机 compose（**禁止**称 Apollo） | 试用壳能力；仍走 aos-api，不直连引擎 |




### 4.3 Web 端


| 项   | 已决                                         |
| --- | ------------------------------------------ |
| 工程  | `apps/web`；与桌面共享 ui-kit / contracts-client |
| 场景  | 会议室、临时 PC、管理员门户 iframe                     |
| 限制  | 无托盘/弱离线；**不**承担「OS 获得感」主叙事                 |




### 4.4 端侧禁止事项


| 禁止                         | 原因           |
| -------------------------- | ------------ |
| ❌ 端直连数据库 / MinIO / LiteLLM | R-ARCH-01    |
| ❌ SaaS 与私有化两套 UI 仓库长期分叉    | 成本与缺陷翻倍      |
| ❌ 「演示桌面」精简壳冒充产品            | R-PROD；桌面即产品 |
| ❌ 把工作区数据全量镜像到端上当主库         | 主权与一致性风险；仅缓存 |

## 5. 端云 UI 切分（已决）

> **总原则：** 按「谁在什么场景干活」切，不按 Web/桌面技术栈切。  
> **一句话：** **端 = 业务操作系统座舱（桌面主入口 + Web 同构）+ 工作区/组织管理；另设运维与交付控制台，Apollo 默认整域在运维面；大模型/采集 = 目录在平台、配置在工作区。**

### 5.1 切分原则

| # | 原则 | 含义 |
| --- | --- | --- |
| P1 | 按角色与场景切，不按技术栈切 | Web/桌面都是端；差在壳能力，不差「业务 vs 运维」菜单归属 |
| P2 | 端 = 业务操作系统座舱 | 一线打开就能干活：数据、本体、决策、工作台、AIP 使用 |
| P3 | 运维/交付面独立 | 装在哪、升什么版、集群健康、租户开通 —— 不默认给每个业务同事 |
| P4 | 同一能力可「端上看结果、云上配策略」 | 例：端里用已配置大模型；网关/密钥治理在运维面 |
| P5 | **Apollo 默认归运维/交付面** | Change / Release / Spoke / Ferry ≠ 一线业务主座舱 |

**澄清：** 「端」≠「只有桌面才有的页面」。**端 = Client 上给业务用户的产品 UI**。运维页可以也是 Web，但是 **另一入口 / 另一角色**（甚至 `ops.` 子域或桌面内「平台管理」需 admin）。

### 5.2 三层 UI（比「端 vs 云」两分更稳）

```text
① 业务座舱（端 · 全员）              ← 桌面主叙事 + Web 同构
② 工作区 / 组织管理（端内 · 管理员）   ← 仍在产品壳，权限收紧
③ 平台运维与交付（运维控制台）         ← Apollo、集群、升级、SaaS 开通台
```

| 层 | 谁用 | 宿主建议 | 与端云关系 |
| --- | --- | --- | --- |
| **① 业务座舱** | 业务员、审批人、分析员 | 桌面默认首页 + Web 同构路由 | **端** |
| **② 工作区/组织管理** | 工作区管理员、组织管理员 | 同一产品壳内「设置 / 管理」 | **端内**（仍是产品，非 Apollo） |
| **③ 平台运维与交付** | 客户 IT / 平台运维 / 我方 SaaS 运营 | 独立运维控制台或强权限入口 | **云侧运维面** |

**已决：** ② 留在端产品里；③ 独立成运维控制台。禁止把 ② 与 ③ 混成同一主导航。

### 5.3 按域归属

#### 5.3.1 归端 · 业务座舱（一线天天用）

- 概览 / COP（**业务态势**，不是机房监控）
- **数据**：连接与同步的业务使用态（「我的链路是否可用」）
- **本体 / Wiki / Action / Draft 业务审批台**
- **Workshop** 模块与画布
- **AIP**：对话、Agent、Logic 的**业务编排与使用**（当前工作区）
- **分析建模** 等产品能力
- **工作区切换**、个人设置、业务通知

桌面特有（仍是端壳，不是新业务域）：托盘、平台地址、离线只读缓存、自动更新。

#### 5.3.2 归端内 · 组织 / 工作区管理（管理员）

- 工作区创建 / 成员 / 角色（对齐 [20a](20a-多用户与工作区整站隔离方案.md) Membership）
- 本工作区 **已配置大模型**、已启用采集链路实例（配置私有）
- 本组织内 **插件目录选用**（浏览「能装什么」并启用到本区）
- 组织级默认工作区等（若需要）

> 对标 Dify「工作区设置」——**不进 Apollo**。

#### 5.3.3 归运维控制台（云/运维面）

| 域 | 归属 | 理由 |
| --- | --- | --- |
| **Apollo 交付**（Channel / Spoke / Promote / Ferry / 气隙包） | **运维面** | 版本与制品通道，非业务决策主路径 |
| 集群健康、容量、备份、证书、探针大盘 | 运维面 | 机房叙事；端最多深链 |
| SaaS **开通租户 / 配额 / 计费** | 运维面（我方） | 不给租户业务员 |
| IdP / Realm 联邦、全局安全策略 | 运维面或客户 IT 门户 | 超出业务座舱 |
| 平台级插件上架、签名、SBOM、强制升级策略 | 运维面 | 「目录从哪来」；端只消费已上架目录 |
| 多 Spoke 拓扑、数据驻留策略 | 运维面 | Hub/Spoke 部署决策 |

**端上对 Apollo 的克制（已决）：**  
业务座舱 **不以 Apollo 为一级主导航**。业务侧若需感知环境，仅允许 **只读徽章/状态**（见 §5.5）；变更/晋升进运维面或仅 `platform_admin` 可见入口。

### 5.4 灰区钉死：插件目录 vs 工作区配置

| 界面 | 放哪 | 说明 |
| --- | --- | --- |
| **可选插件目录**（能选哪些模型 / 连接器） | 端内可浏览；**上架/签名在运维面** | 20a「目录共用」 |
| **本工作区已配置大模型 / 已配链路** | **端 · 工作区设置** | 20a「配置按区」 |
| **网关进程、Vault/密钥保险库、限流熔断** | **运维面** | 端只选用目录项 + 填 secret ref |

**已决：** 业务在端里「选用并配置」；平台在运维面「供给与治理」。

### 5.5 产品拍板（三问已决）

| # | 问题 | 已决 |
| --- | --- | --- |
| **1** | 业务审批人要不要操作版本晋升？ | **只要知情** → 业务座舱仅 **只读状态/徽章**（如「当前环境：生产」）；**不**在座舱做 Promote/Recall |
| **2** | 工作区管理员配大模型能否碰 Vault/网关？ | **不能**。只选插件目录项 + 填 secret ref / 工作区参数；密钥与网关运维在运维面 |
| **3** | 桌面是否做本机 Local-First 一键起平台？ | **可以**，作为试用 **壳能力**；产品文案叫 **「本机平台」**，**禁止**叫做 Apollo |

### 5.6 桌面 vs Web（同属端）

| | 桌面 | Web |
| --- | --- | --- |
| 业务菜单（①②） | **同构** | **同构** |
| 额外 | 安装感、托盘、API 地址、离线只读、更新、「本机平台」 | 无 / 弱 |
| 不建议 | 桌面独有一套 Apollo 深页当主卖点 | 仅 Web、无桌面冒充 OS |

**获得感**来自 **桌面壳 + 同一业务座舱**，不是来自「桌面多几个运维菜单」。

### 5.7 私有化 vs SaaS（菜单几乎不变）

- **①② 业务座舱 / 工作区管理**：两 SKU **同一套端 UI**
- **差异只在 ③ 运维面**：私有化 → 客户 IT 用 Apollo/集群台；SaaS → 我方开通/配额台；租户管理员仍只用端内组织/工作区

禁止：「SaaS 一套网页业务导航、私有化另一套桌面业务导航」。

### 5.8 目标态信息架构（相对现状）

| 现状（诚实） | 目标态 |
| --- | --- |
| Web 中 Apollo / 部分平台页与业务页同壳（便于演示） | 默认登录进 **① 业务座舱** |
| 运维与业务导航易混 | `platform_admin` 才见 **③ 平台运维**（或独立 `ops` 宿主） |
| Apollo 易出现在一级导航 | Apollo **整域**在运维面；座舱最多只读环境徽章 |

### 5.9 角色 × UI 层（速查）

| 角色 | ① 业务座舱 | ② 工作区/组织管理 | ③ 运维控制台 |
| --- | --- | --- | --- |
| 业务员 / 分析员 | ✅ | ❌（或只读自己资料） | ❌ |
| 业务审批人 | ✅（含 Draft）；环境 **只读** | 按授权 | ❌ |
| 工作区管理员 | ✅ | ✅（成员、已配置模型/链路） | ❌（不碰 Vault/网关） |
| 组织管理员 | ✅ | ✅（工作区生命周期） | 视客户授权（通常有限） |
| 平台运维 / 客户 IT | 可选 | 可选 | ✅（Apollo、集群、IdP） |
| 我方 SaaS 运营 | ❌（或不进租户座舱） | ❌ | ✅（开通/配额/计费） |

## 6. 云侧方案（机房 / SaaS）



### 6.1 逻辑组件（两端共用）

```text
[IdP] ──OIDC──► [aos-api / BFF]
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   Ontology/L2   AIP/L3     L1/Pipeline
        │           │           │
        └───────────┴───────────┘
                    ▼
            存储 · 图 · 对象 · 向量
```

边车（LLM 网关、OCR、分析 runtime 等）属云侧；端不可见实现细节。

### 6.2 私有化标准企业（SKU A）拓扑

```text
客户机房
  ├── IdP（客户或我方交付）
  ├── aos-api + 数据面 + 边车
  └── （可选）Apollo Spoke
同事 PC
  ├── AOS 桌面 ──HTTPS──► 客户入口
  └── 浏览器 Web ────────► 同一入口
```

- 工作区：销售 / 供应链 / **测试工作区**（可删）/ 正式案例工作区（如微信商城）  
- 插件目录共用；已配置大模型按工作区（20a §3.4.2）



### 6.3 SaaS（SKU B）拓扑

```text
我方机房（多租户）
  ├── 托管 IdP
  ├── 共享或按租户隔离的控制面/数据面
  └── Org 硬隔离（20a）；计费/配额在控制面扩展（实现刀另开）
租户员工
  ├── AOS 桌面（预置 SaaS Base URL）
  └── Web
```


| 规则           | 说明                                            |
| ------------ | --------------------------------------------- |
| **租户 = Org** | 小公司默认 1 Org + 多工作区；禁止租户间数据可见                  |
| **插件目录**     | 平台级共用目录；已配置实例仍按工作区                            |
| **桌面渠道包**    | 可打「SaaS 版」安装包（仅默认 endpoint / 品牌渠道），**业务代码同构** |




### 6.4 Hub + 多 Spoke / 气隙

- 端仍只连 **控制面入口**；不直连各 Spoke 存储。  
- 与 20a P3 / T09 一致：工作区模型不变，多的是部署与数据主权边界。

## 7. 会话、工作区与端的协作（接 20a）

```text
用户打开桌面/Web
  → IdP 登录
  → aos-api 发会话（含 org · 可进入的工作区列表）
  → 用户选择「工作区」（或恢复上次）
  → 之后所有 API 带服务端认可的工作区上下文（R-ISO-01）
  → 端侧缓存仅服务当前工作区；切换则清空
```


| 端职责               | 云职责                           |
| ----------------- | ----------------------------- |
| 展示工作区切换器（中文「工作区」） | Membership 校验 · 双字段过滤 · Audit |
| 保存「上次工作区」偏好（可本地）  | 权威成员关系与资源归属                   |
| 离线只读缓存（可选）        | 上线后冲突与 Draft 同步               |


**测试工作区 / 案例工作区：** 只是云侧数据分区；端无「演示模式」开关（20a R-PROD）。

## 8. 安全与合规（端云交界）


| 项    | 已决                                                          |
| ---- | ----------------------------------------------------------- |
| 传输   | 生产强制 TLS；企业可双向 TLS / 专线                                     |
| 令牌   | Access 短寿命；Refresh 桌面安全存储；Web 跟 BFF/Cookie 策略（实现对齐 T-CROSS） |
| 证书钉扎 | 桌面可选（高安全客户）                                                 |
| 数据出境 | SaaS 合同约定区域；私有化默认不出客户机房                                     |
| 审计   | 登录、切工作区、端版本、API Base 变更进 Audit                              |
| Dev  | `Bearer dev` 仅本机；**不得**进桌面正式包默认配置                           |

## 11. 验收标准


| #   | 标准                                                      |
| --- | ------------------------------------------------------- |
| C1  | 架构图与话术能分清：端 = Client；云 = 机房/SaaS 服务端；Local-First = 云在本机 |
| C2  | 报价/产品清单中 **桌面端为标准项**；SaaS 与私有化均提供桌面安装                   |
| C3  | Web 与桌面只调 `aos-api`；无引擎直连                               |
| C4  | 切换私有化域名 ↔ SaaS 域名，**无需换业务功能集**（配置/渠道包即可）                |
| C5  | 工作区行为与 [20a](20a-多用户与工作区整站隔离方案.md) 一致；端无演示模式            |
| C6  | 私有化 SKU：数据默认不出客户机房；SaaS SKU：Org 间硬隔离可测                  |
| C7  | 桌面具备可陈述的「OS 获得感」要素：安装器、托盘/关于页、本地更新或明确版本号（实现刀落实）         |
| C8  | 业务座舱不以 Apollo 为一级主导航；业务审批人仅见环境**只读**状态，无 Promote |
| C9  | 工作区管理员可配「已配置大模型」但不可直达 Vault/网关运维；运维面单独承载 |
| C10 | Local-First 入口产品名 = **本机平台**（非 Apollo） |

## 12. 非目标


| 非目标                           | 原因                |
| ----------------------------- | ----------------- |
| ❌ 以「只有 Web 的纯 SaaS」作为 AOS 主品牌 | 削弱操作系统获得感         |
| ❌ 为 SaaS 另起租户模型取代 Org/工作区     | 与 20a 分裂          |
| ❌ 桌面内嵌完整数据面当主库                | 变成另一套 Local DB 产品 |
| ❌ 端侧实现计费收银台（可链到运营台）           | 控制面职责             |
| ❌ 本文件直接编码桌面                   | 先方案；桌面回迁另开实现刀     |
| ❌ 业务座舱一级导航挂满 Apollo           | Apollo 属运维面（§5） |
| ❌ 工作区管理员直操 Vault/LLM 网关进程     | 只选目录 + secret ref（§5.5） |
| ❌ 将 Local-First 称为 Apollo         | 产品名「本机平台」（§5.5） |
