### 4.2 Pipeline（管道编排）

**产品方案要求**（[05](../05-数据集成Connectors-Pipeline-Dataset产品方案.md) §4 · [05a](../05a-数据集成Connectors-Pipeline-Dataset产品设计线框图.md) WF-PB-01~02b · Foundry [pipeline-builder/core-concepts.md](../foundry/pages/zh/foundry/pipeline-builder/core-concepts.md) · [pipeline-builder/navigation.md](../foundry/pages/zh/foundry/pipeline-builder/navigation.md) · [pipeline-builder/transforms-overview.md](../foundry/pages/zh/foundry/pipeline-builder/transforms-overview.md) · [pipeline-builder/outputs-overview.md](../foundry/pages/zh/foundry/pipeline-builder/outputs-overview.md) · [pipeline-builder/management-overview.md](../foundry/pages/zh/foundry/pipeline-builder/management-overview.md)）：

**界面布局（四区域 + 三视图）**：
- **顶部工具栏**：撤销/重做、分支下拉、保存、提议、部署、搭建设置（默认/中型/大型）、搭建检查状态、分享
- **详细信息侧栏**：描述、查看次数、关注者、评论、协作者、访问权限（组织/权限标记）、角色管理、位置/修改时间
- **图表区域**：平移模式、拖动选择、添加数据集、参数配置、变换选择（变换/合并/联合）、编辑、图例颜色、输出侧栏（数据集/Object类型/链接类型）、缩放设置
- **预览面板**：节点数据预览、列名搜索、右键打开完整预览
- **三视图**：编辑（Edit）、提案（Proposals）、历史记录（History）

**变换类型（表达式 + 表变换）**：
- **表达式**（单列输入 → 单列输出）：Cast、Concatenate strings、Length、Split string、Trim、Replace、Regex extract/replace、Substring、Case when、If/Else、Round、Floor/Ceil、Date formatting、Timestamp parsing、Array operations
- **表变换**（整表输入 → 整表输出）：Filter、Drop columns、Keep columns、Rename columns、Pivot、Unpivot、Sort、Aggregate（Group by）、Window（Rank/Lead/Lag）、Explode、Distinct、De-duplicate、Derive（衍生列）
- **Join（合并）**：左/右/内/外合并、多条件匹配、预览、高级配置（列选择/右表前缀）
- **Union（并集）**：模式一致性检查、重复行保留/去除
- **UDF（用户定义函数）**：Python/Java 自定义代码、版本化、可重用

**输出类型**：
- 数据集输出（Dataset）
- 地理时间序列同步（GeoTemporal Series）
- Ontology 输出：对象类型、对象链接类型、时间序列

**管理功能**：
- 参数（Parameters）：可重用的变换参数
- 自定义函数（Custom Functions）：集中定义的变换序列
- 文件夹（File Tree）：节点分组组织
- 颜色分组（Color Groups）：折叠相同颜色节点提高可读性
- 任务分组（Job Groups）：输出分配到任务、计算配置文件
- 检查点（Checkpoints）：中间结果缓存节省计算
- 输入采样（Input Sampling）：降采样预览加速原型设计

**代码实现**：
- 后端：aos-api 内嵌（无独立 pipeline service）· [data_os_store.py](file:///C:/work/projects/wchat/aos-platform/services/aos-api/aos_api/data_os_store.py)（meta_pipeline 表）

### 4.7 Compute Modules（计算模块 · 无服务器容器）

**对照基准**：
- 文档：[foundry/pages/zh/foundry/compute-modules/](file:///C:/work/projects/wchat/docs/palantier/foundry/pages/zh/foundry/compute-modules) 全部 6 个官方文档
- 截图：Compute Module Configure 标签（Containers/Runtime/Volumes/Scaling/External access + 容器详情侧栏 Image/Tag/Env/Volume mounts/Resource constraints/Telemetry/Format/Container log source）· CPU Request/Limit 弹窗 · Scaling 面板特写（Minimum/Maximum replicas + Request concurrency limit）

**产品方案要求**（[foundry/compute-modules/overview.md](../foundry/pages/zh/foundry/compute-modules/overview.md)）：
- **无服务器 Docker 镜像**：在 Foundry 中按负载水平扩缩，由前端应用（Workshop / Slate）调用
- **副本 + 多容器架构**：每个计算模块由若干副本组成；每副本含 1~N 容器；其中 1 个为入口点（需实现永久轮询客户端）
- **多语言支持**：任何可容器化的语言（不限于 Foundry 原生支持语言）
- **应用场景**：集成现有代码库、自定义逻辑、动态扩缩、外部/平台内连接
- **避免场景**：动态垂直扩缩（资源静态/手动）、替换 Foundry 原生能力
- **核心 API**：服务端长轮询下发任务（`/interactive-module/api/internal-query/job`），客户端处理后回传结果（`/interactive-module/api/internal-query/results`）
- **三标签页**：Overview / Query / Configure
- **Configure 区**：
  - Containers 表（NAME / REPOSITORY / IMAGE / TAG）· Add container
  - Runtime（No Runtime · Runtime V1）
  - Volumes（Add volume，副本内容器共享卷）
  - Scaling（Minimum/Maximum replicas + Request concurrency limit 每副本并发）
  - External access（Foundry data / Foundry services / external domains）
- **容器配置侧栏**：Image / Tag / Environment variables / Volume mounts / Resource constraints（CPU Request+Limit / GPU Set / Memory Set）· Telemetry 开关 / Format（Plain text 等） / Container log source（Standard output / Log files）
- **CPU 弹窗**：Request（必填，默认 1）+ Limit（可选，单位 M/G）
- **Artifact Repository 发布**：New → Artifacts Repository → Publish → Docker → Image Name（不支持 `latest` 标签）→ docker push
- **本地开发**：
  - 必备 API 端点（`getJobPath` / `postResultPath`）· 连接信息文件 `CONNECTION_TO_RUNTIME` · 认证 token `MODULE_AUTH_TOKEN` · SSL 证书 `CONNECTIONS_TO_OTHER_PODS_CA_PATH` · 端口 8945
  - Dockerfile（`FROM --platform=linux/amd64 python:latest` + `USER 5000` + `CMD ["python", "app.py"]`）· requirements.txt · `src/app.py` 模板（长轮询 + 任务路由 + 异常重试）
  - `docker build -t mycomputemodule:0.0.1 .`
- **Foundry 内创建**：New → Code Repository → Compute Module → 选语言 → Initialize → `app.py`（不能改路径，函数名即端点名） + `meta.yaml`（依赖） + `gradle.properties`（`userImageName` / `baseImageTag` ≥ 0.15.0） → Commit → Tag version → 触发 Docker 镜像搭建
- **Query 标签**：函数名 + 参数 → Run → 看到结果（缩容至零时首次需等待）
- **定价模型**：vCPU / T4 / V100 / A10G 计算秒（副本数 × 每副本 vCPU/GPU/RAM × 时间 × 系数）；`vcpu_compute_seconds = max(vCPUs_per_replica, GiB_RAM_per_replica / 7.5) * num_replicas * vcpu_usage_rate * time_active_in_seconds`
- **预测扩缩**：跟踪历史查询负载 → 预先扩容；不准确时快速回收；不超最大副本
- **默认资源**：未配置时 1 vCPU + 4 GB RAM + 0 GPU

### 5.3 Action / Function

**产品方案要求**（[06b](../06b-Action与Function产品设计.md) · [06](../06-语义本体Ontology-Mapping产品方案.md) §7 · [06a](../06a-语义本体Ontology-Mapping产品设计线框图.md) WF-OM-05/06）：

**Function（算力核）FUNC-SPEC**：
- **类型安全**（FUNC-01）：Object Schema → TS 接口；类型不一致保存即失败
- **执行环境**（FUNC-02）：服务端隔离沙箱；默认可调用 Ontology 只读 API
- **性能约束**（FUNC-03）：单次执行 ≤60s；内存上限 2GB/次；禁止全表盲扫
- **无 UI**（FUNC-04）：Function 不直接渲染表单；由 Workshop / Action Logic 调用
- **可组合**（FUNC-05）：可被其他 Function / Action Logic 复用（壳核模式）
- **资源隔离**（FUNC-06）：超内存/超时由 Runtime 杀进程

**Action（交互壳）ACT-SPEC**：
- **单一职责**（ACT-01）：一个 Action = 一个业务意图
- **强校验**（ACT-02）：必须配置 **Submission Criteria**（提交标准）
- **写回协议**（ACT-03）：变更写入 L1 Write-back Dataset 或 Ontology Changelog；**严禁绕过 L1 直写底层**
- **副作用声明**（ACT-04）：邮件/钉钉/外部 API 必须显式声明 Notification / Webhook
- **乐观 UI**（ACT-05）：前端先改本地态；失败回滚
- **可调用 Function**（ACT-06）：Logic 可编排 Function（核），Action 只做壳
- **幂等**（ACT-07）：同一 idempotencyKey/业务键重复提交不产生重复
- **软删除协议**（ACT-08）：删除类 Action 写 is_deleted；禁物理抹行
- **Draft 隔离存储**（ACT-09）：Draft 态写入独立 Dataset，与生产物理隔离
- **副作用重试**（ACT-10）：Webhook 失败 retry×3 → DLQ → 人工重放

**壳核模式**：Action（交互壳）+ Function（算力核）组合；Function 负责计算，Action 负责表单、权限、副作用

## 12. W1 分支建议优先项

基于差距优先级，w1 分支建议聚焦以下几项（高优先级 + 中优先级中影响面大的）：

| 序号 | 项 | 理由 |
| --- | --- | --- |
| W1-1 | **Function 表达式引擎** | Action 的核心增强；HR-01 要求 LLM 不直写 Ontology，须经 Action + Function |
| W1-2 | **Logic 编排真接入** | AIP 最大缺口；LangGraph 参考落地 |
| W1-3 | **Funnel 可视化映射编辑器** | L1→L2 链路关键环节；当前可视化弱 |
| W1-4 | **Build 引擎** | Pipeline 执行核心；Job/JobSpec + 事务锁定 |
| W1-5 | **Funnel 四阶段管道** | L2 核心引擎；Changelog/Merge/Indexing/Hydration |
| W1-6 | **Action 写回协议** | L1→L2→L1 闭环核心；ACT-03 约束 |
| W1-7 | **壳核模式** | Action 调用 Function；FUNC/ACT 规范落地 |
| W1-8 | **Transform 算子库** | Pipeline 核心能力；Filter/Join/Aggregate/Explode |
| W1-9 | **MediaReference 桥接** | 非结构化→结构化关键桥梁；L1 链路核心 |
| W1-10 | **Function 类型安全 + 沙箱** | FUNC-01/FUNC-02；运行时安全基础 |
| W1-11 | **Pipeline 重试机制** | 数据集成稳定性基础 |
| W1-12 | **Evals 评测集** | AIP 质量控制；LLM 输出可信度基础 |
| W1-13 | **Data Lineage 可视化** | 数据可追溯性基础；管道调试必备 |
| W1-14 | **Functions Python Builder** | Pipeline 与函数集成；UDF 在管道中使用 |
| W1-15 | **Dataset Preview SQL控制台** | 数据验证与调试；开发效率关键 |

**停车场项（w1 不开）**：Iceberg / Parquet / 真 Jupyter / Full Spoke / Helm / 200+ Connector / 分布式追踪 / Capability Adapter 重能力 / **OKF 垂直 Schema 预训练**（后续电商预训练补入）/ Agent Proxy / Agent Worker / Linter / Foundry Rules / Dynamic Scheduling / Interfaces / **Compute Module 真 K8s 编排** / **Compute Module 多语言支持**。
