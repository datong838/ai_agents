## 一、系统性问题（全站通病）

通过分析首页（`/`）和组件注册表（`/workshop/widget-registry`）两个样本，发现以下系统性问题在大量页面重复出现：

### S1. 内容宽度不一致
- **视觉稿**：每个页面的 `.p-content` 内容区**撑满**侧栏右边缘（`px-6`，无 max-width）
- **实现**：多数页面用 `.content-inner { max-width: 72rem (1152px) }` 或自定 `max-w-[1200px]` 居中限宽
- **影响**：内容区两侧出现不等宽留白，视觉松散
- **修正方向**：live 页面去掉居中限宽，撑满 `.p-content`；仅保留视觉稿中明确限宽的页面（如首页 900px）

### S2. PageChrome 标题区与页面内 header 重复
- **视觉稿**：标题+描述只出现**一次**（在 `.p-content` 内容流中裸放）
- **实现**：`PageChrome` 组件渲染了一个 `<header class="page-chrome">`，但很多页面又在内容区**重复**写了一组 `<h1>+<p>`
- **影响**：双标题区，视觉冗余
- **修正方向**：每页只保留一处标题区。如果页面有自己的 header，去掉 PageChrome 的 title/lede；反之去掉页面内的重复 header

### S3. 页面内多余的工具栏/搜索框
- **视觉稿**：搜索框在**顶栏**（`.p-header-center .p-search`），页面内没有搜索框
- **实现**：很多页面用了 `BpToolbar` 组件在页面内再放一个搜索框
- **影响**：搜索功能重复
- **修正方向**：评估每个 BpToolbar 是否视觉稿中有对应。视觉稿没有的，移到顶栏或删除

### S4. 按钮规格不统一
- **视觉稿**：`.p-btn` 系列（primary 高度 32px，sm 高度 28px，圆角 4px，品牌色 `--p-blue: #2B6CB0`）
- **实现**：混用 `.btn`（padding 撑高度，无固定 height）、内联 `style` 按钮、`Link` 伪按钮
- **影响**：按钮高度/颜色/圆角不统一
- **修正方向**：统一到视觉稿 `.p-btn-*` 规范，固定高度 32px/28px

### S5. 卡片图标配色单一
- **视觉稿**：图标方块按**来源/类型**分色（indigo/amber/emerald）
- **实现**：多数统一用 `var(--aos-accent)` 蓝色
- **修正方向**：按视觉稿补齐分色逻辑

### S6. 视觉稿有但实现缺失的区块
- **现象**：底部 callout、快捷链接行、特定操作区等
- **修正方向**：逐页补齐

### S7. 实现有但视觉稿没有的区块
- **现象**：`BpMetricGrid` 指标网格、`BpBanner` 告警条等
- **修正方向**：与产品确认——保留（功能增强）还是删除（严格对齐）

### S8. 标题字号偏大（widget-registry 实践发现）
- **视觉稿**：页面标题用 Tailwind `text-xl` = **20px**
- **实现**：`.page-chrome h1 { font-size: 24px }` — 比 视觉稿 大 4px
- **影响**：标题视觉份量过重，与 视觉稿 的精致克制感不匹配
- **修正方向**：`.page-chrome h1` 从 24px → **20px**（已修，line 741）
- **覆盖范围**：**全站所有用 PageChrome 的页面**（~60+ 页）

### S9. 品牌色混用：accent(#2B6CB0) vs indigo-600(#4F46E5)（widget-registry 实践发现）
- **视觉稿**：存在**两套蓝色**，混用但各有分工：
  - `.p-btn-primary` 系列 → `--p-blue: #2B6CB0`（灰蓝，用于标准按钮）
  - Tailwind `bg-indigo-600` → `#4F46E5`（靛蓝，用于 tab 选中态、图标高亮、callout 按钮）
  - 73 个 视觉稿 中 13 个用了 indigo-600，主要集中在 widget-registry / aip-* / ontology-wiki 等页面
- **实现**：**一律用 `var(--aos-accent)`(#2B6CB0)**，没有区分两种蓝
- **影响**：Tab 选中态、底部 callout 等需要靛蓝的地方显示成灰蓝，色感不对
- **修正方向**：
  - 标准 `.p-btn-primary` 按钮保持 `--aos-accent`（#2B6CB0）— **不要改**
  - Tab 选中态、callout 按钮、图标高亮等**按视觉稿逐页判断**：如果 HTML 源码用了 `indigo-600`，则实现改用 `var(--aos-indigo-600)`
  - **判断方法**：grep 对应 HTML 文件中的 `indigo-600`
- **已修**：widget-registry 的 `.wr-tab.is-active`、`.wr-callout-primary`（line 7027, 7153）

### S10. 按钮偏高：line-height 继承导致撑高（widget-registry 实践发现）
- **视觉稿**：Tailwind 按钮使用**固定行高**（`text-xs`=16px, `text-sm`=20px），不继承 body
- **实现**：body 全局 `line-height: 1.5`，按钮未显式指定 → 小字号按钮被撑高
  - 12px 字号 + 1.5 行高 = 18px，加 padding 后比 视觉稿 高 2-4px
- **影响**：按钮看起来比 视觉稿 胖，不够精致
- **修正方向**：所有按钮/标签类**显式指定 line-height**，不继承 body
  - Tab/tag 类（12px 字号）→ `line-height: 16px`
  - 标准按钮（14px 字号）→ `line-height: 20px`
- **已修**：widget-registry 的 `.wr-tab`、`.wr-callout-primary`、`.wr-callout-secondary`
- **覆盖范围**：**全站所有按钮/tab/标签类 CSS 规则**（需要逐个检查）

### S11. Tab 微规格：padding / font-weight / hover（2026-07-28 对账复核）

对照视觉稿 Tailwind Tab（如 `px-3 py-1.5`）与实现（如 `.wr-tab` / 同类 tab）逐项核查：

| 项 | 视觉稿（HTML） | 实现 | 结论 |
|----|----------------|------|------|
| **内边距** | `px-3 py-1.5` = 水平 **12px** / 垂直 **6px** | CSS `padding: 6px 12px`（上/下 6 · 左/右 12） | ✅ **等价**，无遗漏 |
| **未选中 font-weight** | 未加 `font-medium`（默认 normal） | `font-weight: 400` | ✅ **一致** |
| **未选中 hover** | `hover:bg-gray-50`（`#F9FAFB`） | `hover: background: var(--aos-surface-hover)` | ⚠ **接近但不相同**（见下） |

**`--aos-surface-hover` 实测**（`packages/ui-kit/tokens.css` 浅色主题）：

| Token | 浅色值 | 与 gray-50 差 |
|-------|--------|---------------|
| `--aos-surface-hover` | `#F7F8FA` | 相对 `#F9FAFB` 略偏冷灰，肉眼几乎不可辨 |
| Tailwind `gray-50` | `#F9FAFB` | — |

- **修正方向**：默认可接受用 `--aos-surface-hover`（主题可切换、暗色主题也能工作）。若某页截图对比仍觉「hover 不够白」，再对该页显式对齐 `#F9FAFB` 或新增 `--aos-gray-50` alias，**不要**全局硬编码 hex。
- **SOP**：每页对账时把 Tab（及同类 chip/segmented）加入检查，避免只查主按钮。

### S12. 禁止把 Tailwind 工具类直接抄进 React（2026-07-28 变量管理器图1/图2 发现）

- **现象**：`VariablesPage` 使用 `grid grid-cols-4 gap-3`、`text-xl`、`aos-panel`、`flex`、`px-4` 等类名；React 工程**未接入 Tailwind**，类名全部失效 → 统计卡竖排塌陷、页面「很乱」。
- **视觉稿**：HTML Demo 有 Tailwind，所以同样的 class 在 `foundry/html/*.html` 里正常。
- **影响**：比配色问题更严重——**结构层直接坏掉**；只改 indigo 无法消除山寨感。
- **修正方向**：
  1. 对账时若发现 TSX 含 Tailwind 工具类 → 记为 P0，迁到 `styles.css` 的页面前缀类（如 `.vr-*`）
  2. SOP 检查清单增加第 13 项：**无依赖未构建的 Tailwind/utility class**
  3. 全站扫描：`rg "grid-cols-|text-\\[|flex-wrap|px-4 py-" apps/web/src/pages`

### S9 补充说明（与续修 G1 联动）

S9 已描述 accent vs indigo **双轨并存**。2026-07-28 复核强调：

> 系统主色 `--aos-accent` = `#2B6CB0`（偏灰蓝）；视觉稿大量使用 Tailwind `indigo-600` = `#4F46E5`（蓝紫）。**肉眼可辨**。
>
> **所有需要「视觉稿那种蓝紫色」的控件**（Tab 选中、主 CTA callout、发送按钮、保存按钮、链接强调色等）**必须走 `--aos-indigo-600`，禁止误用 `--aos-accent`。**
>
> `.p-btn-primary` / 标准壳层主按钮仍走 `--aos-accent`（视觉稿 `--p-blue`），**不要全局替换**。

详见 **§六-B 续修 G1**。

│  Step 1: 读取 HTML 视觉稿源码               │

### 10 项检查清单（每页必查）→ 现为 **13 项**

1. **标题区**：是否有重复 header？（S2）

4. **按钮规格**：高度/圆角/字号是否对齐 `.p-btn-*`？（S4）

## 八、验收标准

每个页面修正后需通过：
1. **结构一致性**：React 页面的 DOM 结构与 HTML 视觉稿对齐（区块顺序、嵌套层级）

3. **配色一致性**：所有颜色用 CSS 变量，不硬编码 hex
4. **按钮一致性**：高度/圆角/字号符合 `.p-btn-*` 规范
5. **按钮行高**：所有按钮/tab/tag 类显式指定 line-height（不继承 body 1.5）
6. **品牌色分轨（续修 G1）**：HTML 含 indigo 的位置用 `--aos-indigo-600`（`#4F46E5`）；`.p-btn-primary` / `--p-blue` 位置用 `--aos-accent`（`#2B6CB0`）；**禁止混用**
7. **标题字号**：PageChrome h1 = 20px（已全局修好）
8. **无冗余区块**：标题不重复、搜索不重复
9. **无缺失区块**：视觉稿有的区块都有对应实现（或注明产品决策原因）
10. **Tab 微规格（S11）**：未选中 `font-weight: 400`；hover 用 `--aos-surface-hover`（≈ `#F9FAFB`）可接受
11. **浏览器 1:1**：截图对比通过，不以静态清单代替
