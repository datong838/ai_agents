## 1. 问题与目标

227 的 W1～W4 已交付大量页面、路由和单元测试，但「控件被渲染」不等于「用户可完成任务」。本轮要系统清理以下完成幻觉：

1. 按钮可点但没有 handler，或 handler 不产生任何可观察结果。  
2. 标注「保存/发布/执行/连通」但只修改内存或伪造成功。  
3. 拖拽、排序、连线在源码中有事件，但在真实浏览器中不可用。  
4. 失败时静默回落到 MOCK/localStorage，却没有明确「演示路径」。  
5. 测试只检查常量、文案或复制的数组，没有渲染页面并触发用户交互。

**目标**：建立 227 范围内的全量页面清单，找出所有虚假/断链/不顺畅交互，分波修复并用真实浏览器验收，而不是再次调高主观完整度百分比。

## 2. 「真交互」强制口径

| 类型 | 必须满足 | 禁止认定为完成 |
|------|----------|------------------|
| 按钮/菜单 | 有可达 handler；点击后导航、状态、数据或明确反馈至少一项改变 | 空 handler、无 handler、`href="#"`、只有 hover 样式 |
| 保存/发布 | 调用明确 API，成功后重读可见；失败时不伪造成功 | 只 `setState`、只 localStorage 且未标演示、直接跳到「已成功」 |
| 拖拽/排序 | 鼠标和键盘路径可用，位置/顺序可保存，刷新后可重放 | 只声明 `draggable`，只测常量，只改页面内存 |
| 执行/试跑/连通 | 返回真实执行状态和证据；未注册能力时 fail-closed | 本地随机数、`mock://` 却显示为生产成功 |
| MOCK/降级 | 页面显著标注「演示路径」，写操作不污染真数据 | 无提示静默降级，或演示结果冒充 API 结果 |
| 测试 | 至少覆盖控件触发→状态/API→反馈；拖拽再加浏览器验收 | 在测试里复制一份生产常量后只检查数量 |

### 分支与合并规则

1. 每个 Wave 开始前四 worker 必须与 m1 同 tip，工作树干净。  
2. commit 前缀：`w1(228-ui):`、`w2(228-ui):`、`w3(228-ui):`、`w4(228-ui):`。  
3. Worker 不改 m1、不 merge 其他 worker、不 push；完成后提交变更和测试证据给 Planner 审查。  
4. Planner 合并顺序为 W1→W2→W3→W4；每合入一支就跑阶段回归，不用后续全量结果替代阶段证据。  
5. 任一 worker 涉及共享路由、全局 CSS、OpenAPI 或 migration head 时，先交 Planner 单点协调，不并行修同一文件。

### 阶段门

1. **Audit Gate**：35 页每页都有控件清单、代码证据、严重度和验收项。  
2. **P0 Gate**：空按钮、假成功、不可用拖拽清零；每合入一个 worker 都跑当前阶段回归。  
3. **Persistence Gate**：声称保存/发布的生产路径重载可重放；演示路径显著标注。  
4. **Browser Gate**：至少完整点验每页的主任务；画布必须真拖放、移动、连线、保存、刷新重放。  
5. **Full Gate**：`bash scripts/ci.sh full` 全部通过，并复查方案/代码/测试数据一致性。
6. **Hermetic Gate**：默认全量单元测试不得因本机 `.env` 中存在外部 LLM 凭证而自动实连网络；外部提供方冒烟测试必须由显式环境开关单独启用，避免网络超时把功能回归误报为代码失败。

### Wave 3A 独立复核追加门

1. Pipeline 保存必须覆盖：保存期间二次编辑、管道切换、旧 GET/PUT 晚到、错误回包、失败保留 dirty、服务重启后重放、并发 GET/PUT 一致快照。  
2. 后端只有在数据已经写入项目既有持久层且可重启重读时才能返回 `persisted=true`；持久层失败必须让写请求失败，不能静默保留内存成功。  
3. 文档删除等不可逆写操作若出现“服务端已执行、客户端未收到回包”，前端必须通过列表 GET 重读确认最终状态；不能仅凭丢失的 DELETE 回包把已删除项继续显示为失败。
4. Evals 的 run/report/gate-check 必须引用同一 suite 和同一次报告，一次用户操作只能新增一次运行历史。  
5. Events 的创建、启停、删除必须校验 `ok/item` 并重读；event ID 的 GET/PUT/DELETE 必须受 path 中 module ID 约束。

## 7. 禁止项

1. 不为让静态扫描通过而给空按钮加 `onClick={() => {}}`。  
2. 不把本地状态或 localStorage 冒充服务端持久化。  
3. 不用「后端未实现」作为伪成功理由；未实现时必须禁用、fail-closed 或明示演示。  
4. 不在本轮做与交互闭环无关的大规模视觉重写。
