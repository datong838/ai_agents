# 228 AIP 生产写回 C0 租户与审批安全闭环方案

> 版本：v1.0（2026-08-02，编码前冻结）
> 基线：`aos-platform` m1 `bc9711a`
> 状态：Stage C C1 已完成，C0.2 可进入开发；本方案退出门关闭前，Automate、Draft 自动提交和 Ontology 生产写回保持禁用
> 上游：[`228-AIP-Logic-Stage-C发布治理与服务端闭环方案.md`](./228-AIP-Logic-Stage-C发布治理与服务端闭环方案.md)

---

## 1. 目标

在不启用任何具体电商平台执行器的前提下，修复 AIP 通用生产写回主链的租户、审批、幂等、并发和路由真实性问题，为后续电商平台专项提供安全底座。

## 2. 当前 P0 风险

1. `obj_instance`、部分 branch、lineage、wiki 表的主键或查询缺少完整 org/project 维度，不能证明跨租户隔离。
2. Draft 持久化与 Phase3 内存路由存在重复 method/path，注册顺序可能静默切换实际实现。
3. Draft approve 缺少强制审批角色、创建人与审批人职责分离、持久幂等和请求 hash。
4. Draft approve 未采用 CAS/行锁冻结 proposed snapshot，并发请求可能重复写对象或 lineage。
5. Action marking/字段权限部分异常路径存在 fail-open 风险。
6. branch merge 可绕过 Draft/Action 直接触碰生产对象。
7. 旧 Automate 不执行 canonical Logic 即返回 completed 和随机 proposal ID。

## 3. Wave C0.2-A：租户化迁移

1. 为对象、Wiki、lineage、branch/overlay 生产表补充 `org_id + project_id` 复合键、唯一约束和索引。
2. 迁移既有数据时必须显式分配 legacy scope；不得丢弃或覆盖现有行。
3. 所有读写 SQL 必须以 Principal scope 过滤；跨租户资源统一 404，避免存在性泄漏。
4. 增加两个租户使用相同 object/type/id、wiki key、branch id、lineage id 的隔离测试。
5. downgrade 必须保护多租户冲突数据；无法无损降级时明确 fail-closed，而不是静默合并。

## 4. Wave C0.2-B：Draft 与 Action 审批

1. 删除或迁出重复 Draft method/path，canonical 公共入口唯一指向 PostgreSQL 实现。
2. Draft 增加 revision、审批事件和评论表；合法状态迁移由服务端状态机定义。
3. approve/reject/transition/comment 强制 Principal，审批角色和创建人/审批人职责分离。
4. 写接口强制持久化 `Idempotency-Key + request_hash`：同键同请求重放，同键异请求 409，API 重启后仍有效。
5. approve 以 `SELECT ... FOR UPDATE` 或等价 CAS 冻结 proposed/action snapshot；并发审批只允许一次终态与一次 lineage。
6. 在写对象前重新验证 Action Type、Submission Criteria、required markings、字段权限和对象 revision。
7. 对象写入、Draft 终态、审批事件与 lineage 同事务；任一步注入失败全部回滚。

## 5. Wave C0.2-C：Branch 与 Automation

1. branch merge 不再直接修改生产对象；统一生成受控 Draft 或 Action proposal。
2. 新建租户隔离、持久化的 Automation Binding，只允许绑定 immutable `publication_id + graph_revision + graph_hash`。
3. trigger/run 均有不可变 ID、请求 hash、状态机、熔断状态和审计时间；不得用内存单例作生产真源。
4. 自动化执行只允许读取 publication snapshot，并通过注册的通用 executor 生成 proposed edits。
5. 运行成功也只能创建可重读 PostgreSQL Draft，返回真实 draft ID；没有真实 Draft 时 run 必须失败。
6. 任何 Eval 失效、publication 不一致、executor 缺失、熔断、权限或持久化失败均不得返回 completed。

## 6. 并行文件边界

| 角色 | 独占范围 | 依赖 |
|---|---|---|
| W1 | 对象/Wiki/lineage/branch 租户迁移与 store/SQL 测试 | 无 |
| W2 | Draft/Action 状态机、审批、幂等、事件与测试 | W1 schema；先用 fixture 接口开发 |
| W3 | Automation Binding/Run store、executor Protocol 与测试 | Stage C publication + W2 Draft 接口 |
| Planner | 重复路由收口、manifest/OpenAPI、SDK/页面集成、迁移串链、合并与全量门 | 三路完成后串行 |

共享 Router、manifest、OpenAPI 和迁移 head 由 Planner 单点处理。

## 7. 测试退出门

1. 跨租户 list/get/write/approve/reject/lineage/branch 全部隔离。
2. 并发批准只有一次对象写入、一次终态、一次 lineage；失败请求稳定为冲突或幂等重放。
3. 同幂等键异请求 409；服务重启后同请求可重放。
4. 无审批角色、创建人自批、marking 不足、字段权限不足、对象 revision 冲突全部阻断。
5. 写对象、更新 Draft、审批事件、lineage 任一步故障均事务回滚。
6. branch merge 不能直接触碰生产表。
7. Automation 无真实执行不得 completed；成功只生成真实 Draft 且 `productionWritten=false`。
8. 治理路径 duplicate method/path 为零；迁移 single-head；OpenAPI 确定性通过。
9. 后端/SDK/Web 专项、累计、全量、typecheck/build、interaction-honesty 和浏览器主任务逐波通过。

## 8. 明确非目标

1. 不接入淘宝、天猫、京东、拼多多、抖音、快手、Amazon、Shopify 等具体平台。
2. 不保存真实商家凭据，不注册真实外部写 executor，不发送生产 webhook。
3. 不以 demo/mock/localStorage 代替持久化治理链。
4. 本方案完成只代表通用安全底座可承接专项，不代表任何电商平台已经联通。
