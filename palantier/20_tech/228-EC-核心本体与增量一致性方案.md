# 228-EC 核心本体与增量一致性方案

> 版本：v1.1 · 2026-08-01
> 状态：通用核心 7 OT 与增量一致性内核已完成并合入 `m1`
> 边界：新增平台无关的一致性内核，不改 legacy Ontology/Pipeline，不做具体平台映射

## 使用的 Rules

1. 先方案后编码，新增专用表，避免破坏现有 `obj_instance`/`graph_edge` 数据。
2. Money/Time/Enum/Identity 只引用 W1，不定义第二套。
3. 对象、Link、Checkpoint、幂等收据必须同事务、同租户、fail-closed。
4. 所有夹具为合成数据；不接真实商家、店铺或平台 API。

## 一、核心 7 OT 冻结

固定为 `Shop`、`Product`、`ProductSku`、`Category`、`Order`、`OrderLine`、`Shipment`。Customer、Payment、Refund 及平台特有 OT 延后，不以嵌入字段冒充已完成。

每个对象都带完整 ExternalIdentity、`sourceUpdatedAt`、`sourceTimezone`、`rawStatus`、`isDeleted`、`schemaVersion`。最小业务字段：

- Shop：name/status/currency/timezone。
- Product：shopId/title/status/categoryId/createdAt/updatedAt。
- ProductSku：productId/status/barcode/price/currency/updatedAt。
- Category：parentCategoryId/name/status/updatedAt。
- Order：shopId/status/totalAmount/currency/createdAt/updatedAt。
- OrderLine：orderId/skuId/quantity/unitPrice/lineAmount/currency/updatedAt。
- Shipment：orderId/status/carrier/trackingNo/shippedAt/updatedAt。

核心 Link 名称固定为 `Order.lines`、`OrderLine.ofSku`、`ProductSku.ofProduct`、`Product.inCategory`、`Shop.sellsProduct`、`Order.fulfilledBy`。Link 两端必须存在、属于同 org/workspace；禁止悬挂或跨租户 Link。

## 二、增量一致性语义

- 读取与 checkpoint 使用 `(updated_time, external_id)` 复合游标，输入 batch 先稳定排序。
- lookback 只扩大读取窗口；落库通过 ExternalIdentity + source version + payload hash 去重。
- 旧版本不覆盖新版本；相同版本、相同 hash 为幂等；相同版本、不同 hash 返回冲突。
- DELETE 写 tombstone，不物理删除审计数据；关联 Link 同步 tombstone。
- 对象 upsert→Link upsert→checkpoint CAS→idempotency receipt 必须单事务；任一步失败全部回滚。
- 同一 idempotency key+同 request hash 返回原结果；同 key+不同 hash 冲突。

## 三、持久化设计

新增专用表：

1. `ecom_object`：复合身份、OT、props、源版本/时区、raw_status、payload_hash、deleted_at。
2. `ecom_link`：同租户 source/target 身份、canonical link type、payload_hash、deleted_at。
3. `ecom_sync_checkpoint`：tenant+platform+scope+stream 主键、复合 cursor、CAS version。
4. `ecom_ingest_receipt`：同作用域 idempotency_key 唯一、request_hash、result。

不迁移、不改写旧 Ontology 表；旧路径继续标记 legacy/dev。W2 后续通过 BatchCommand 调用该内核，不得直写旧全局表。
