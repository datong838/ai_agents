## 1. 使用 Rules

1. 先复核产品方案、技术方案和现有 API，再编码。
2. 有真实统一契约的操作，必须执行写入、严格校验回包、GET 重读核验；没有统一契约的操作必须禁用、只读或显著标为演示。
3. 不把 React state、进程内单例、localStorage、硬编码样例或另一套同名 API 冒充生产持久化。
4. 写请求失败时保留原数据和编辑草稿；写已提交但重读失败时必须使用独立文案，不得误报“写入失败”或“全部成功”。
5. Worker 独占文件，默认不改共享路由、全局 CSS、API client、OpenAPI 产物和路由探针。
6. 每个页面先补组件交互测试，再跑专项；每完成一个内部阶段回归已完成阶段；Planner 每合并一个 Worker 再跑阶段回归。
7. Wave 3B 全部合并后必须跑 Web 全量、后端全量、生产构建、OpenAPI/路由门和浏览器主任务回归。

## 3. 统一写操作状态机

所有页面写操作统一采用以下状态，不允许用一个布尔“成功”覆盖部分失败：

1. `idle/dirty`：服务端快照与本地草稿分离。
2. `submitting`：冻结目标 ID 和请求快照；禁止重复提交。
3. `submitted`：写 API 回包通过目标 ID、状态和关键字段校验。
4. `verifying`：GET 同一资源重读。
5. `verified`：重读与请求快照一致，以 GET 结果覆盖 UI、清 dirty。
6. `submit_failed`：写未提交；保留草稿。
7. `verify_failed`：写可能已提交，但重读失败或不一致；保留 dirty，并显示“写入已提交但重读核验失败”。

路由/选择切换必须使用请求代次或取消信号，旧请求不得覆盖新资源。

## 4. W1 方案：Module Interface、Draft Inbox、AIP Analyst

### 4.1 Module Interface

**真源**：`GET/POST /v1/modules`；`GET/PUT /v1/modules/{id}/interface`。

1. 创建 Module：增加 busy/error；POST 回包校验 `id/name`，GET 模块列表确认新 ID，选中新 Module 后再 GET interface。
2. 保存接口：冻结 module ID 与完整草稿；PUT 校验 moduleId，随后 GET 重读并深比较 name、description、version、entryParams、expose；一致后才清 dirty。
3. GET interface 失败时不得生成可写 MOCK；首次失败显示不可编辑空态，有旧成功快照则标“陈旧只读”。
4. PUT 失败不得切换 demo；POST/PUT 成功而重读失败使用 `verify_failed` 文案。
5. Loop 图仅标“规划/示意”，本波不伪造 Loop 执行能力。

### 4.2 Draft Inbox

**唯一生产真源**：PG `draft_dataset` 对应的 canonical list/detail/approve/reject。现有 `/transition` 写入另一套内存引擎，**禁止接入**。

1. live 模式只开放批准、驳回；评论、编辑、历史、撤回、提交、进入审批、退回修改全部禁用并说明契约未支持。
2. 批准严格校验 id、`status=approved`、`productionWritten=true`、lineageId，再 GET 列表确认状态。
3. 驳回严格校验 id、`status=rejected`、`productionWritten=false`，再 GET 列表确认状态。
4. canonical reject 不持久化理由，本波不宣称理由已保存。
5. live 详情不得合成 actor、当前时间或 timeline；无历史接口时显示“审批历史 API 未提供”。
6. demo 本地状态机如保留，所有写操作必须标“仅当前会话演示”，与 live 分支完全隔离。

### 4.3 AIP Analyst

**事实口径**：当前 `/v1/aip/analyst/query` 查询硬编码服务端样例表，不是生产 Ontology 实时查询。

1. 初始 result 为空；内置查询列表标“本地样例”，不得冒充用户收藏/历史。
2. 成功结果统一标“服务端样例数据”；unknown table fallback 另标“回落样例”；空 rows/columns 不注入 MOCK。
3. HTTP 失败显示错误并保留上次已确认结果，不自动替换本地 MOCK。
4. 新建查询实现为未保存本地草稿：清结果、清 active ID、置 dirty。
5. 保存没有服务端契约：允许 localStorage 时必须显著标“仅此浏览器”，写后读回一致才报成功；否则按钮禁用。
6. CSV/JSON 只导出当前实际展示的样例结果，文件与内容带 source、SQL、generatedAt；无结果禁用。真实受治理数据未来必须走 `/v1/analytics/export`。

### 4.4 W1 文件所有权与测试

独占：

- `apps/web/src/pages/s2/ModuleInterfacePage.tsx` 及测试；
- `apps/web/src/pages/DraftInboxPage.tsx` 及测试；
- `apps/web/src/pages/s2/AipAnalystPage.tsx` 及测试；
- 如统一 sample 语义，仅可再改 `services/aos-api/aos_api/aip_analyst_query.py` 和对应测试。

禁止改：ontology SDK、canonical Draft routers/runtime write、shared API client、全局 CSS、App/routes。

组件测试必须覆盖创建/保存写后重读、旧请求隔离、live 禁用无契约动作、审批回包错配、Analyst 初始空态/失败不注入 MOCK/导出当前结果。

## 5. W2 方案：Observability、Capacity、Model Catalog、Studio

### 5.1 Observability

1. summary、traces、alerts 按 Tab 独立加载；一个失败不得把全页切成 demo。
2. live 空数据即真实空；Token 明标估算，trend 明标采样推演；当前 traces 只称“采样路由统计”。
3. 无 span 明细 API 时隐藏/禁用 waterfall，不得把 MOCK_SPANS 套在 live Trace 上。
4. Alerts 接 `GET/PUT /api/aip/alerts`；确认/静默校验 id/status 后 GET 重读。
5. Dashboard Add Widget 无持久化契约，禁用并标规划中。
6. Export 导出当前 Tab 实际数据和 source/range/generatedAt；demo 文件必须显式带 demo。

### 5.2 Capacity

1. 项目和用户两个“管理”改为真实草稿编辑。
2. 分别 PUT project/user limits，校验 scope/scopeKey/RPM/TPM，再 GET 同 scope 重读。
3. Cancel 恢复最近一次服务端快照；失败保留草稿。
4. 后端不支持的 team/daily budget/per-model 管理改只读或禁用，不得展示可保存控件。

### 5.3 Model Catalog

1. 注册只允许 live：POST register 校验 `ok` 与 modelId，随后 GET registered models 确认。
2. live 空目录/空已注册列表不回填 MOCK；demo 模式注册禁用。
3. Settings 和 Enablement 没有组织 enrollment/法律启用契约，全部只读/禁用；严禁用“模型注册”冒充“组织启用”。

### 5.4 Studio

1. Agent 列表以 `/v1/aip/agents` 为唯一 live 真源。
2. Prompt PUT 后 GET 重读；失败不写 localStorage、不宣称成功。
3. Tools 目录走 `/v1/aip/tools`，Agent 分配走 agent-scoped GET/PUT；不得再把 per-agent UI 写到全局 `/v1/aip/tools/config`。
4. 后端最小新增 `POST /v1/aip/agents` 和 `PUT /v1/aip/agents/{id}/tools`，引擎保存后 GET 可重放。
5. 若共享 CreateAgentWizard 无法安全协调，本波禁用新建 Agent；不得保留 session-only 假创建。
6. Try chat 失败即失败；Publish 的硬编码 87% 只可标示意/只读。

### 5.5 W2 文件所有权与测试

独占四个页面及各自测试；Studio 可独占 `phase3_aip_agents.py`、`aip_agents_engine.py` 和对应测试。默认不改 CreateAgentWizard、agentsCore、wave_ext、API client、全局 CSS。

W2 内部按 Observability→Capacity→Model Catalog→Studio 四阶段开发；每阶段专项绿并回归前序阶段。组件测试必须覆盖真实空、Tab 独立失败、写后重读、写成功重读失败、取消回滚和禁用按钮不发请求。

## 6. W3 方案：Wiki、Property、Function

### 6.1 Wiki Detail / Diff

1. Wiki/WikiVersion 增向后兼容的 widgets、variables 快照；更新请求带 expected_version，锁内冲突返回 409。
2. 前端 PUT 完整 schema 后 GET 重读，校验 id/version/schema；失败保留 dirty。
3. API 失败不再伪造“本地保存”；demo/new 无 POST 时保存禁用。
4. workflow 没有真实编排 API，改“规划中、不可拖拽”。
5. Diff 的恢复缺少并发与审计 API，本波直接禁用，移除假恢复 modal/成功消息。

### 6.2 Property Editor

1. 只在现有 Phase4 Ontology 真源补 `PUT/DELETE .../properties/{prop_id}`，禁止切到 OMA 另一套属性真源。
2. name 为稳定只读标识；仅开放后端真实字段。
3. DELETE 同步清理 column mappings；PUT/DELETE 后 GET properties 重读。
4. status、visibility、formatter、默认值等无 DTO 字段的控件禁用或只读。

### 6.3 Function Editor

1. name、mode 后端不可写，改只读；只编辑 display_name、description、body、return_type、status、category、params。
2. PUT 校验 id 后 GET 重读并整体覆盖 UI，不强留本地 mode。
3. live 试跑失败 fail-closed；simulate 仅用于显式 demo。
4. API 写失败不把整页切成 demo。

### 6.4 W3 文件所有权与测试

独占 WikiDetail/WikiDiff/PropertyEditor/FunctionEditor 页面及测试；后端独占 ontology_wiki_engine、phase4_ontology_wikis router、ontology_engine、phase4_ontology_types router 及对应测试。Function 后端默认不改。

OpenAPI 与路由数量会变化，但 W3 不改共享产物/探针，全部合并后由 Planner 单点更新。

## 7. W4 方案：Styles、Widget Registry、Maturity、Data Connectors

### 7.1 Styles

1. 主题列表/详情只走 `/v1/themes`；真实空不回填成可写假列表，API 失败标演示只读。
2. 新建主题 POST，校验 `ok/item.id` 后 GET 列表和详情重读。
3. 保存样式 PUT，校验目标 id 后 GET 详情重读并比较 mode/tokens/description；失败保留 dirty。
4. Reset 恢复最近一次服务端快照；built-in/preset 的删除规则保持后端口径。
5. 不在本波做全站视觉重写，只完成主题数据真实闭环。

### 7.2 Widget Registry

1. `/v1/widget-plugins` 为画布插件真源；失败时静态库必须显著标“内置演示目录”。
2. “浏览组件市场”至少切到 market 来源并给出真实空/未安装状态；无市场安装 API 时禁用安装动作。
3. “在画布使用”携带 pluginId/canvasKind 导航到 `/workshop/canvas`；Canvas 只接受当前 palette 中已安装、可用的插件，自动添加后置 dirty，未知/未安装插件显示错误且不添加。
4. 不允许只关 modal 后声称已使用。

### 7.3 Maturity

1. 没有 L4 评审创建 API，因此“申请 L4 上线评审”改名“查看 L4 申请条件”，点击仅导航/展示条件，不宣称已提交申请。
2. 本地 L3 标记继续明确“本地 UI”，不得冒充服务端成熟度评估。
3. Evals/Draft/熔断状态只展示 API 实际来源，失败不伪造绿灯。

### 7.4 Data Connectors

1. `runtimeMode` 加入 source DTO 与持久化 props，POST 回包校验 id/runtimeMode，刷新 GET `/v1/sources` 后重放。
2. 删除 `runtimeById` 前端会话记忆，不再用它补造服务端字段。
3. 老 source 无 runtimeMode 时显示“未设置/历史数据”，不得静默默认为当前向导选择。
4. 创建成功但重读失败使用 verify_failed，不导航到伪成功详情。

### 7.5 W4 文件所有权与测试

独占 StylesPage、WidgetRegistryPage、extras.tsx 的 Maturity 段、DataPage 及各自测试；为 Widget 入口可最小修改 CanvasPage 及新增入口测试；后端可改 theme/widget/source DTO 所在独占文件。禁止改 App/routes、API client、全局 CSS、OpenAPI/路由共享产物。

组件/API 测试必须覆盖主题 POST/PUT→GET、错误回包、Widget 已安装/未知入口、L4 不产生写请求、runtimeMode 刷新重放与旧 source 兼容。

## 9. 残余风险与后续边界

1. Module Interface 现有后端仍有固定 dev org/project 债务，本波前端真实性修复不等于完成租户隔离。
2. Draft transition/comment/history 需要统一 PG 模型和迁移，不能复用 Phase3 内存引擎。
3. Analyst 是样例 SQL 执行器；生产分析必须进入受治理 Analytics/Ontology 链路。
4. Observability 当前是进程采样与路由聚合，不是完整分布式 tracing。
5. Model Enablement、Dashboard Widget、Wiki restore、L4 review 都因缺少后端契约而保持只读/禁用。
6. Theme/Module Interface 等早期 store 的租户模型需另立安全方案，不在本次 UI 真实性波次偷偷扩面。
