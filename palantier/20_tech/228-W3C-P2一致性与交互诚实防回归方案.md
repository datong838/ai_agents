## 3. 全局交互语义

### 3.1 读取与刷新

1. 页面首次加载的每个资源记录 `loading/error/source/loadedAt`，不同资源失败不得互相覆盖。
2. “刷新”表示重新加载页面当前主任务依赖的全部资源；只刷单项时按钮命名为“刷新数据源”“刷新采样”等具体对象。
3. fallback 仅在主路径失败或明确返回 demo 标志时启用，并保留 primary error；刷新主路径成功后必须退出 fallback。
4. 旧请求通过代次或取消信号隔离，路由/资源切换后不得回写旧页面。

### 3.2 只读与演示

1. 演示写操作每次反馈必须带“仅当前演示/仅此浏览器/不写服务端”，不能只靠页顶一次性横幅。
2. 只读 checkbox/select/input 必须带 `disabled/readOnly`、可读说明和无写请求测试。
3. 真 0、未知、不可用分别展示 `0`、`—`、错误说明，不互相替代。

### 3.3 破坏性操作

Graph Health TTL 归档采用固定两阶段：

1. POST `dryRun:true`，校验 `dryRun=true`、候选数量与候选 ID/预览。
2. UI 展示影响范围、TTL 规则和“不会物理删除核心对象”说明。
3. 用户二次确认后 POST `dryRun:false`；校验候选/归档数量，再 GET graph-health 重读。
4. 预览失败、候选变化无法解释、执行回包不一致时不得报归档成功。

## 4. W1：Variables、Object Type Detail、Source Detail

### 4.1 Variables

**真源**：现有 modules variables API；API 不可用时只保留显式 demo。

1. live CRUD 保持写后重读；demo 新建/编辑/删除每次完成反馈都追加“仅当前演示，不写服务端”。
2. demo 刷新不得宣称保留；切回 live 后用服务端列表完全覆盖 demo state。
3. 画布引用验证沿用现有变量规范化函数，demo 变量在画布绑定处也必须标演示来源。
4. 组件测试覆盖 demo 三种写动作反馈和 live 失败不误报。

### 4.2 Object Type Detail

1. 保存元数据、Properties 或实例分支写入后，先校验写回包，再 GET `/v1/ontology/object-types/{id}` 详情。
2. 以详情重读结果覆盖 name/description/status/properties/actions/links 等派生区，不只刷新列表 endpoint。
3. 写已提交但详情重读失败时保留 dirty，显示“写入已提交但详情重读失败”。
4. 请求代次绑定 typeId/branchId，切换对象类型或分支后旧重读不可覆盖。

### 4.3 Source Detail

1. 抽取统一 `applySchemaTree(tree, source)`：无论 live、API demo 还是 catch fallback，都同步 `schemaTree`、展开状态、首表选择和列列表。
2. 空 tree 时清 `activeSchemaTable/activeColumns/preview`，不得保留上一数据源选择。
3. 页头“刷新”必须并行重读 source 列表、datasets/pipelines 映射和 Schema 树；若保留单资源刷新则改名“刷新数据源信息”。
4. Schema/preview fallback 展示 primary error、演示来源；真实空与 fallback 空分开。
5. 路由 sourceId 变化立即清旧选择，并用代次隔离全部依赖请求。

### 4.4 W1 文件与测试

独占 `VariablesPage.tsx`、`objectTypeDetail.tsx`、`sourceDetailPage.tsx` 及其测试；只在确有详情 GET 缺口时修改对应独占 router/test。禁止改共享 API client、App/routes、全局 CSS。

阶段顺序：Variables → Object Type → Source Detail；每阶段回归前序。组件测试至少覆盖 demo 反馈、详情重读失败、fallback 首表同步、刷新全部依赖、路由竞态。

## 5. W2：Link Type、Action Type、Dataset Preview

### 5.1 Link Type Usage

1. 复用现有 link usage endpoint；进入 Usage Tab 或 linkId 变化时读取。
2. 按 API 真实维度映射 Workshop、AIP、Pipeline；没有对应维度时展示 `—` 和“接口未提供”，不得补 0。
3. API 成功返回 0 显示真 0；失败保留错误且所有指标为不可用。
4. 刷新 Usage 只重读 usage，不改变编辑表单 dirty。

### 5.2 Action Type UI / Capabilities

1. 先核对 Action DTO/PUT：不在 DTO 的 User Interface 占位与 Capabilities checkbox 全部 `disabled/readOnly`。
2. 区域标题明确“当前只读/规划中”，checkbox 绑定真实显示值（若 API 有）或统一未配置，不提供假编辑手势。
3. 保存请求不得携带不存在的字段，也不得宣称这些只读区已保存。
4. 测试点击/键盘操作不产生 PUT，且受支持字段保存仍正常。

### 5.3 Dataset Preview fallback

1. Dataset 列表当前 canonical ID 为 `ri.dataset.*`（RID）；页面必须使用与该列表同源且只读的 `GET /v1/analytics/datasets/preview?datasetRid=...&limit=...` 预览，不得把 RID 交给独立且默认空的 Phase-5 内存存储。既有 POST 仅保留 SDK 兼容；页面不得用 POST 读取，以免被离线写队列误判为待同步写操作。
2. 若未来列表返回明确的 Phase-5 `id`，才可使用 `/v1/datasets/{id}/preview`；两种 ID 不得靠猜测互换。主路径的 error/source 单独保存，不再 catch 后静默吞掉。
3. fallback 只能使用已确认的 secondary 数据；显示“主预览失败，当前来自 …”及原错误摘要。
4. 主路径真实空展示“预览成功但暂无行”；fallback 空展示“回落来源暂无行”，不得混用。
5. 刷新重新尝试主路径；一旦成功清除 fallback/error。
6. 导出只允许当前有真实展示行且 source 可追溯；文件 metadata 带 source/datasetId/generatedAt。

### 5.4 W2 文件与测试

独占 `LinkTypeEditorPage.tsx`、`ActionTypeEditorPage.tsx`、`DatasetPreviewPage.tsx`（若实际入口在 CanvasTabs，仅改 Dataset 段）及测试；原则上不新增后端路由。

阶段顺序：Link → Action → Dataset；组件测试覆盖真 0/不可用、只读控件不发请求、primary error 保留、fallback/真实空区分、刷新恢复主路径。

## 6. W3：Model Router、Graph Health

### 6.1 Model Router 单一真源

1. 盘点同页现有 `/v1/aip/model-router*` 与 `/api/models/router*`；选择能够同时承担列表、编辑、测试的一套 canonical router/config DTO。
2. 若 canonical 缺版本字段，最小增加 `version/updatedAt`；PUT 采用 expectedVersion 或 ETag 等价并发保护。
3. 页面加载、规则编辑、保存、测试全部使用同一 endpoint/DTO；删除另一套同名 state 与隐式默认规则。
4. 保存：PUT 校验目标/version，GET 重读深比较后清 dirty。
5. 测试请求携带刚重读的 config version；服务端回包返回 evaluatedVersion，前端不一致则 fail-closed。
6. Circuit config 若仍为独立全局护栏，可保留独立 endpoint，但必须明确不属于任务路由规则，不能混成同一“保存全部”。

### 6.2 Graph Health TTL

1. “运行 TTL 归档”首次点击只触发 `dryRun:true`。
2. modal/确认区展示 candidateCount、preview/IDs、TTL 天数和 soft archive 说明。
3. 二次确认才执行 `dryRun:false`，回包校验后 GET graph-health 重读；取消不发执行请求。
4. dry-run 结果为 0 时禁用执行并显示“无候选”；API 失败不打开确认。
5. 执行期间冻结预览快照；完成后清预览并展示实际 archivedCount。

### 6.3 W3 文件与测试

独占 `aip.tsx` 的 ModelRouter 段、`ontology.tsx` 的 GraphHealth 段及对应测试；后端仅可改 model router canonical 独占模块/router/tests。TTL 已支持 dryRun，默认不改后端。

阶段顺序：Model Router → Graph Health；测试覆盖双真源移除、版本错配、保存后测试同版本、dry-run/取消/执行三路径及错误 fail-closed。

## 7. W4：35 页清单、扫描门与六页关键回归

### 7.2 静态扫描门

新增 `scripts/ci/check-interaction-honesty.*` 与测试，至少阻断：

1. 已登记生产页新增 `onClick={() => undefined}`、空 handler、`href="#"` 假入口。
2. 可点击 button 没有 handler、submit、真实 link 或明确 disabled（允许白名单必须带原因与到期条件）。
3. 生产成功文案附近只执行 `setState/localStorage` 且清单声明 server write。
4. fallback 常量在未出现显著 source/demo 文案时注入 live 页面。
5. 35 页清单缺页、重复 route 或缺关键测试引用。

扫描门只做高置信规则，不能用海量脆弱正则阻塞正常 JSX；先为现存合理模式建立最小、可审计白名单。

### 7.3 六页组件回归

为 Capability、Model Providers、Ontology Discover、Local Platform、Ops Start Guide、Apollo 各补至少一个 DOM 主任务测试：

- Capability：配置/连通动作调用真实 API，失败不显示成功。
- Model Providers：真实空与失败可辨，敏感值不回显。
- Discover：搜索/选择真实数据，API 失败不把样例冒充结果。
- Local Platform：探活/依赖状态来自真实调用，自动确保失败可见。
- Ops Start Guide：步骤入口均为真实导航或明确只读说明。
- Apollo：关键变更/发布入口具备真实 API 或明确禁用，不出现空 handler。

### 7.4 W4 文件与测试

W4 默认只新增 manifest、扫描脚本/测试和六页组件测试，不改六页业务代码；若测试发现回归，只做对应页最小修正并逐项说明。禁止改其他 Worker 独占页面。
