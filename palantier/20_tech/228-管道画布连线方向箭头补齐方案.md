## 1. 使用 Rules

1. 先方案后编码；本次只修复 Pipeline Builder 的连线方向可读性，不改变 Graph API、节点坐标、连接保存结构或执行语义。
2. AIP Logic 与 Pipeline Builder 是两套独立画布；上一波 AIP 箭头不得被误判为管道页面已覆盖。
3. 复用管道现有 SVG path，只增加页面实例唯一的 marker 与 `marker-end`，不重写连线或节点布局。
4. 箭头必须沿 source→target 指向目标节点，并在浅色、深色主题下沿用现有 accent token。
5. 完成后执行 Pipeline 专项、Web 全量、TypeScript、production build、interaction-honesty 和真实浏览器验收。

## 2. 当前差距与根因

1. 管道页面的 `.bp-pipe-flow-svg` 只绘制 `<path class="flow-line">`，没有 `<defs><marker>`，path 也没有 `marker-end`。
2. 因此连接关系存在，但在横线、斜线和复杂布局中无法直接识别 source→target 方向。
3. 该问题与 AIP Logic 的实现无共享 SVG 组件，必须在管道画布单独补齐。

## 3. 冻结实现

1. `PipelineCanvasPage` 使用 `useId` 生成页面实例唯一 marker id。
2. 在管道 SVG 内增加固定大小的三角箭头 marker；每条正式连接 path 设置同一实例的 `markerEnd`。
3. 箭头颜色使用 `var(--aos-accent)`，连线、节点、保存和交互逻辑保持原样。

不修改后端、数据库、Graph DTO、Pipeline 保存/部署/执行代码及 AIP Logic 文件。

## 5. 验收与风险

1. 已有 2 条或更多管道边时，每条 `.flow-line` 均存在有效 `marker-end`，marker 三角形可见并指向 target。
2. 页面刷新、节点拖动、连线增删、属性折叠与保存快照不受影响。
3. 风险是箭头被目标节点遮挡；使用固定像素 marker，并让三角主体位于终点前方，保证节点边缘外仍可辨识。
4. 回滚仅涉及上述三个前端文件，无数据迁移。
