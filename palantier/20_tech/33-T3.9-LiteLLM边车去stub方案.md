## 使用的 Rules

| Rule | 应用 |
| --- | --- |
| 先方案后编码 | 本文通过后再动 compose / gateway |
| 最小更改 | 只换 Facade 下游实现；不改 Draft/写生产路径 |
| 不破既有 | 单测无边车时允许 `fallback-mock`；冒烟对真边车断言 |
| 军规 | 密钥不进响应体；LiteLLM 仅 Dev compose，不进客户产品包品牌面 |

---

## 1. 目标 / 非目标

| 目标（DoD） | 非目标（本刀不做） |
| --- | --- |
| LiteLLM **独立进程/容器** | 真 OpenAI/Azure 计费账号（可选后插） |
| aos-api 仅 HTTP 调边车 | UI import litellm / openai SDK |
| chat 通 **1 个 Provider**（`aos-dev`） | 多 Provider 复杂路由产品页 |
| 密钥以 `vault:` ref 声明 | HashiCorp Vault 真集群 |
| warmup/providers 反映边车态 | Langfuse 观测边车 |

---

## 2. 架构

```
apps/web ──► aos-api /v1/aip/chat|buddy/ask
                 │
                 │ HTTP (Bearer = master key from env↔vault ref)
                 ▼
         aos-dev-litellm :4000   ←── LiteLLM Proxy（进程隔离）
                 │
                 │ OpenAI 兼容
                 ▼
         aos-dev-llm-echo :8081  ←── Dev Provider（无厂商密钥；可换成真 upstream）
```

**Dev 默认上游 = echo**，证明「隔离 + 插件式 Provider」；换真厂商只改 `litellm_config.yaml` / secrets，**不改 Facade**。

---

## 3. 配置与密钥

| 项 | 值 |
| --- | --- |
| `AOS_LITELLM_URL` | `http://127.0.0.1:4000` |
| `AOS_LITELLM_MODEL` | `aos-dev` |
| `AOS_LLM_API_KEY_REF` | `vault:secret/data/aos/llm#master`（响应只回 ref） |
| `AOS_LLM_MASTER_KEY` | 仅 `.secrets.env`（gitignore）解析 ref → 实际 Bearer |
| `AOS_LITELLM_FALLBACK` | `mock`（默认，pytest）/ `off`（集成要求边车） |

## 5. 自测计划

1. `pytest`：无边车 → fallback 仍绿；gateway 单元测绿  
2. `docker compose up -d aos-dev-llm-echo aos-dev-litellm` → health  
3. 设 `AOS_LITELLM_FALLBACK=off` 重启 aos-api → `/v1/aip/chat` 答案前缀含边车路径、`sidecar=litellm`  
4. smoke 扩展断言（边车 online 时）  
5. 确认 `apps/web` 无 litellm/openai import（既有军规扫描）

## 6. 风险

| 风险 | 处置 |
| --- | --- |
| 拉 LiteLLM 镜像慢/失败 | 本地 Dockerfile `pip install litellm[proxy]`；失败记阻塞不停 fallback |
| 无厂商 key | echo Provider；文档标明非生产模型 |
| 单测依赖 Docker | 默认 fallback；live 标记 optional |
