## 2. 一键启动

```powershell
cd c:\work\projects\wchat\aos-platform
powershell -File scripts\demo\start-local.ps1
```

成功标志终端出现：**`RESULT: DEMO HEALTH OK`**

| 开关 | 含义 |
| --- | --- |
| `-InfraOnly` | 只起 Docker 前置（PG/MinIO/MySQL/LLM/OCR/analytics 等），不起 API/Web |
| `-SkipInstall` | 跳过 `pip install -e .` / `npm install` |
| `-SkipWeb` | 只起 API，不起 Vite |

**启动后默认进程：**

| 组件 | 地址 | 说明 |
| --- | --- | --- |
| PostgreSQL | `:5433`（容器 `aos-dev-pg`） | 元数据 / 对象 |
| MinIO | `:9000` | 对象存储 |
| aos-api | http://127.0.0.1:8080 | `GET /v1/health` |
| apps/web | http://127.0.0.1:5173 | 演示入口 `/demo` |
| LiteLLM（边车） | `:4001` | 可选；健康检查 WARN 可不挡 |
| OCR（边车） | `:8082` | 可选；健康检查 WARN 可不挡 |
| analytics-runtime（边车） | `:8084` | TA.1；`AOS_ANALYTICS_URL`；**勿占 8083**（Keycloak） |

**演示鉴权（Dev）：**

```text
Authorization: Bearer dev
X-Org-Id: dev-org
X-Project-Id: dev-project
```

环境：`AOS_AUTH_ALLOW_DEV=1`（`start-local.ps1` 已设）。

**常用入口：**

| 用途 | URL |
| --- | --- |
| 客户演示导航 | http://127.0.0.1:5173/demo |
| Web 概览 | http://127.0.0.1:5173/ |
| API 探活 | http://127.0.0.1:8080/v1/health |

## 3. 停止

```powershell
cd c:\work\projects\wchat\aos-platform

# 停 API + Web（保留 Docker 数据面）
powershell -File scripts\demo\stop-local.ps1

# 同时停核心 compose 栈
powershell -File scripts\demo\stop-local.ps1 -AlsoInfra
```

PID 文件：`deploy/dev/demo-pids/aos-api.pid` · `aos-web.pid`

## 4. 健康检查

```powershell
# 标准（PG + MinIO + API 必绿；Web/边车有则查，无则 WARN）
powershell -File scripts\demo\health-check.ps1

# 只要基础设施
powershell -File scripts\demo\health-check.ps1 -InfraOnly

# Web 也必须绿
powershell -File scripts\demo\health-check.ps1 -RequireWeb
```

| 结果 | 含义 |
| --- | --- |
| `RESULT: DEMO HEALTH OK` | 可继续演示 / 冒烟 |
| `RESULT: DEMO HEALTH FAIL (n)` | 先看 FAIL 行；常见：Docker 未开、API 未起、PG 未 ready |

**探针对照：**

| 名称 | 检查方式 |
| --- | --- |
| PostgreSQL | `docker exec aos-dev-pg pg_isready -U aos_app -d aos_meta` |
| MinIO | `http://127.0.0.1:9000/minio/health/live` |
| aos-api | `http://127.0.0.1:8080/v1/health` |
| web | `http://127.0.0.1:5173/`（默认非强制） |
| LiteLLM / OCR / Analytics | 可选 WARN |

**分析建模边车（TA.1）：**

```powershell
# compose
docker compose -f deploy/dev/docker-compose.yml up -d aos-dev-analytics
# 或本机
powershell -File scripts/demo/start-analytics-sidecar-host.ps1

Invoke-RestMethod http://127.0.0.1:8084/health
# → status=ok · engine=shaped-dev

# Facade（需 AOS_ANALYTICS_URL=http://127.0.0.1:8084）
Invoke-RestMethod http://127.0.0.1:8080/v1/analytics/health
# → status=ok · sidecar=ok · sessionsCapable

# TA.2 创建会话（Bearer dev）
$h = @{ Authorization = "Bearer dev"; "Content-Type" = "application/json" }
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/v1/notebooks/sessions `
  -Headers $h -Body '{"objectType":"WorkOrder","purpose":"explore"}'
# → status=idle · uiUrl 含 ticket
```

手工探活示例：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/v1/health
# 期望含 status=ok（或等价健康字段）
```

## 6. 日志与排障

| 文件 | 用途 |
| --- | --- |
| `deploy/dev/aos-api.out.log` / `aos-api.err.log` | API 标准输出/错误 |
| `deploy/dev/aos-web.out.log` / `aos-web.err.log` | Vite 日志 |
| `deploy/dev/demo-pids/*.pid` | 启停用 PID |

| 现象 | 处理 |
| --- | --- |
| health 红 · PG | `docker compose -f deploy/dev/docker-compose.yml ps`；确认 Desktop/WSL docker |
| API 起不来 · 端口占用 | `stop-local.ps1` 后重起；查 `:8080` |
| ensure-seed 500 | 看 `aos-api.err.log`；确认 PG 可连、先 health 绿 |
| Web 打不开 | `start-local.ps1` 勿带 `-SkipWeb`；或单独起 `apps/web` 的 `npm run dev` |
| 客户问 Jupyter / Full Spoke | 诚实后置（G-ALIGN-09 / Apollo 停车场） |
