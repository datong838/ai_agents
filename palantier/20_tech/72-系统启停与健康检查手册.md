### 1.2 前置


| 项      | 要求                                          |
| ------ | ------------------------------------------- |
| OS     | Windows 10+ / macOS / Linux                 |
| Docker | 已开（或 [24](24-AOS客户侧前置组件安装SOP.md) native 降级） |
| 运行时    | Python 3.11+ · Node 18+                     |
| 目录     | `aos-platform/`                             |


### 1.3 启动

**云（本机平台）+ Web：**

```powershell
# Windows
cd aos-platform
powershell -File scripts\demo\start-local.ps1
```

```bash
# macOS / Linux
cd aos-platform
bash scripts/demo/start-local.sh
# Docker Hub 不可达时：
bash scripts/demo/start-local-native.sh
```

#### 1.3.1 如何判断 Docker Hub 不可达

> **真源对齐**：[24](24-AOS客户侧前置组件安装SOP.md) §4.4 · **本机探活**页也会做一次 **主动探活**（`/settings/local-platform` → Docker Hub 行）。

「Hub 不可达」= **Docker 引擎往往正常**，但 **拉镜像失败**（访问 `registry-1.docker.io` 超时/失败），**不是** Docker Desktop 没开。

**跑 `start-local.sh` 时的征兆：** 卡在 `docker compose … up` / `docker pull`，日志出现 `context deadline exceeded`、`i/o timeout`、访问 `registry-1.docker.io` 失败 → 改用 `start-local-native.sh`。

**主动探活（命令行）：**

```bash
# Docker 守护进程（OK 也不代表 Hub 通）
docker info >/dev/null && echo daemon_ok

# Hub 注册表（401 也算「通」；超时/连接失败才算不通）
curl -sI -m 10 https://registry-1.docker.io/v2/

# 或试拉
docker pull hello-world
```


| 结果                                    | 含义          | 启动脚本                    |
| ------------------------------------- | ----------- | ----------------------- |
| `curl` 很快返回（如 HTTP 401）               | Hub **可达**  | Win=`start-local.ps1` · mac/Linux=`start-local.sh` |
| `curl` 超时 / 连接失败，**本机已有镜像 / 栈已绿** | Hub **不可达**，但不阻塞启停 | **继续**当前脚本；Hub 行仅为 WARN |
| `curl` 超时且 **缺镜像、compose pull 失败** | Hub **不可达** | mac/Linux → `start-local-native.sh`；Win → WSL/镜像加速或已缓存镜像，**勿**照搬 mac native 路径 |


**产品面：** 运维交付 → **本机探活** → 「Docker Hub（镜像拉取）」状态点；点「重新检测」会再探一次。  
Hub 红 **≠** 引擎挂；若 PG/API/Web 已绿，可忽略 Hub 行继续用。

成功：`**RESULT: DEMO HEALTH OK**`


| 开关（Win）        | 含义                 |
| -------------- | ------------------ |
| `-InfraOnly`   | 只起 Docker 前置       |
| `-SkipInstall` | 跳过 pip/npm install |
| `-SkipWeb`     | 只起 API             |


**桌面（推荐）：**

```bash
# 须先本机 API :8080 绿
export PATH="$HOME/tools/node-v22.17.0-darwin-arm64/bin:$PATH"
cd /Users/ddt/work/projects/ai_agent/aos-platform/apps/desktop
npm install && npm run tauri dev
# API Base：channel.local.json 或欢迎页填 http://127.0.0.1:8080
# 产品入口：「本机探活」探活（禁称 Apollo）
```

**默认端口：**


| 组件                  | 地址                                             |
| ------------------- | ---------------------------------------------- |
| PostgreSQL          | `:5433`                                        |
| MinIO               | `:9000`                                        |
| aos-api             | [http://127.0.0.1:8080](http://127.0.0.1:8080) |
| Web                 | [http://127.0.0.1:5173](http://127.0.0.1:5173) |
| LiteLLM / OCR       | `:4001` / `:8082`（可选 WARN）                     |
| analytics / Jupyter | `:8084` / `:8888`（可选 · §6.1）                   |


**Dev 鉴权：**

Web：`http://127.0.0.1:5173/` · 本机探活页：`/settings/local-platform`（侧栏 **运维交付** · [163](163-运维交付归口与禁演示临时候补方案.md) · 更名 [170](170-本机平台更名本机探活方案.md)） · API：`/v1/health`

## 2. ② 标准企业版 SOP（单机房私有化）

### 2.1 适用与边界


| 项      | 说明                                                                             |
| ------ | ------------------------------------------------------------------------------ |
| 适用     | 标准企业全套部署 · **1 Org · 多工作区** · **单 Spoke**                                      |
| 拓扑     | 云在 **客户 DC/VPC**；端（桌面+Web）指客户入口域名                                              |
| 运维     | 客户 IT（我方可实施/维保）；Apollo 运维面给客户 IT                                               |
| **诚实** | 生产 IdP / 真 HA 以合同与 [24](24-AOS客户侧前置组件安装SOP.md) 为准；Dev `Bearer dev` **禁止**当客户签收 |


### 2.2 前置（云侧 · 客户机房）

按 [24](24-AOS客户侧前置组件安装SOP.md) 客户自装/联调：


| 类别    | 示例                                    |
| ----- | ------------------------------------- |
| 计算/编排 | Compose 增强或 K8s（单 Spoke）              |
| 数据    | PostgreSQL · 对象存储（MinIO/兼容 S3）        |
| 身份    | 客户 IdP（OIDC）· 见 [60](60-生产IdP联调手册.md) |
| 平台    | aos-api + 业务服务 · 反向代理/TLS             |


**本机开发者笔记本**一般 **不起** `start-local` 冒充客户机房。

### 2.3 启动

**云（客户机房）**— 由实施/客户运维按交付包与 Apollo/Compose/Helm 规程拉起（生产命令以现场 Runbook 为准；Dev 对照可参考 `deploy/dev/docker-compose.yml` **仅作形态参考**）。

探活（在能访问机房网络的机器上）：

```bash
curl -fsS https://<客户-aos-api>/v1/health
bash scripts/ci/probe-prod-idp.sh   # 已配 AOS_OIDC_* 时
```

**端（用户 PC）：**

```bash
# Web：配置平台 API Base = 客户域名后
cd apps/web && npm run dev          # 开发联调
# 或浏览器打开客户门户静态/托管 Web

# 桌面：安装包或开发态
cd apps/desktop && npm run tauri dev
# channel.private.json → 用户填写客户 API Base
# 或 MDM 下发锁定 Base
```

打包（实施打客户渠道包）：

```bash
bash scripts/ci/pack-desktop-mac.sh --check    # / --bundle
bash scripts/ci/pack-desktop-linux.sh --check
```

### 2.4 停止


| 角色   | 动作                                                         |
| ---- | ---------------------------------------------------------- |
| 用户端  | 退出桌面 / 关浏览器；**不停**机房云                                      |
| 客户运维 | 按机房 Runbook stop/scale（Compose/K8s）；**不是** `stop-local.sh` |


### 2.5 健康


| 检查                      | 谁做        |
| ----------------------- | --------- |
| `GET /v1/health` · 依赖组件 | 客户运维 / 监控 |
| 桌面「平台地址」可达 · 登录 IdP     | 用户 / 实施验收 |
| 工作区切换不串数（20a）           | 实施抽检      |


客户 IdP 验收规程（微商城案例）：[161](161-客户生产IdP验收规程-微商城案例.md) · `accept-customer-idp.sh`（**规程 ≠ 已签收**）。

## 3. ③ 集团版 SOP（Hub + 多 Spoke）

### 3.1 适用与边界


| 项         | 说明                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 适用        | 集团多地、多 Org、数据面分 Spoke                                                                                                           |
| 拓扑        | **Hub** 控制面 + **多 Spoke** 数据面；端连 Hub；**禁止跨 Spoke 串读**                                                                           |
| **诚实·现状** | 真多集群舰队仍后置；当前 **Full Spoke = helm-mock MVP**（[158](158-Full-Spoke运行时MVP方案.md)）；运维深水 MVP（[160](160-Apollo-Full运维深水MVP方案.md)）≠ 真舰队 |


### 3.2 前置


| 项         | 说明                                                |
| --------- | ------------------------------------------------- |
| Hub       | 控制面 API · Channel/Release · 租户/Org 目录             |
| Spoke × N | 各地数据面；与 Org 绑定（[143](143-TWA9-多Org与Spoke绑定方案.md)） |
| 端         | 同一桌面/Web；登录后 Org/Spoke 上下文由 Hub 下发                |


### 3.3 启动（分两层）

**A. 研发明日路径（mock · 可本机）：**

```bash
# 本机单机栈可先起（同 §1），再开 mock
# AOS_FULL_SPOKE_MODE=mock
bash scripts/ci/helm-template-spoke-full.sh   # 无集群 → SKIP
# Web：Org 切到绑定 Full Spoke 的 org；Apollo 运维面可见 helm-mock
```

**B. 目标生产路径（须点名立项）：**

1. 起 Hub 控制面与制品通道
2. 各地 Spoke Agent 注册 / 心跳 / apply-plan
3. 端只配 **Hub 入口**；不要把 Spoke 数据面 URL 散落给业务员

停止：分 Hub / Spoke 运维面分别停；端侧同 §2.4。

### 3.4 健康


| 检查                 | 含义                                                       |
| ------------------ | -------------------------------------------------------- |
| Hub `/v1/health`   | 控制面活                                                     |
| Spoke 心跳 / catalog | 舰队成员在线（生产）或 mock 元数据（Dev）                                |
| Org 切换后数据隔离        | 不串 Spoke                                                 |
| 版本矩阵               | [145](145-TWB7-Ferry端版本矩阵方案.md) `/v1/ops/version-matrix` |

| 角色  | 动作                                    |
| --- | ------------------------------------- |
| 客户  | 仅退出端                                  |
| 我方  | 按多租户运维规程；租户暂停走开通台，不是客户本机 `stop-local` |


### 4.5 健康

```bash
curl -fsS https://<saas-api>/v1/health
# 运营：开通台租户状态 · 配额 · Org 隔离抽检
```
