## 1. 一句话目标

在统一平台内提供 **Jupyter（主）+ SQL（强）** 的分析工作区（**首波不含 R**）：左侧 Ontology/Dataset 浏览器，单元格可查对象与 Dataset，分析结果经 **Draft/Action** 回写 Ontology 或 Dataset（**分析员不自批**），全程带 Marking / 谱系；本地可演示；**不**宣称 Contour/Quiver/Vertex（首波亦不做 Contour 子集页）。

---

## 2. 边界（硬）

| 做（本阶段） | 不做（停车场 / 后置） |
| --- | --- |
| Notebook 运行时边车 + aos-api Facade | 把 JupyterLab 当 AOS 发行壳二次开发话术 |
| Web 嵌入/深链 Notebook **7** UI（自有壳） | UI 直连 Jupyter Server / 厂商 LLM SDK |
| Python kernel + SQL 单元格（或 SQL magic） | 真多租户 JupyterHub K8s 舰队（可二期） |
| 读 Ontology/Dataset；写回走 Draft（**无自批**） | 绕过 Draft 直写生产；分析员自批 |
| Vertex **子集**（TA.8 可选） | 完整 AutoML / 分布式训练平台 |
| Contour / Quiver 子集（**TA.8 可选非阻塞**） | 首波不做；全集后置 |
| 扩展 [72](72-系统启停与健康检查手册.md) 启停 | Full Spoke / 生产 IdP / Ferry 加深（仍停车场） |
| — | **R 内核**（TA.R 后置）· **JupyterLab**（二期） |

**与 1.4：** T08 Workshop **不**并入 Notebook 运行时；允许「从对象页跳进 Notebook」深链，但画布 ≠ 分析建模。

## 3. 从前序开发沉淀的约束（必须遵守）

来自 Wave / TB.* / 横切实操：

1. **Facade 优先**：`apps/web` → 只调 `aos-api` → 边车（同 LiteLLM / OCR / OpenFGA 模式）。  
2. **重依赖进程隔离**：Notebook/Kernel **独立进程/容器**，禁止捆进 `aos-api` 主进程（同 R-ARCH-02）。  
3. **可演示优先**：先本地 Docker 一键 + 一条「分析→回写」故事，再谈 Hub/多用户。  
4. **写回闭环复用 TB.4**：`proposed` → Draft 批准 → `decision_lineage`；勿新开旁路写库。  
5. **治理同 TX.4**：对象字段 Marking、Notebook 输出导出也要能脱敏/拒绝。  
6. **种子 + smoke**：`ensure-seed` / `run-*-smoke.ps1` 模式延续；新 API 进冒烟。  
7. **话术诚实**：未完成前禁止「1.3 已交付」；完成 MVP 也只称「Notebook+回写 MVP」，不称 Contour 全集。

## 4. 逻辑架构（目标态草案）

```text
apps/web  /analytics/*  /notebooks/*
        │  (仅 aos-api)
        ▼
aos-api  Analytics Facade
        ├── /v1/notebooks/*          会话/内核代理（元数据在 PG）
        ├── /v1/datasets/*           已有 L1 面
        ├── /v1/objects/* · Draft    已有 L2 写回
        └── /v1/analytics/sql        SQL 探索（可选 DuckDB/边车）
                │
                ▼
        analytics-runtime（边车）
        ├── Jupyter Server (+ Lab 或 Notebook 7 UI)
        ├── ipykernel (Python)
        ├──（可选）IRKernel (R) —— 二期
        └── 预装：pandas/polars、aos-sdk 客户端（只走 Facade HTTP）
```

自有包建议名（目录可后拆）：`services/analytics-runtime/` 或 `deploy/dev/jupyter-sidecar/`；契约进 `packages/contracts`。

## 5. 开源组件参考矩阵（按经验选型）

> **用法说明：** 「参考」= 读架构/协议/交互、或 **客户自装/边车进程**；「库依赖」= Apache2/MIT/BSD 可进 SBOM；「禁止」= AGPL/BSL 服务端进客户包或 UI 直连 SDK。  
> 登记原则对齐 [21](21-AOS开源选型与功能清单.md) · [23](23-AOS开源引用与交付军规.md)。

### 5.1 Notebook 运行时（1.3 核心）

| 组件 | License（常见） | 建议用法 | 为何选 / 经验对照 |
| --- | --- | --- | --- |
| **Jupyter Server** | BSD | **边车主进程**；API/内核协议真源 | 官方后端；对标 LiteLLM「形边车」而非嵌主 API |
| **JupyterLab** *或* **Notebook 7** | BSD | 边车内 UI；AOS Web **深链/iframe 壳** | Lab=IDE 向；NB7=轻。首波建议 **Notebook 7** 降复杂度，二期 Lab |
| **ipykernel** | BSD | Python 内核 | 标配 |
| **jupyterlab-git**（可选） | BSD | 仅边车扩展参考 | 勿强依赖；Code Repo 仍走自有 `/v1/code-repos` |
| **papermill** | BSD | 参数化批量跑本 | 对齐「可调度分析」；经 Facade 触发 |
| **jupytext** | MIT | `.ipynb` ↔ md/py | 便于 Git 与 Code Repo 目录 |
| **nbconvert** | BSD | 导出 HTML/PDF | 交付物；输出受 Marking 裁剪 |
| **nbclient** | BSD | 无头执行 | 冒烟/CI 跑样例本 |
| **JupyterHub** | BSD | **二期**多用户 Spawner 参考 | 首波单用户边车即可；Hub≈「运维加深」，勿抢 MVP |
| **Elyra** | Apache-2.0 | 流水线式 Notebook 参考 | 可选；勿整仓二次开发话术 |
| **Marimo** | Apache-2.0 | **备选**响应式 Notebook | 产品文案写 Jupyter，首波 **不**替换；可作交互参考 |

**不建议首波：** Deepnote/Hex（闭源 SaaS）；把 **code-server** 当主分析壳（偏 IDE，偏离 02 界面示意）。
