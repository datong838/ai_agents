### 为何仍不做（产品/风险）

| 项 | 原因 |
| --- | --- |
| Wiki 直写生产 | 活知识进生产必须走 Draft→审批，防止未审内容直接覆盖 `wiki_page`；放开 PUT 会破坏治理闭环 |

| Dataset 分支自动同步 | 依赖数据平台 Dataset 分支契约与同步作业；本体 overlay 与数据分支解耦，避免假同步 |

## 2. 契约摘要

### Wiki Draft / Graph health / OKF / Funnel
（同 v1，不变）

### Branches（v2）

```json
POST /v1/ontology/branches { "id", "name", "baseRef" }
→ { id, name, baseRef, readonly: false, changeCount: 0 }

GET /v1/ontology/branches
→ { items: [{ id, name, baseRef, readonly, changeCount }] }

GET /v1/ontology/branches/{id}/diff
→ { branchId, baseRef, items: [{ objectType, objectId, kind: "added"|"modified"|"deleted", base?, branch? }] }

POST /v1/ontology/branches/{id}/merge
→ { ok, branchId, baseRef, merged }

POST /v1/ontology/branches/{id}/checkout
{ "objectType", "objectId", "patch"?: {} }
→ 从 base 拷入 overlay（可 patch）；便于演示「分支上有变更」
```

### Objects + branch

```text
GET  /v1/objects/{type}?branch=X     → 有效视图（main=生产表；开发分支=base∪overlay）
GET  /v1/objects/{type}/{id}?branch=X
PUT  /v1/objects/{type}/{id}?branch=X  body: props 字段
     · branch 缺省/只读/main → 拒绝写 overlay（生产仍走 Draft）
     · 开发分支 → upsert overlay
```

### 存储

```sql
CREATE TABLE obj_branch_overlay (
  branch_id TEXT NOT NULL REFERENCES meta_branch(id) ON DELETE CASCADE,
  object_type TEXT NOT NULL,
  object_id TEXT NOT NULL,
  props JSONB NOT NULL DEFAULT '{}'::jsonb,
  op TEXT NOT NULL DEFAULT 'upsert',  -- upsert | delete
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (branch_id, object_type, object_id)
);
```

语义：overlay **只存相对 base 的变更**；不在创建分支时全量拷贝。
