## 对抗与一致性结论

1. 重复、空白、超长 Idempotency-Key 和非法/重复/超大 If-Match 在 Service 调用前失败。
2. 同一 installation、同一 ETag、不同幂等 key 的并发 submit 只有一次成功；输家无 receipt，最终仅 2 个 revision/2 个 event。
3. apply/verify/rollback evidence 由服务端从 immutable identity/event/decision 重建，inner/outer hash 均在回读时验证。
4. marking 在写入时拒绝、读取时隐藏；list 在 SQL 计数和分页前过滤，admin 不绕过 marking。
5. concrete Installation Service 六个 action 已与冻结 Protocol 保持 keyword-only、无自由参数的一致签名。
6. 用户已有 `apps/web/src/shell/AppShell.tsx` 与掘金文档改动未被暂存或修改。
