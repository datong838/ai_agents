## 3. 关键安全结论

- resolve/get 成功响应必须通过运行时 parser；缺字段、额外字段、非法 UUID/hash/enum/time 均失败关闭。
- 出站 resolve/create 使用白名单 serializer；租户、操作者、snake_case、hash/evidence 注入不会发送。
- Resolve POST 成功不等于可创建；必须 GET 回读同一 revision，完整响应不一致时失败关闭。
- 输入变化使 lock stale；只有已回读、非 stale 的 lock 可创建 draft。
- 网络/500 为结果未知，只允许复用原幂等键恢复同一命令；离线写不排队。
- HTTP 422 校验/解析资源上限进入稳定 invalid_request 策略，不再落入 unknown。
- 浏览器不运行 Resolver，不重算 canonical hash、diff 或 evidence；四 hash 不可编辑。
