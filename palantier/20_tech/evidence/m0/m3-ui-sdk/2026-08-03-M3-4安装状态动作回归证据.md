## 3. 关键安全结论

- submit/apply/verify 只发送 `{}`；reject/rollback 只发送规范化 reason；Approve 只发送当前服务端四 Hash。
- Approve 动作前先 GET Installation，再 GET 对应 Composition Lock；只比较四 Hash，不计算 Hash。
- 用户确认后若 revision、ETag、requestedBy、四 Hash 或 active pointer 有变化，直接 conflict 并要求重新确认，不静默升级到新事实。
- 每个新命令使用新幂等键；network/500 恢复只复用原 key/body/If-Match；状态已分叉时禁止回放。
- 409 和 412 统一回读但不自动覆盖。当前后端 stale CAS 主要返回 409；前端同时兼容 OpenAPI 声明的 412。
- `TRUST_ROOT_UNAVAILABLE=503` 是运行时失败关闭兼容，当前 OpenAPI 尚未声明；前端不把它伪装成已发布契约，也不自动重试。
- 客户端没有 Evidence 输入或注入路径；dry_apply、verification、rollback Evidence 均来自服务端响应。
