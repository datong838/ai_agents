## 3. HTTP 真实链路

测试使用随机隔离 PostgreSQL schema、真实本地 HS256 JWT 签发与校验、真实 Installation Router、InstallationService、PostgresCompositionStore 和 PostgresInstallationStore。

链路：

`maker create → maker submit → maker self-approve 403 → checker stale ETag 409 → checker approve → installer apply → installer verify/active → installer rollback`

结论：

- ETag 按 `1 → 6` 前进，每个新命令使用独立 Idempotency-Key。
- maker 自批与旧 ETag 失败不写 receipt、revision 或 event；最终 commands/revisions/events 均为 6。
- decision actor 为 checker；dry_apply、verification、rollback Evidence 只由服务端产生。
- 首次 active 的 `previousActiveRevision=null`；rollback 后 active/previous pointer 均回到空基线。
- Composition Lock 由真实 Store 测试 fixture 预置，未声称公开 Resolve HTTP 已在本链执行；外部 release revalidation 使用确定性测试替身。

## 4. 兼容修复

Desktop 累计 typecheck 首次发现共享 SDK 使用 `Object.hasOwn` 和 `Error(message, {cause})`，超出其冻结 lib。方案回写后只做等价替换：

- `Object.prototype.hasOwnProperty.call` 代替 `Object.hasOwn`。
- 单参数 Error 构造后显式保留 cause。
- 不改变错误类型、recovery、status、trace、详情隐藏或网络未知结果语义。
