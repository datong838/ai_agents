## 1. 本波范围

M5-1 只在测试层复用现有生产 ManifestLoader、Registry Service/Store、ReleasePolicy 和 RegistrySnapshotReader，证明四个无业务 Bundle 可以用运行时密钥签名并经真实 PostgreSQL 发布。没有修改生产代码、迁移、Router、OpenAPI、Web 或 Bundle source，也没有接入任何具体电商平台。

## 2. 交付

- `m5_bundle_support.py`：临时复制四包、局部生成 Ed25519 私钥、生成 publisher-scoped Frozen trust root、构造 canonical payload、写临时签名并重载。
- `test_m5_ecommerce_bundle_loader.py`：五类 Evidence、hash 稳定、签名排除、每次密钥不同和篡改失败关闭。
- `test_m5_ecommerce_bundle_registry_pg.py`：真实 PG create→validate→maker/checker publish、重启 Service/Store/SnapshotReader 回读。
- `test_m5_ecommerce_release_security.py`：受控文件/签名篡改、SBOM/Evals 缺失或失败、trust root 过期/撤销/revision 变化。
- `test_m5_ecommerce_cross_contract.py`：运行时 fixture 与四个仓库 manifest/sourceRef 真源对拍。

## 3. 关键事实

- 私钥仅存在于 `copy_and_sign_m5_bundles()` 局部变量，不返回、不持久化。
- 每次准备的公钥、trust-root revision 和签名都不同；四包 content hash 不变。
- `bundle.signature.json` 只存在于临时目录，不进入 artifacts/content hash。
- 四包均具有 current valid 的 `manifest_validation/content_hash/signature_verification/sbom/bundle_evals`。
- creator 与 validator 自发布均失败且零额外事件；独立 publisher 成功。
- 重启后 snapshot 恰含四个 candidate，三叶只依赖 core，snapshot hash 稳定。
- 篡改、证据缺失/失败及当前 trust root 变化均失败关闭。
