# TI-1 E3-0R 历史证据追溯与执行基线决策

> 日期：2026-08-04
>
> 结论：E1 逐记录身份不可恢复；保留历史断点，冻结 E3-0 当前逐记录执行基线
>
> 数据操作：只读，未修改 PostgreSQL、对象存储、检索、缓存或业务数据

## 1. 追溯范围

- AOS 五个工作树、Palantier 方案与 evidence 目录中的 dump、backup、snapshot、audit、ledger、WAL 和指纹产物。
- Git 中 E1 `621a1bb`、E2 `a7df658` 到 E3-0 `26102d4` 的提交与测试时间线。
- 本地 PostgreSQL 容器、持久卷、服务参数、容器日志、WAL/归档和 backup label 状态。
- E1/E2 已提交证据中的真实迁移、事务探针和 TWA 非幂等测试说明。

## 3. 无法恢复的证据

- 未发现 E1 时点全库或受影响表的逻辑备份。
- 未发现 E1 记录级稳定指纹集、CI 数据库快照或离线审计包。
- PostgreSQL 16.14 当前为 `wal_level=replica`、`archive_mode=off`、`log_statement=none`、`logging_collector=off`；无归档 WAL 和 backup label。
- 容器日志只可靠记录错误语句，不能证明所有成功 INSERT/UPDATE/DELETE，也不能重建已删除行的原始身份。

因此不能把代码路径、失败日志或聚合差值冒充为逐记录历史审计。

## 4. 决策

1. E1 聚合数字永久保留为不可覆盖的历史基线，并登记 `HISTORICAL_IDENTITY_DISCONTINUITY`。
2. E3-0 当前脱敏逐记录快照冻结为执行基线；后续 batch 必须引用其 snapshot hash。
3. 当前未知或断链记录没有 A 级双向证据时全部进入逻辑 QUARANTINE，不回填、不造父记录、不删除。
4. E1 中当前已不存在的记录只保留聚合断点，不生成虚假的逐记录 decision。
5. 后续 GREEN 只表示当前执行集合的决策守恒、可逆回填与恢复演练通过；最终文档持续披露历史连续性风险。

## 5. 授权边界

用户已要求连续完成 E3 和微商城接入前置准备。由此解锁本地/共享非生产的 E3-1～E3-4 安全实施，但不包含客户/生产库、真实微商城连接、物理删除或不可恢复操作。
