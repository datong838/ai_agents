## 一、私域管家定位

### 1.1 职责边界

**私域管家管"关系"** — 谁、什么时候、怎么触达。

| 职责 | 不做什么 |
|------|---------|
| ✅ 客户沉淀：老客分批导入企微 | ❌ 卖什么（导购顾问的职责） |
| ✅ 客户打标：肤质/消费力/偏好/互动频次 | ❌ 生成推荐方案（导购顾问的职责） |
| ✅ 主动提醒：X天没互动了，该触达了 | ❌ 写文案（内容官的职责） |
| ✅ 跟进排期：加粉第N天该说什么 | ❌ 做活动（活动策划师的职责） |
| ✅ 客户分层：高价值/重点维护/分销候选 | ❌ 数据分析看板（数据参谋的职责） |

### 1.2 核心洞察

> 微商城现状：私域裸奔——企微有但空、老客没进、种子池30个还没用起来。
> **这不是"做活动"能解决的问题，是从 0 搭的问题。**

私域管家解决的就是"从 0 搭"的问题。

## 二、技能链总览

私域管家包含 5 个技能，按执行顺序：

```
技能1：客户沉淀    →  技能2：客户打标  →  技能3：客户分层
                                           │
                         ┌─────────────────┘
                         ▼
              技能4：跟进排期  ←→  技能5：主动提醒
              （排期驱动触达）     （异常驱动触达）
```

| 技能 | 触发条件 | 核心动作 | 风险等级 | 需要审批 |
|------|---------|---------|---------|---------|
| 1.客户沉淀 | 手动/批量触发 | 查询 Customer OT → 生成导入方案 | medium | ✅ 导入话术需确认 |
| 2.客户打标 | 沉淀后自动 | LLM 分析客户行为 → 生成标签 | low | ❌ 自动执行 |
| 3.客户分层 | 打标后自动 | 聚合标签 → LTV 计算 → 分层 | low | ❌ 自动执行 |
| 4.跟进排期 | 分层后自动 | 生成 N 天触达计划 | medium | ✅ 首次计划需确认 |
| 5.主动提醒 | 定时巡检（每日） | 检测异常 → 生成提醒 | high | ✅ 触达动作需确认 |

## 三、技能1：客户沉淀

### 3.1 场景

30 个老客在微商城有购买记录（Customer OT 有数据），但企微里没加。需要分批导入，话术个性化，防封频控。

### 3.2 Plan Mode 设计

```
用户输入："帮我把微商城的老客导入企微"
        │
        ▼
┌──────────────────────────────────────────┐
│ Clarification Gate                       │
│ Q1: 导入哪个批次？（全部/最近30天/高价值）  │
│ Q2: 导入到哪个企微账号？                   │
│ Q3: 每天导入多少个？（防封频控）           │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Task Understanding                       │
│ 类型：customer_onboarding                │
│ 关键实体：Customer OT (30 条)             │
│ 约束：每日 ≤10 个，话术个性化              │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 查询 Customer OT                 │
│   action_type: ontology_query             │
│   query: GET /v1/objects/Customer        │
│        ?filter=totalOrders>=1             │
│        &sort=registeredAt DESC             │
│   risk: low                               │
│                                          │
│ Step 2: 为每个客户生成导入话术            │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "根据客户购买历史生成企微好友     │
│   申请话术，要个性化、有温度"               │
│   risk: low                               │
│                                          │
│ Step 3: 分批导入（每天 ≤10 个）           │
│   action_type: action_writeback           │
│   action: AddToWeCom (需新增 Action Type) │
│   risk: medium                            │
│   requires_approval: true                 │
│                                          │
│ Step 4: 记录导入结果到 Episodic Memory    │
│   action_type: tool_call                  │
│   tool: memory.write                       │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 3.3 TAOR 循环详解

```python
# 私域管家技能1的 LogicFlow 模板定义

CUSTOMER_ONBOARDING_FLOW = {
    "name": "私域管家-客户沉淀",
    "description": "将微商城老客分批导入企微，话术个性化",
    "blocks": [
        # ── Block 1: 查询客户 ──
        {
            "id": "blk-query",
            "kind": "tool",
            "name": "查询待导入客户",
            "config": {
                "tool": "ontology_query",
                "object_type": "Customer",
                "filter": {"totalOrders": {"$gte": 1}},
                "sort": "-registeredAt",
                "limit": 30
            },
            "inputs": []
        },
        # ── Block 2: LLM 生成话术 ──
        {
            "id": "blk-llm-script",
            "kind": "llm",
            "name": "生成个性化导入话术",
            "config": {
                "system_prompt": """你是私域运营专家。根据客户购买历史生成企微好友申请话术。
要求：
1. 个性化：提到客户买过的产品
2. 有温度：像朋友推荐，不像广告
3. 简短：≤30字
4. 防封：不含敏感词（最、第一、绝对等）

输出 JSON 数组，每个元素包含：
- customer_id
- nickname
- script（好友申请话术）
- reason（为什么这么说）""",
                "model": "private-medium",
                "temperature": 0.7,
                "max_tokens": 2048
            },
            "inputs": ["blk-query"]
        },
        # ── Block 3: 分批导入 ──
        {
            "id": "blk-import",
            "kind": "tool",
            "name": "分批导入企微",
            "config": {
                "tool": "action_writeback",
                "action_type": "AddToWeCom",  # 需在 Ontology 中新增此 Action Type
                "batch_size": 10,
                "delay_between_batches": 3600  # 每批间隔1小时
            },
            "inputs": ["blk-llm-script"]
        },
        # ── Block 4: 记录到记忆 ──
        {
            "id": "blk-memory",
            "kind": "task",
            "name": "记录导入结果",
            "config": {
                "tool": "memory.write",
                "layer": "episodic",
                "event": "customer_onboarding",
                "tags": ["private_domain", "wecom_import"]
            },
            "inputs": ["blk-import"]
        }
    ]
}
```

### 3.4 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 查询 Customer OT | low | 自动执行 |
| LLM 生成话术 | low | 自动执行 |
| 导入企微（AddToWeCom） | **medium** | **话术需人工确认后批量发送** |
| 记录到记忆 | low | 自动执行 |

### 3.5 Reflection 自审规则

```python
REFLECTION_RULES = {
    "customer_onboarding": [
        # 规则1：话术长度检查
        {
            "name": "script_length_check",
            "condition": "len(script) <= 30",
            "on_fail": "truncate_and_regenerate"
        },
        # 规则2：敏感词检查
        {
            "name": "sensitive_word_check",
            "condition": "not contains_sensitive_words(script)",
            "on_fail": "regenerate_without_sensitive",
            "max_retries": 3
        },
        # 规则3：个性化检查（必须提到产品名）
        {
            "name": "personalization_check",
            "condition": "mentions_product(script, customer.history)",
            "on_fail": "regenerate_with_product_mention"
        }
    ]
}
```

### 3.6 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 美妆行业话术模板、敏感词库、防封规则 |
| **Episodic** | 历史经验 | 上次导入成功率、哪类话术转化率高 |
| **Working** | 当前任务 | 待导入客户列表、已生成话术、导入进度 |

### 3.7 验收标准

- [ ] 输入30个Customer OT对象，输出30条个性化话术
- [ ] 每条话术 ≤30 字，不含敏感词
- [ ] 话术提到客户买过的产品名
- [ ] 导入前展示话术列表供用户确认
- [ ] 导入结果记录到 Episodic Memory

## 四、技能2：客户打标

### 4.1 场景

客户沉淀到企微后，需要对每个客户打标签：肤质、消费力、偏好、互动频次。

### 4.2 TAOR 循环

```
Step 1: 查询客户购买历史
  ontology_query: GET /v1/objects/Customer/{id}?expand=orders,order_goods

Step 2: LLM 分析客户画像
  llm_call: "根据以下购买历史，为客户生成标签：
    - 肤质：干性/油性/混合/敏感
    - 消费力：低/中/高（基于客单价）
    - 偏好：护肤/彩妆/个护（基于品类分布）
    - 互动频次：活跃/一般/沉默（基于最近购买时间）
  输出 JSON"

Step 3: 写入标签到 Customer OT
  action_writeback: UpdateCustomerTags (需新增 Action Type)
  risk: low (标签不影响交易)

Step 4: 更新 Semantic Memory
  tool_call: memory.write (layer=semantic, tag=customer_profile)
```

### 4.3 标签 Schema

```python
class CustomerTags(BaseModel):
    customer_id: str
    skin_type: str = ""  # dry | oily | combination | sensitive | unknown
    spending_power: str = ""  # low | medium | high
    preference: list[str] = []  # skincare | makeup | personal_care
    interaction_frequency: str = ""  # active | normal | dormant
    last_active_days: int = 0  # 距上次互动天数
    ltv: float = 0.0  # 生命周期价值
    tags_source: str = "ai_inferred"  # ai_inferred | manual | imported
    confidence: float = 0.0  # 置信度
```

## 六、技能4：跟进排期

### 6.1 排期模型

基于客户分层，生成 N 天触达计划：

| 客户类型 | 第1天 | 第3天 | 第7天 | 第14天 | 第30天 |
|---------|-------|-------|-------|--------|--------|
| 新客（首单<30d） | 感谢+使用指导 | 关心使用体验 | 推搭配产品 | 会员权益 | 复购提醒 |
| 潜力客户 | 个性化推荐 | 内容种草 | 限时优惠 | — | 复购提醒 |
| 沉默客户 | 问候+召回 | — | 新品推荐 | — | 大额优惠 |
| 高价值客户 | 1V1 专属服务 | 新品优先体验 | — | 生日关怀 | 积分兑换 |

### 6.2 TAOR 循环

```python
FOLLOWUP_SCHEDULING_FLOW = {

        {
            "id": "blk-llm-schedule",

                "system_prompt": """你是私域运营排期专家。根据客户分层生成触达计划。

规则：
1. 每日触达不超过5人（防封频控）

3. 触达方式：企微消息/朋友圈/社群@/1V1电话
4. 排期格式：JSON 数组，每条含 customer_id, day_offset, channel, purpose, script_hint

注意：
- script_hint 只给方向（如"推荐搭配面霜"），不写完整话术（话术由导购顾问生成）

            "id": "blk-save-schedule",

## 七、技能5：主动提醒

### 7.1 提醒触发条件

| 条件 | 提醒内容 | 优先级 |
|------|---------|--------|
| X天没互动 | "王姐5天没互动了，上次买了精华" | medium |
| 消耗周期到达 | "精华30ml日均0.5ml→用完约60天→第50天提醒复购" | high |
| 差评预警 | "检测到差评→立即提醒+生成安抚话术" | critical |
| 大额订单 | "客户下单$1200跨境首单→风险提醒" | high |
| 生日/纪念日 | "客户生日→关怀+专属优惠" | low |

## 八、数字同事协作接口

私域管家与其他5个数字同事的协作：

```
私域管家                    导购顾问
    │                         │
    │ ── 客户分层+排期 ──→     │
    │   (谁是高价值、           │
    │    该什么时候触达)        │
    │                         │
    │ ←─ 触达结果反馈 ────     │
    │   (客户买了没、           │

## 九、需要新增的 Action Type

当前 Ontology 已有 5 个 Action Type（refundOrder / cancelOrder / updateShippingStatus / adjustInventory / escalateToSupervisor），私域管家需要新增：

| Action Type | 模式 | 说明 | 风险等级 |
|-------------|------|------|---------|
| `AddToWeCom` | Write Back | 添加客户到企业微信 | medium |
| `UpdateCustomerTags` | Write Back | 更新客户标签 | low |
| `UpdateCustomerSegment` | Write Back | 更新客户分层 | low |
| `CreateFollowupSchedule` | Write Back | 创建跟进排期 | medium |
| `AddToFollowupSchedule` | Write Back | 添加到现有排期 | low |
| `SendWeComMessage` | Side Effect | 发送企微消息 | **high** |

这些 Action Type 需要在 Ontology Manager 中注册（通过 `POST /v1/ontology/action-types`），并配置对应的 Function（Python/SQL）实现。
