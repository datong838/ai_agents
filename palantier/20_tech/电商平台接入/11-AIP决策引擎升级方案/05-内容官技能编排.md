## 一、内容官定位

### 1.1 职责边界

**内容官管"说什么"** — 文案、脚本、标题、封面，以及内容的审核和复盘。

| 职责 | 不做什么 |
|------|---------|
| ✅ 脚本生成：直播脚本/短视频脚本/朋友圈文案 | ❌ 卖什么（导购顾问的职责） |
| ✅ 标题优化：多版本标题 + 热度预估 | ❌ 客户分层/触达（私域管家的职责） |
| ✅ 封面描述：AI 绘图 prompt 生成 | ❌ 做活动策划（活动策划师的职责） |
| ✅ 内容审核：敏感词/品牌调性/合规检查 | ❌ 数据分析（数据参谋的职责） |
| ✅ 内容复盘：效果分析 + 优化建议 | ❌ 视频剪辑/图片处理（工具类） |
| ✅ 素材模板：行业话术库/模板管理 | ❌ 实际发布操作（运营手动或平台 API） |

### 1.2 核心洞察

> 电商内容现状：运营写文案靠感觉，没有 A/B 测试，不知道哪条内容带货。
> **内容官不是"代写"，是"带着数据写"** — 结合历史内容表现、产品卖点、人群画像生成内容。

### 1.3 适用平台

| 平台 | 内容形态 | 内容官侧重 |
|------|---------|-----------|
| 抖音/快手 | 短视频、直播 | 脚本节奏、钩子设计、带货话术 |
| 微商城（朋友圈/社群） | 图文、文案 | 种草文案、互动话术、转发语 |
| 淘宝/天猫/京东/拼多多 | 详情页、主图文案 | 卖点提炼、痛点对应、信任状 |

## 二、技能链总览

内容官包含 6 个技能，按内容生产流程：

```
技能1：内容策略生成  →  技能2：脚本/文案生成  →  技能3：标题优化
                                                │
                                     ┌──────────┘
                                     ▼
                               技能4：封面描述生成
                                     │
                                     ▼
                               技能5：内容自检审核
                                     │
                                     ▼
                               技能6：内容复盘与优化
```

| 技能 | 触发条件 | 核心动作 | 风险等级 | 需要审批 |
|------|---------|---------|---------|---------|
| 1.内容策略生成 | 手动/新建内容条目时 | 分析产品+人群 → 生成内容方向 | low | ❌ 自动执行 |
| 2.脚本/文案生成 | 策略生成后/手动 | 生成多版本脚本/文案 | low | ✅ 运营确认后采用 |
| 3.标题优化 | 脚本生成后/手动 | 生成多版本标题 + 热度预估 | low | ❌ 运营自选 |
| 4.封面描述生成 | 脚本生成后/手动 | 生成 AI 绘图 prompt | low | ❌ 运营自选 |
| 5.内容自检审核 | 生成后自动 | 敏感词/调性/合规检查 | medium | ✅ 高风险内容需人工确认 |
| 6.内容复盘与优化 | 发布后/手动 | 分析效果 → 生成优化建议 | low | ❌ 自动输出 |

## 三、技能1：内容策略生成

### 3.1 场景

运营新建一条内容，但不知道"写什么方向"。内容官根据产品信息、目标人群、历史内容表现，生成内容策略建议。

### 3.2 Plan Mode 设计

```
用户输入："给新品面霜写一条抖音短视频内容"
        │
        ▼
┌──────────────────────────────────────────┐
│ Clarification Gate                       │
│ Q1: 内容类型？（短视频/直播/图文）         │
│ Q2: 目标平台？（抖音/快手/朋友圈）         │
│ Q3: 核心卖点？（补水/抗衰/美白）           │
│ Q4: 目标人群？（干皮/油皮/敏感肌）         │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Task Understanding                       │
│ 类型：content_strategy                    │
│ 关键实体：Product OT（新品面霜）           │
│         Customer OT（目标人群画像）        │
│ 约束：3 个方向，每个方向含钩子+结构+收尾    │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取 Product OT                  │
│   action_type: ontology_query             │
│   query: GET /v1/objects/Product/{id}    │
│   risk: low                               │
│                                          │
│ Step 2: 读取历史内容表现（Episodic）       │
│   action_type: tool_call                  │
│   tool: memory.read                       │
│   layer: episodic                         │
│   filter: {product: "面霜", platform: "抖音"}
│   risk: low                               │
│                                          │
│ Step 3: 生成 3 个内容方向                 │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "基于产品卖点和历史表现生成3个   │
│           内容方向，每个含钩子+正文结构+收尾"
│   risk: low                               │
│                                          │
│ Step 4: 写入 Working Memory               │
│   action_type: tool_call                  │
│   tool: memory.write                      │
│   layer: working                          │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 3.3 输出结构

```typescript
interface ContentStrategy {
  directions: {
    id: string;
    name: string;                     // 方向名称（如「痛点直击型」）
    hook: string;                     // 开头钩子
    structure: string[];              // 正文结构（3-5个要点）
    ending: string;                   // 收尾/CTA
    expectedPerformance: 'high' | 'medium' | 'low';  // 预估表现
    reason: string;                   // 为什么选这个方向
  }[];
  recommendedIndex: number;           // 推荐选择第几个
  audienceInsights: string[];          // 人群洞察
}
```

### 3.4 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 读取 Product OT | low | 自动执行 |
| 读取历史内容记忆 | low | 自动执行 |
| 生成内容策略 | low | 自动执行，运营自选方向 |

### 3.5 Reflection 自审规则

```python
REFLECTION_RULES = {
    "content_strategy": [
        {
            "name": "direction_count_check",
            "condition": "len(directions) == 3",
            "on_fail": "regenerate_exact_count"
        },
        {
            "name": "product_mention_check",
            "condition": "all(dir.mentions_product(product_info) for dir in directions)",
            "on_fail": "inject_product_selling_points"
        },
        {
            "name": "audience_match_check",
            "condition": "all(dir.matches_audience(audience_profile) for dir in directions)",
            "on_fail": "adjust_for_target_audience"
        }
    ]
}
```

### 3.6 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 美妆行业话术模板、内容结构框架、平台规则 |
| **Episodic** | 历史经验 | 哪类内容点击率高、钩子类型效果排序、最佳发布时间 |
| **Working** | 当前任务 | 产品信息、目标人群、生成的策略选项 |

### 3.7 验收标准

- [ ] 输入产品ID + 平台 + 内容类型，能输出 3 个内容方向
- [ ] 每个方向包含：钩子、结构、收尾、预估表现、推荐理由
- [ ] 能从 Episodic Memory 读取历史内容表现数据
- [ ] 失败场景：产品信息不足时，能主动询问补充信息

## 四、技能2：脚本/文案生成

### 4.1 场景

运营选定内容方向后，内容官生成具体的脚本/文案。生成 3 个版本，运营可选择和编辑。

### 4.2 Plan Mode 设计

```
用户输入："选择方向1（痛点直击型），生成抖音短视频脚本"
        │
        ▼
┌──────────────────────────────────────────┐
│ Task Understanding                       │
│ 类型：content_generation                  │
│ 关键实体：ContentItem OT（内容条目）       │
│         Product OT（产品信息）             │
│         Strategy（选定的内容方向）         │
│ 约束：3 个版本，不同风格，每版 ≤150字        │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取产品+内容方向信息              │
│   action_type: ontology_query             │
│   risk: low                               │
│                                          │
│ Step 2: 读取行业话术模板（Semantic）       │
│   action_type: tool_call                  │
│   tool: memory.read                       │
│   layer: semantic                         │
│   risk: low                               │
│                                          │
│ Step 3: 生成 3 版脚本（不同风格）          │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "生成3版抖音短视频脚本，风格分别：│
│           1.干货科普型 2.情感共鸣型 3.对比测评型"
│   risk: low                               │
│   verification_skill: content_audit       │
│                                          │
│ Step 4: 自检（调用技能5：内容自检审核）     │
│   action_type: skill_call                 │
│   skill: content_self_audit               │
│   risk: medium                            │
│                                          │
│ Step 5: 写入 Artifact                    │
│   action_type: tool_call                  │
│   tool: artifact.create                   │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 4.3 输出结构

```typescript
interface GeneratedContent {
  versions: {
    id: string;
    style: string;                      // 风格名称
    title: string;                      // 暂定标题
    script: string;                     // 完整脚本/文案
    wordCount: number;                  // 字数
    duration?: number;                  // 预估时长（秒，仅视频）
    highlights: string[];               // 金句/亮点
    cta: string;                        // 行动号召
  }[];
  recommendedIndex: number;
  auditResult: AuditResult;             // 自检结果（来自技能5）
}
```

### 4.4 不同平台的 Prompt 差异

| 平台 | 内容类型 | Prompt 关键约束 |
|------|---------|----------------|
| 抖音 | 短视频脚本 | 时长≤60s、前3秒钩子、字幕分段、口播感 |
| 快手 | 短视频脚本 | 更接地气、老铁文化、直接带货 |
| 朋友圈 | 图文文案 | ≤200字、配图建议、互动引导（评论/点赞） |
| 社群 | 群内文案 | 口语化、限时感、@提醒、表情符号 |
| 淘宝详情页 | 文案 | 痛点→卖点→信任状→促单，FAB法则 |

### 4.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 生成脚本/文案 | low | 自动执行 |
| 内容自检 | medium | 自动执行，不通过则高亮问题 |
| 运营确认采用 | low | 运营选择版本后自动写入内容条目 |

### 4.6 Reflection 自审规则

```python
REFLECTION_RULES = {
    "content_generation": [
        # 规则1：字数检查
        {
            "name": "word_count_check",
            "condition": "word_count <= max_word_count",
            "on_fail": "trim_and_regenerate",
            "max_retries": 2
        },
        # 规则2：卖点完整性（必须覆盖核心卖点）
        {
            "name": "selling_point_coverage",
            "condition": "covers_core_selling_points(script, product.points, 0.8)",
            "on_fail": "inject_missing_selling_points"
        },
        # 规则3：CTA 存在性
        {
            "name": "cta_presence",
            "condition": "has_clear_cta(script)",
            "on_fail": "add_cta_to_ending"
        },
        # 规则4：版本多样性（3版风格要有明显差异）
        {
            "name": "style_diversity",
            "condition": "style_diversity_score(versions) >= 0.7",
            "on_fail": "regenerate_with_more_style_variation"
        }
    ]
}
```

### 4.7 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 美妆话术库、平台文案规范、FAB法则模板 |
| **Episodic** | 历史经验 | 哪种风格转化率高、最佳字数/时长、CTA 效果对比 |
| **Working** | 当前任务 | 产品信息、选定方向、生成的多版本文案 |

### 4.8 验收标准

- [ ] 输入产品ID + 平台 + 内容类型 + 方向，能输出 3 个版本
- [ ] 每个版本含：标题、完整脚本、字数、亮点、CTA
- [ ] 3 个版本风格有明显差异（多样性得分 ≥0.7）
- [ ] 自动触发内容自检（技能5），结果随脚本一起返回
- [ ] 失败场景：平台不在支持列表时，提示并询问是否继续

## 五、技能3：标题优化

### 5.1 场景

运营有了脚本/文案，但标题不够吸引人。内容官生成 5 个优化标题，并给出热度预估。

### 5.2 Plan Mode 设计

```
用户输入："帮我优化这条短视频的标题"
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取内容条目 + 脚本               │
│   action_type: ontology_query             │
│   risk: low                               │
│                                          │
│ Step 2: 读取历史标题表现（Episodic）       │
│   action_type: tool_call                  │
│   tool: memory.read                       │
│   layer: episodic                         │
│   filter: {platform, content_type}        │
│   risk: low                               │
│                                          │
│ Step 3: 生成 5 个优化标题                 │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "生成5个优化标题，风格分别：      │
│           悬念型/痛点型/数字型/对比型/提问型"
│   risk: low                               │
│                                          │
│ Step 4: 热度预估（基于历史数据）            │
│   action_type: tool_call                  │
│   tool: prediction.heat_score             │
│   risk: low                               │
│                                          │
│ Step 5: 输出排序后的标题列表               │
│   action_type: tool_call                  │
│   tool: artifact.create                   │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 5.3 输出结构

```typescript
interface OptimizedTitles {
  titles: {
    id: string;
    title: string;
    style: string;                      // 标题风格
    heatScore: number;                  // 热度预估 0-100
    heatBasis: string;                  // 预估依据（基于XX历史数据）
    wordCount: number;
  }[];
  sortedBy: 'heat' | 'length';          // 排序方式
  recommendedIndex: number;
}
```

### 5.4 标题风格库

| 风格 | 公式 | 示例 |
|-----|------|------|
| 悬念型 | 问题/留白 + 好奇心 | "为什么你的面霜越涂越干？" |
| 痛点型 | 痛点 + 解决方案暗示 | "干皮冬天卡粉？试试这招" |
| 数字型 | 具体数字 + 效果承诺 | "3天见效！干皮救星来了" |
| 对比型 | Before/After 对比 | "涂vs不涂，差别居然这么大" |
| 提问型 | 直击灵魂的问题 | "你真的会涂面霜吗？" |
| 利益型 | 直接说好处 | "一瓶=补水+抗衰+美白" |
| 恐惧型 | 不做的后果 | "再这样涂面霜，脸就毁了" |

### 5.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 生成优化标题 | low | 自动执行 |
| 热度预估 | low | 自动执行，仅供参考 |

### 5.6 Reflection 自审规则

```python
REFLECTION_RULES = {
    "title_optimization": [
        {
            "name": "title_count_check",
            "condition": "len(titles) == 5",
            "on_fail": "regenerate_exact_count"
        },
        {
            "name": "style_uniqueness",
            "condition": "all_unique_style(titles)",
            "on_fail": "regenerate_with_unique_styles"
        },
        {
            "name": "length_check",
            "condition": "all(len(t) <= 30 for t in titles)",  # 抖音标题≤30字
            "on_fail": "trim_long_titles"
        }
    ]
}
```

### 5.7 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 标题公式库、平台标题规范、禁用词 |
| **Episodic** | 历史经验 | 各风格点击率、最佳标题长度、高热度关键词 |
| **Working** | 当前任务 | 原始标题、脚本内容、生成的5个标题 |

### 5.8 验收标准

- [ ] 输入原始标题 + 脚本，能输出 5 个优化标题
- [ ] 5 个标题风格各不相同
- [ ] 每个标题有热度预估分和预估依据
- [ ] 按热度从高到低排序
- [ ] 抖音标题不超过 30 字

```typescript
  versions: {
    id: string;
    style: string;                      // 封面风格（如「产品特写型」）
    prompt: string;                     // AI 绘图 prompt（英文，适配 Midjourney/SD）
    promptChinese: string;              // 中文描述（供运营理解）
    composition: string;                // 构图说明
    colorPalette: string;               // 色调
    textOverlay: {                      // 文字叠加建议
      text: string;
      position: string;
      fontSize: string;
    };
    recommendedTool: 'midjourney' | 'stable_diffusion' | 'dall_e';
  }[];
  recommendedIndex: number;
}
```

### 6.4 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 生成封面描述 | low | 自动执行 |

### 6.5 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 美妆封面设计规范、AI 绘图关键词库、平台尺寸要求 |
| **Episodic** | 历史经验 | 哪种封面点击率高、色调偏好、文字位置效果 |
| **Working** | 当前任务 | 脚本摘要、产品图参考、生成的 3 版描述 |

### 6.6 验收标准

- [ ] 输入脚本 + 产品，能输出 3 版封面描述
- [ ] 每版含：英文 prompt、中文描述、构图、色调、文字叠加建议
- [ ] 尺寸适配对应平台（抖音 9:16、朋友圈 1:1 等）

## 七、技能5：内容自检审核

### 7.1 场景

内容生成后自动执行的自检流程，确保内容合规、符合品牌调性、无敏感词。这是一个 Verification Loop 技能，被其他内容生成技能嵌入调用。

### 7.2 检查项清单

| 检查类别 | 检查项 | 方法 | 不通过处理 |
|---------|-------|------|-----------|
| **敏感词** | 违禁词、极限词（最、第一、绝对） | 关键词匹配 + 语义检测 | 高亮标记，自动替换建议 |
| **品牌调性** | 是否符合品牌人设/语气 | 语义相似度对比品牌知识库 | 提示风险，建议调整 |
| **合规性** | 广告法、平台规则 | 规则引擎 | 高亮违规项，必须修改 |
| **事实准确性** | 产品功效不夸大 | 对比 Product OT 数据 | 标注存疑处，需人工确认 |
| **格式规范** | 字数、时长、分段 | 规则检查 | 自动调整或提示 |

### 7.3 输出结构

```typescript
interface AuditResult {
  overallStatus: 'pass' | 'warning' | 'fail';
  checks: {
    category: string;
    item: string;
    status: 'pass' | 'warning' | 'fail';
    severity: 'low' | 'medium' | 'high';
    description: string;
    suggestion?: string;           // 修复建议
    position?: {                   // 问题位置
      startIndex: number;
      endIndex: number;
    };
  }[];
  summary: string;                  // 审核总结
  requiresManualReview: boolean;    // 是否需要人工复核
}
```

### 7.4 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 自动审核 | low | 自动执行 |
| 审核不通过（高风险） | medium | 阻止发布，必须人工确认 |
| 审核不通过（低风险） | low | 提示但不阻止 |

### 7.5 验收标准

- [ ] 能检测出常见极限词（最、第一、绝对等）
- [ ] 能检测出广告法违规表述（国家级、最高级等）
- [ ] 能标注问题位置和修改建议
- [ ] 高风险内容标记「需人工复核」
- [ ] 审核速度 < 2s / 千字

## 八、技能6：内容复盘与优化

### 8.1 场景

内容发布后，分析效果数据，生成复盘报告和优化建议。

### 8.2 Plan Mode 设计

```
触发条件：发布后 7 天 / 手动触发
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取内容效果数据                  │
│   action_type: ontology_query             │
│   query: ContentItem.metrics              │
│   risk: low                               │
│                                          │
│ Step 2: 对比历史基准（Episodic）           │
│   action_type: tool_call                  │
│   tool: memory.read                       │
│   layer: episodic                         │
│   filter: {platform, content_type}        │
│   risk: low                               │
│                                          │
│ Step 3: 效果分析（好/坏/原因）             │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "分析这条内容的表现，找出亮点和问题"
│   risk: low                               │
│                                          │
│ Step 4: 生成优化建议                      │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "基于分析结果，给出3条具体优化建议"
│   risk: low                               │
│                                          │
│ Step 5: 写入 Episodic Memory（经验沉淀）   │
│   action_type: tool_call                  │
│   tool: memory.write                      │
│   layer: episodic                         │
│   tags: ["content_optimization", platform]
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 8.3 输出结构

```typescript
interface ContentReview {
  contentItemId: string;

  // 效果概览
  metrics: ContentMetrics;
  performanceRating: 'S' | 'A' | 'B' | 'C';  // 表现评级
  percentile: number;                        // 历史百分位

  // 分析
  highlights: string[];                      // 亮点
  issues: string[];                          // 问题

  // 优化建议
  suggestions: {
    id: string;
    priority: 'high' | 'medium' | 'low';
    suggestion: string;
    expectedImprovement: string;             // 预期提升
    actionLink?: string;                     // 操作链接
  }[];

  // 经验沉淀
  lessonLearned?: {
    type: 'success' | 'failure';
    content: string;
    context: string;
  };
}
```

### 8.4 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 读取效果数据 | low | 自动执行 |
| 生成复盘报告 | low | 自动执行 |
| 写入 Episodic Memory | low | 自动执行，运营可编辑/删除 |

### 8.5 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 行业基准数据、优化方法论 |
| **Episodic** | 历史经验 | 历史内容表现库、成功/失败案例、优化效果追踪 |
| **Working** | 当前任务 | 当前内容数据、对比基准、分析过程 |

### 8.6 验收标准

- [ ] 输入内容ID，能输出现象+原因+建议的完整复盘
- [ ] 表现评级准确（和人工判断一致率 ≥ 80%）
- [ ] 优化建议具体可执行，不是空话
- [ ] 成功经验自动写入 Episodic Memory
- [ ] 运营可标记「有用/无用」，反馈用于优化模型
