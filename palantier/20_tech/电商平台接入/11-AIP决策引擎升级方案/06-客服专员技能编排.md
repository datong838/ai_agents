## 一、客服专员定位

### 1.1 职责边界

**客服专员管"出了问题怎么办"** — 订单查询、售后处理、物流跟踪、投诉解决。

| 职责 | 不做什么 |
|------|---------|
| ✅ 订单查询：订单状态、物流信息、发票 | ❌ 产品推荐（导购顾问的职责） |
| ✅ 售后处理：退换货、退款、补发、维修 | ❌ 写文案/做内容（内容官的职责） |
| ✅ 物流跟踪：物流查询、异常件处理 | ❌ 做活动策划（活动策划师的职责） |
| ✅ 投诉处理：客诉受理、升级、安抚 | ❌ 数据分析（数据参谋的职责） |
| ✅ 政策解答：退换货政策、保修政策、会员权益 | ❌ 客户运营/触达（私域管家的职责） |
| ✅ 满意度追踪：服务评价、NPS 调研 | ❌ 财务处理（退款走财务系统，客服只发起） |

### 1.2 核心洞察

> 电商客服现状：人工客服成本高、响应慢、夜班难覆盖、培训成本高、服务质量不稳定。
> **客服专员不是"机器人自动回复"，是"懂业务的 24 小时客服"** — 能查数据、办业务、懂安抚，搞不定才转人工。

### 1.3 服务场景

| 场景 | 占比（预估） | 处理方式 |
|------|-------------|---------|
| 订单查询 | 30% | 全自动（AI 直接回答） |
| 物流查询 | 25% | 全自动 |
| 退换货咨询 | 15% | AI 判断 + 引导自助 |
| 退款咨询 | 10% | AI 判断 + 引导自助 |
| 产品使用咨询 | 10% | AI 回答 + 转导购顾问 |
| 投诉/差评 | 5% | AI 首接安抚 + 转人工 |
| 其他 | 5% | AI 兜底 + 转人工 |

### 1.4 人机协作模式

```
客户进线
    ↓
AI 客服专员 首接
    │
    ├─ 简单问题 → 直接回答 → 服务评价 → 结束
    │
    ├─ 需要操作（退换货/退款） → 引导自助操作 → 操作结果通知
    │
    ├─ 复杂问题 / 高情绪 → 自动转人工
    │       │
    │       └─ 转人工时同步：
    │           · 客户信息
    │           · 历史对话
    │           · AI 已做的处理
    │           · 初步判断和建议
    │
    └─ 搞不定的问题 → 转人工 + 记录学习
```

## 二、技能链总览

客服专员包含 6 个技能，按服务流程：

```
技能1：意图识别    →  技能2：订单查询    →  技能3：物流跟踪
                                          │
                               ┌──────────┘
                               ▼
                         技能4：售后处理
                               │
                               ▼
                         技能5：投诉处理
                               │
                               ▼
                         技能6：满意度管理
```

| 技能 | 触发条件 | 核心动作 | 风险等级 | 需要审批 |
|------|---------|---------|---------|---------|
| 1.意图识别 | 客户首句消息 | 识别意图+提取实体+判断优先级 | low | ❌ 自动执行 |
| 2.订单查询 | 订单类意图 | 查询订单+状态+金额+商品 | low | ❌ 自动回答 |
| 3.物流跟踪 | 物流类意图 | 查询物流轨迹+异常件识别 | low | ❌ 自动回答 |
| 4.售后处理 | 退换货/退款/补发 | 判断资格+引导操作+创建工单 | medium | ✅ 高金额售后需人工审批 |
| 5.投诉处理 | 投诉类/高情绪 | 情绪识别+安抚+升级流程 | high | ✅ 投诉必须有人工参与 |
| 6.满意度管理 | 服务结束后 | 评价收集+NPS+服务质检 | low | ❌ 自动发起 |

## 三、技能1：意图识别

### 3.1 场景

客户发来第一条消息，快速识别意图、提取关键实体、判断是否需要紧急处理。

### 3.2 Plan Mode 设计

```
用户输入："我的快递怎么还没到？"
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 意图分类                          │
│   action_type: llm_call                   │
│   model: private-small                    │
│   task: "客服意图分类"                     │
│   categories: [                           │
│     "order_query",                        │
│     "logistics_query",                    │
│     "return_refund",                      │
│     "complaint",                          │
│     "product_consult",                    │
│     "policy_consult",                     │
│     "other"                               │
│   ]                                        │
│   risk: low                               │
│                                          │
│ Step 2: 实体提取                          │
│   action_type: llm_call + rule_based      │
│   entities: ["order_id", "phone",          │
│              "product_name", "date",       │
│              "amount"]                     │
│   risk: low                               │
│                                          │
│ Step 3: 情绪识别                          │
│   action_type: llm_call                   │
│   model: private-small                    │
│   levels: ["calm", "mildly_upset",         │
│            "angry", "furious"]             │
│   risk: medium                            │
│                                          │
│ Step 4: 优先级判定                        │
│   action_type: rule_engine                │
│   factors: ["情绪等级", "金额大小",         │
│             "问题类型", "客户等级"]         │
│   priority: "low" | "normal" | "high" | "urgent"
│   risk: low                               │
│                                          │
│ Step 5: 路由到对应技能                    │
│   action_type: skill_router               │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 3.3 输出结构

```typescript
interface IntentRecognition {
  // 意图
  primaryIntent: string;
  secondaryIntent?: string;
  confidence: number;           // 置信度 0-1

  // 实体
  entities: {
    orderId?: string;
    phone?: string;
    productName?: string;
    date?: string;
    amount?: number;
    other?: Record<string, string>;
  };

  // 情绪
  sentiment: 'calm' | 'mildly_upset' | 'angry' | 'furious';
  sentimentConfidence: number;

  // 优先级
  priority: 'low' | 'normal' | 'high' | 'urgent';
  priorityReason: string;

  // 路由
  nextSkill: string;
  needsHuman: boolean;          // 是否需要直接转人工
  humanReason?: string;         // 转人工原因

  // 澄清问题（如果信息不足）
  clarificationQuestions?: string[];
}
```

### 3.4 客服意图分类体系

| 一级分类 | 二级分类 | 示例话术 |
|---------|---------|---------|
| **订单查询** | 订单状态、订单金额、订单详情、取消订单 | "我的订单发货了吗" |
| **物流查询** | 物流轨迹、预计到达、地址修改、异常件 | "快递到哪了" |
| **退换货** | 退货、换货、退货地址、退货进度 | "想退货怎么办" |
| **退款** | 退款申请、退款进度、退款金额、退款方式 | "什么时候退款" |
| **补发** | 漏发、错发、补发进度 | "漏发了一件" |
| **投诉** | 产品质量、服务态度、物流投诉、差评 | "你们这质量也太差了" |
| **产品咨询** | 使用方法、成分、保质期、适用人群 | "孕妇能用吗" |
| **政策咨询** | 退换货政策、保修政策、会员权益 | "7天无理由怎么算" |
| **发票** | 发票申请、发票进度、发票修改 | "怎么开发票" |
| **其他** | 找人、合作建议、其他 | "找你们经理" |

### 3.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 意图识别 | low | 自动执行 |
| 情绪识别 | low | 自动执行，结果不展示给客户 |
| 转人工判断 | medium | 高优先级/高情绪自动转人工 |

### 3.6 Reflection 自审规则

```python
REFLECTION_RULES = {
    "intent_recognition": [
        {
            "name": "confidence_threshold",
            "condition": "confidence >= 0.7 or has_clarification_questions",
            "on_fail": "ask_clarification"
        },
        {
            "name": "urgent_escalation_check",
            "condition": "if_urgent_then_human_or_skill(priority, sentiment)",
            "on_fail": "escalate_immediately"
        },
        {
            "name": "entity_extraction_completeness",
            "condition": "if_needs_order_then_has_order_id(intent, entities)",
            "on_fail": "ask_for_order_id"
        }
    ]
}
```

### 3.7 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 意图分类体系、常见问法、实体提取规则 |
| **Episodic** | 历史经验 | 历史对话意图分布、误识别案例、高优场景模式 |
| **Working** | 当前任务 | 客户消息、识别结果、待澄清问题 |

### 3.8 验收标准

- [ ] 意图识别准确率 ≥ 90%（Top 1）
- [ ] 关键实体（订单号等）提取准确率 ≥ 95%
- [ ] 情绪识别准确率 ≥ 80%
- [ ] 高情绪客户（angry/furious）自动升级处理
- [ ] 信息不足时主动提问澄清

## 四、技能2：订单查询

### 4.1 场景

客户查询订单相关信息，AI 直接查询并回答。

### 4.2 Plan Mode 设计

```
用户输入："帮我查一下订单 12345"
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 验证客户身份                      │
│   action_type: tool_call                  │
│   tool: customer_verification.verify      │
│   method: "order_id_match + phone_last4"  │
│   risk: medium                            │
│                                          │
│ Step 2: 查询订单数据                      │
│   action_type: ontology_query             │
│   query: Order OT + OrderItem OT          │
│   risk: low                               │
│                                          │
│ Step 3: 生成自然语言回答                  │
│   action_type: llm_call                   │
│   model: private-small                    │
│   prompt: "用友好、清晰的语言回答订单查询"   │
│   risk: low                               │
│                                          │
│ Step 4: 主动关联服务                      │
│   action_type: llm_call                   │
│   task: "根据订单状态推荐下一步服务"        │
│   risk: low                               │
│                                          │
│ Step 5: 输出回答                          │
│   action_type: tool_call                  │
│   tool: response.generate                 │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 4.3 输出结构

```typescript
interface OrderQueryResponse {
  // 订单基本信息
  order: {
    orderId: string;
    status: string;           // 待付款/待发货/待收货/已完成/已取消
    createTime: string;
    payTime?: string;
    shipTime?: string;
    completeTime?: string;

    totalAmount: number;
    discountAmount?: number;
    actualPayment: number;

    items: {
      productName: string;
      sku: string;
      quantity: number;
      price: number;
      image?: string;
    }[];

    shippingAddress?: {
      name: string;
      phone: string;
      address: string;
    };
  };

  // 自然语言回答
  response: string;

  // 主动建议
  suggestions: {
    type: string;
    text: string;
    action?: string;         // 可触发的动作
  }[];
}
```

### 4.4 常见查询类型与应答模板

| 查询类型 | 信息要素 | 主动建议 |
|---------|---------|---------|
| 订单状态 | 状态、下一步动作、时间节点 | 物流查询/催发货/提醒收货 |
| 订单金额 | 商品金额、优惠、实付 | 发票申请/退款咨询 |
| 配送信息 | 快递、预计到达、收货地址 | 修改地址/物流跟踪 |
| 取消订单 | 取消资格、退款说明 | 换货建议/优惠券补偿 |

### 4.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 订单查询 | medium | 必须通过身份验证（订单号+手机号后4位 或 已登录） |
| 展示地址 | medium | 手机号中间 4 位打码，地址可脱敏 |

### 4.6 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 订单状态定义、应答模板、政策口径 |
| **Episodic** | 历史经验 | 常见问题、最佳回答、客户偏好 |
| **Working** | 当前任务 | 客户信息、订单数据、回答内容 |

### 4.7 验收标准

- [ ] 输入订单号能快速查询订单信息（< 3秒）
- [ ] 回答清晰友好，包含关键信息
- [ ] 身份验证通过才能查询
- [ ] 敏感信息（手机号/地址）脱敏显示
- [ ] 根据订单状态主动建议下一步操作

## 五、技能3：物流跟踪

### 5.1 场景

客户查询物流信息，AI 查询物流轨迹并回答，识别异常件并主动处理。

### 5.2 Plan Mode 设计

```
用户输入："我的快递到哪了"
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 获取订单号（从对话/历史）          │
│   action_type: context_retrieval          │
│   risk: low                               │
│                                          │
│ Step 2: 查询物流轨迹                      │
│   action_type: tool_call                  │
│   tool: logistics.track                  │
│   provider: "auto"                        │
│   risk: low                               │
│                                          │
│ Step 3: 异常件识别                        │
│   action_type: tool_call                  │
│   tool: logistics.anomaly_detect           │
│   anomalies: ["delay", "lost", "damaged",  │
│              "wrong_address", "returned"]  │
│   risk: medium                            │
│                                          │
│ Step 4: 生成回答+建议                     │
│   action_type: llm_call                   │
│   model: private-small                    │
│   prompt: "清晰说明物流状态，异常时给出解决方案"
│   risk: low                               │
│                                          │
│ Step 5: 如异常，自动创建售后工单           │
│   action_type: tool_call                  │
│   tool: after_sales.create_ticket         │
│   condition: "if_anomaly"                 │
│   risk: medium                            │
└──────────────────────────────────────────┘
```

### 5.3 输出结构

```typescript
interface LogisticsTrackingResponse {
  // 物流基本信息
  logistics: {
    orderId: string;
    trackingNumber: string;
    carrier: string;          // 快递公司
    status: string;           // 待揽收/运输中/派送中/已签收/异常

    // 轨迹
    traces: {
      time: string;
      status: string;
      location: string;
      description: string;
    }[];

    // 预计送达
    estimatedDelivery?: string;

    // 异常信息
    anomaly?: {
      type: string;
      description: string;
      severity: 'low' | 'medium' | 'high';
      suggestedAction: string;
    };
  };

  // 自然语言回答
  response: string;

  // 下一步建议
  nextActions: {
    action: string;
    label: string;
    type: 'info' | 'warning' | 'action';
  }[];
}
```

### 5.4 异常件处理流程

| 异常类型 | 识别方式 | 自动处理 | 人工介入条件 |
|---------|---------|---------|-------------|
| **延迟** | 超过预计送达时间 24h | 安抚客户 + 催促物流 + 发优惠券 | 延迟 > 72h 或高价值订单 |
| **丢失** | 物流停滞 > 72h | 安抚客户 + 补发/退款建议 + 创建工单 | 一律转人工确认 |
| **破损** | 客户反馈 + 照片 | 引导上传凭证 + 创建售后工单 | 高价值商品 + 客户情绪激动 |
| **错发地址** | 地址不符 | 联系物流拦截 + 重新发货 | 一律转人工 |
| **退回** | 包裹被退回 | 通知客户 + 确认原因 + 退款/重发 | 一律转人工 |

### 5.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 物流查询 | low | 身份验证后自动查询 |
| 异常件识别 | medium | 自动识别，高风险自动转人工 |
| 创建售后工单 | medium | 自动创建，需人工最终处理 |

### 5.6 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 物流术语、异常类型、处理流程 |
| **Episodic** | 历史经验 | 常见物流问题、最佳安抚话术、各快递特点 |
| **Working** | 当前任务 | 物流数据、异常判断、回答内容 |

### 5.7 验收标准

- [ ] 能查询主流快递公司的物流轨迹
- [ ] 能识别 5 类常见异常件
- [ ] 异常件有明确的处理建议
- [ ] 高风险异常自动转人工
- [ ] 回答清晰，时间地点明确

## 六、技能4：售后处理

### 6.1 场景

客户申请退换货、退款、补发等售后，AI 判断资格、引导操作、创建工单。

### 6.2 Plan Mode 设计

```
用户输入："我要退货"
        │
        ▼
┌──────────────────────────────────────────┐
│ Clarification Gate                       │
│ Q1: 哪个订单？                           │
│ Q2: 退货原因？（质量问题/不喜欢/尺码不符等）│
│ Q3: 商品是否完好？包装是否保留？            │
│ Q4: 有没有凭证照片？（质量问题需要）       │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 验证客户身份+订单信息              │
│   action_type: ontology_query             │
│   risk: medium                            │
│                                          │
```

### 6.4 售后类型与处理流程

### 7.4 投诉分级与升级机制

| 等级 | 判定条件 | 响应方式 | 处理时限 |
|-----|---------|---------|---------|
| 一般投诉 | 情绪平静，问题明确 | AI 直接处理或引导自助 | 24h 内 |
| 重要投诉 | 情绪激动，金额较大，或涉及质量 | AI 首接安抚 → 转人工 | 2h 内响应 |
| 紧急投诉 | 情绪激烈，威胁投诉平台/曝光，或涉及安全 | 立即转人工 + 主管介入 | 30min 内响应 |
| 舆情风险 | 社交媒体大V / 威胁曝光 / 集体投诉 | 立即转人工 + 公关介入 | 立即响应 |

### 7.5 共情安抚黄金法则

1. **先共情，后解决** — "非常抱歉给您带来了不好的体验"
2. **不辩解，不推诿** — 不说"这不是我们的问题"
3. **表达重视** — "您的问题我们非常重视"
4. **引导表达** — "您能具体说一下情况吗"
5. **给出预期** — "我会尽快帮您处理"

|------|---------|------|
| 投诉识别 | medium | 自动识别 |
| 安抚回应 | medium | 自动生成，但禁止做出超出权限的承诺 |
| 转人工 | high | 重要投诉及以上**必须**转人工 |
| 承诺赔偿 | high | **AI 禁止承诺任何赔偿/补偿**，只能说"我们会尽力为您争取" |
