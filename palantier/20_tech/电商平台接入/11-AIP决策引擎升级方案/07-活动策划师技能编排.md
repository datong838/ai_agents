## 一、活动策划师定位

### 1.1 职责边界

**活动策划师管"怎么卖"** — 选品、定价、优惠、节奏，以及活动的效果预估和复盘。

| 职责 | 不做什么 |
|------|---------|
| ✅ 活动方案生成：选品/定价/优惠策略 | ❌ 写文案脚本（内容官的职责） |
| ✅ 效果预估：GMV/订单/ROI 区间预测 | ❌ 客户触达（私域管家的职责） |
| ✅ 执行监控：实时数据+异常告警 | ❌ 数据分析深度归因（数据参谋的职责） |
| ✅ 活动复盘：经验提取+下次优化建议 | ❌ 产品管理/库存管理（运营系统） |
| ✅ 优惠规则引擎：多平台优惠配置 | ❌ 实际打款/发货（财务/仓储系统） |
| ✅ 活动节奏设计：预热/爆发/返场 | ❌ 广告投放（投放团队职责） |

### 1.2 核心洞察

> 电商活动现状：拍脑袋定目标，凭感觉选品，活动结束才知道赚不赚钱。
> **活动策划师不是"帮你做PPT"，是"带着数据做方案"** — 基于历史活动数据、库存状况、人群画像生成可执行方案。

### 1.3 适用平台

| 平台 | 活动形态 | 活动策划师侧重 |
|------|---------|---------------|
| 淘宝/天猫 | 聚划算、百亿补贴、天天特卖 | 平台规则适配、赛马机制、流量获取 |
| 京东 | 秒杀、品牌闪购、京券东券 | 自营vs POP、仓储配合、京准通协同 |
| 拼多多 | 百亿补贴、限时秒杀、多多进宝 | 低价策略、拼团玩法、社交裂变 |
| 微商城 | 拼团、秒杀、会员日、积分兑换 | 社群裂变、会员体系、私域专属 |
| 抖音/快手 | 直播带货、短视频带货 | 主播配合、投放协同、内容节奏 |

## 二、技能链总览

活动策划师包含 6 个技能，按活动生命周期：

```
技能1：活动目标拆解  →  技能2：选品建议  →  技能3：定价策略
                                                    │
                                         ┌──────────┘
                                         ▼
                                   技能4：优惠配置
                                         │
                                         ▼
                                   技能5：效果预估
                                         │
                                         ▼
                                   技能6：活动复盘
```

| 技能 | 触发条件 | 核心动作 | 风险等级 | 需要审批 |
|------|---------|---------|---------|---------|
| 1.活动目标拆解 | 新建活动时 | 目标→子目标→每日拆解 | low | ❌ 自动执行 |
| 2.选品建议 | 目标拆解后 | 基于历史表现+库存生成选品清单 | low | ✅ 运营确认选品 |
| 3.定价策略 | 选品确认后 | 成本核算+竞品分析+定价建议 | medium | ✅ 价格需运营确认 |
| 4.优惠配置 | 定价确认后 | 优惠券/满减/赠品规则设计 | medium | ✅ 优惠力度需审批 |
| 5.效果预估 | 方案完成后 | 基于历史数据的区间预估 | low | ❌ 自动输出 |
| 6.活动复盘 | 活动结束后 | 效果分析+经验提取+优化建议 | low | ❌ 自动输出，运营可编辑 |

## 三、技能1：活动目标拆解

### 3.1 场景

运营说"618 要做 100 万 GMV"，活动策划师把总目标拆解到每一天、每个渠道、每个品类。

### 3.2 Plan Mode 设计

```
用户输入："618大促，目标GMV 100万，6.1-6.18，全平台"
        │
        ▼
┌──────────────────────────────────────────┐
│ Clarification Gate                       │
│ Q1: 核心目标？（GMV/订单/ROI/拉新）        │
│ Q2: 目标平台？（全平台/单平台）             │
│ Q3: 活动类型？（大促/日常/会员日）          │
│ Q4: 预算约束？（优惠预算/投放预算）         │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取历史同类活动数据               │
│   action_type: ontology_query             │
│   query: Activity OT + Order OT           │
│   risk: low                               │
│                                          │
│ Step 2: 读取品类销售占比（基准分布）         │
│   action_type: ontology_query             │
│   query: Product.category + sales         │
│   risk: low                               │
│                                          │
│ Step 3: 目标拆解（按天×渠道×品类）          │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "基于历史数据将100万GMV拆解为     │
│           每日目标+各渠道占比+品类分布"     │
│   risk: low                               │
│                                          │
│ Step 4: 写入 Working Memory               │
│   action_type: tool_call                  │
│   tool: memory.write                      │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 3.3 输出结构

```typescript
interface ActivityGoalBreakdown {
  totalGoal: {
    type: GoalType;
    value: number;
    period: { start: string; end: string };
  };

  // 按天拆解
  dailyBreakdown: {
    date: string;
    targetGMV: number;
    targetOrders: number;
    phase: 'warmup' | 'peak' | 'flashsale' | 'return';  // 活动阶段
  }[];

  // 按渠道拆解
  channelBreakdown: {
    channel: string;
    targetGMV: number;
    share: number;         // 占比
  }[];

  // 按品类拆解
  categoryBreakdown: {
    category: string;
    targetGMV: number;
    share: number;
  }[];

  // 关键节点
  keyMilestones: {
    date: string;
    event: string;        // 如「开门红」「品类日」「冲刺日」
    expectedGMV: number;
  }[];

  confidence: 'high' | 'medium' | 'low';
  basis: string;          // 拆解依据说明
}
```

### 3.4 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 读取历史活动数据 | low | 自动执行 |
| 生成目标拆解 | low | 自动执行，运营可调整 |

### 3.5 Reflection 自审规则

```python
REFLECTION_RULES = {
    "goal_breakdown": [
        {
            "name": "total_sum_check",
            "condition": "sum(daily.targetGMV) == totalGoal.value",
            "on_fail": "recalculate_daily_breakdown"
        },
        {
            "name": "historical_benchmark_check",
            "condition": "abs(totalGoal.value / historical_avg - 1) <= 1.0",  # 不超过历史的200%
            "on_fail": "flag_as_aggressive_and_justify"
        },
        {
            "name": "peak_day_density",
            "condition": "peak_day_gmv <= 0.3 * total_goal",  # 峰值日不超过30%
            "on_fail": "redistribute_peak_to_surrounding_days"
        }
    ]
}
```

### 3.6 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 电商大促节奏模板、品类占比基准、渠道分布参考 |
| **Episodic** | 历史经验 | 历次活动目标vs实际、每日波动规律、峰值日分布 |
| **Working** | 当前任务 | 总目标、时间范围、平台范围、拆解结果 |

### 3.7 验收标准

- [ ] 输入总目标+时间+平台，能输出按天/渠道/品类的三维拆解
- [ ] 每日目标之和 = 总目标
- [ ] 有置信度评估和拆解依据说明
- [ ] 活动阶段划分合理（预热/爆发/返场）

## 四、技能2：选品建议

### 4.1 场景

基于目标拆解结果，结合历史销售数据、库存状况、产品毛利，生成活动选品清单（Top N SKU）。

### 4.2 Plan Mode 设计

```
用户输入："给618大促选品，目标GMV 100万"
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取产品基础数据+库存+毛利         │
│   action_type: ontology_query             │
│   query: Product OT + Inventory OT        │
│   risk: low                               │
│                                          │
│ Step 2: 读取历史活动选品表现（Episodic）    │
│   action_type: tool_call                  │
│   tool: memory.read                       │
│   layer: episodic                         │
│   filter: {activity_type: "big_sale"}     │
│   risk: low                               │
│                                          │
│ Step 3: 选品评分模型计算                   │
│   action_type: tool_call                  │
│   tool: product_scoring.calculate         │
│   factors: [                              │
│     "历史销量(权重30%)",                    │
│     "毛利率(权重25%)",                      │
│     "库存深度(权重20%)",                    │
│     "活动爆发力(权重15%)",                  │
│     "复购率(权重10%)"                       │
│   ]                                        │
│   risk: low                               │
│                                          │
│ Step 4: LLM 生成选品理由+结构               │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "基于评分结果生成Top20选品清单，   │
│           按梯队分组，每个SKU配推荐理由"     │
│   risk: low                               │
│                                          │
│ Step 5: 库存预警检查（Verification）       │
│   action_type: skill_call                 │
│   skill: inventory_warning_check          │
│   risk: medium                            │
│                                          │
│ Step 6: 写入 Artifact                    │
│   action_type: tool_call                  │
│   tool: artifact.create                   │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 4.3 输出结构

```typescript
interface ProductSelection {
  products: {
    tier: 'S' | 'A' | 'B' | 'C';           // 梯队
    productId: string;
    productName: string;
    category: string;

    // 评分
    totalScore: number;                    // 0-100
    scoreBreakdown: {
      salesHistory: number;
      margin: number;
      inventory: number;
      burstPotential: number;
      repurchaseRate: number;
    };

    // 关键数据
    originalPrice: number;
    suggestedActivityPrice?: number;       // 建议活动价（技能3填充）
    margin: number;                        // 毛利率
    stock: number;
    safetyStock: number;                   // 安全库存（3天销量）

    // 推荐
    reason: string;                        // 推荐理由
    expectedContribution: number;          // 预计贡献 GMV
  }[];

  // 结构分析
  structure: {
    tierDistribution: Record<string, number>;  // 各梯队SKU数
    categoryDistribution: Record<string, number>;
    priceRangeDistribution: Record<string, number>;
  };

  // 库存预警
  inventoryWarnings: {
    productId: string;
    warning: 'low_stock' | 'no_stock' | 'overstock';
    suggestion: string;
  }[];

  totalExpectedGMV: number;
  confidence: 'high' | 'medium' | 'low';
}
```

### 4.4 选品梯队策略

| 梯队 | 定位 | SKU数 | 资源倾斜 |
|-----|------|-------|---------|
| S 级 | 爆款/引流款 | 3-5个 | 首页banner、主图、最大流量 |
| A 级 | 利润款/主力款 | 5-10个 | 二级页面、关联推荐 |
| B 级 | 补充款/凑单款 | 10-20个 | 品类页、满凑单推荐 |
| C 级 | 清仓款/测试款 | 剩余 | 清仓区、小流量测试 |

### 4.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 读取产品+库存数据 | low | 自动执行 |
| 生成选品建议 | low | 自动执行，运营可增删调整 |
| 库存预警 | low | 自动提示，不阻止 |

### 4.6 Reflection 自审规则

```python
REFLECTION_RULES = {
    "product_selection": [
        {
            "name": "gmv_contribution_check",
            "condition": "sum(expectedContribution) >= target_gmv * 0.9",  # 选品至少覆盖90%目标
            "on_fail": "expand_selection_or_adjust_expectations"
        },
        {
            "name": "inventory_safety_check",
            "condition": "all(p.stock >= p.safety_stock for p in s_tier + a_tier)",
            "on_fail": "flag_inventory_risk_and_suggest_replenishment"
        },
        {
            "name": "margin_floor_check",
            "condition": "weighted_avg_margin >= min_margin_threshold",
            "on_fail": "replace_low_margin_products"
        },
        {
            "name": "category_balance_check",
            "condition": "no_category_exceeds(category_distribution, 0.4)",  # 单品类不超过40%
            "on_fail": "rebalance_category_distribution"
        }
    ]
}
```

### 4.7 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 选品方法论、品类搭配规则、毛利基准线 |
| **Episodic** | 历史经验 | 历次活动爆款清单、各品类转化率、库存周转数据 |
| **Working** | 当前任务 | 目标GMV、时间范围、产品数据、选品结果 |

### 4.8 验收标准

- [ ] 输入目标GMV+时间+品类范围，能输出 Top 20 选品清单
- [ ] 每个SKU有评分、推荐理由、预计贡献
- [ ] 按 S/A/B/C 梯队分组
- [ ] 自动检测库存预警
- [ ] 选品总预期 GMV 覆盖目标的 90% 以上

## 五、技能3：定价策略

### 5.1 场景

基于选品清单和成本结构，生成活动定价建议，包括原价/活动价/折扣率/利润空间。

### 5.2 Plan Mode 设计

```
用户输入："给选中的SKU定价，目标整体毛利率不低于30%"
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取成本+竞品价格数据              │
│   action_type: ontology_query             │
│   query: Product.cost + Competitor.price  │
│   risk: low                               │
│                                          │
│ Step 2: 读取历史定价表现（Episodic）        │
│   action_type: tool_call                  │
│   tool: memory.read                       │
│   layer: episodic                         │
│   filter: {pricing_history}               │
│   risk: low                               │
│                                          │
│ Step 3: 定价模型计算                       │
│   action_type: tool_call                  │
│   tool: pricing_engine.calculate          │
│   strategy: "value_based"                 │
│   constraints: {min_margin: 0.3}          │
│   risk: medium                            │
│                                          │
│ Step 4: LLM 生成定价说明+价格梯队          │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "生成定价策略说明，包含价格带、   │
│           折扣梯度、利润测算"              │
│   risk: medium                            │
│                                          │
│ Step 5: 利润核算验证（Verification）       │
│   action_type: skill_call                 │
│   skill: profit_verification              │
│   risk: medium                            │
│                                          │
│ Step 6: 写入 Artifact                    │
│   action_type: tool_call                  │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 5.3 输出结构

```typescript
interface PricingStrategy {
  // 整体策略
  overall: {
    strategyType: 'value_based' | 'cost_plus' | 'competitor_based';
    overallDiscountRate: number;         // 整体折扣率
    weightedAvgMargin: number;           // 加权平均毛利率
    targetMarginFloor: number;           // 目标毛利率底线
  };

  // SKU级定价
  productPricing: {
    productId: string;
    originalPrice: number;
    activityPrice: number;
    discountRate: number;
    cost: number;
    margin: number;
    priceTier: 'high' | 'mid' | 'low';
    pricingNote: string;                 // 定价说明
  }[];

  // 价格梯度
  priceTiers: {
    tier: string;
    priceRange: [number, number];
    skuCount: number;
    targetAudience: string;
  }[];

  // 利润测算
  profitForecast: {
    expectedRevenue: number;
    expectedCost: number;
    expectedGrossProfit: number;
    expectedMargin: number;
    worstCaseMargin: number;             // 最差情况毛利率
  };

  // 竞品对标
  competitorBenchmark: {
    productId: string;
    ourPrice: number;
    competitorPrice: number;
    priceDifference: number;
    position: 'lower' | 'same' | 'higher';
  }[];
}
```

### 5.4 定价策略类型

| 策略 | 适用场景 | 核心逻辑 |
|-----|---------|---------|
| **价值定价** | 新品/独家款/高认知度品牌 | 基于用户感知价值定价，成本只做底线 |
| **成本加成** | 标品/成熟品类 | 成本 × (1 + 目标毛利率) |
| **竞品对标** | 价格敏感品类 | 比竞品低 5-10% 或持平 |
| **梯队定价** | 多SKU产品矩阵 | 引流款(低价) + 利润款(高价) + 形象款(超高价) |

### 5.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 生成定价建议 | medium | 自动生成，**价格必须运营确认** |
| 利润核算验证 | medium | 自动执行，不通过则高亮警告 |
| 低于成本价预警 | high | 阻止定价，必须人工确认 |

### 5.6 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 定价方法论、价格带分布、行业平均毛利 |
| **Episodic** | 历史经验 | 各价格段转化率、折扣力度效果曲线、竞品价格历史 |
| **Working** | 当前任务 | 选品清单、成本数据、定价结果 |

### 5.7 验收标准

- [ ] 输入选品清单+毛利目标，能输出每个SKU的活动价
- [ ] 加权平均毛利率 ≥ 目标毛利率
- [ ] 有价格梯队说明（高/中/低价位布局）
- [ ] 有利润测算（最好/基准/最差情况）
- [ ] 低于成本价自动告警

## 六、技能4：优惠配置

### 6.1 场景

基于定价策略和活动目标，设计优惠规则（优惠券/满减/赠品/秒杀等），并计算优惠成本。

### 7.4 预估模型方法论

```
预估模型 = 基准法 + 因子调整法 加权融合

基准法（占比40%）：
  历史同类活动的平均表现 × 规模调整系数

因子调整法（占比60%）：
  基础GMV = 流量预估 × 转化率预估 × 客单价预估

  其中：
  - 流量预估 = 自然流量 + 付费流量预测 + 活动引流
  - 转化率预估 = 基准转化率 × 折扣力度系数 × 选品吸引力系数
  - 客单价预估 = 基准客单价 × 满减拉动系数 × 捆绑销售系数
```
