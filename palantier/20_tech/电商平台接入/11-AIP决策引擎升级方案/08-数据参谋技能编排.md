## 一、数据参谋定位

### 1.1 职责边界

**数据参谋管"为什么"** — 异常归因、趋势预测、用户洞察、决策建议。

| 职责 | 不做什么 |
|------|---------|
| ✅ 异常检测：自动识别数据异常 + 初判原因 | ❌ 写报表/做可视化（BI工具职责） |
| ✅ 归因分析：流量/转化/客单 全链路归因 | ❌ 数据采集/清洗（数据工程职责） |
| ✅ 趋势预测：GMV/订单/用户 短期预测 | ❌ 底层数据仓库建设（基础设施职责） |
| ✅ 用户画像：分层/标签/RFM 分析 | ❌ 具体执行动作（运营手动或其他数字同事） |
| ✅ 决策建议：投放优化/选品调整/定价建议 | ❌ 财务报表/税务合规（财务职责） |
| ✅ 自动报告：日报/周报/月报 生成 | ❌ 数据准确性保证（源系统职责） |

### 1.2 核心洞察

> 电商数据现状：数据散在各平台，运营只会看报表不会分析，异常了不知道为什么。
> **数据参谋不是"帮你拉数"，是"帮你思考"** — 从数据中发现问题、找到原因、给出建议。

### 1.3 适用平台

| 平台类型 | 数据来源 | 数据分析侧重 |
|---------|---------|-------------|
| 公域（淘宝/天猫/京东/拼多多） | 平台数据 + 订单系统 | 流量分析、转化漏斗、ROI分析 |
| 私域（微商城） | 自有数据 + 企微数据 | 客户生命周期、复购分析、LTV |
| 内容平台（抖音/快手） | 平台数据 + 内容数据 | 内容表现、粉丝增长、直播数据 |
| 跨境（Shopify/Amazon） | 平台数据 + 物流数据 | 多币种、物流时效、差评分析 |

## 二、技能链总览

数据参谋包含 6 个技能，按分析深度递进：

```
技能1：异常检测  →  技能2：归因分析  →  技能3：趋势预测
                                              │
                                   ┌──────────┘
                                   ▼
                             技能4：用户画像
                                   │
                                   ▼
                             技能5：决策建议
                                   │
                                   ▼
                             技能6：自动报告
```

| 技能 | 触发条件 | 核心动作 | 风险等级 | 需要审批 |
|------|---------|---------|---------|---------|
| 1.异常检测 | 定时（5min）/ 手动 | 检测异常 + 初判原因 | low | ❌ 自动告警 |
| 2.归因分析 | 异常触发 / 手动 | 全链路归因 + 贡献拆解 | low | ❌ 自动输出 |
| 3.趋势预测 | 每日 / 手动 | 短期趋势 + 区间预测 | low | ❌ 自动输出，仅供参考 |
| 4.用户画像 | 每周 / 手动 | RFM分层 + 标签体系 + 人群洞察 | low | ❌ 自动输出 |
| 5.决策建议 | 异常/复盘触发 / 手动 | 基于分析的可执行建议 | medium | ✅ 高风险建议需确认 |
| 6.自动报告 | 定时（日/周/月） | 生成结构化分析报告 | low | ❌ 自动生成 |

## 三、技能1：异常检测

### 3.1 场景

实时监控核心指标，自动识别异常（突变/趋势偏离/周期异常），并给出初判原因。

### 3.2 Plan Mode 设计

```
触发条件：每 5 分钟巡检一次核心指标
        │
        ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取核心指标实时数据               │
│   action_type: ontology_query             │
│   metrics: [gmv, orders, uv, conversion_rate]
│   time_window: "last_1h_5min_granularity" │
│   risk: low                               │
│                                          │
│ Step 2: 异常检测算法计算                   │
│   action_type: tool_call                  │
│   tool: anomaly_detection.detect          │
│   algorithms: [                            │
│     "3sigma_spike",                       │  # 突变检测
│     "trend_deviation",                    │  # 趋势偏离
│     "cycle_anomaly",                      │  # 周期异常
│     "correlation_break"                   │  # 关联异常
│   ]                                        │
│   risk: low                               │
│                                          │
│ Step 3: 初判原因（快速归因）                │
│   action_type: tool_call + llm_call       │
│   tool: root_cause.quick_analyze          │
│   prompt: "基于以下维度快速排查异常原因：    │
│           时间维度/平台维度/指标关联/外部事件"
│   risk: low                               │
│                                          │
│ Step 4: 生成异常记录 + 告警                │
│   action_type: tool_call                  │
│   tool: anomaly.create_alert              │
│   risk: medium                            │
│                                          │
│ Step 5: 写入 Anomaly OT + 触发洞察        │
│   action_type: ontology_write             │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 3.3 输出结构

```typescript
interface DetectedAnomaly {
  id: string;
  metric: MetricType;
  platform: Platform | 'all';

  // 异常信息
  detectedAt: string;
  severity: 'critical' | 'warning' | 'info';
  type: 'spike' | 'drop' | 'trend_deviation' | 'cycle_anomaly' | 'correlation_break';
  direction: 'up' | 'down';

  // 数值
  expectedValue: number;
  actualValue: number;
  deviation: number;
  deviationPercent: number;

  // 检测算法
  detectionAlgorithm: string;
  confidence: number;          // 置信度 0-1

  // 初判原因
  preliminaryCauses: {
    dimension: string;         // 维度（时间/平台/渠道/产品）
    cause: string;             // 可能原因
    confidence: number;        // 置信度
    evidence: string;          // 数据支撑
  }[];

  // 建议动作
  suggestedAction: 'investigate' | 'monitor' | 'notify_team';

  // 关联
  relatedInsightId?: string;
  investigationTaskId?: string;  // 触发深度归因的任务ID
}
```

### 3.4 异常分级与响应

| 级别 | 条件 | 通知方式 | 自动动作 |
|-----|------|---------|---------|
| 🔴 紧急 | 偏离 > 50% 或核心指标归零 | 站内 + 邮件 + 短信 | 创建深度归因任务 |
| 🟡 关注 | 偏离 20-50% | 站内 + 邮件 | 推送初判原因 |
| 🟢 提示 | 偏离 10-20% | 站内提示 | 记录日志 |

### 3.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 读取指标数据 | low | 自动执行 |
| 异常检测 | low | 自动执行 |
| 推送告警 | low | 自动推送 |
| 创建归因任务 | low | 自动创建 |

### 3.7 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 行业基准值、正常波动范围、节假日影响因子 |
| **Episodic** | 历史经验 | 历史异常案例、已知波动模式、误报记录 |
| **Working** | 当前任务 | 实时数据、检测结果、初判原因 |

### 3.8 验收标准

- [ ] 5 分钟内检测出核心指标异常（偏离 > 20%）
- [ ] 每类异常有初判原因和置信度
- [ ] 误报率 < 10%（运营标记的误报 / 总告警数）
- [ ] 分级告警准确（紧急/关注/提示）
- [ ] 已知模式（如节假日、大促）不误报

## 四、技能2：归因分析

### 4.1 场景

发现异常后，或运营主动发起，对指标变化进行全链路归因，找到根本原因。

### 4.2 Plan Mode 设计

```
用户输入："分析一下今天GMV下降的原因"
        │
        ▼
┌──────────────────────────────────────────┐
│ Clarification Gate                       │
│ Q1: 分析哪个指标？（GMV/订单/转化率/UV）    │
│ Q2: 时间范围？（今日/近7天/自定义）         │
│ Q3: 对比基准？（昨日/上周同期/上月同期）     │
│ Q4: 深度？（快速/标准/深度）                │
└──────────────┬───────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Plan Generation — 生成执行计划            │
│                                          │
│ Step 1: 读取全链路数据                     │
│   action_type: ontology_query             │
│   dimensions: [time, platform, channel, product, region]
│   metrics: [uv, click, add_cart, order, pay, gmv]
│   risk: low                               │
│                                          │
│ Step 2: 指标拆解（乘法分解）               │
│   action_type: tool_call                  │
│   tool: attribution.metric_decompose      │
│   formula: "GMV = UV × 转化率 × 客单价"   │
│   method: "shapley_value"                 │
│   risk: low                               │
│                                          │
│ Step 3: 维度下钻（找到影响最大的维度）       │
│   action_type: tool_call                  │
│   tool: attribution.dimension_drilldown   │
│   risk: low                               │
│                                          │
│ Step 4: 漏斗分析（转化各环节）             │
│   action_type: tool_call                  │
│   tool: attribution.funnel_analysis      │
│   risk: low                               │
│                                          │
│ Step 5: LLM 生成归因报告 + 建议            │
│   action_type: llm_call                   │
│   model: private-medium                   │
│   prompt: "基于数据分析结果，生成归因报告，  │
│           包含现象+原因+证据+建议"         │
│   risk: low                               │
│                                          │
│ Step 6: 自检验证（Verification）          │
│   action_type: skill_call                 │
│   skill: data_accuracy_verification       │
│   risk: medium                            │
│                                          │
│ Step 7: 写入 Artifact + Insight OT       │
│   action_type: tool_call                  │
│   risk: low                               │
└──────────────────────────────────────────┘
```

### 4.3 输出结构

```typescript
interface AttributionAnalysis {
  // 基本信息
  metric: MetricType;
  analysisPeriod: { start: string; end: string };
  comparisonPeriod: { start: string; end: string };
  change: {
    absolute: number;
    percent: number;
    direction: 'up' | 'down' | 'flat';
  };

  // 指标拆解（乘法分解）
  metricDecomposition: {
    formula: string;           // 如 "GMV = UV × 转化率 × 客单价"
    factors: {
      factor: string;
      contribution: number;    // 该因子的贡献值（可正可负）
      contributionPercent: number;  // 贡献占比
      direction: 'up' | 'down';
    }[];
    primaryDriver: string;     // 最主要驱动因子
  };

  // 维度下钻
  dimensionBreakdown: {
    dimension: string;
    items: {
      value: string;
      metricValue: number;
      change: number;
      contribution: number;
      contributionPercent: number;
    }[];
    topContributors: string[]; // 贡献最大的 Top 3
  }[];

  // 漏斗分析
  funnelAnalysis: {
    stages: {
      name: string;
      currentValue: number;
      comparisonValue: number;
      change: number;
      conversionRate: number;
      changeInConversion: number;
    }[];
    bottleneckStage: string;   // 流失最严重的环节
    bottleneckReason: string;
  };

  // 根因总结
  rootCauses: {
    cause: string;
    severity: 'high' | 'medium' | 'low';
    evidence: string;
    confidence: number;
  }[];

  // 建议
  suggestions: {
    priority: 'high' | 'medium' | 'low';
    suggestion: string;
    expectedImpact: string;
    actionLink?: string;
  }[];

  dataQualityScore: number;   // 数据质量分 0-100
  confidence: 'high' | 'medium' | 'low';
}
```

### 4.4 归因方法库

| 方法 | 适用场景 | 说明 |
|-----|---------|------|
| **Shapley 值分解** | 指标 = A × B × C | 计算各因子的边际贡献，解决交互项问题 |
| **维度下钻** | 多维度数据 | 逐个维度拆解，找到贡献最大的维度项 |
| **漏斗分析** | 转化链路 | 分析各环节转化率变化，定位瓶颈 |
| **路径分析** | 用户行为 | 分析用户行为路径变化 |
| **对比分析** | A/B 场景 | 对照组 vs 实验组 |
| **相关性分析** | 多指标关联 | 分析指标间相关性变化 |

### 4.5 权限门控

| 操作 | 风险等级 | 门控 |
|------|---------|------|
| 读取分析数据 | low | 自动执行 |
| 生成归因分析 | low | 自动输出 |
| 发布归因结论 | medium | 运营可标记「已确认」 |

### 4.7 记忆依赖

| 记忆层 | 用途 | 具体内容 |
|--------|------|---------|
| **Semantic** | 行业知识 | 归因方法论、行业基准、漏斗参考值 |
| **Episodic** | 历史经验 | 历史归因案例、常见原因模式、季节性规律 |
| **Working** | 当前任务 | 分析数据、拆解结果、归因结论 |

### 4.8 验收标准

- [ ] 输入指标+时间+对比基准，能输出完整归因报告
- [ ] 包含：指标拆解、维度下钻、漏斗分析、根因总结、建议
- [ ] 各因子贡献值之和 ≈ 总变化（误差 < 5%）
- [ ] 有数据质量评分和置信度评估
- [ ] 相关性 ≠ 因果，有明确的免责声明

## 五、技能3：趋势预测

### 5.3 输出结构

```typescript
interface TrendForecast {
  metric: MetricType;
  forecastHorizon: number;        // 预测天数
  forecastStartDate: string;

  // 预测数据
  forecast: {
    date: string;
    predictedValue: number;       // 预测值（集成模型加权平均）
    lowerBound80: number;         // 80% 置信区间下限
    upperBound80: number;         // 80% 置信区间上限
    lowerBound95: number;
    upperBound95: number;
  }[];

  // 模型对比
  modelComparison: {
    model: string;
    accuracy: number;             // 历史准确率（MAPE）
    weight: number;               // 集成权重
  }[];

  // 趋势判断
  trendAssessment: {
    direction: 'up' | 'down' | 'flat';
    magnitude: 'strong' | 'moderate' | 'weak';
    confidence: 'high' | 'medium' | 'low';
    keyDrivers: string[];
  };

  // 关键节点
  keyDates: {
    date: string;
    event: string;               // 如「周末高峰」「节假日低谷」
    expectedImpact: string;
  }[];

  // 风险提示
  caveats: string[];             // 预测的前提假设和局限性
  dataSufficiency: 'sufficient' | 'moderate' | 'insufficient';
}
```

### 5.5 记忆依赖

| 记忆层 | 用途 | 具体内容 |

### 5.6 验收标准
