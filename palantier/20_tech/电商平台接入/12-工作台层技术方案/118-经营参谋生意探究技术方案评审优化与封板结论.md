## 3. 评审规则

逐项检查八个轴：产品一致性、四层所有权、数据军规、状态机、一致性与恢复、安全治理、证据诚实性、可实施性。

- `P0`：越权、真实数据/动作风险、Authority 分裂或根本不可实施，立即阻断；
- `P1`：核心合同或一致性缺口，内部技术评审前必须关闭；
- `P2`：实施时需精确冻结的细节，不阻断方案评审，但属于编码前硬门。

## 4. 第一轮评审：P0=0，P1=4

### P1-01：116 未显式引用视觉基线

整改：116 已加入视觉稿相对链接和本机入口，并增加视觉元素到技术合同的逐项映射；同时声明演示状态不代表运行状态。结论：关闭。

### P1-02：Case 与 Run 生命周期混用

整改：

- `BusinessInvestigationCase` 是长期经营上下文，生命周期为 `DRAFT → ACTIVE → ARCHIVED → CLOSED`；
- `BusinessInvestigationRun` 是单次分析执行，承载三波串行状态；
- AIP `TaskRun` 只执行分析任务，不成为 Case 或领域 Run 的第二真源；
- 工作区分别展示 Case 与当前 Run 状态。

结论：关闭。

### P1-03：计划、并发与幂等规则不足

整改：引入 `SchedulePolicyRef`、`triggerKey` 和唯一键 `(tenant, case, analysisType, triggerKey)`；同一 Case/analysisType 只允许一个 active Run；周期重叠默认跳过并留 Receipt；专题分析以独立类型或 Case 并行。结论：关闭。

### P1-04：工作区选择与截止时间语义不足

整改：Workbench View 增加 `viewRevision/viewHash/etag/dataCutoff/selectionRevision`；渠道、经营实体、Case、Run 是原子选择集；选择改变立即作废旧内容；数据截止、投影生成、页面刷新分别展示。结论：关闭。

## 5. 第二轮复审：P0=0，P1=1

### P1-05：跨服务半完成与孤儿引用风险

问题：领域 Run、AIP 编译/TaskRun、DataRequirement 和 Artifact 发布跨越多个服务，同步串联会造成超时误判或孤儿资源。

整改：

- 统一采用 `本层事务 + Outbox + 不可变 Receipt + CAS` 的 Receipt-first Saga；
- 领域 Run 先进入 `PREPARING`，收到 AIP CompilationReceipt 后才进入可执行态；
- AIP 以稳定 command id 幂等编译，前端不得扇出创建跨层资源；
- Artifact 发布和 DataRequirement fulfill 必须携带 exact revision/hash 与 Receipt；
- 超时进入 `UNKNOWN/RECONCILING`，reconcile 只收敛状态和投影，不删除不可变历史。

结论：关闭。

## 6. 第三轮终审：P0=0，P1=0，P2=3
