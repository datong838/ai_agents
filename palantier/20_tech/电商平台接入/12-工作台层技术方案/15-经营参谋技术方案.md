# 经营参谋增长指挥中心技术方案

> Module：`ecommerce.analyst`｜Route：`/workshop/analyst`｜Bundle：growth

> 新增需求入口：经营参谋默认首 Tab“生意探究”已形成独立的[跨四层技术总方案](115-经营参谋生意探究跨四层技术总方案.md)、[Workshop 分册](116-经营参谋生意探究工作区技术方案.md)、[Adapter 分册](117-生意探究平台观察数据需求与语义水合Adapter契约.md)和[AIP 分册](../AIP通用能力实施方案/160-AIP生意探究分析编排证据评估与方案决策实施方案.md)。[119 号开发总控计划](119-BI-W0经营参谋生意探究全量开发清单与波次实施计划.md)保留 93 项任务和显式依赖 DAG。2026-08-26 BI-W0A/W0B 已补齐“原子 Skill → Logic 编排 → 职责绑定 → 工作台贡献视图”，并统一到既有 `InsightRevision → DecisionSummaryRevision → GrowthPlanRevision → TaskGraphRevision → EffectReview` 主链；精确施工包复审 `P0=0/P1=0`，当前只等待明确 BI-W1 首刀实现授权，不代表运行或发布 GREEN。

## 1. 读模型

`AnalystReadModel` 组合 Metric definition/value/quality/cutoff、Observation/Evidence、Task/Receipt/Usage、EffectReview，不复制事实。长查询使用 QueryJob；保存分析使用权威 SavedExploration。

W2-06 operation 固定为 `GET /v1/ecommerce-workshop/views/analyst` / `ecommerceWorkshopAnalystViewGet`，共享 `overview/drivers/diagnosis/plan/effects/evidence/quality` 七个 view 与同一分析上下文。每个 view 返回相同 `resourceRevision/evaluatedAt/dataCutoff`，并分别声明 metric source/query、模型、Eval、plan materialization 与专业 Module Handoff readiness；某一项 GREEN 不覆盖另一项 RED。

Metric card 的最小合同是 exact MetricDefinitionRevision + observation/result revision + unit/grain/window/timezone/cohort/filter + numerator/denominator + source run/cutoff/quality/reconciliation refs。值、变化率或图点缺少 definition、分母、cutoff 或 quality 时进入 unknown/blocked；历史值存在、last-build 成功或 HTTP 200 都不能覆盖最新 source run failed。比较口径不兼容时展示 Diff 和 conflict，不做隐式换算或拼接。

## 2. 领域对象

AnalysisBrief/DecisionBrief typed spec、DecisionEvidenceSelection、AnalysisEvalPack、InsightRevision、DecisionSummary、GrowthPlanSpec/Revision、TaskGraph materialization binding 与 EffectReview。Plan 保存目标、constraints、budget、expected effect、confidence、stop conditions、exact metric/evidence/method/eval refs。

生意探究的 `BusinessDossier/ProblemMap/OpportunityMap/SolutionPortfolio` 是 Case/Run 领域制品，只能通过 exact refs 向上述既有主链贡献输入；“GrowthPlanCandidate”不是 canonical resource，只是 `GrowthPlanRevision(DRAFT)` 的产品称谓。人工批准产生 `GrowthPlanRevision(APPROVED)` successor，禁止新增平行表、Store 或 resourceType。

Observation、correlation、attribution 与 causal claim 是不可静默升级的不同类型；只有经批准的方法、exact 数据、Evidence 与 Eval 才能产生因果表述。DecisionSummary 保存可审计的结论、证据链、归因路径、关键假设、反证、替代解释和不确定性，不保存或展示模型私有思维链。Insight/Decision/Plan 引用同一 frozen cutoff 下的 exact metric/evidence/method/eval revisions；新数据、方法漂移或假设更正只使旧结论 stale 并产生 superseding revision，不回写历史。

AIP-8 只提供领域中立的 query/plan/saved-exploration shell、权限与异步作业基元；电商 InsightRevision、DecisionSummary、GrowthPlanRevision、EffectReview schema/authority 和领域 materializer 由 SolutionPack/Workshop L1 持有。双方只通过 exact contracts/refs 连接，不复制页面或业务状态。

## 3. Plan 到执行

prepare/freeze AnalysisBrief + EvidenceBundle + Eval → Query/Explore → Insight/Plan Draft → Review/Eval → ImpactPreview → Approval → TaskGraph materialize → 日常总控 Handoff → 专业 Module → Receipt/EffectReview。审批后证据/指标/Eval 漂移阻止 materialize。

GrowthPlan 的 `draft/approved/materialized/executing/completed/effect-matured/corrected` 分轴；materialize 是显式、幂等、all-or-nothing 的服务端命令，只消费一个 approved exact GrowthPlanRevision，固定 objective/constraint/budget/stop condition/evidence refs，并以 mapping ledger 保持 `eligiblePlanItemCount = createdOrExistingCanonicalTaskCount`。同 key 同 hash 回读同一 TaskGraphRevision，异 hash 冲突；部分失败不遗留孤儿 Task。批准后 metric/evidence/method/eval 漂移阻断物化，修正计划生成 successor，不把 Task 挂到旧 plan。

EffectReview 必须声明 baseline、comparison、maturity window、eligible population、attribution method、assumptions、limitations、unknown/inconclusive、exact plan/task/action/receipt refs 与 counterfactual 限制；窗口未成熟只显示 pending，不把短期波动包装成效果成功。late data、方法漂移和假设修正生成 successor EffectReview，历史结论仍可达。EffectReview 只能提出 MemoryCandidate，不能自动晋升 Wiki/记忆。

## 4. 前端

七 view 共享 Brief/Plan/selection/cutoff；所有归因显示 EvidenceBundle coverage、证据、假设、反证和 uncertainty，不展示私有思维链。图探索通过 SavedExploration ref 按需展开；指标 unknown 不显示 0。

## 5. API 与安全

Module view 聚合 Metric/Observation/Plan/Task refs；commands 创建 Insight/Plan/Review/Handoff，不接受任意 SQL 或 org/project。查询只走受控 semantic/metric/query job；purpose/marking 先于指标和 Evidence payload 读取。

W2 页面纯只读，不包含任意 SQL、保存、Insight/Plan mutation、批准、materialize、dispatch 或 Memory promote。SavedExploration 必须通过唯一 PostgreSQL authority 的 exact ref、share/revoke/expiry、restart persistence 与权限门后才可投影；现存旧内存实现不能作为完成证据。聚合还要执行最小样本、小群体、purpose/marking、PII 与差分披露策略，禁止通过图表、错误信息或导出反推个体。

## 6. 测试与门

Brief/Evidence/Eval CAS、metric definition drift、stale/partial、查询取消恢复、SavedExploration、四类 Insight 不静默升级、DecisionSummary 无私有思维链、Plan CAS、Impact unknown、未批准/漂移不可 materialize、all-or-nothing TaskGraph 与 mapping/count 守恒、预算/stop condition、跨 Module lineage、EffectReview maturity/late-data/inconclusive/correction、MemoryCandidate 非自动晋升。Readiness 分查询源/指标、分析模型、Eval、计划 materialize 和专业 Module Handoff；模型可用不代表数据/证据可用。前置 AIP-8/9 与任务生产公共契约按功能 gated，先交付只读态势也必须真实数据。

W2-06 的硬前置是 W1-10、W2-00、受控 query capability 与 Analyst aggregate GREEN；Order、OrderLine、CustomerLite、Payment 等指标源的最新 run 必须成功或有经批准的逐指标降级。W3-13 还依赖 W3-10、W2-06、DEP-C0、DEP-A8、`DEP-ANALYST-METRIC-OBSERVATION-QUALITY`、`DEP-INSIGHT-DECISION-AUTHORITY`、`DEP-GROWTH-PLAN-AUTHORITY`、`DEP-GROWTH-PLAN-TASKGRAPH-MATERIALIZER`、`DEP-EFFECT-REVIEW-AUTHORITY`、`DEP-EFFECT-MATURITY-POLICY` 与 `DEP-A8-GENERIC-ANALYST-SHELL`。AOS-000041 已把 Binding Canonical API/OpenAPI 推进到 GREEN_WITH_WARNINGS，但 AIP-8、五类 Analyst 领域 authority、aggregate View/Store/strict SDK 仍未完成，真实 binding 仍为 0；不能关闭 Analyst 门。

验收覆盖 definition/unit/grain/timezone/cohort/filter/cutoff 兼容、numerator/denominator 守恒、late/revised/missing、unknown 非 0、最新失败不被历史值覆盖、相关非因果、无私有思维链、Plan CAS/TaskGraph 原子物化/mapping 数量/stop condition、Effect maturity/correction、MemoryCandidate 非自动晋升、SavedExploration 持久/撤销，以及 `org-org` 正向、`dev-org` 负向和三视口键盘。完整预检见 87 号与 101 号 ADR。
