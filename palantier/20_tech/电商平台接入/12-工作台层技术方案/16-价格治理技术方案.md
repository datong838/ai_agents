# 价格治理技术方案

> Module：`ecommerce.price-governance`｜Route：`/workshop/price-governance`｜Bundle：growth  
> 当前状态：`W6-05 IMPLEMENTATION_IN_PROGRESS / ZERO_EXTERNAL_EFFECT`；`W4-08`、`W6-01` 与 `W2-07` 前置已重核，按 [53-W6-05-价格ResearchJob同款MatchPolicy与BatchPrepare预检ADR.md](53-W6-05-价格ResearchJob同款MatchPolicy与BatchPrepare预检ADR.md) 第 7 节施工。通用 ResearchJob/生产契约与 Shell 仍不等于价格领域已实现。

## 1. 领域边界与真源

价格治理只消费 O1 的 canonical Product/ProductSku/Order exact refs，不覆盖商品价格、订单金额或外部页面原文真源。领域 authority 包括：

- `PriceObservationRevision`：规范化价格、币种、计价单位、促销/税费/运费口径、observedAt 与 original Artifact refs；
- `ComparisonSnapshotRevision`：同 cutoff 下可比 Observation 集与 originals 映射，可重建、不成为价格事实；
- `ProductMatchObservation` / `ProductMatchDecisionRevision`：机器匹配事实与人工/政策决定分离；
- `PriceCaseRevision`：异常、证据、政策、影响与处置 refs；
- `MonitoringPolicyRevision`：市场/渠道/类目、价格基准、容差、freshness、调度与 Eval exact refs；
- `CompetitorValueCardRevision`：价格之外的规格、服务和权益差异，只引用受控 Evidence。

所有 authority tenant-scoped、append-only revision、CAS/幂等、RLS/FORCE RLS。读取聚合必须可重建并记录 source revision、cutoff、build version、completeness。

## 2. ResearchJob 与来源治理

freeze typed ResearchBrief + Evidence/Eval/Responsibility exact refs 后，才可由 Schedule/Run 创建 canonical ResearchJob。`PriceResearchProfileRevision` 固定 provider/source allowlist、URL policy、许可、市场/币种/单位、抓取频率、rate/capacity、输出 Schema、retention 和 PII/Secret 规则；executor 不接受前端任意 URL，不记录 Cookie/Token。

外部 Artifact 先通过许可、hash、Schema、恶意内容、时间戳和最小披露 gate，再由受控 Normalizer 形成 Observation。Provider disabled、许可 unknown/denied、回调验签失败、事件 gap、Artifact/schema/hash 漂移进入 blocked/unknown/reconcile；手动导入也必须是受信 Artifact + Receipt，不能绕过同一治理门。

## 3. Observation 与 originals 守恒

Normalizer 必须显式给出 price basis：标价/到手价、SKU/组合、数量单位、币种、税费、运费、优惠条件和有效区间。无法统一口径的 Observation 标记 `unknown/not_comparable`，不得强制换算为 0 或参与异常判断。

聚合投影满足每个展示值都可回到至少一个 immutable original；去重保留被合并 refs，迟到事件按 observedAt/source sequence 重建。许可撤销、freshness 过期或 original 缺失使 Snapshot stale/blocked，旧 Receipt 可审计但不能授权新处置。

## 4. 同款 Match 契约

Match 固定 Product/SKU revision、candidate Observation、feature schema、model/Logic publication、policy、EvidenceBundle、cutoff 与 content hash，输出 features/confidence/explanation/evidence refs。阈值以下、规格冲突或 originals 不足时保持 `PRELIMINARY`，只允许人工确认/补证，不能自动进入价格异常或淘汰来源。

Observation 与 Decision 分离；人工决定记录 actor/reason/evidence/version。Product/SKU、feature/model/policy/Evidence 或 identity 变化使旧 Decision stale。解释展示证据链、特征摘要、关键假设和不确定性，不展示模型推理链。

## 5. MonitoringPolicy 与异常 Case

Policy 固定适用范围、价格口径、阈值/容差、时间窗、freshness、最低 originals、match confidence、货币/单位规则、Eval publication 和例外；组织 Overlay 只能按 Schema 收紧或禁用，不能静默放宽平台安全基线。

PriceCase 由同版 Policy/Eval 对可比 Observation 计算，记录 calculation inputs/hash、decision reason、Impact refs 和状态。价格采集或同款识别可用不代表通知/建议/调价 capability 可用；Policy/Eval/Observation 漂移后旧 Case 不改写，只追加 stale/新 revision。

## 6. Price Batch prepare 零副作用

`prepare` 收集 Product/SKU/市场目标，稳定去重并计算来源许可、匹配、freshness、调度、rate/capacity、成本和预计数据量；只创建 `PriceResearchBatchRevision` 与 items，不启动 ResearchJob、不调用 provider、不发通知、不创建调价 Proposal。

每个 item 为 `eligible / excluded / needs_review / unknown` 并带 reason refs，满足：

`input = eligible + excluded + needs_review + unknown + deduplicated`

`freeze` 用 expected version/If-Match 与 Idempotency-Key 固化 ResearchBrief/Evidence/Eval/Responsibility/ResearchProfile/MonitoringPolicy/target/item hashes。任一 exact ref、许可、source capability、rate/capacity 或预算漂移即 stale，必须重新 prepare；后续 start 属于 W6-06/公共执行门，不得静默换版。

## 7. 异常与动作边界

通知函、价值差异卡、价格/活动建议和调价是独立 Draft/Impact/Approval/Lease/Receipt 门；采集、匹配或监控通过不能点亮调价。需要活动让利时 Handoff 内容与活动；受影响订单交统一运营；客户补救只传 PriceCase/Order scoped ref 与 purpose，禁止复制竞品原始响应或客户资料。

四类处置必须使用不同的版本化 contract 与风险政策：

- **内部建议/价值卡**：只生成受控 Artifact/Draft，不调用外部账号；仍需绑定 PriceCase、Policy/Eval、Evidence 和 Impact，并保留人工采用/拒绝 Receipt；
- **外部价格通知**：固定收件主体、模板/内容审核、渠道账号、频控、时效与 provider capability；发送批准不能授权调价；
- **跨 Module Handoff**：仅传 PriceCase/Product/Order scoped refs、purpose 与 requestedOutcome；接收方 accept/reject/request-more，禁止复制 originals/客户列表；
- **调价**：默认 `disabled / R4-specialized-gate-required`，必须独立 maker-checker、margin/floor/MAP/库存/订单影响、账号 binding、预算、canary、kill、补偿与 EffectReview；一个批准只覆盖一个 exact target set 和一个价格变更 Diff。

Proposal/Impact/Approval/Lease 必须共同绑定 `PriceCase + target set + action contract + account/capability + policy + budget + content hash`；任一项漂移即失效。内部建议不能借用外部发送或调价的 account/Lease，调研 Adapter 也不能注册为价格写 Adapter。

外部结果 unknown 只允许 reread/Webhook/人工 Case；“回滚”是停止扩量、回读权威状态、对账并创建新补偿提案，不是回滚数据库或覆盖历史 Receipt。

## 8. Module API 与前端

统一 Module API 返回治理/竞品/调度三视图、case/timeline 与最小摘要：Brief/Evidence/Eval/Responsibility/Observation/Match/Policy/Batch/Impact refs、readiness、blockers、cutoff、freshness、conflict/license 和 originals reachability。commands 只创建 MatchDecision、PolicyRevision、Batch、Handoff 或后续 Draft refs；BFF 不抓网页、不算第二套异常、不直调调价 provider。

W2-07 operation 固定为 `GET /v1/ecommerce-workshop/views/price-governance` / `ecommerceWorkshopPriceGovernanceViewGet`。它只返回 `governance/competitor/schedule` 三个 read view，分别投影 Observation/Snapshot/Match/Policy/Case、价值差异与 originals、Research schedule/source license/run/gap/reconcile；不注册任何 command。

所有 quote 显式携带 basis、SKU/组合、quantity/unit、currency、tax、shipping、promotion condition、effective window、observedAt、freshness、license 与 original refs。ComparisonSnapshot 只包含同 market/currency/unit/quantity/basis/tax/shipping/promotion/window/cutoff 的可比项；not-comparable、unknown、stale、unlicensed 与 PRELIMINARY 分别显示，不进入异常或价格差总数。每个展示值必须可达至少一个 immutable original，去重保留全部 merged refs。

页面将 `collection/match/policy-case/notification/advice-handoff/repricing` readiness 分轴。调研、采集、同款或 Case 任一 GREEN 都不能点亮通知或调价；repricing 持续 `disabled/R4-specialized-gate-required`。W2 不接受任意 URL，不提供 collect/normalize/decide/edit-policy/prepare/freeze/start/notify/advise/handoff/reprice 控件。

正式页面必须展示 Observation 原始口径、同款 PRELIMINARY/人工决定、Policy Diff、批次数量守恒、`prepare 0 外部调用`、调研与调价分门、partial/unknown/reconcile 和可干预入口。依赖未就绪时只显示诚实七态，不注入静态视觉稿示例数据。
