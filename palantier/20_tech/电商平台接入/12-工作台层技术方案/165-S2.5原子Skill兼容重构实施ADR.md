## 1. 决策

在已完成的 S2 与 S3 之间插入 `S2.5`。S2.5 不是推倒重写，也不把 163/164 的全部远期目标提前实现；它只建立后续 S3～S7 不再固化“大角色 Skill”语义所需的最小兼容地基：

1. 对历史 37 项逐项分类，保留旧 canonical identity、revision 和历史引用；
2. 让 SolutionPack 在继续发布原有 `6 Agent / 37 evaluated Skill / 10 Capability` 的同时，严格校验兼容映射；
3. 新增 Workshop 公共 `SkillContributionView` 的 Task Cockpit 只读试点；
4. 重新运行 S2 累计门，证明改动没有使现有八页面、API、SDK 和 fail-closed 能力倒退。

## 2. 现场审查事实

### 2.1 保留，不重构

- AIP Skill 发布、Eval、Binding readiness、ModelRoute、Policy、Capability health 与 tenant fail-closed 已有唯一 authority；
- Task Cockpit 已有 Plan/Stage、Responsibility、AssigneeResolution、Handoff、Approval、ReviewIssue 和 ActionReceipt 只读合同；
- S2 W2-02～W2-10 开发已完成，当前 `NO_RELEASE` 是数据、runtime、shared-context 与浏览器正向证据轴的诚实决定，不是代码缺口。

### 2.2 必须整改

- `AipSolutionPackPublisher` 当前将每条角色 Logic 机械发布为一个同名 Skill；
- 37 项混合了 Skill、Logic、Tool、Domain、Channel 与职责编排；
- Workshop 尚无统一的 Skill contribution 只读合同，页面无法用同一结构说明“谁使用了哪个 exact Skill、为何可用或阻断”。

## 3. S2.5 文件级施工清单

### S2.5-A · 37 项兼容分类

- 新增 `bundles/solutions/ecommerce-growth/content/logic/ecommerce-37-skill-compatibility-map.json`；
- 每项必须包含唯一 legacy Logic/Skill、分类、候选目标、兼容模式和发布状态；
- 允许分类：`KEEP_ATOMIC / SPLIT / MERGE / MOVE_TO_TOOL / MOVE_TO_DOMAIN / MOVE_TO_CHANNEL / MOVE_TO_OVERLAY / DEPRECATE`；
- 所有候选目标均为 `planned_not_published`，不能冒充已发布 revision。

### S2.5-B · SolutionPack 兼容校验

- 发布器必须校验映射恰好覆盖 37 项、无重复、旧 SkillRef 与旧 LogicRef 精确匹配；
- 每项必须为 `retain_exact_legacy`，不得静默重命名、删除或重绑；
- 发布结果继续严格保持 `6/37/10`，旧 hash/idempotency 测试不得倒退；
- 本波不创建新数据库表、不执行 migration、不写租户运行数据。

### S2.5-C · Task Cockpit 公共只读投影试点

- 新增独立 GET：`/v1/ecommerce-workshop/views/task-cockpit/runs/{runId}/skill-contributions`；
- 只读 canonical `AgentRun + SkillBinding + SkillRevision + AgentInstance/AgentTemplate`；
- 返回 exact Skill、Logic、AgentInstance、mutable Binding version、运行状态和 readiness freshness；
- 无 AgentRun 时返回空贡献与 `NO_CANONICAL_AGENT_RUN_CONTRIBUTION`，不得伪造 Skill 使用；
- stale/unknown/blocked 不得显示为 available；不提供 Start/Handoff/Action Command。

### S2.5-D · Web 增量展示

- 在现有 Task Cockpit Run 详情中追加“专业贡献”区域；
- 业务标题优先，exact refs 渐进披露；
- unknown/stale/blocked、关键假设和缺失输入诚实显示；
- 新区域失败不得清空现有 Stage、职责、审批、ReviewIssue、ActionReceipt 内容。

### S2.5-E · S2 累计门重跑

- 后端专项：SolutionPack、Task Cockpit、HTTP/OpenAPI；
- Web 专项：strict parser/client、TaskCockpitPage；
- 累计：Workshop API、Web 全量、typecheck/build、OpenAPI deterministic；
- 浏览器：Task Cockpit 1280/1440/1920，既有八路由关键 landmark/current-location 回归；
- 重跑 W2 cumulative evaluator。S2.5 不得将已有 RED 轴伪造为 GREEN，最终仍可能是诚实的 `NO_RELEASE`。

## 4. 零倒退兼容军规

1. 旧 `ecommerce.skill.<legacyId>@1`、历史 Task/Run/Binding/Receipt 均不可变；
2. 不自动迁移、不自动重绑、不删除旧资产；
3. 新端点是 additive，旧 API 和 strict parser 合同不增加隐式字段；
4. 新视图只投影 canonical authority，不建立第二 SkillRun/AgentRun store；
5. UI 只展示服务端 allowed/readiness 事实，不本地推导在线或可执行；
6. `org-org/dev-project` 是正向租户，`dev-org/dev-project` 仅作隔离 canary；
7. 本波零 Provider、零外部 Action、零真实业务数据写入。

## 5. 回退策略

- 代码回退只移除新增 GET 和新增 UI 区块；
- 兼容映射是设计/校验资产，不改变旧发布记录；
- 因无数据迁移、无历史重绑，回退不需要修改任何 Task/Run/Binding/Receipt；
- 若新视图依赖不可用，端点失败关闭，现有 Task Cockpit 其他只读区块继续可用。

## 6. 退出门

- 37/37 分类覆盖且旧 ID 精确守恒；
- SolutionPack `6/37/10` 与幂等回读保持 GREEN；
- Skill contribution 正向、空态、stale、drift、跨租户测试 GREEN；
- 现有 Task Cockpit 专项与 S2 累计回归无减少；
- 页面三视口无新增横向溢出、无执行按钮、console 无新增错误；
- 形成 Delivery Receipt、安全提交、authority CAS、deterministic sync 与 Prime 回读。

## 7. S2.5 之后

S2 不重复开发 W2-02～W2-10。S2.5 完成后只重新执行 S2 累计决定、刷新清单与证据；随后在用户约定的暂停点报告，再进入 S3。
