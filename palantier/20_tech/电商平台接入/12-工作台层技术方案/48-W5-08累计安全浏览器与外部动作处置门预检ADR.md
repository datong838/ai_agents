## 3. 安全累计门

安全套件按 exact allowlist ActionType 分门运行，至少覆盖：无 scope 零可见、跨租户 0 泄漏、maker-checker、账号错配、Preview/Policy/Adapter drift、幂等冲突、Lease/reservation 并发、dispatch crash、timeout unknown、Webhook spoof/replay/gap、PII/Secret/redaction、预算超限、Kill 生效与 reset。

`dev-org/dev-project` 只作 `org-org/dev-project` 的负向隔离 canary；其失败或空数据不能冒充真实正向成功。高风险 Action 保持 disabled 并可见 reasonCode，不因低风险一项 GREEN 自动放开。

## 4. 浏览器累计门

正式浏览器验收使用构建产物和真实 HTTP，不使用静态视觉稿、Mock response、fixture 或页面内注入状态。每个获准低风险 Action 至少验证：

1. 准备/Preview/Diff、审批资格与到期、Lease/reservation、执行前漂移复验；
2. Receipt、Usage settlement、lineage 与 provider reread 分状态展示；
3. 刷新/重进后从服务端恢复，不从 localStorage 或 toast 推导完成；
4. timeout/unknown 只允许对账，Webhook gap/冲突进入 Case；
5. Kill 后新动作 disabled、在途动作进入 reconcile、reset 不复活旧 Lease；
6. 三视口、键盘/focus、权限差异、network/console 与跨租户负向证据。

本地 API 不可达页面只算失败关闭样本，不算上述端到端验收。

## 5. “回滚”语义

外部动作一旦 dispatch，数据库、TaskRun 或 Bundle rollback 都不能证明 Provider 副作用消失。W5 使用“停止扩大 + provider reread + reconcile + 必要时新 compensation Action”的处置模型：

- 未 dispatch：拒绝并释放 reservation；
- 已 dispatch、结果明确 failed：结算/释放并保留 Receipt；
- applied/partial：按版本化 CompensationPolicy 生成新 Proposal，独立 Preview/审批/Lease；
- unknown：保持 unknown，自动或人工对账，证据不足不补偿；
- 系统回滚只关闭入口/Adapter binding，不删除历史 Receipt、Usage、Lineage 或 Case。

Runbook 必须记录值班职责、告警阈值、Kill 操作、Provider 联系/限流、Webhook backlog、unknown SLA、预算核对、补偿决策与恢复门。
