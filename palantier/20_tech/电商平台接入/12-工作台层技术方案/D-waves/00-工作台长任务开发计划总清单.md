## 2. 长任务执行规则

1. 用户已于 2026-08-14 明确授权按本清单连续执行 W1～W8，直至工作台层开发完成；无需逐波重复等待确认，但每个 Task 的依赖、安全与副作用门仍须独立关闭。
2. 每波开工前重新读取项目 authority、`01-当前项目状态.md`、`06-当前执行检查点.md`、活动 Lease 和 Git 状态，并复核 Alembic single head、AIP/Adapter readiness。
3. 只有依赖全部 GREEN、收到明确授权并完成 Task Receipt/Lease 后，Task 才能由 `BLOCKED_DEPENDENCY` 进入 `AUTHORIZED`/`IN_PROGRESS`。
4. 只有代码、定向与累计测试、正式 HTTP/浏览器证据、回滚或补偿演练、Delivery Receipt 全部闭合，才能勾选 Task；计划完成、文档完成或静态页面完成均不能勾选开发 Task。
5. 每完成一个 Task，在对应条目末尾补充 Delivery Receipt、提交或证据引用；开发分支每完成一波先更新本分支 D-waves、Delivery Receipt 与安全提交。`authority.json`、01/06 和共享记忆只在 m1 串行集成阶段 CAS 更新，避免 w1/w2 并发覆盖。
6. 长任务中断后，从“依赖已 GREEN 的第一个未勾选 Task”恢复；先回读 Receipt/提交/测试，不重复外部副作用，不从对话印象推断完成状态。
7. `org-org/dev-project` 是唯一真实正向证据；`dev-org/dev-project` 只做跨租户和隔离负向验证。
8. 任一 authority/强一致投影非 CURRENT、同文件存在未知并发修改、AIP/Adapter/Provider 状态 unknown、跨租户或迁移门异常时立即停止。
