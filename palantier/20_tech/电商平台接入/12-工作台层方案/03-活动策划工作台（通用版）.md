# 活动策划工作台（通用版）

> 状态：**设计方案 v1.0** — 通用层框架 + 核心功能详细设计
> 定位：面向活动策划师（数字同事）的活动全生命周期管理工作台
> 关联：`00-总览-从OrderManagement到数字同事工作台.md` §五 · `../11-AIP决策引擎升级方案/07-活动策划师技能编排.md`（已编写）
> 适用平台：淘宝、天猫、京东、拼多多、微商城

---

## 一、定位

活动策划工作台是**通用层**工作台，定义跨平台活动管理的共性框架。各平台细分差异在各自接入方案目录下定义。

| 属性 | 说明 |
|------|------|
| **通用层定义** | 活动方案、效果预估、执行监控、活动复盘 |
| **对接数字同事** | 活动策划师（Activity Planner） |
| **不走画布编辑** | 采用左侧列表 + 右侧详情固定布局 |
| **复用组件** | BpCard、BpTabs、ActivityPlannerWidget、TaskListPanel |

## 三、核心功能详细设计

### 3.1 活动方案生成

#### 3.1.1 新建活动
- **基础信息**：活动名称、时间范围、目标平台、关联内容日历条目
- **目标设定**：
  - 核心目标（单选）：GMV / 订单量 / ROI / 拉新数 / 复购率
  - 目标值：输入具体数值
  - 目标拆解：系统自动按天/按渠道拆解（如 GMV ¥100万 → 日均 ¥5.5万）

#### 3.1.2 AI 生成活动方案（活动策划师协作）
```
[运营] 填写活动基础信息 → 点击「生成方案」
  ↓
[系统] 创建 Task → 调用活动策划师 Skill
  ↓
[活动策划师] Plan Mode：
  Step 1: 分析历史活动数据（从本体层读取 Activity OT）
  Step 2: 分析产品库存与定价空间（从 Product OT 读取）
  Step 3: 生成选品建议（Top 20 SKU，含推荐理由）
  Step 4: 生成定价策略（原价/活动价/折扣率）
  Step 5: 生成优惠配置（满减/优惠券/赠品规则）
  Step 6: 自检（利润核算/库存预警/规则冲突检测）
  ↓
[系统] Diff 视图展示方案（含选品/定价/优惠三部分）
  ↓
[运营] 编辑/确认 → 方案锁定
  ↓
[系统] 写入 ActivityPlan，活动状态更新为「策划中」
```

#### 3.1.3 方案版本管理
- 每次 AI 生成或人工修改都保存一个版本
- 支持版本对比（Diff 视图）
- 支持回滚到任意历史版本
- 版本标签：「AI 初稿」「运营修改」「最终版」

### 3.2 效果预估

#### 3.2.1 预估模型
```
预估输入：
- 历史同类活动数据（近 6 个月）
- 当前产品库存与定价
- 平台流量预估（从平台 API 或行业数据读取）
- 投放预算（Dou+/直通车/朋友圈广告等）

预估输出：
- GMV 区间（乐观/基准/悲观）
- 订单量区间
- ROI 区间
- 拉新数区间
- 流量需求（UV/曝光量）
```

#### 3.2.2 预估置信度
| 置信度 | 条件 | 展示方式 |
|-------|------|---------|
| 高 | 历史同类活动 ≥ 3 次，数据完整 | 窄区间（±10%），绿色标识 |
| 中 | 历史同类活动 1-2 次，或数据部分缺失 | 中区间（±20%），黄色标识 |
| 低 | 无历史数据，或新品类/新平台 | 宽区间（±40%），红色标识 + 提示「建议小范围测试」 |

#### 3.2.3 实时修正
- 活动执行中，每 6 小时基于实际数据重新跑预估模型
- 当实际偏离预估 > 30% 时，触发异常告警
- 提供「调整建议」（加大投放/调整选品/延长活动）

### 3.3 执行监控

#### 3.3.1 活动执行进度
- **甘特图视图**：展示各 Step 的计划时间 vs 实际时间
- **当前 Step 高亮**：显示正在执行的 Step 及剩余任务
- **阻塞检测**：若某 Step 超时未完成，标红并提示原因

#### 3.3.2 实时数据看板
| 指标 | 数据来源 | 更新频率 |
|-----|---------|---------|
| 实时 GMV | 平台 API / 订单系统 | 5 分钟 |
| 实时订单 | 订单系统 | 5 分钟 |
| 实时 UV | 平台 API | 5 分钟 |
| 转化率 | 计算（订单/UV） | 5 分钟 |
| 库存消耗 | 库存系统 | 15 分钟 |
| 优惠核销 | 平台 API | 15 分钟 |

#### 3.3.3 异常告警
| 异常类型 | 触发条件 | 告警方式 | 自动动作 |
|---------|---------|---------|---------|
| 目标偏离 | 实际 GMV < 预估的 70% | 站内消息 + 邮件 | 推送调整建议 |
| 库存预警 | 某 SKU 库存 < 安全库存 | 站内消息 + 短信 | 建议下架或补货 |
| 优惠超发 | 优惠券核销率 > 120% | 站内消息 + 邮件 | 自动暂停优惠券发放 |
| 流量暴跌 | UV 环比下降 50% | 站内消息 | 检查平台状态 |

### 3.4 活动复盘

#### 3.4.1 自动复盘报告
活动结束后 24h 内，系统自动生成复盘报告：

```
【活动复盘报告】618大促
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
一、目标达成
  · GMV 目标：¥100万 | 实际：¥112万 | 达成率：112% ✅
  · 订单目标：2000单 | 实际：2356单 | 达成率：118% ✅
  · ROI 目标：3.5 | 实际：4.1 | 达成率：117% ✅

二、执行回顾
  · 选品：Top 3 SKU 贡献 60% GMV
  · 定价：折扣率 30% 时转化率最高
  · 优惠：满减券核销率 85%，优惠券 ROI 4.5

三、亮点与问题
  · 亮点：直播时段 GMV 占比 40%，超预期
  · 问题：某 SKU 库存不足导致缺货 2 小时

四、经验教训
  · 经验：直播+满减组合效果最好 → 写入 Episodic Memory
  · 教训：库存安全阈值应设为 3 天销量 → 写入 Episodic Memory

五、下次优化建议
  · 增加直播场次
  · 库存安全阈值调整
```

#### 3.4.2 经验沉淀
- **自动提取**：系统从复盘报告中自动提取「经验」和「教训」
- **人工确认**：运营可编辑/删除自动提取的内容
- **写入记忆**：确认后写入 Episodic Memory，供后续活动策划师参考
- **经验复用**：下次生成方案时，活动策划师自动读取相关经验

## 四、数据模型

### 4.1 Activity（活动）

```typescript
interface Activity {
  id: string;
  name: string;                  // 活动名称（如「618大促」）
  type: ActivityType;            // 活动类型
  platform: Platform[];          // 目标平台（可多选）
  status: ActivityStatus;        // 状态

  // 时间
  startDate: string;             // 开始日期
  endDate: string;               // 结束日期

  // 目标
  primaryGoal: GoalType;         // 核心目标
  targetValue: number;           // 目标值
  dailyBreakdown?: number[];     // 按天拆解

  // 关联
  contentItemIds: string[];      // 关联内容条目（从内容日历读取）
  productIds: string[];          // 选品列表

  // 方案
  plan?: ActivityPlan;           // 活动方案

  // 预估
  forecast?: ActivityForecast;   // 效果预估

  // 实际结果
  actualResult?: ActivityResult; // 活动结果（结束后填充）

  // 复盘
  report?: ActivityReport;       // 复盘报告

  createdAt: string;
  updatedAt: string;
  createdBy: string;
}

type ActivityType = 'big_sale' | 'daily' | 'member_day' | 'new_user' | 'custom';
type ActivityStatus = 'planning' | 'pending_approval' | 'approved' | 'running' | 'finished' | 'cancelled';
type GoalType = 'gmv' | 'orders' | 'roi' | 'new_users' | 'repurchase_rate';
```

### 4.2 ActivityPlan（活动方案）

```typescript
interface ActivityPlan {
  version: number;               // 版本号
  versionLabel?: string;         // 版本标签

  // 选品
  selectedProducts: {
    productId: string;
    rank: number;                // 推荐排序
    reason: string;              // 推荐理由（AI 生成）
    originalPrice: number;
    activityPrice: number;
    discountRate: number;
    stock: number;
    safetyStock: number;         // 安全库存
  }[];

  // 定价策略
  pricingStrategy: {
    overallDiscountRate: number; // 总折扣率
    tieredPricing?: {            // 阶梯定价
      minQty: number;
      price: number;
    }[];
  };

  // 优惠配置
  promotions: {
    type: 'coupon' | 'full_reduction' | 'gift' | 'flash_sale';
    name: string;
    rules: Record<string, any>;  // 各平台优惠规则不同，用 JSON
    budget?: number;             // 优惠预算
  }[];

  // 素材需求
  materialRequirements: {
    type: 'banner' | 'poster' | 'video' | 'copy';
    quantity: number;
    platform: Platform[];
  }[];

  createdAt: string;
  createdBy: string;             // "ai" 或运营者 ID
}
```

### 4.3 ActivityForecast（效果预估）

```typescript
interface ActivityForecast {
  confidence: 'high' | 'medium' | 'low';  // 置信度

  // 预估区间
  gmv: { optimistic: number; baseline: number; pessimistic: number };
  orders: { optimistic: number; baseline: number; pessimistic: number };
  roi: { optimistic: number; baseline: number; pessimistic: number };
  newUsers: { optimistic: number; baseline: number; pessimistic: number };

  // 流量需求
  trafficNeed: {
    uv: number;
    exposure: number;
    conversionRate: number;      // 预估转化率
  };

  // 输入数据摘要
  dataBasis: {
    historicalActivities: number; // 参考的历史活动数
    dateRange: string;            // 历史数据时间范围
    note?: string;                // 特殊说明（如「新品无历史数据」）
  };

  generatedAt: string;
  generatedBy: string;           // "ai"
}
```

### 4.4 ActivityReport（复盘报告）

```typescript
interface ActivityReport {
  // 目标达成
  goalAchievement: {
    goalType: GoalType;
    target: number;
    actual: number;
    achievementRate: number;     // 达成率
  }[];

  // 执行回顾
  executionReview: {
    stepName: string;
    plannedTime: string;
    actualTime: string;
    status: 'on_time' | 'delayed' | 'advanced';
    note?: string;

  // 亮点与问题

  // 经验教训（写入 Episodic Memory）

  // 优化建议
  suggestions: string[];

  generatedAt: string;
```

## 五、状态流转

### 5.1 活动状态机

```
┌─────────┐    新建活动     ┌─────────┐    生成方案    ┌─────────┐
│   无    │ ─────────────→ │  策划中  │ ────────────→ │ 待审批  │
└─────────┘                └─────────┘               └────┬────┘
     ↑                                                    │
     │              ┌─────────┐    取消活动              │ 审批通过
     └──────────────│  已取消 │ ←───────────────────────┘
        取消发布    └─────────┘                         └────┬────┘
                                                            │ 启动
                                                       ┌────┴────┐
                                                       │ 执行中  │
                                                       └────┬────┘
                                                            │ 结束
                                                       ┌────┴────┐
                                                       │ 已结束  │
                                                       └─────────┘
```

### 5.2 Step 执行状态

每个活动方案包含 5 个 Step，每个 Step 有独立状态：

| Step | 名称 | 状态 | 说明 |
|-----|------|------|------|
| Step 1 | 选品 | 未开始 / 进行中 / 已完成 / 阻塞 | 选品建议生成 + 运营确认 |
| Step 2 | 定价 | 未开始 / 进行中 / 已完成 / 阻塞 | 定价策略生成 + 运营确认 |
| Step 3 | 优惠配置 | 未开始 / 进行中 / 已完成 / 阻塞 | 优惠规则配置 + 平台 API 同步 |
| Step 4 | 素材准备 | 未开始 / 进行中 / 已完成 / 阻塞 | 关联内容日历条目，素材准备 |
| Step 5 | 效果监控 | 未开始 / 进行中 / 已完成 / 阻塞 | 活动执行中实时监控 |

### 6.2 Permission Gate 设计

| 动作 | 风险等级 | 门控策略 |
|-----|---------|---------|
| 生成方案 | 低 | 自动执行，无需确认 |
| 修改已锁定方案 | 中 | Diff 视图展示变更，确认后执行 |
| 提交审批 | 中 | 检查方案完整性（选品/定价/优惠缺一不可） |
| 启动活动 | 高 | 必须运营负责人审批，检查库存充足 |
| 修改优惠规则（执行中） | 高 | Diff 视图 + 审批，检查是否超预算 |
| 取消活动 | 高 | 二次确认 + 记录原因，已发放优惠券需处理 |
