# 数据参谋驾驶舱（通用版）

> 状态：**设计方案 v1.0** — 通用层框架 + 核心功能详细设计
> 定位：面向数据参谋（数字同事）的统一 BI 驾驶舱
> 关联：`00-总览-从OrderManagement到数字同事工作台.md` §六 · `../11-AIP决策引擎升级方案/08-数据参谋技能编排.md`（已编写）
> 适用平台：**全平台**（淘宝/天猫/京东/拼多多/抖音/快手/Shopify/Amazon/微商城）

---

## 一、定位

数据参谋驾驶舱是**全平台通用**工作台，对接数据参谋（数字同事），提供跨平台的统一数据看板、异常告警和归因分析。

| 属性 | 说明 |
|------|------|
| **通用层定义** | BI 看板、异常检测、归因分析、决策建议 |
| **对接数字同事** | 数据参谋（Data Analyst） |
| **不走画布编辑** | 采用网格布局（指标卡 + 图表 + AI 洞察） |
| **复用组件** | BpCard、BIDashboardWidget、AIInsightPanelWidget |

## 三、核心功能详细设计

### 3.1 统一指标看板

#### 3.1.1 指标卡设计
- **布局**：响应式网格，默认 4 列（GMV/订单/访客/转化率），可配置
- **每个指标卡显示**：
  - 指标名称 + 平台标识（多平台聚合时显示「全平台」）
  - 当前值（大字号，突出显示）
  - 环比变化（↑↓箭头 + 百分比，红绿色）
  -  sparkline 迷你趋势图（7 天）
  - 目标进度条（如有设定目标）

#### 3.1.2 核心指标定义
| 指标 | 计算方式 | 适用平台 | 数据源 |
|-----|---------|---------|--------|
| GMV | 订单金额总和 | 全平台 | 订单系统 |
| 订单量 | 订单数 | 全平台 | 订单系统 |
| 访客数(UV) | 独立访客数 | 全平台 | 平台 API |
| 转化率 | 订单量 / UV | 全平台 | 计算 |
| 客单价 | GMV / 订单量 | 全平台 | 计算 |
| ROI | GMV / 投放成本 | 全平台 | 计算 |
| 拉新数 | 首次购买用户数 | 全平台 | 客户系统 |
| 复购率 | 复购客户数 / 总客户数 | 私域/跨境 | 客户系统 |

#### 3.1.3 趋势图
- **时间维度**：今日/7天/30天/90天/自定义
- **对比模式**：
  - 同比（vs 去年同期）
  - 环比（vs 上一周期）
  - 目标对比（vs 设定目标）
- **多平台叠加**：不同平台用不同颜色曲线，支持显示/隐藏

#### 3.1.4 平台切换
- **聚合视图**：默认展示全平台汇总数据
- **单平台视图**：点击平台标签切换，只看该平台数据
- **平台对比**：并排展示多个平台的同一指标

### 3.2 异常检测

#### 3.2.1 检测类型
| 异常类型 | 检测算法 | 适用指标 |
|---------|---------|---------|
| 突变检测 | 3-sigma 法则 / Z-score | GMV、订单、UV |
| 趋势偏离 | 线性回归残差分析 | 转化率、ROI |
| 周期异常 | 同比偏离度（当前 vs 历史同期） | UV、订单 |
| 关联异常 | 指标间相关性断裂（如 UV↑但转化↓） | 复合指标 |

#### 3.2.2 异常分级与响应
| 级别 | 条件 | 展示 | 通知 | 自动动作 |
|-----|------|------|------|---------|
| 🔴 紧急 | 偏离 > 50% 或核心指标归零 | 顶部横幅 + 声音告警 | 短信 + 邮件 + 站内 | 创建数据参谋分析任务 |
| 🟡 关注 | 偏离 20%-50% | 指标卡红框 + AI 洞察区 | 邮件 + 站内 | 推送初判原因 |
| 🟢 提示 | 偏离 10%-20% | 指标卡黄色提示 | 站内 | 记录日志，不打扰 |

#### 3.2.3 异常根因初判
检测到异常后，系统自动执行以下排查：
1. **时间维度**：是否同时间段历史也异常（排除周期性因素）
2. **平台维度**：是单平台异常还是全平台异常（排除平台因素）
3. **指标关联**：关联指标是否同时异常（定位原因链）
4. **外部事件**：是否有已知外部事件（大促/节假日/系统故障）

初判结果展示在 AI 洞察区，供数据参谋进一步分析参考。

### 3.3 归因分析

#### 3.3.1 流量来源归因
```
流量来源分布（桑基图/饼图）
├── 直访（直接访问、收藏、老客）
├── 搜索（站内搜索、SEO）
├── 推荐（算法推荐、关联推荐）
├── 广告（直通车、Dou+、朋友圈广告）
└── 社交（分享、社群、短视频引流）

每个来源展示：
- 流量占比
- 转化率
- GMV 贡献
- 趋势变化
```

#### 3.3.2 转化漏斗分析
```
曝光 → 点击 → 加购 → 下单 → 支付

每个环节展示：
- 环节转化率（本环节 / 上一环节）
- 总体转化率（本环节 / 曝光）
- 行业基准对比（如有数据）
- 环节流失原因初判（AI 分析）

示例：
曝光 10,000 → 点击 1,200 (12%) → 加购 360 (30%) → 下单 180 (50%) → 支付 162 (90%)
                                                      ↑
                                                   流失严重
                                                   原因：运费过高？
```

#### 3.3.3 活动效果归因
- 活动期间 GMV 拆解：自然 GMV vs 活动拉动 GMV
- 活动拉动 GMV 再拆解：优惠券拉动 / 满减拉动 / 直播拉动
- 活动 ROI 计算：活动成本（优惠成本 + 投放成本）vs 活动拉动 GMV

### 3.4 AI 洞察（数据参谋协作）

#### 3.4.1 洞察生成流程
```
[系统] 定时触发（每日 9:00）或异常触发
  ↓
[系统] 创建 Task → 调用数据参谋 Skill
  ↓
[数据参谋] Plan Mode：
  Step 1: 读取昨日/近 7 天核心指标数据
  Step 2: 对比历史基准，识别异常点
  Step 3: 执行归因分析（流量/转化/客单）
  Step 4: 识别机会点（增长机会/优化空间）
  Step 5: 生成决策建议（投放/定价/选品）
  Step 6: 自检（数据准确性/逻辑自洽/风险披露）
  ↓
[系统] AI 洞察面板展示
  ↓
[运营] 查看 → 标记「已读」/「重要」/「误报」
```

#### 3.4.2 洞察分类
| 类型 | 标识 | 说明 | 示例 |
|-----|------|------|------|
| 异常 | 🔴 | 数据异常，需关注 | 转化率连续 3 天下降 |
| 机会 | 🟡 | 增长机会，建议行动 | 周末访客量上升 15% |
| 达成 | 🟢 | 目标达成，正向反馈 | 今日 GMV 已达成日目标的 105% |
| 风险 | 🟠 | 潜在风险，提前预警 | 某 SKU 库存仅够 2 天 |

#### 3.4.3 洞察交互
- **展开详情**：点击洞察卡片展开详细分析过程（数据参谋的推理链）
- **一键行动**：部分洞察支持直接跳转（如「建议加大周末投放」→ 跳转活动策划）
- **反馈机制**：运营可标记「有用/无用/误报」，反馈用于优化数据参谋模型

## 四、数据模型

### 4.1 DashboardConfig（看板配置）

```typescript
interface DashboardConfig {
  id: string;
  name: string;                  // 看板名称（如「今日概览」）
  userId: string;                // 所属用户

  // 指标卡配置
  metricCards: MetricCardConfig[];

  // 图表配置
  charts: ChartConfig[];

  // 平台筛选
  platforms: Platform[];         // 默认展示的平台
  defaultPlatform: 'all' | Platform;

  // 时间范围
  defaultTimeRange: 'today' | '7d' | '30d' | '90d';

  createdAt: string;
  updatedAt: string;
}

interface MetricCardConfig {
  metric: MetricType;            // 指标类型
  platforms: ('all' | Platform)[]; // 展示平台
  showSparkline: boolean;        // 是否展示迷你图
  showTarget: boolean;           // 是否展示目标进度
  order: number;                 // 排序
}

type MetricType = 'gmv' | 'orders' | 'uv' | 'conversion_rate' | 'aov' | 'roi' | 'new_users' | 'repurchase_rate';
```

### 4.2 MetricSeries（指标时间序列）

```typescript
interface MetricSeries {
  metric: MetricType;
  platform: Platform | 'all';
  granularity: 'hour' | 'day' | 'week' | 'month';

  // 时间序列数据
  dataPoints: {
    timestamp: string;
    value: number;
    comparisonValue?: number;    // 对比值（同比/环比）
    targetValue?: number;         // 目标值
  }[];

  // 统计摘要
  summary: {
    total: number;
    avg: number;
    max: number;
    min: number;
    momChange: number;           // 环比变化
    yoyChange?: number;          // 同比变化
  };

  updatedAt: string;
}
```

### 4.3 Anomaly（异常记录）

```typescript
interface Anomaly {
  id: string;
  metric: MetricType;
  platform: Platform | 'all';

  // 异常信息
  detectedAt: string;
  severity: 'critical' | 'warning' | 'info';
  type: 'spike' | 'drop' | 'trend_deviation' | 'cycle_anomaly' | 'correlation_break';

  // 数值
  expectedValue: number;         // 预期值
  actualValue: number;           // 实际值
  deviation: number;             // 偏离值
  deviationPercent: number;      // 偏离百分比

  // 根因初判
  preliminaryCause?: string;     // 初判原因
  causeFactors?: string[];       // 可能因素列表

  // 状态
  status: 'active' | 'investigating' | 'resolved' | 'false_positive';
  resolvedAt?: string;
  resolvedBy?: string;
  resolutionNote?: string;

  // 关联
  relatedInsightId?: string;     // 关联 AI 洞察

  createdAt: string;
}
```

### 4.4 Insight（AI 洞察）

```typescript
interface Insight {
  id: string;
  type: 'anomaly' | 'opportunity' | 'achievement' | 'risk';
  title: string;
  description: string;

  // 数据支撑
  supportingData: {
    metric: MetricType;
    value: number;
    context: string;              // 数据上下文
  }[];

  // 建议
  suggestions: {
    action: string;
    expectedImpact: string;       // 预期影响
    priority: 'high' | 'medium' | 'low';
    link?: string;                // 跳转链接
  }[];

  // 来源
  generatedBy: string;           // "ai"
  taskId?: string;               // 关联的 AI Task

  // 反馈
  feedback?: 'useful' | 'useless' | 'false_positive';
  feedbackBy?: string;

  // 状态
  isRead: boolean;
  isImportant: boolean;

  createdAt: string;
}
```

### 4.5 FunnelStage（漏斗阶段）

```typescript
interface FunnelStage {
  id: string;
  name: string;                  // 阶段名称（如「曝光」）
  order: number;                 // 顺序

  // 数据
  userCount: number;             // 用户数
  conversionRate: number;        // 本环节转化率（vs 上一环节）
  overallConversionRate: number; // 总体转化率（vs 曝光）

  // 行业基准
  industryBenchmark?: number;    // 行业平均转化率

  // 流失分析
  dropOffReasons?: {
    reason: string;
    confidence: number;          // 置信度
  }[];
}
```

## 九、各平台细分差异

| 差异维度 | 公域（淘宝/京东等） | 私域（微商城） | 跨境（Shopify/Amazon） |
|---------|------------------|--------------|---------------------|
| **核心指标** | GMV、UV、转化率、ROI | 拉新数、复购率、LTV | 订单量、客单价、物流时效 |
| **数据源** | 平台数据 + 自有数据 | 自有数据 + 企微数据 | 平台数据 + 物流数据 |
| **异常检测** | 流量异常、转化异常 | 客户流失预警、互动下降 | 物流延迟、差评激增 |
| **AI 洞察** | 投放优化、选品建议 | 客户分层、触达时机 | 库存预警、汇率波动 |
| **归因模型** | 平台内归因（直通车/推荐） | 社群归因（群主/活动） | 广告归因（Facebook/Google） |
| **数据延迟** | T+1（部分实时） | 实时 | T+1（Amazon）/ 实时（Shopify） |

**细分差异写入位置**：各平台自有接入方案目录下的 `工作台细分.md`
