## 一、工作台层在 AOS 架构中的位置

```

│                     L6 数字同事层                         │
│  私域管家 · 导购顾问 · 内容官 · 客服 · 活动 · 数据参谋     │
├─────────────────────────────────────────────────────────┤
│                     L4 AIP 决策引擎层                     │
│  TAOR 循环 · Plan Mode · 权限防线 · Evals 门控            │
├──────────────────┬──────────────────────────────────────┤
│  L3 FDE 编排层    │       L5 行业 Wiki 层                  │
├──────────────────┴──────────────────────────────────────┤
│                  L2 工作台层（本文档）                     │
│  客户关系 · 内容日历 · 活动策划 · 数据参谋 · 订单管理      │
├─────────────────────────────────────────────────────────┤
│                  L1 平台基础设施层                         │
│  Ontology · Action Engine · Draft Engine · 模型路由       │
└─────────────────────────────────────────────────────────┘
```

**工作台层是数字同事与用户的交互界面**：
- 数字同事在后台执行 TAOR 循环
- 工作台在前端展示 Task / Plan / Artifact / 日志
- 用户通过工作台审批计划、确认话术、查看产出

### 2.3 Claude Code 理念映射

| 理念 | 工作台对应 |
|------|----------|
| Task + Artifact + Action | 数据模型（非 Conversation + Message） |
| Plan Mode | 中栏可编辑执行计划 |
| Diff 视图 | 权限门控精确展示变更 |
| Permission Gate | 步骤级批准/编辑/跳过/推迟 |
| Checkpoint | 日志流中检查点标记 |
| Verification Loop | 合规检查（话术3项/退款金额/成分兼容） |
| TAOR 循环 | 任务状态流转 |
| Trust Trajectory | 信任渐进式放松（新用户高频确认→老用户自动化） |

### 4.2 集成路径

```
数字同事技能（AIP 后端）
    │
    ├─ 用户在工作台 [新建任务▼]
    │   → POST /v1/aip/skills/{name}/execute
    │   → 创建 Task + 生成 Plan
    │
    ├─ 工作台展示 Task
    │   → GET /v1/aip/tasks?agent={agent}
    │   → 任务列表（左栏）
    │
    ├─ 用户审批 Plan
    │   → POST /v1/aip/tasks/{id}/plan/approve
    │   → TAOR 循环开始执行
    │
    ├─ 工作台展示 Artifact
    │   → GET /v1/aip/tasks/{id}/artifacts
    │   → 产出面板（右栏）
    │
    └─ AI 洞察反哺
        → 用户点击 [生成触达任务]
        → 新 Task 出现在任务列表 → 闭环
```

### 5.1 技术路线

**固定布局 + 组件复用，不走画布编辑**。理由详见 `05-客情维护平台设计方案.md` §1.5。

复用基础设施：
- `BpCard` / `BpTabs` / `.bp-hover-card` — 视觉组件
- `BpShell` 顶栏 — 导航框架
- `nav.ts` — 菜单注册
- `routes.tsx` — 路由注册
- Widget 注册思路 — 组件按需加载

不使用 `CanvasPage` 拖拽系统，理由：
- 画布是配置态（`CanvasNode[]` 静态配置）
- 工作台是运行态（`Task[]` 动态运行时，TAOR 循环驱动）
- 两者数据模型不匹配

## 八、关键设计决策

| # | 决策 | Why | 影响 |
|---|------|-----|------|
| 1 | **固定三栏布局，不走画布编辑** | 工作台是运行态非配置态；画布拖拽不适合任务驱动场景 | 复用画布视觉组件但不使用拖拽系统 |
| 2 | **Task + Artifact 数据模型**（非 Conversation + Message） | 工作流产品而非对话产品；Task 可审计可回溯 | 与 AIP TAOR 循环天然对接 |
| 3 | **5 类共性工作台 + 80/20 复用** | 80% 共性下沉通用层，20% 差异下放各平台 | 各平台只需写差异部分 |
| 4 | **11 个通用 Widget** | 组件级复用，减少重复开发 | 新增工作台只需配置 Widget 组合 |
| 5 | **工作台 ↔ 数字同事一对一映射** | 每类工作台对接 1-2 个数字同事 | 用户在工作台操作即触发数字同事执行 |
| 6 | **AI 洞察反哺闭环** | 洞察可一键生成新任务 | 形成"执行→洞察→执行"正循环 |
| 7 | **权限门控步骤级** | 批准/编辑/跳过/推迟，非全量审批 | 细粒度控制，兼顾效率与安全 |
| 8 | **Diff 视图展示变更** | 用户精确看到什么变了 | 避免"盲批"，提升信任 |

## 九、风险与缓解

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| CanvasPage 组件迁移风险 | 中 | 不删除 CanvasPage，工作台新建独立页面 |
| 响应式布局在小屏体验差 | 低 | <1280px 降级为单栏+抽屉 |
| 各平台 API 差异大导致适配成本高 | 中 | 80/20 原则 + 差异下放各平台 `工作台细分.md` |
| 数字同事技能未上线导致工作台空壳 | 高 | Phase 1-3 依赖 AIP 层完成；Mock 模式先行 |
