## 二、第一层 — 可信度分级

### 2.1 L1-L4 详细定义

| 级别 | 名称 | 来源 | auto_use | cite_source | 门控 |
|------|------|------|---------|------------|------|
| **L1** | 权威 | 官方文档、法规、API 规范 | ✅ 是 | 否 | 无门控，直接入库 |
| **L2** | 专业 | 第三方数据库、行业报告、人工经验 | ✅ 是 | ✅ 是 | 无门控，直接入库 |
| **L3** | 经验 | 自学习、运营复盘、客户反哺 | ❌ 否 | ✅ 是 | 需 Draft 审核 |
| **L4** | 推测 | 网络爬取碎片、竞品推测 | ❌ 否 | ✅ 是 | 需 Draft 审核 |

### 2.2 来源到级别的映射

```python
# aip_knowledge_governance.py（新增）

class ConfidenceClassifier:
    """可信度分类器 — 根据来源自动分级。"""

    SOURCE_TO_LEVEL = {
        # L1 权威
        "pipe1_seed": "L1",           # 种子知识（23篇方案）
        "pipe5_nmpa": "L1",           # NMPA 法规
        "official_api_doc": "L1",     # 官方 API 文档

        # L2 专业
        "pipe5_cosdna": "L2",         # CosDNA 成分库
        "pipe7_manual": "L2",         # 人工经验注入
        "industry_report": "L2",      # 行业报告

        # L3 经验
        "pipe2_self_learning": "L3",  # 自学习
        "pipe6_customer": "L3",       # 客户反哺
        "auto_pattern_detection": "L3", # 自动模式检测

        # L4 推测
        "pipe3_web": "L4",           # 网络爬取
        "pipe4_competitor": "L4",    # 竞品推测
    }

    def classify(self, source: str) -> str:
        return self.SOURCE_TO_LEVEL.get(source, "L3")  # 默认 L3
```

### 2.3 可信度动态调整

```python
    async def adjust_confidence_score(self, entry_id: str, feedback: str) -> None:
        """根据上游反馈动态调整置信度分数。

        与 02 文档管道2 的 adjust_confidence 对接。
        """
        entry = await self._semantic.get(entry_id)

        if feedback == "positive":
            entry.confidence_score = min(1.0, entry.confidence_score + 0.05)
            entry.positive_feedback += 1
        elif feedback == "negative":
            entry.confidence_score = max(0.0, entry.confidence_score - 0.1)
            entry.negative_feedback += 1

        # 累积正反馈 ≥ 10 且无负反馈 → 自动提升级别
        if (entry.positive_feedback >= 10 and
            entry.negative_feedback == 0 and
            entry.confidence_level in ("L3", "L4")):
            entry.confidence_level = self._promote_level(entry.confidence_level)

        await self._semantic.update(entry_id,
            confidence_score=entry.confidence_score,
            confidence_level=entry.confidence_level,
            positive_feedback=entry.positive_feedback,
            negative_feedback=entry.negative_feedback)

    def _promote_level(self, current: str) -> str:
        """级别提升：L4→L3→L2（不到 L1，L1 只能来源决定）。"""
        promotion = {"L4": "L3", "L3": "L2"}
        return promotion.get(current, current)
```

## 三、第二层 — 写入门控

### 3.1 门控策略

```python
class WriteGate:
    """写入门控 — 根据可信度决定直接入库还是进 Draft。"""

    GATE_POLICY = {
        "L1": {"action": "direct", "audit": False},
        "L2": {"action": "direct", "audit": True},   # 入库但记录审计日志
        "L3": {"action": "draft", "audit": True},    # 进 Draft 草稿区
        "L4": {"action": "draft", "audit": True},    # 进 Draft 草稿区
    }

    async def write(self, entry: KnowledgeEntry) -> WriteResult:
        """带门控的写入。"""
        policy = self.GATE_POLICY.get(entry.confidence_level, self.GATE_POLICY["L3"])

        if policy["action"] == "direct":
            # 直接入库 Semantic 层
            entry_id = await self._semantic.store(entry)

            if policy["audit"]:
                await self._audit_log(entry_id, "direct_write", entry)

            return WriteResult(
                status="stored",
                entry_id=entry_id,
                gate_passed=True,
            )
        else:
            # 写入 Draft 草稿区，等待审核
            draft_id = await self._draft_store.store(entry)

            return WriteResult(
                status="pending_review",
                entry_id=draft_id,
                gate_passed=False,
                review_url=f"/drafts/{draft_id}",
            )
```

### 3.2 Draft 审批流程（复用现有 DraftInbox）

```
管道写入 L3/L4 → Draft 草稿区
                    │
                    ├─ 运营人员审核（客情维护平台 → DraftInbox）
                    │   ├─ 通过 → 入库 Semantic（级别不变）
                    │   ├─ 驳回 → 标记 rejected（不入库）
                    │   └─ 修改 → 修改后通过 → 入库
                    │
                    └─ 7 天未审核 → 自动过期（不入库）
```

### 3.3 Draft 审批接口

```python
class KnowledgeReviewHandler:
    """Draft 审批处理器 — 复用 aip_drafts_engine.py。"""

    async def approve(self, draft_id: str, reviewer: str, modifications: dict | None = None) -> str:
        """审核通过 → 入库 Semantic。"""
        draft = await self._draft_store.get(draft_id)
        entry = KnowledgeEntry(**draft.content)

        if modifications:
            # 审核人修改后入库
            for k, v in modifications.items():
                setattr(entry, k, v)
            entry.created_by = f"{entry.created_by} (reviewed by {reviewer})"

        entry_id = await self._semantic.store(entry)
        await self._draft_store.mark_approved(draft_id, reviewer, entry_id)
        return entry_id

    async def reject(self, draft_id: str, reviewer: str, reason: str) -> None:
        """审核驳回。"""
        await self._draft_store.mark_rejected(draft_id, reviewer, reason)

    async def auto_expire(self) -> int:
        """7 天未审核自动过期。"""
        expired = await self._draft_store.find_expired(days=7)
        for d in expired:
            await self._draft_store.mark_expired(d.id)
        return len(expired)
```

## 四、第三层 — 时效管理

### 4.1 时效策略

```python
class TimeToLiveManager:
    """时效管理 — 过期检查 + 复查提醒 + 自动降级。"""

    # 定时调度：每日 03:30 检查
    SCHEDULE = "30 3 * * *"

    async def run_daily_check(self) -> dict:
        """每日时效检查。"""
        return {
            "expired": await self._mark_expired(),
            "review_due": await self._notify_review_due(),
            "degraded": await self._auto_degrade(),
        }

    async def _mark_expired(self) -> int:
        """标记过期知识（effective_until < now）。"""
        expired = await self._semantic.find_expired()
        for entry in expired:
            await self._semantic.update(entry.id,
                effective_until=time.time(),
                tags=entry.tags + ["expired"])
        return len(expired)

    async def _notify_review_due(self) -> int:
        """复查到期提醒（review_cycle_days 到期）。"""
        now = time.time()
        entries = await self._semantic.find_all()
        due = [e for e in entries
               if now - e.last_reviewed_at > e.review_cycle_days * 86400]

        for entry in due:
            # 发送复查提醒到工作台
            await self._notify_review(entry)

        return len(due)

    async def _auto_degrade(self) -> int:
        """自动降级 — 长期无正反馈且负反馈多的知识降级。"""
        entries = await self._semantic.find_all()
        degraded = 0

        for entry in entries:
            if (entry.negative_feedback > 3 and
                entry.positive_feedback < entry.negative_feedback and
                entry.confidence_level != "L4"):

                new_level = {"L1": "L2", "L2": "L3", "L3": "L4"}.get(entry.confidence_level)
                await self._semantic.update(entry.id, confidence_level=new_level)
                degraded += 1

        return degraded
```

### 4.2 复查周期配置

| category | review_cycle_days | 理由 |
|---------|------------------|------|
| platform_rule | 30 | 平台规则月度可能变更 |
| ingredient | 90 | 成分知识相对稳定 |
| script_template | 30 | 话术需定期更新 |
| industry_trend | 15 | 趋势变化快 |
| competitor | 7 | 竞品信息时效性强 |
| customer_behavior | 30 | 行为模式月度复查 |
| expert_knowledge | 60 | 专家经验较稳定 |
| fde_api_doc | 30 | API 版本月度检查 |
| fde_mapping_pattern | 30 | 映射模式月度复查 |

## 五、与提升机制的对接

### 5.1 L3→L2 提升（与 01 文档 §七对接）

```
Episodic 高频模式（≥5次）→ 自动检测
        │
        ▼
写入 Semantic（L3）→ 走第二层门控 → Draft 审核
        │
        ├─ 审核通过 → 入库 L3
        │   ├─ 累积正反馈 ≥10 → 自动提升 L2（§2.3）
        │   └─ 长期无反馈 → 保持 L3
        │
        └─ 审核驳回 → 不入库
```

### 5.2 提升触发条件

```python
class PromotionGate:
    """提升门控 — 与 01 文档 MemoryPromoter 对接。"""

    PROMOTION_CRITERIA = {
        "L4_to_L3": {
            "min_positive_feedback": 5,
            "max_negative_feedback": 1,
            "min_confidence_score": 0.6,
            "min_hit_count": 10,
        },
        "L3_to_L2": {
            "min_positive_feedback": 10,
            "max_negative_feedback": 0,
            "min_confidence_score": 0.7,
            "min_hit_count": 20,
        },
    }

    async def check_promotion(self, entry_id: str) -> str | None:
        """检查是否满足提升条件。"""
        entry = await self._semantic.get(entry_id)
        criteria = self.PROMOTION_CRITERIA.get(f"{entry.confidence_level}_to_?")

        if not criteria:
            return None

        if (entry.positive_feedback >= criteria["min_positive_feedback"] and
            entry.negative_feedback <= criteria["max_negative_feedback"] and
            entry.confidence_score >= criteria["min_confidence_score"] and
            entry.hit_count >= criteria["min_hit_count"]):

            new_level = self._promote_level(entry.confidence_level)
            await self._semantic.update(entry_id, confidence_level=new_level)
            return new_level
        return None
```

## 六、与 Evals 门控的对接

### 6.1 Reflection 规则注册过滤

11-Evals 门控需要从 Semantic 层获取 Reflection 规则（01 文档 §8.3）。治理层确保只有 L1/L2 级规则被 Evals 使用：

```python
class ReflectionRuleFilter:
    """Reflection 规则过滤 — 只暴露 L1/L2 给 Evals。"""

    async def get_rules_for_evals(self, agent: str) -> list[KnowledgeEntry]:
        """获取数字同事的 Reflection 规则（L1/L2 only）。"""
        return await self._semantic.retrieve(
            query="reflection rules",
            filters=RetrievalFilters(
                category=["expert_knowledge"],
                owner_agents=[agent],
                confidence_level=["L1", "L2"],  # 只给 Evals L1/L2 级规则
            ),
            top_k=50,
        )
```

### 6.2 Eval 失败 → 知识降级

当 Evals 发现某条规则频繁失败（负反馈），触发治理降级：

```python
    async def on_eval_failure(self, rule_entry_id: str, failure_count: int) -> None:
        """Eval 失败 → 降低规则置信度。"""
        if failure_count >= 3:
            await self.adjust_confidence_score(rule_entry_id, "negative")
```

### 7.2 验收标准

**§二 可信度分级**：
- [ ] 7 个管道来源全部映射到 L1-L4
- [ ] 未知来源默认 L3
- [ ] 动态调整：正反馈 +0.05 / 负反馈 -0.1
- [ ] 自动提升：正反馈 ≥10 且无负反馈 → L3→L2

**§三 写入门控**：
- [ ] L1/L2 直接入库
- [ ] L3/L4 进 Draft 草稿区
- [ ] Draft 审批走 `aip_drafts_engine.py`（复用不新建）
- [ ] 7 天未审核自动过期

**§四 时效管理**：
- [ ] 每日 03:30 定时检查
- [ ] 过期知识标记 `effective_until=now`
- [ ] 复查到期提醒发送到工作台
- [ ] 自动降级：负反馈 >3 且 > 正反馈

**§五 提升机制**：
- [ ] L3→L2 需正反馈 ≥10 + 负反馈=0 + 置信度 ≥0.7 + 命中 ≥20
- [ ] L4→L3 需正反馈 ≥5 + 负反馈 ≤1 + 置信度 ≥0.6 + 命中 ≥10

**§六 Evals 对接**：
- [ ] Evals 只获取 L1/L2 级 Reflection 规则
- [ ] Eval 失败 ≥3 次触发规则降级

**通用**：
- [ ] 关闭治理时所有写入直接入库（降级模式）
- [ ] 零修改 `aip_drafts_engine.py`

## 九、关键设计决策

| # | 决策 | Why | 影响 |
|---|------|-----|------|
| 1 | L1/L2 无门控直接入库，L3/L4 进 Draft 审核 | 权威/专业来源可信；经验/推测来源需人工把关 | L1/L2 入库零延迟；L3/L4 有审核延迟 |
| 2 | Draft 审批复用 `aip_drafts_engine.py` | 已有 Draft→Approved/Rejected 状态机 + UI；不造轮子 | 少写一个审批模块 |
| 3 | 自动提升需正反馈 ≥10 | 避免偶然正反馈导致低质量知识提升 | Semantic 层质量有保障 |
| 4 | 自动降级：负反馈 >3 且 > 正反馈 | 差评多的知识应降级，减少被检索概率 | 过时知识自动淘汰 |
| 5 | Evals 只用 L1/L2 级 Reflection 规则 | L3/L4 规则未经验证，用于门控有风险 | Evals 门控可靠性有保障 |
| 6 | 时效管理每日 03:30 检查 | 低峰时段执行，不影响业务 | 过期知识 24h 内处理 |
| 7 | 复查周期按 category 差异化 | 竞品信息 7 天复查；成分知识 90 天复查 | 高时效知识及时更新，稳定知识省成本 |
