## 二、三层记忆全景

### 2.1 架构

```
┌─────────────────────────────────────────────────────────────┐
│                    三层记忆系统                                │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  Semantic Layer（长期语义记忆）                       │   │
│  │  存储：行业知识、平台规则、话术模板、成分库             │   │
│  │  检索：混合检索（向量+关键词+RRF重排）                  │   │
│  │  来源：七条知识管道                                    │   │
│  │  治理：L1-L4 可信度分级 + 写入门控 + 时效管理           │   │
│  │  实现：PostgreSQL + pgvector                          │   │
│  │  Embedding：bge-large-zh-v1.5 (1024维, 本地部署)       │   │
│  └──────────────────────┬──────────────────────────────┘   │
│                         │                                   │
│  ┌──────────────────────▼──────────────────────────────┐   │
│  │  Episodic Layer（情景记忆）                           │   │
│  │  存储：历史会话、执行记录、FDE映射经验、成功/失败案例     │   │
│  │  检索：时间索引 + 平台标签 + FDE三级检索                │   │
│  │  特点：90天TTL，重要经验自动提升到 Semantic             │   │
│  │  实现：Redis (热) + PostgreSQL (冷)                    │   │
│  └──────────────────────┬──────────────────────────────┘   │
│                         │                                   │
│  ┌──────────────────────▼──────────────────────────────┐   │
│  │  Working Layer（工作记忆）                             │   │
│  │  存储：当前任务上下文、中间变量、执行状态                 │   │
│  │  策略：超token限制→指针；八段式压缩；渐进式披露          │   │
│  │  特点：任务结束即清除，重要内容提升到 Episodic            │   │
│  │  实现：内存 + Redis（指针持久化）                       │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 三层职责对比

| 维度 | Semantic | Episodic | Working |
|------|---------|---------|---------|
| 时效 | 长期 | 90 天 TTL | 任务结束清除 |
| 存储 | PG + pgvector | Redis + PG | 内存 + Redis |
| 检索 | 混合检索（向量+关键词+RRF） | 时间索引+元数据 | 直接访问 |
| 容量 | <50 万条 | <10 万条（90天滚动） | <8000 token |
| 提升来源 | Episodic 高频模式 | Working 任务结束 | TAOR 循环 |
| 被谁用 | 6数字同事 Think + FDE API + Evals 规则 | FDE 跨平台复用 + 数字同事经验 | TAOR 当前步骤上下文 |

### 2.3 提升机制

```
Working Memory（任务进行中）
    │ 任务结束 + reusability > 0.5
    ▼
Episodic Memory（90天TTL）
    │ 频率 ≥5次 + importance ≥0.7
    ▼
Semantic Memory（长期，L3级）
    │ 正反馈 ≥10 + 负反馈=0
    ▼
Semantic Memory（L2级，无需审核）
```

详见 `01-三层记忆系统设计.md` §七。

## 四、知识治理全景

### 4.1 三层过滤

```
第一层：可信度分级（L1-L4）
  ├─ L1 权威（官方/法规/种子）→ 自动使用，不引用来源
  ├─ L2 专业（第三方库/人工）→ 自动使用，引用来源
  ├─ L3 经验（自学习/客户）→ 需审核，引用来源
  └─ L4 推测（网络/竞品）→ 需审核，引用来源

第二层：写入门控
  ├─ L1/L2 → 直接入库 Semantic
  └─ L3/L4 → Draft 草稿区 → 人工审核 → 通过入库 / 驳回 / 7天过期

第三层：时效管理
  ├─ 每日 03:30 检查过期知识
  ├─ 复查到期提醒（按 category 差异化周期）
  ├─ 自动降级（负反馈 >3 且 > 正反馈）
  └─ 自动提升（正反馈 ≥10 且无负反馈）
```

### 4.2 治理与 Evals 的协同

```
Semantic 层 Reflection 规则
  │ 只暴露 L1/L2 给 Evals（§6.1）
  ▼
Evals 门控使用规则验证
  │ 验证失败 ≥3 次
  ▼
触发治理降级（confidence_score -0.1 × 3）
```

详见 `03-知识治理三层过滤.md`。

| 依赖方 | Semantic | Episodic | Working | 接口 |
|--------|---------|---------|---------|------|

### 5.3 FDE 跨平台复用

```
接入淘宝后 → Episodic 记录经验
  │
接入微商城时 → 三级检索：
  ├─ Tier 1: 同平台（微商城）→ 无（首次接入）
  ├─ Tier 2: 同认证类型（oauth2）→ 命中淘宝经验
  └─ Tier 3: 通用 → 命中任意平台经验
  │
  ▼ 第二次接入同类平台耗时降低 ≥ 50%
```

## 八、关键设计决策汇总

| # | 决策 | Why | 来源文档 |
|---|------|-----|---------|
| 1 | **pgvector** 而非 Milvus/Qdrant | <50万条足够；复用 PG；运维成本低 | 01 §5.1 |
| 2 | **混合检索**（向量+关键词+RRF） | 电商术语精确匹配+语义模糊查询兼顾 | 01 §6.1 |
| 3 | **FDE 三级检索**（同平台→同认证→通用） | 跨平台复用是 FDE 核心价值 | 01 §3.4 |
| 4 | **八段式压缩**（近3步完整/4-6步摘要/更早转指针） | 参考 Claude Code，控 token 成本 | 01 §4.3 |
| 5 | **提升机制三级** + 频率≥5次自动触发 | 避免低频噪声进 Semantic | 01 §7.1 |
| 6 | **重要度四因子**（成败/复用/稀缺/反馈） | 量化 TTL 和提升决策依据 | 01 §3.3 |
| 7 | **bge-large-zh-v1.5 本地部署** | 中文为主；私有化不调外部 API | 01 §5.3 |
| 8 | **MemorySystem 统一门面** | 上游不耦合存储细节 | 01 §8.4 |
| 9 | **管道写入统一走治理门控** | 不绕过治理，L3/L4 需审核 | 02 §1.3 |
| 10 | **管道2 失败教训 > 成功经验** | 失败教训更稀缺更有价值 | 02 §3.2 |
| 11 | **L1/L2 无门控，L3/L4 进 Draft** | 权威/专业可信；经验/推测需把关 | 03 §3.1 |
| 12 | **Draft 审批复用 aip_drafts_engine.py** | 不造轮子 | 03 §3.2 |
| 13 | **自动提升需正反馈 ≥10** | 避免偶然正反馈导致低质量提升 | 03 §5.2 |
| 14 | **Evals 只用 L1/L2 级 Reflection 规则** | L3/L4 未验证，用于门控有风险 | 03 §6.1 |
| 15 | **冷启动优先管道1/5/7** | L1/L2 级无需审核，冷启动最快 | 04 §1.3 |

## 九、风险与缓解

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| pgvector 性能瓶颈（>50万条） | 低 | 接口抽象可迁移 Qdrant |
| CosDNA 爬取被限流 | 中 | 分批爬取 + 缓存 + 降级到手动导入 |
| L3/L4 Draft 审核积压 | 中 | 7天自动过期 + 运营提醒 |
| bge 模型本地部署资源不足 | 低 | 可降级为 API 调用（配置切换） |
| 冷启动知识质量不达标 | 中 | 50 条人工标注验收 + 依赖覆盖验证 |
| FDE 三级检索无命中（全新平台） | 低 | 降级为无经验模式，不影响首次接入 |
