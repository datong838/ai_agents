# 228-全网同款控价与同类目竞品比价任务方案

> 状态：**产品与任务契约方案 v1.0 · 2026-08-03 · 待评审 · 未编码**
> 适用范围：品牌自有商品、授权渠道商品、同类目竞争商品；淘宝/天猫、京东、拼多多、抖音、快手、微信小店及后续可核验渠道
> 上位产品方案：[228-新电商达人增长与控价任务产品方案](228-新电商达人增长与控价任务产品方案.md)
> 六同事总纲：[228-电商增长参谋长与六数字同事协同进化实施方案](228-电商增长参谋长与六数字同事协同进化实施方案.md)
> 架构约束：复用 `GrowthPlan`、`AgentTask`、`TaskGraph`、`Handoff`、`Evidence`、`Artifact`、`EffectReview` 和六数字同事，不新增“控价智能体”或平行调度系统

## 0. 使用的 Rules

1. 把“同款价格治理”和“同类目竞品比价”拆成两个任务；同类目竞品不能进入控价处置。
2. “恶性倾销”属于需要事实与法律判断的结论，系统只生成“疑似异常低价候选”，不得自动认定违法。
3. 同款判断必须核验品牌、型号、规格、包装、数量、赠品、区域、税费和运费，不能只凭标题或图片相似。
4. 价格必须拆分标价、券、满减、会员、直播、平台补贴、运费和赠品价值；不把所有低价都归因于商家。
5. 每小时检查是可配置的高优先级策略，不是全网所有商品的统一频率；平台 capability、限流、成本与风险优先。
6. 数据获取仅允许官方 API、授权数据源、合规公开页面观察、批准的 Research Adapter 和人工上传证据。
7. 通知、申诉、举报、渠道沟通及任何账号写操作必须经过人工批准；G6 前只能生成草稿和人工任务。
8. 禁止虚假下单、恶意退款、刷单、骚扰商家、威胁、绕验证码、规避限流和未经授权收集个人信息。

## 1. 核心结论

全网价格任务应建立两个相互关联但目的不同的闭环：

### 1.1 同款价格治理

针对品牌自有商品、授权经销商品或有明确渠道合同依据的相同 SKU，持续观察各平台实际可得价，识别疑似低于批准价格边界、异常促销或渠道乱价的情况，形成证据并由人工决定是否沟通、申诉、举报或转法务。

```text
品牌/SKU/渠道政策
 → 同款商品发现
 → 价格构成归一
 → 疑似异常检测
 → 再次取证与人工复核
 → 合规处置草稿
 → 人工批准和执行
 → 定时复查
 → 恢复、关闭或升级
```

### 1.2 同类目竞品比价

针对竞品和同类目商品，观察价格带、规格、卖点、促销、销量/评价等合法可用事实，帮助判断本商品的价格定位、竞争力和活动策略。竞品低价本身不是“乱价”，不能进入控价、投诉或要求恢复价格的流程。

```text
类目与竞争问题
 → 竞品样本定义
 → 价格/规格/权益归一
 → 价格带与价值对比
 → 竞争机会和风险
 → 活动/商品/内容建议
 → 效果观察与报告
```

### 1.3 关于每小时检查

**可以每小时检查，但应只用于核心同款 SKU 和高风险渠道。** 全网长尾商品、整个类目和所有竞争对手统一每小时扫描，会显著增加平台限流、成本、误报、页面变动和合规风险。首期采用“分层频率 + 事件提频 + 失败退避”的自适应调度。

## 2. 业务边界与商品关系分级

### 2.1 商品关系分级

| 级别 | 定义 | 主要证据 | 允许任务 |
|---|---|---|---|
| `EXACT_SKU` | 同品牌、同型号、同规格、同包装/数量，关键标识一致 | GTIN/EAN/UPC、品牌商品码、平台 SKU、型号、规格 | 比价；有权利/合同依据时可进入价格治理 |
| `SAME_PRODUCT_VARIANT` | 同一商品但规格、数量、包装或赠品不同 | 商品族、型号、规格换算、包装证据 | 归一化比价；默认不能直接按绝对价格控价 |
| `LIKELY_SAME` | 多项证据相似但关键标识缺失 | 标题、图片 hash、属性、店铺、人工证据 | 只生成待复核候选，不进入处置 |
| `CATEGORY_COMPETITOR` | 同类目、相近受众/用途的其他品牌或产品 | 类目、功能、价格带、用户场景 | 仅竞品比价与市场研究 |
| `UNRELATED` | 商品不具备有效可比性 | 规格/用途冲突或证据不足 | 排除 |

### 2.2 可治理与不可治理

进入价格治理必须同时满足：

1. 商品关系达到人工确认的 `EXACT_SKU`，或品牌/渠道规则明确覆盖对应商品族。
2. 客户对该品牌、渠道或合同具有可说明的治理依据。
3. 价格口径、地区、时间、促销和补贴被拆分。
4. 至少有一条可复核证据；高风险处置建议使用跨时间双证据。
5. 人工确认这是需要处理的异常，而不是合法促销、平台补贴、清仓或数据错误。

下列情况只能比价，不能控价：其他品牌同类目商品、无授权关系的竞争对手、自有品牌无法覆盖的第三方商品、仅标题相似商品、证据不足或权利依据不明确的商品。

## 3. 六数字同事协作情况

并非每个价格事件都需要六位同事同时参与。数据参谋、活动策划师和导购顾问是核心三角；其余三位按任务需要参与。

| 数字同事 | 角色 | 主要责任 | 主要产物 | 参与强度 |
|---|---|---|---|---|
| **数据参谋** | 任务 owner / 监测总控 | 监测范围、调度、数据质量、同款候选、异常检测、证据完整性、趋势和复盘 | `PriceMonitoringPolicyRevision`、观察、异常、报告 | 核心、持续参与 |
| **活动策划师** | 促销与价格机制解释 | 识别满减、券、会员、直播、平台补贴、大促和自家活动冲突；提出价格/活动策略建议 | `PromotionPriceExplanation`、`PricingScenarioDraft` | 核心、异常与大促参与 |
| **导购顾问** | 商品可比性与价值分析 | 核验规格/套装/赠品，完成单位价格和价值对比，解释竞品差异与替代关系 | `ProductComparableDecision`、`CompetitorValueCard` | 核心、匹配与比价参与 |
| **内容官** | 竞品卖点与内容情报 | 提炼竞品公开卖点、促销表达、内容策略和消费者认知；输出我方内容建议 | `CompetitorMessagingBrief` | 比价任务按需参与 |
| **客服专员** | 合规沟通和案例支持 | 汇总消费者反馈、价格疑问；生成渠道/商家沟通草稿，跟踪工单和回复 | `PriceCommunicationDraft`、`PriceServiceCase` | 处置阶段参与 |
| **私域管家** | 授权渠道关系维护 | 对已建立关系的经销商维护沟通历史、频控、跟进和恢复确认 | `ChannelRelationshipFollowup` | 仅授权渠道按需参与 |

### 3.1 不适合的职责分配

- 客服专员不负责判定“恶性倾销”或自动威胁商家。
- 私域管家不负责抓取陌生卖家联系方式，也不绕过拒绝继续联系。
- 内容官不负责同款技术判定，其竞品内容分析不能替代 SKU/规格证据。
- 活动策划师只能解释价格机制和提出策略，不能自行修改价格、佣金或提交举报。
- 数据参谋负责形成候选和建议，最终的渠道权利、法律结论和对外处置由人工负责。

### 3.2 人工角色

| 人工角色 | 决定权 |
|---|---|
| 品牌/渠道负责人 | 确认授权关系、价格政策适用范围、异常是否需要处理 |
| 商品运营 | 核验商品、规格、包装、活动和价格构成 |
| 法务 | 评估合同、知识产权、不正当竞争/倾销等法律问题和对外表述 |
| 平台运营 | 通过平台允许渠道进行申诉、举报、通知和结果登记 |
| 定价/经营负责人 | 批准我方价格、优惠、活动和竞争策略变更 |

## 4. 任务输入与策略冻结

每个监测任务先创建 `PriceMonitoringPolicyRevision`：

| 输入域 | 必填内容 |
|---|---|
| 任务类型 | `EXACT_PRODUCT_GOVERNANCE` 或 `CATEGORY_COMPETITOR_BENCHMARK` |
| 商品范围 | 品牌、商品族、SKU/型号、规格、包装、图像/条码和类目 |
| 渠道范围 | 平台、地区、店铺白名单/观察名单、搜索词和 URL 种子 |
| 价格口径 | 标价、券后、满减、会员、直播、补贴、税费、运费、赠品 |
| 治理依据 | MAP/建议价/渠道合同价/授权策略及适用范围；没有则标记 `NO_GOVERNANCE_BASIS` |
| 竞品集合 | 直接竞品、替代品、价格带和样本更新规则 |
| 调度策略 | 频率层级、活跃时间、事件提频、预算、限流和失败退避 |
| 异常规则 | 绝对阈值、相对差值、持续时间、连续观察次数和风险等级 |
| 证据策略 | API 响应、页面 URL、截图、时间、地区、登录态、hash 和保留期 |
| 处置策略 | 人工复核人、通知/申诉/法务路径、SLA 和停止条件 |

商品、阈值、调度、平台、价格口径、治理依据或处置路径变化都产生新 revision；旧批准不得自动覆盖新策略。

## 5. 价格口径与归一化

### 5.1 原始价格事实

每条 `PriceObservationEvidence` 至少记录：

- 平台、店铺、页面/API、商品和 SKU 标识。
- 标价、当前售价、券、满减、会员价、直播价、平台补贴和商家优惠。
- 运费、税费、地区、币种、配送限制和登录/会员条件。
- 件数、净含量、规格、包装、赠品和组合内容。
- 观察时间、数据截止时间、采集方式、capability、响应/截图 hash。
- 页面是否可见、库存/可售状态和价格是否需要进入结算页才能确认。

### 5.2 可比价格

```text
实际可得价
= 商品支付价
- 可明确归属且当前可用的优惠
+ 必付运费/税费
- 经批准口径折算的赠品价值
```

同时计算：单件价、每 100g/ml 价格、标准包装折算价和套装总价。赠品价值、会员门槛和平台补贴必须单列，不能隐含进一个无法解释的“最低价”。

### 5.3 价格异常不是法律结论

系统可以使用受控枚举：

- `BELOW_POLICY_CANDIDATE`：疑似低于客户价格政策。
- `UNUSUAL_DROP`：相对历史出现异常降幅。
- `CROSS_CHANNEL_GAP`：跨渠道差价超过阈值。
- `SUBSIDY_DRIVEN`：低价主要由平台补贴形成。
- `PROMOTION_EXPLAINED`：由已知合法促销解释。
- `IDENTITY_UNCERTAIN`：同款证据不足。
- `DATA_QUALITY_RISK`：价格不可复现或数据可能错误。

不得由模型直接输出“违法倾销”“恶意竞争”“售假”等对外结论。

## 6. 调度策略：是否每小时检查

### 6.1 推荐频率分层

| 层级 | 对象 | 建议基础频率 | 使用场景 |
|---|---|---|---|
| L0 事件驱动 | 自有/授权数据的价格、活动、商品状态事件 | webhook/事件到达即处理 | 平台支持可靠回调时优先，减少轮询 |
| L1 核心同款 | 核心品牌 SKU、重点平台、历史乱价高风险店铺 | **每 1 小时** | 用户提出的主要场景；要求能力、配额和证据稳定 |
| L2 重点观察 | 非核心同款、重点竞品、重点活动商品 | 每 4 小时 | 平衡新鲜度与调用/观察成本 |
| L3 类目大盘 | 同类目价格带、竞品集合、长尾渠道 | 每日 1～2 次 | 用于竞争情报和趋势，不需小时级 |
| L4 长期基线 | 全量长尾、季节趋势、竞品组合变化 | 每周 | 更新样本、价格带和类目结构 |
| 临时加速 | 大促、异常出现、处置后恢复检查 | 15～30 分钟或每小时，有限窗口 | 必须设置结束时间、预算和退避 |

结论：**核心同款每小时检查合理；同类目全网比价通常每日或每 4 小时足够。** 如果平台只允许较低频率、按调用收费或页面观察成本高，系统必须自动下调，不能为了“每小时”伪造新鲜数据。

### 6.2 自适应调度

```text
基础频率
 → capability/配额/成本预检
 → 带 jitter 的分散调度
 → 增量观察与内容 hash 比较
 → 无变化：保持或逐步降频
 → 异常：短时提频并补充证据
 → 限流/错误/验证码/权限变化：指数退避并转人工
 → 处置后：进入恢复复查窗口
 → 稳定恢复：回到基础频率
```

必须配置：时区、活跃时间、随机抖动、最大并发、平台/租户预算、连续失败阈值、提频最长时间和下次运行时间。调度器不能运行任意脚本，只能调用已注册、只读且通过 capability 检查的 adapter。

### 6.3 两次确认规则

瞬时价格可能来自缓存、限时券、库存切换或页面实验。除非是可靠官方事件或人工紧急确认，高风险异常建议满足以下之一才进入正式案例：

- 相隔一个合理窗口的两次观察均可复现；或
- API 价格、公开页面/结算证据等两个独立来源一致；或
- 人工复核并明确接受单次证据的不确定性。

二次确认不是无限重试。遇到验证码、封禁提示、权限不足或平台明确限制时立即停止自动观察。

### 6.4 新鲜度 SLO

| 对象 | 目标新鲜度 | 超时显示 |
|---|---|---|
| L1 核心同款 | 目标 1 小时内 | `STALE`，不使用旧价格触发新处置 |
| L2 重点观察 | 目标 4 小时内 | 降级为趋势参考 |
| L3 类目大盘 | 目标 24 小时内 | 报告标记数据截止时间 |
| 处置后复查 | 按案例 SLA，建议 1～2 小时 | `RECHECK_OVERDUE` 并提醒人工 |

新鲜度是目标而不是保证；数据源不可用时必须显示最后成功时间和原因。

## 7. 同款价格治理任务 DAG

```text
G01 读取商品主数据、治理依据、渠道和调度策略
 → G02 获取 API/公开页面/人工价格观察
 → G03 商品 identity 与规格匹配
 → G04 价格构成、单位和地区归一
 → G05 阈值、历史和跨渠道异常检测
 → G06 平台补贴、活动、会员和数据质量解释
 → G07 二次取证和证据包完整性检查
 → G08 人工确认：误报/观察/需要处置/转法务
 → G09 生成沟通、申诉、举报或法务材料草稿
 → G10 人工批准并通过合规渠道执行
 → G11 按 SLA 定时复查价格和回复
 → G12 恢复、无变化、升级、撤回或关闭
 → G13 效果、耗时、误报和经验复盘
```

关键依赖：

- G03 未达到确认标准，G08 只能选择继续观察或误报，不能提交处置。
- G06 发现平台补贴或合法活动足以解释价格时，默认不生成商家违规草稿。
- G08 人工未确认、G10 未单独批准时，外部通知/申诉/举报不可达。
- G11 复查只观察事实，不自动重复发送通知或升级。

## 8. 同类目竞品比价任务 DAG

```text
B01 定义类目、消费者场景、我方商品和决策问题
 → B02 建立有代表性的竞品样本和证据
 → B03 商品属性、规格、包装、权益和价格归一
 → B04 价格带、价值、销量/评价可用事实和促销比较
 → B05 识别直接竞品、替代品、引流款和高价值款
 → B06 导购顾问生成可比性与价值差异
 → B07 内容官提炼竞品卖点和表达差异
 → B08 活动策划师形成我方价格/优惠/组合场景草稿
 → B09 数据参谋评估毛利、库存、转化和风险
 → B10 人工决定保持、测试、调整商品/内容/活动或继续观察
 → B11 观察决策效果并复盘
```

竞品比价输出是决策支持，不直接改价。任何我方价格、券、组合或活动变化都需要独立 GrowthPlan/ActionProposal 和审批。

## 9. 状态机

### 9.1 价格观察状态

```text
SCHEDULED → FETCHING → OBSERVED → NORMALIZED → MATCH_PENDING
          → MATCHED → EVALUATED
          → NORMAL | ANOMALY_CANDIDATE | DATA_QUALITY_RISK
```

### 9.2 价格治理案例状态

```text
ANOMALY_CANDIDATE
 → EVIDENCE_PENDING
 → READY_FOR_REVIEW
 → HUMAN_CONFIRMED
 → ACTION_DRAFTED
 → PENDING_APPROVAL
 → APPROVED_FOR_MANUAL_ACTION
 → SUBMITTED
 → RECHECKING
 → RESTORED | NO_CHANGE | ESCALATED | FALSE_POSITIVE | CLOSED
```

`APPROVED_FOR_MANUAL_ACTION` 不等于已发送，`SUBMITTED` 不等于平台接受，`RESTORED` 必须有新的价格观察证据。

### 9.3 竞品洞察状态

```text
SAMPLE_DEFINED → OBSERVING → BENCHMARK_READY → INSIGHT_DRAFT
               → REVIEWED → DECISION_RECORDED → OBSERVING_EFFECT → CLOSED
```

## 10. 核心 Artifact

| Artifact | 用途 | 关键不变量 |
|---|---|---|
| `PriceMonitoringPolicyRevision` | 监测范围、频率、阈值、预算和处置策略 | 批准精确 revision |
| `ProductIdentityProfile` | 品牌、型号、SKU、规格、包装和标识 | 商品主数据有来源 |
| `PriceObservationEvidence` | 单次价格与页面/API 证据 | 时间、地区、口径、hash、来源齐全 |
| `ProductComparableDecision` | EXACT/VARIANT/LIKELY/CATEGORY 判定 | 结论与证据可解释、可人工覆盖 |
| `NormalizedPriceFact` | 实际价、单位价及价格构成 | 不隐藏补贴、运费和赠品假设 |
| `PriceAnomalyCandidate` | 异常类型、阈值、解释和风险 | 不是违法结论 |
| `PriceGovernanceCase` | 人工确认、证据、处置与复查时间线 | 状态来源真实回执 |
| `PriceCommunicationDraft` | 合规通知/申诉/举报材料草稿 | 草稿不等于已执行 |
| `PriceRestorationCheck` | 处置后的新价格观察 | 必须引用新 evidence |
| `CompetitorBenchmarkSnapshot` | 同类目竞品价格/价值快照 | 样本、时间和可比性透明 |
| `CompetitorValueCard` | 功能、规格、价格和卖点差异 | 不把营销文案当已验证事实 |
| `PriceIntelligenceReview` | 趋势、误报、处置和经营效果复盘 | 区分事实、推断和未知 |

## 11. Handoff 最小披露

| 从 → 到 | 允许传递 | 禁止传递 |
|---|---|---|
| 数据参谋 → 导购 | 商品/价格 evidence refs、规格和可比性问题 | 卖家个人信息、未授权账号数据 |
| 导购 → 活动策划师 | 单位价、规格差异、替代关系和价值卡 | 未确认的同款/违规结论 |
| 数据参谋 → 内容官 | 竞品公开卖点 refs、类目洞察问题 | 抓取原文全文、内部处置策略 |
| 活动策划师 → 数据参谋 | 补贴/活动解释、我方策略场景和约束 | 未批准的价格写操作 |
| 人工复核 → 客服 | 已确认案例、可披露证据、沟通目的和批准边界 | 内部法律意见、无关商家数据 |
| 客服 → 人工运营 | 沟通草稿、工单状态、对方结构化回复 | 威胁性文案、自动法律结论 |
| 数据参谋 → 私域管家 | 授权渠道 token、关系状态、跟进窗口和频控 | 陌生卖家个人联系方式 |
| 全员 → 数据参谋 | Artifact/Outcome refs、耗时、结果、失败原因 | 不必要的 PII 和自由文本 |

## 12. 工作台设计

### 12.1 全网价格驾驶舱

- 我方 SKU × 平台 × 店铺价格矩阵，展示标价、实际可得价、单位价和价格组成。
- L1/L2/L3 监测范围、上次成功、下次运行、新鲜度、限流、成本和失败原因。
- 正常、疑似异常、待补证、待复核、待处置、复查中、已恢复和升级案例。
- 每个异常可查看同款证据、历史价格曲线、平台活动解释、截图/API hash 和决策时间线。

### 12.2 竞品比价驾驶舱

- 我方商品与直接竞品/替代品的规格、单位价、权益、促销和公开卖点对比。
- 类目价格带、价格指数、促销密度、样本覆盖和数据截止时间。
- 导购价值卡、内容差异、活动场景以及人工决策和后续效果。
- 明确标记“竞品研究，不属于价格治理”的商品。

### 12.3 调度控制台

- 频率层级、启停、时区、活跃窗口、jitter、预算、并发、失败退避和提频到期时间。
- 平台 capability、限流余量、按调用成本、最近错误和人工接管状态。
- 手动运行只创建一次受控 run，不能绕过同一 adapter 的权限和限流。
- 任何改频、扩平台、扩 SKU 和提频都生成新的 policy revision 和审计事件。

## 13. 指标体系

### 13.1 监测质量

- 核心 SKU 覆盖率、平台/店铺覆盖率、按频率层级的按时完成率。
- 数据新鲜度、成功率、限流率、页面不可复现率、单位观察成本。
- 同款自动判定准确率、人工改判率、规格归一失败率。
- 异常误报率、漏报抽检率、证据完整率和二次确认成功率。

### 13.2 价格治理

- 新增异常候选、人工确认率、待处理积压和首次响应时间。
- 处置提交率、平台/渠道接受率、恢复率、平均恢复时间和复发率。
- 因平台补贴/合法活动关闭的比例，防止把正常低价当违规。
- 沟通投诉、平台警告、错误处置和法务升级数量。

### 13.3 竞品情报

- 竞品样本覆盖、价格带变化、我方价格指数和价值差异。
- 竞品促销频率、价格变化速度、直接竞品/替代品变化。
- 由洞察产生的实验数、实施率、毛利/转化/销量变化和负面护栏。

不把“抓到多少低价”作为唯一 KPI，否则会激励误报和过度处置。

## 14. 风险、审批与停止条件

| 风险 | 默认控制 |
|---|---|
| 同款误判 | 多标识匹配、规格/包装校验、人工确认、高风险双证据 |
| 价格口径错误 | 拆分券/补贴/会员/直播/运费/赠品，保留原始值 |
| 误称恶性倾销 | 只输出异常候选，法律结论转法务 |
| 平台限流/封禁 | capability 和配额预检、jitter、退避、立即停止绕过 |
| 高频成本失控 | 分层频率、内容 hash、预算上限、无变化降频 |
| 页面/价格瞬时变化 | 二次确认、时间与地区证据、不可复现标记 |
| 错误通知/举报 | 人工复核、独立 Action 批准、maker-checker、回执 |
| 商家骚扰 | 单案例频控、统一工单、回复等待期、拒绝后停止 |
| 竞品研究越界 | 仅合法公开/授权数据，不获取个人信息和私密经营数据 |
| 自动调价风险 | 本方案不直接改价；任何我方调价另走高风险 Action |

立即暂停自动观察或后续批次的条件：平台警告/验证码/封禁风险、连续限流、权限撤回、预算耗尽、误报异常升高、同款模型漂移、证据存储失败、数据源条款变化或人工 kill switch。

## 15. 与 G0～G6 的映射

| 波次 | 本任务交付边界 |
|---|---|
| G0 | 冻结价格任务 payload、Artifact refs、marking、审批和禁止动作；不运行调度 |
| G1 | 数据参谋完成只读观察、同款候选、价格归一、异常和竞品报告草稿 |
| G2 | 导购完成商品可比性/价值卡，内容官生成竞品表达分析，客服生成沟通草稿 |
| G3 | 活动策划师完成促销解释与我方策略场景；私域管家仅维护授权渠道关系 |
| G4 | 从多周期验证结果生成受治理的阈值、匹配和处置经验候选 |
| G5 | 各平台 Connector 提供官方 API/OAuth/Webhook/限流/价格事实；公开观察由批准的只读 adapter 承担 |
| G6 | 独立批准后才允许通知、申诉、举报等受控 Action；支付、退款、恶意下单和通用自动调价不开放 |

当前 M5 完成前不得提前编码电商 G0～G6。本方案不改变 M3 当前开发顺序，也不把现有 demo schedule 视为已经具备小时级生产调度。

## 16. 分阶段开发建议

### PG0：口径、同款和证据契约

- 冻结商品关系分级、价格组成、Artifact、状态、marking 和治理依据。
- 用真实但脱敏的同款、变体、套装、赠品和竞品样本建立 Evals。
- 重点验证同款误判、单位价格、平台补贴和无法复现价格。

### PG1：人工触发的只读 MVP

- 先选 10～20 个核心 SKU、2～3 个平台，人工触发观察。
- 生成同款判定、价格证据、异常候选和竞品比价报告，不对外处置。
- 与运营共同校准误报、价格口径、证据质量和页面/API 成本。

### PG2：分层调度

- 对验证通过的 adapter 开放 L1 每小时、L2 每 4 小时、L3 每日调度。
- 加入 jitter、限流、预算、失败退避、新鲜度和调度控制台。
- 先单租户小规模运行，证明 7～14 天稳定后再扩 SKU/平台。

### PG3：案例与恢复闭环

- 增加人工复核、沟通/申诉草稿、执行登记、回复和恢复复查。
- 形成误报、恢复时间、复发率和渠道关系的完整复盘。
- 仍以人工渠道执行为主。

### PG4：受控 Action

- 仅对 G5 已核验、G6 已批准的平台动作逐项开放。
- 每种动作独立 feature flag、频控、审批、回执、补偿和 kill switch。
- 不开发虚假购买、恶意退款、刷单、自动法律指控或绕平台限制的 Action。

## 17. 验收标准

1. 同款、变体、疑似同款、同类目竞品能正确分流，竞品不会进入控价处置。
2. 价格观察能解释券、满减、会员、直播、平台补贴、运费、税费、赠品和规格换算。
3. L1 核心 SKU 可以按小时形成新 evidence；权限/限流/失败时显示 stale，不复用旧数据伪装新观察。
4. 异常提频有预算、时限、退避和自动恢复基础频率，不形成无限高频任务。
5. 每个价格治理案例都有治理依据、同款证据、价格构成、时间、地区、人工结论和处置回执。
6. 没有人工确认和独立 Action 批准时，通知、申诉、举报和调价路径不可达。
7. 竞品报告展示样本、可比性、数据截止时间和不确定性，不把营销文案当事实。
8. 处置后能按 SLA 复查并以新证据进入恢复、无变化、升级或误报状态。
9. 双租户、重复 run、并发调度、回调乱序、平台超时、限流和撤权测试通过。
10. 禁止动作在方案、UI、执行器和 Evals 四层均不可达。

## 18. 下一步建议

1. 选一个客户品牌，列出首批 10～20 个核心 SKU、治理依据、主要平台和重点观察店铺。
2. 每个 SKU 建立标准商品档案，明确型号、规格、包装、条码、图片和可接受的价格组成。
3. 选择 5～10 个同类目竞品，明确它们只用于比价，不进入控价案例。
4. 先人工运行 3～7 天，验证同款准确率、价格可复现性、平台补贴解释和单位观察成本。
5. 通过验证后仅对核心 SKU 开启每小时观察；重点竞品每 4 小时、类目大盘每日。
6. 连续稳定运行 7～14 天并通过安全评审后，再形成 PG2 编码实施方案；本文件本身不授权代码修改或外部处置。
