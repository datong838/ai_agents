# 228-带货达人邀约签约与长期运营任务方案

> 状态：**产品与任务契约方案 v1.0 · 2026-08-03 · 待评审 · 未编码**
> 适用平台：微信小店、抖音电商、快手电商及后续具备达人合作能力的平台
> 上位产品方案：[228-新电商达人增长与控价任务产品方案](228-新电商达人增长与控价任务产品方案.md)
> 六同事总纲：[228-电商增长参谋长与六数字同事协同进化实施方案](228-电商增长参谋长与六数字同事协同进化实施方案.md)
> 架构约束：复用 `GrowthPlan`、`AgentTask`、`TaskGraph`、`Handoff`、`Artifact`、`Evidence`、`EffectReview` 与六数字同事，不新增第七个“达人智能体”

## 0. 使用的 Rules

1. 达人邀约是一个长期经营任务，不是“一键群发”按钮；必须覆盖候选、邀约、谈判、签约、履约、效果和关系维护全周期。
2. 每日 100 个邀约是可配置运营容量，不是系统承诺；平台频控、人工审核、团队承接能力和投诉护栏优先。
3. 预计每 100 个邀约仅 2～3 个达人接活，作为首期容量规划基线，不伪装成保证转化率。
4. 数据参谋是任务 owner，其他五位数字同事通过标准任务和 Handoff 协作；不共享无边界上下文。
5. 平台官方 API 只按已核验 capability 使用；没有邀约写接口时只生成草稿，由人工在平台内执行并登记回执。
6. 达人联系方式、合同、佣金、收款、寄样地址和聊天内容按最小授权、字段 marking、保留期和审计处理。
7. 自动发送、佣金、挂品、签约确认、寄样、支付和其他生产写操作必须等待 G6，且逐动作审批、幂等、回执、补偿和 kill switch 齐全。
8. 禁止骚扰、重复轰炸、购买非公开联系方式、伪造合作案例、虚假承诺收益、绕验证码和规避平台频控。

## 1. 核心结论

本方案把达人合作定义为一个由数据参谋总控、六数字同事协作的长期任务域：

```text
商品与经营目标
  → 找到合适达人并去重
  → 每日分批生成个性化邀约
  → 人工批准并通过已授权渠道发送
  → 回复识别与商务谈判
  → 条款审批与签约
  → 寄样、选品、挂品、排期和内容准备
  → 直播/短视频带货
  → GMV、订单、佣金、退款和 ROI 复盘
  → 分层维护、复邀、成长或退出
```

首期按照“每天最多处理约 100 个唯一达人、约 2～3 个接活”的漏斗规划。若连续执行 30 天，理论上会新增约 60～90 个接活达人，因此系统必须同时约束签约审核、寄样库存、运营跟进和活动档期容量；不能只扩大邀约量而没有后端承接能力。

## 2. 目标、非目标与完成定义

### 2.1 业务目标

- 从商品、受众、毛利、库存和活动目标出发，持续获得匹配的 KOC/腰部/头部达人。
- 保证同一店铺不重复骚扰同一达人，跨平台身份只有具备证据时才合并。
- 在低回复率场景下稳定运营候选漏斗，并找到影响接活率的真实原因。
- 把口头约定转成可审计的商务条款、合同版本、履约任务和效果记录。
- 识别高潜达人，形成可复用的长期合作池，降低下一次合作成本。

### 2.2 非目标

- 不承诺达人必定回复、签约、开播或产生 GMV。
- 不抓取非公开手机号、微信号、地址和个人画像。
- 不用群控、模拟点击或 RPA 绕过平台开放能力和频控。
- 不让模型自行签署合同、确定最终佣金、付款、寄样或公开发布内容。
- 不把一次带货 GMV 直接解释为达人净贡献；必须同时观察退款、佣金、样品、优惠和履约成本。

### 2.3 任务完成定义

一次达人合作任务只有同时满足以下条件才算闭环：

1. 候选来源、筛选条件、评分、去重和批准均可追溯。
2. 每次邀约都有唯一 attempt、内容 revision、渠道、发送者、时间和回执。
3. 达人回复、拒绝、失联、谈判、签约和履约均使用明确状态，不靠自由文本猜测。
4. 合同/平台合作关系、佣金、商品、档期、寄样和素材责任均被确认。
5. 带货结果经过观察窗口，能回读订单、GMV、佣金、退款、成本和异常。
6. 产生继续合作、培育、暂停或退出的明确结论，并进入长期关系计划。

## 3. 六数字同事协作分工

### 3.1 责任矩阵

| 数字同事 | 在达人任务中的定位 | 主要责任 | 主要产物 | 不负责 |
|---|---|---|---|---|
| **数据参谋** | 任务 owner / 增长参谋长 | 商品目标拆解、候选发现、去重、评分、每日批次、漏斗监控、效果归因、暂停建议 | `CreatorRecruitmentPlan`、候选快照、批次、漏斗、复盘 | 不自行批准发送、签约或付款 |
| **活动策划师** | 商务与活动 owner | 合作方式、佣金/坑位费建议、预算、毛利、商品组合、档期、停止条件、合同商务包 | `CreatorCommercialOfferRevision`、`CreatorCampaignPlan` | 不代替法务签合同，不越权定价 |
| **内容官** | 邀约与内容 owner | 达人研究摘要、个性化邀约、商品卖点、内容 brief、直播/短视频素材包、品牌合规 | `CreatorOutreachDraft`、`CreatorContentBrief` | 不自动群发，不编造功效与销量 |
| **导购顾问** | 商品匹配顾问 | 商品—达人—受众匹配、选品、规格/价格/库存核验、卖点与异议解释、替代商品 | `CreatorProductMatchCard`、`CreatorSelectionProposal` | 不以敏感画像推断达人能力 |
| **客服专员** | 履约支持与异常 owner | 接活后的 FAQ、寄样/物流跟踪、商品使用问题、平台/订单异常工单、SLA 与升级 | `CreatorServiceCase`、回复草稿、异常记录 | 不承担冷启动群发，不承诺超权限赔付 |
| **私域管家** | 达人关系 owner | 联系同意、频控、关系阶段、回访、复邀、生日/节点关怀、沉默唤醒、退订和抑制 | `CreatorRelationshipPlan`、触达草稿、关系健康度 | 不绕过拒绝/退订，不持有无关 PII |

### 3.2 人工角色

| 人工角色 | 必须保留的决定权 |
|---|---|
| 经营负责人 | 批准目标、每日容量、预算、毛利护栏、发送批次和停止条件 |
| 达人商务/运营 | 核实达人身份、执行平台内邀约、谈判、登记回复、推进挂品和排期 |
| 法务/授权签约人 | 审核合同、主体、知识产权、违约、结算和数据条款并完成签署 |
| 财务 | 核验佣金/服务费/坑位费、发票、结算和付款 |
| 仓储/履约 | 批准并执行寄样，核对库存、地址和物流回执 |

任何模型或数字同事都不能替代合同签署、付款和高风险平台写操作的责任主体。

## 4. 任务输入与计划冻结

每轮任务先建立 `CreatorRecruitmentPlan`，至少冻结：

| 输入域 | 必填内容 |
|---|---|
| 商品事实 | 商品/SKU、价格、库存、毛利区间、主要卖点、禁用表述、样品成本、履约范围 |
| 目标 | 新品试销、直播放量、短视频种草、清库存、长期达人池等 |
| 达人条件 | 平台、层级、粉丝范围、品类、受众、历史 GMV/订单、开播活跃、风险条件；缺失字段必须显示 unavailable |
| 商务条件 | 佣金区间、坑位费上限、样品政策、优惠、结算周期、预算和可谈边界 |
| 活动条件 | 期望开播/发布窗口、库存预留、素材交付时间、平台规则 |
| 邀约策略 | 日容量、批大小、渠道、发送窗口、个性化字段、跟进次数、冷却期 |
| 安全护栏 | 投诉/拉黑/拒绝阈值、重复率、退订、平台限流、品牌与合规规则 |
| 效果窗口 | 首次回复、签约、首次发布、订单归因和长期复购的观察窗口 |

计划任何关键字段变化都产生新 revision；旧批准不能覆盖新商品、新佣金、新渠道或新日容量。

## 5. 端到端任务 DAG

```text
R01 读取商品、库存、毛利、目标和平台 capability
 → R02 拉取/导入候选并保存来源证据
 → R03 平台内去重、证据化跨平台关联、拒绝/退订抑制
 → R04 商品—达人—受众资格过滤
 → R05 匹配、成本、活跃、履约与风险评分
 → R06 生成短名单 revision
 → R07 人工批准当日邀约批次
 → R08 内容官生成个性化邀约草稿并质检
 → R09 发送前重新检查频控、权限、商品和商务条件
 → R10 人工/受控 Connector 分批发送并记录回执
 → R11 回复分类、跟进和商务谈判
 → R12 条款审批、主体核验与签约
 → R13 寄样、选品、挂品、素材、档期和内容准备
 → R14 直播/短视频带货与异常支持
 → R15 数据回读、归因、财务核验与效果复盘
 → R16 关系分层、复邀、培育、暂停或退出
```

依赖规则：

- R07 未批准，R10 不可达。
- R09 检查失败，已批准的批次也必须暂停，不能用旧批准强行发送。
- R12 未完成，不能把达人显示为“已签约”。平台接受合作与正式合同签署需分别记录。
- R13 的寄样、挂品和档期各有独立回执；任一完成不能推断其他动作完成。
- R15 数据窗口未闭合时只能输出 `PRELIMINARY`，不得直接晋升长期核心达人。

## 6. 候选与邀约漏斗

### 6.1 漏斗口径

```text
候选总量
 → 唯一候选
 → 合格候选
 → 批准邀约
 → 已发送
 → 有效送达
 → 有回复
 → 有意向
 → 接活/进入谈判
 → 条款达成
 → 已签约
 → 已挂品/已排期
 → 已发布/已开播
 → 产生有效订单
 → 复邀合作
```

每层必须分别计数。以下概念不得混用：

- “发送 100 个”不等于“有效送达 100 个”。
- “达人回复”不等于“达人接活”。
- “口头同意/平台接受”不等于“合同已签署”。
- “已签约”不等于“已开播”。
- “产生 GMV”不等于“合作盈利”。

### 6.2 首期容量模型

| 参数 | 首期建议 | 说明 |
|---|---|---|
| 每日唯一邀约上限 | 100/店铺/任务，InstanceOverlay 可下调 | 受平台限流、人工容量和账号健康度约束，不保证能发满 |
| 单批数量 | 10～20 | 小批观察文案、送达、投诉和回复，再决定是否继续 |
| 接活规划基线 | 2～3/100 个有效邀约 | 用于人力和库存容量估算，不作为模型承诺 |
| 跟进次数 | 默认不超过 2 次 | 间隔和有效期由平台规则、客户策略配置 |
| 明确拒绝 | 立即停止本轮跟进 | 进入冷却或永久抑制，禁止换账号继续骚扰 |
| 退订/不再联系 | 永久抑制，除非对方主动重新同意 | 优先级高于任何增长计划 |

每天 100 个邀约必须拆成小批次运行：首批结果出现高退订、高投诉、平台警告、回复质量异常或运营承接超载时，后续批次自动进入 `PAUSED`，等待人工决定。

### 6.3 每日运行节奏

| 时段 | 动作 | Owner | 产物 |
|---|---|---|---|
| 数据就绪后 | 更新候选、历史接触、商品/库存/佣金和 capability | 数据参谋 | `CreatorRecruitmentReadiness` |
| 发送前 | 生成当天 100 人以内短名单和分批计划 | 数据参谋 | `CreatorOutreachBatchRevision` |
| 批准前 | 检查商品匹配、商务条件、文案事实、重复和频控 | 导购、活动、内容、私域 | 审批包 |
| 发送窗口 | 分批人工/受控发送，逐条写回回执 | 达人运营 | `CreatorOutreachAttempt[]` |
| 当日持续 | 回复分类、FAQ、谈判、人工升级 | 内容、活动、客服 | 回复/谈判任务 |
| 日终 | 更新漏斗、阻断原因和次日建议 | 数据参谋 | `CreatorRecruitmentDailyReview` |
| 周期结束 | 签约、带货、成本和效果复盘 | 数据参谋 + 活动 | `CreatorPerformanceReview` |

## 7. 邀约生成与个性化

### 7.1 每条邀约必须使用的事实

- 达人称呼和平台身份；无法确认真实姓名时只用平台昵称。
- 为什么匹配：达人历史品类/内容特征与商品受众的具体交集。
- 商品是什么：经核验的核心卖点、价格带、库存与履约范围。
- 合作方式：直播、短视频、橱窗、专场或其他真实可提供方式。
- 商务范围：佣金/服务费/样品只表达已经批准且允许公开的范围。
- 明确 CTA：是否愿意了解、查看样品/资料或进入商务沟通。
- 品牌和联系人身份、退订/不再联系入口，以及平台要求的信息。

禁止使用：虚假“专属邀请”、不存在的历史销量、保证收益、虚假稀缺、未经允许引用其他达人姓名、敏感画像推断和无法兑现的寄样/佣金承诺。

### 7.2 个性化层级

| 层级 | 使用场景 | 生成要求 |
|---|---|---|
| L0 通用模板 | 事实不足，只允许人工补充后发送 | 不得伪装已研究达人 |
| L1 品类匹配 | 已知达人主要品类 | 写明商品与品类的匹配原因 |
| L2 内容匹配 | 有合法的公开/授权内容证据 | 引用具体内容主题，不复制或过度推断 |
| L3 合作匹配 | 有历史合作与绩效 evidence | 结合上次结果提出下一次合作假设 |

模板版本、模型版本、事实 revision、人工修改和最终发送文本必须留痕；不保存模型思维链。

## 8. 回复、谈判和签约

### 8.1 回复分类

| 分类 | 下一步 |
|---|---|
| 无回复 | 按批准的跟进策略等待；超过次数进入 `NO_RESPONSE` |
| 明确拒绝 | 记录标准原因，停止跟进并进入冷却/抑制 |
| 愿意了解 | 发送已批准的商品/合作资料包，创建商务任务 |
| 询问佣金/费用 | 活动策划师基于毛利、预算和权限给出建议，超边界转人工 |
| 索要样品 | 核验资格、库存、地址用途和寄样批准后创建寄样任务 |
| 要求特殊承诺 | 事实/法务/预算检查；不可兑现时明确拒绝 |
| 投诉/不再联系 | 立即停止、记录抑制、检查是否存在批量策略问题 |
| 身份或安全异常 | 暂停合作，人工核验主体与风险 |

自动回复分类只能产生建议；低置信度、价格谈判、法律条款、负面情绪和异常身份必须转人工。

### 8.2 商务条款 revision

`CreatorCommercialOfferRevision` 至少包含：

- 合作主体与平台 identity refs。
- 商品/SKU、合作方式、内容/直播交付数量和质量标准。
- 佣金比例、服务费/坑位费、样品政策、优惠和预算上限。
- 档期、素材、挂品、发布、保留时长和数据回传要求。
- 知识产权、品牌表述、平台规则、保密与数据用途。
- 结算条件、发票、退款/退货影响、争议与退出条款。
- 双方负责人、审批人、版本 hash、有效期和 evidence refs。

达人提出任何超出批准边界的修改都必须生成新 revision 并重新审批，旧版本不得静默覆盖。

### 8.3 签约状态

```text
NOT_STARTED
 → IDENTITY_CHECK
 → TERMS_NEGOTIATING
 → TERMS_AGREED
 → CONTRACT_DRAFTED
 → INTERNAL_APPROVED
 → SENT_FOR_SIGNATURE
 → PARTIALLY_SIGNED
 → SIGNED
 → EFFECTIVE
 → EXPIRED | TERMINATED | DISPUTED
```

平台内“接受邀请”与正式合同 `SIGNED` 是两个独立事件。只有签署系统/人工上传的可验证回执才能进入 `SIGNED`；聊天中的“可以”只能进入 `TERMS_AGREED` 或待核验状态。

## 9. 接活后的履约协作

签约后为每个达人建立 `CreatorCollaborationCase`，包含以下并行工作包：

| 工作包 | 主责数字同事 | 必要检查 | 完成证据 |
|---|---|---|---|
| 选品与组合 | 导购顾问 | 受众匹配、库存、价格、规格、替代品 | 批准的选品 revision |
| 佣金与活动 | 活动策划师 | 毛利、预算、档期、优惠、停止条件 | 平台/人工配置回执 |
| 寄样 | 客服专员 + 人工履约 | 资格、地址用途、库存、物流、签收 | 寄样批准、物流与签收回执 |
| 挂品 | 活动策划师 + 平台运营 | 商品、佣金、计划、有效期 | 平台挂品/计划回执 |
| 内容素材 | 内容官 | 真实卖点、品牌/平台合规、版权 | 达人内容 brief 与素材包 revision |
| 直播/发布排期 | 活动策划师 | 档期、库存、客服和履约容量 | 达人确认与平台排期 evidence |
| 达人问题支持 | 客服专员 | FAQ、商品使用、物流和异常 SLA | `CreatorServiceCase` 时间线 |

任一工作包阻塞时不得把整个合作显示为“准备完成”；工作台必须展示具体责任人、截止时间和阻断原因。

## 10. 带货效果与归因

### 10.1 核心效果事实

| 维度 | 指标 |
|---|---|
| 触达漏斗 | 发送、送达、回复、意向、接活、条款达成、签约率及各阶段耗时 |
| 履约漏斗 | 寄样签收、挂品、排期、发布/开播、首单时间、按期交付率 |
| 交易 | 曝光、观看、点击、商品访问、订单、GMV、支付转化、客单价 |
| 成本 | 佣金、坑位费、样品、优惠、物流、内容支持和人工运营成本 |
| 质量 | 退款/退货、投诉、低质流量、异常订单、内容违规和履约异常 |
| 效率 | ROI、毛利贡献、单个签约达人成本、单个有效达人获取成本 |
| 长期 | 二次合作率、90/180 天活跃、复邀响应、累计贡献和关系健康度 |

### 10.2 评价原则

- 每个指标保存平台、定义、统计窗口、数据截止时间、revision 和来源。
- 平台未提供的字段显示 `unavailable`，不能用 0 填充。
- 同时报告绝对量和相对效率，避免只偏爱粉丝量大或单次 GMV 高的达人。
- 退款窗口未闭合、佣金未结算或订单归因不完整时，只能给 `PRELIMINARY` 结论。
- 达人贡献必须扣除或单列佣金、样品、坑位费、优惠和退款影响。

### 10.3 达人绩效分层

| 层级 | 建议定义 | 后续动作 |
|---|---|---|
| 试合作 | 已签约但效果窗口未闭合 | 控制预算，完成首轮验证 |
| 成长 | 内容/履约稳定且有潜力 | 优化选品、素材和档期，逐步扩大 |
| 核心 | 多周期稳定贡献、合规且关系健康 | 优先新品、长期计划和更深合作 |
| 观察 | 数据不足、效果波动或履约不稳 | 降低频率，设置改善条件 |
| 风险 | 投诉、违规、异常流量、合同/履约问题 | 暂停并人工调查 |
| 退出 | 明确拒绝、长期无效、重大违规或合同终止 | 停止合作并保留最小审计记录 |

分层由可解释规则和人工复核共同完成，不能只靠模型主观标签。

## 11. 长期关系维护

私域管家接收经过批准的最小 Handoff，不持有完整合同、支付和无关订单信息。长期关系计划包括：

- 合作结束后的感谢、结果回顾和问题收集。
- 按达人层级、擅长品类、档期和历史表现制定复邀窗口。
- 新品、节日、大促和补货机会的定向合作草稿。
- 对成长达人提供更适合的选品、内容支持和合作机制建议。
- 对沉默达人执行有限次数的唤醒；无回复或拒绝后进入冷却。
- 对核心达人持续观察履约、合规、内容质量和平台风险，防止只看 GMV。
- 明确记录不再联系、退订、关系终止和数据删除请求。

关系状态建议：

```text
NEW → CONTACTED → ENGAGED → NEGOTIATING → PARTNERED
    → TRIAL → ACTIVE → CORE
    → DORMANT → REACTIVATION
    → PAUSED | SUPPRESSED | TERMINATED
```

关系维护的成功指标是复邀响应、重复合作、稳定履约和长期净贡献，不是消息发送次数。

## 12. 核心 Artifact 与状态真源

| Artifact | 用途 | 关键不变量 |
|---|---|---|
| `CreatorRecruitmentPlan` | 本轮目标、商品、容量和护栏 | 批准精确 revision |
| `CreatorCandidateSnapshot` | 候选事实、来源、时间和 marking | 不可用昵称猜测跨平台身份 |
| `CreatorProductMatchCard` | 商品—达人—受众匹配和风险 | 缺失字段显式 unavailable |
| `CreatorShortlistRevision` | 不可变短名单及排序理由 | 人工批准后才能生成发送批次 |
| `CreatorOutreachBatchRevision` | 每日分批、渠道、频控和停止条件 | 批次 hash 变化需重批 |
| `CreatorOutreachDraft` | 个性化邀约草稿 | 草稿不等于已发送 |
| `CreatorOutreachAttempt` | 每一次发送/人工执行事实 | 唯一幂等键、渠道回执 |
| `CreatorResponseEvent` | 回复、拒绝、退订、意向和时间 | 自由文本最小化，分类可复核 |
| `CreatorCommercialOfferRevision` | 商务谈判条款 | 任何变更产生新 revision |
| `CreatorContractRef` | 合同版本与签署回执引用 | 不把聊天同意当签署 |
| `CreatorCollaborationCase` | 寄样、挂品、排期、内容和异常 | 子任务状态独立回读 |
| `CreatorPerformanceReview` | 交易、成本、质量和结论 | 窗口未闭合只能 preliminary |
| `CreatorRelationshipPlan` | 复邀、维护、冷却和抑制 | 退订/拒绝优先 |

平台后台、Connector、人工登记和合同系统是事实来源；前端本地状态和模型文本不是状态真源。

## 13. Handoff 最小披露

| 从 → 到 | 允许传递 | 禁止传递 |
|---|---|---|
| 数据参谋 → 导购 | 商品/达人事实 refs、匹配任务、缺失字段 | 联系方式、完整聊天、合同 |
| 导购 → 内容官 | 匹配原因、选品、真实卖点和禁用表述 | 达人无关个人信息 |
| 数据参谋 → 活动策划师 | 候选层级、商品、预算和效果目标 | 未脱敏身份/聊天原文 |
| 内容官 → 达人运营 | 已批准邀约 revision、平台 identity token | 平台 secret、内部评分细节 |
| 达人运营 → 活动策划师 | 结构化意向、报价、档期和问题摘要 | 无关聊天和私密信息 |
| 签约/运营 → 客服 | 合作 ref、寄样 token、商品、SLA | 完整合同、收款信息 |
| 全员 → 数据参谋 | Artifact/Outcome refs、阶段、指标、失败原因 | 不必要的 PII 和自由文本 |
| 数据参谋 → 私域管家 | 关系阶段、同意、频控、复邀窗口、绩效摘要 | 合同全文、付款、无关订单 |

服务端必须按接收者、purpose 和 marking 重新授权，不能因前一位同事有权限就自动透传。

## 14. 工作台设计

### 14.1 达人招募驾驶舱

- 今日候选、唯一候选、合格、待批准、分批发送、送达、回复、接活和签约。
- 100 人日容量进度、平台限流、批次暂停、投诉/拒绝和运营承接容量。
- 按平台、商品、达人层级、候选来源、负责人和任务状态筛选。
- 每个达人展示来源、匹配理由、历史接触、频控、当前 owner 和下一动作。

### 14.2 商务与签约看板

- 意向、谈判、条款待批、合同待签、部分签署、生效、过期、争议。
- 佣金、费用、样品、商品、档期等关键字段的 revision 对比。
- 明确显示“平台接受”“条款达成”“合同签署”三种不同状态。

### 14.3 履约与效果看板

- 寄样、挂品、素材、档期、发布/开播和异常任务。
- GMV、订单、佣金、退款、样品和 ROI，均显示数据窗口与新鲜度。
- 试合作、成长、核心、观察、风险和退出分层，以及人工复核入口。

### 14.4 长期关系看板

- 活跃、核心、沉默、待复邀、冷却、抑制和终止。
- 下一联系日期、联系目的、频控、同意和上次合作结论。
- 任何退订/不再联系状态必须醒目标识并阻断触达。

## 15. 风险、审批和停止条件

| 风险 | 默认控制 |
|---|---|
| 重复骚扰 | 平台 identity 去重、历史 attempt 检查、拒绝/退订抑制 |
| 100 人批量触达 | 小批执行、批次批准、平台限流、双人/指定角色审批 |
| 文案虚假承诺 | 商品事实 revision、claim guard、人工审稿 |
| 商务越权 | 佣金/费用/样品边界、超限新 revision、经营/法务/财务审批 |
| 合同误判 | 签署回执才可进入 SIGNED，聊天同意不能代替 |
| 地址和付款敏感数据 | 专用系统 token 化引用，最小显示，禁止进入模型上下文 |
| 寄样损失 | 资格、库存、预算和地址用途审批，物流回执 |
| 虚假/异常流量 | 订单质量、退款、异常模式和人工调查 |
| 运营超载 | 签约、寄样、内容和客服容量门；后端承接不足时停止新邀约 |
| 平台风控 | capability snapshot、频控、错误率、警告和账号健康度实时门禁 |

立即暂停后续批次的建议条件：平台警告/封禁风险、投诉或退订异常上升、重复邀约出现、商品/佣金 revision 失效、库存/履约不足、未处理回复超出 SLA、签约/寄样队列超过团队容量、数据源不可用或权限撤回。

## 16. 与 G0～G6 的实施映射

| 波次 | 本任务的交付边界 |
|---|---|
| G0 | 增加达人任务 payload、Artifact refs、状态枚举、审批、marking 和禁止动作；不执行 |
| G1 | 数据参谋完成候选、去重、评分、每日批次、漏斗和只读/草稿复盘 |
| G2 | 内容官生成邀约/素材草稿；导购完成商品匹配；客服生成履约支持草稿 |
| G3 | 活动策划师管理商务/活动 revision；私域管家管理关系、频控、复邀和抑制 |
| G4 | 仅把经多周期验证的匹配、文案、商务和运营经验提升为受治理记忆候选 |
| G5 | 微信小店、抖音、快手 Connector 提供各自已核验的候选、合作、订单和效果事实 |
| G6 | 逐项开放批准后的邀约、合作商品/佣金等受控 Action；签约、付款和高风险动作仍由专用系统和人工完成 |

当前 M5 完成前不得提前编码 G0～G6。本方案只冻结业务任务、协作和安全边界，不改变现有 AOS 内核及 M3 当前开发顺序。

## 17. 分阶段开发拆分建议

### CR0：任务与状态契约

- 冻结本方案的 Plan、Artifact、状态、Handoff、marking、批准和幂等规则。
- 明确“回复、接活、条款达成、签约、开播、有效订单”的不同口径。
- 使用 fixture 完成状态机、双租户、拒绝/退订和重复邀约负向验证。

### CR1：只读候选与草稿闭环

- 人工/CSV/已核验 Connector 导入种子达人。
- 数据参谋完成去重、匹配、评分、短名单和 100 人以内分批计划。
- 内容官、导购、活动分别生成邀约、选品和商务草稿；人工执行后登记回执。

### CR2：回复、商务与签约协同

- 结构化回复分类、谈判任务、条款 revision、合同引用和审批包。
- 客服承接寄样/商品问题，活动策划师承接档期/佣金，法务和财务保留决定权。
- 仍不开放自动发送、自动签约和自动付款。

### CR3：履约、效果与长期关系

- 串联寄样、挂品、内容、排期、开播/发布和异常时间线。
- 数据参谋完成成本、订单、退款和 ROI 复盘。
- 私域管家完成关系分层、复邀、冷却、退订与长期维护。

### CR4：受控平台 Action

- 仅对 G5 已 `LIVE_VERIFIED` 且通过 G6 安全评审的单项能力开放。
- 每个平台、每个动作独立 feature flag、日限额、批次审批、回执和 kill switch。
- 先单租户小批灰度，再逐步扩大；不能直接开放 100 人自动群发。

## 18. 验收标准

1. 100 人候选中存在重复、历史拒绝、退订和字段缺失时，系统能正确排除或降级，且给出原因。
2. 未批准批次、商品/商务 revision 过期、平台权限缺失或频控命中时，发送路径不可达。
3. 每条最终邀约都能追溯到达人事实、商品事实、模板版本、人工修改和执行回执。
4. 2～3 个接活达人可以分别进入谈判、签约、寄样、挂品和排期，未接活者不会被伪造为成功。
5. 平台接受、条款达成、合同签署、开播和产生订单能被明确区分并独立回读。
6. 带货效果同时展示 GMV、订单、佣金、费用、样品、退款和 ROI；窗口未闭合时明确 preliminary。
7. 达人可进入试合作、成长、核心、观察、风险或退出，并生成有频控的长期关系计划。
8. 明确拒绝或不再联系后，后续邀约和复邀均被服务端阻断。
9. 双租户同达人 ID、并发回复、重复回调、回调乱序和撤权测试通过。
10. 不具备官方写能力的平台只显示“人工执行/待登记”，不会伪装自动发送成功。

## 19. 下一步建议

1. 由产品、达人运营、法务、财务和仓储共同评审本方案，重点确认“接活、签约、有效达人”的业务口径。
2. 用一个真实商品填写 `CreatorRecruitmentPlan`，选择 20 个脱敏/测试候选做 CR1 桌面推演，不立即上 100 人发送。

4. 完成微信小店 WX0 账号实测，并分别核验抖音、快手的达人发现、邀请、合作和效果回读 capability。
5. 在 M5 和对应 G 波次门禁允许后，再形成编码实施方案；本文件本身不授权修改生产代码或执行达人触达。
