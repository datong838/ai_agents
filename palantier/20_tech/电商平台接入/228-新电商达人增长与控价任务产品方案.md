# 228-新电商达人增长与控价任务产品方案

> 状态：**客户需求基线 v1.0 · 2026-08-03 · 待产品评审**
> 来源：2026-08-03 客户沟通纪要
> 适用平台：微信小店、抖音电商、快手电商；价格监测可扩展至拼多多、淘宝、京东等公开渠道
> 架构约束：复用现有 GrowthPlan、AgentTask、TaskGraph、Handoff、Evidence、Review 与六数字同事，不新增平行任务系统

## 0. 使用的 Rules

1. 先把客户语言转成可验收任务、产物和安全边界，再进入平台 API 与编码设计。
2. “找达人”和“控价”是跨平台任务模板，不写死到单个平台或 AOS 内核。
3. 客服继续使用既有客服专员 S01～S06，不在本方案重复设计。
4. 平台 API、字段、权限和限流以实施时官方文档与实测 capability snapshot 为准；会议口述不视为已获权限。
5. 联系方式、粉丝画像、邀约、佣金、举报和价格处置均按最小数据、人工批准、审计和平台规则失败关闭。
6. 禁止把虚假下单、恶意退款、骚扰达人、绕过平台限制、爬取非公开个人信息写成产品能力。

## 1. 客户结论

本次沟通形成两个优先级最高的新电商经营任务：

1. **达人增长任务**：持续发现、筛选、评估和协作微信小店、抖音、快手的带货达人，重点覆盖低成本、高匹配、可规模化合作的 KOC/腰部达人。
2. **价格治理任务**：持续发现跨平台低价、乱价和疑似窜货，形成证据、分级、通知与复核闭环。

二者都不是单个功能按钮，而是由数据参谋驱动、多智能体协作、产出 Artifact、需要批准门的长期任务。

会议中的“10 万粉以上”和“1～3 万粉 KOC”并不冲突，应建成可配置的达人分层，而不是写死阈值。首期默认以 KOC/腰部达人为主，高粉达人作为独立预算层。

## 2. 产品定位

```text
经营目标 / 商品计划
        ↓
数据参谋创建任务与筛选策略
        ↓
平台 Connector 获取授权数据 / 人工导入
        ↓
候选发现、去重、评分、风险检查
        ↓
人工批准合作批次或价格处置批次
        ↓
活动策划师 / 内容官协作生成方案与素材
        ↓
受控邀约或处置 Action
        ↓
结果、订单、佣金、价格恢复与 EffectReview
```

任务列表是入口，聊天是辅助；每次执行必须留下候选、证据、决策、动作和结果。

## 3. 任务一：达人增长

### 3.1 任务目标

将当前人工每天约 10～20 个、重复搜索且难追踪的流程，升级为持续、去重、可审计的候选漏斗。目标不是简单堆积联系方式，而是提高“合格候选 → 有效邀约 → 接受合作 → 挂品/开播 → 订单/GMV”的转化效率。

### 3.2 可配置筛选条件

| 维度 | 示例 | 规则 |
|---|---|---|
| 平台 | 微信小店、抖音、快手 | 必填，可多选 |
| 达人层级 | KOC、腰部、头部 | 不以单一粉丝阈值代替 |
| 粉丝数 | 1～3 万、10 万以上 | 区间配置，会议参数只是客户初始偏好 |
| 粉丝画像 | 50 岁以上占比 | 仅在平台授权且满足隐私/聚合阈值时使用 |
| 活跃度 | 近 30 天开播率、开播场次 | 需记录统计窗口和数据新鲜度 |
| 带货能力 | GMV、订单、转化、客单价 | 不同平台口径分别映射 |
| 品类匹配 | 商品类目、历史带货类目 | 评分需可解释 |
| 成本 | 佣金、坑位费、样品成本 | 与预算和毛利护栏联动 |
| 风险 | 违规、退货率、争议、异常流量 | 只用授权或公开可信证据 |

### 3.3 任务 DAG

```text
T1 定义商品、目标、平台、预算和人群
 → T2 拉取/导入候选
 → T3 跨平台身份归一与去重
 → T4 资格过滤和数据质量检查
 → T5 匹配度、成本、风险评分
 → T6 生成候选短名单与原因
 → T7 人工批准邀约批次
 → T8 生成个性化邀约草稿
 → T9 受控发送/人工发送并记录回执
 → T10 合作、寄样、挂品、佣金与档期跟踪
 → T11 订单/GMV/佣金归因与复盘
```

首期允许 T2～T8 只读/草稿运行；T9 及佣金、挂品等写操作必须等 G6 和具体平台授权。

### 3.4 多智能体协作

| 角色 | 责任 |
|---|---|
| 数据参谋 | 任务 owner；数据质量、候选发现、去重、评分、漏斗与复盘 |
| 活动策划师 | 合作批次、佣金方案、直播档期、预算与停止条件 |
| 内容官 | 商品卖点、达人匹配解释、邀约和直播内容 brief 草稿 |
| 导购顾问 | 商品/受众适配与转化假设 |
| 客服专员 | 仅处理既有咨询/售后协同，不承担达人外联主责 |
| 人工运营 | 批准候选批次、佣金、联系方式使用和平台写操作 |

不新增“达人智能体”；新增的是领域任务类型和 Artifact。

### 3.5 核心 Artifact

- `CreatorDiscoveryBrief`：商品、目标、筛选条件、预算、平台和数据窗口。
- `CreatorCandidateSnapshot`：候选事实快照、来源、时间、marking 和去重键。
- `CreatorScorecard`：匹配、成本、活跃、带货、风险及可解释原因。
- `CreatorShortlistRevision`：不可变短名单版本与批准状态。
- `CreatorOutreachDraft`：邀约草稿、渠道、频控和所需批准。
- `CreatorCollaborationCase`：邀请、回复、合作、寄样、挂品、佣金和档期状态。
- `CreatorPerformanceReview`：GMV、订单、佣金、退款、ROI 和复用建议。

联系方式不是任务成功标准。若平台不提供联系方式，只保存平台内可授权联系标识；电话、微信号属于高敏感字段，必须有合法来源、用途和保留期。

### 3.6 核心指标

- 每日新增唯一候选数、重复率、数据完整率。
- 合格率、短名单批准率、邀约送达/回复/接受率。
- 合作到挂品率、挂品到开播率、开播到首单时间。
- 达人 GMV、订单、转化、佣金、退款、ROI。
- KOC/腰部/头部分层成本和边际收益。
- 人工耗时、单个有效合作成本和自动化失败率。

不把“每天找到 100～200 人”作为唯一 KPI；数量必须同时受质量、频控、投诉和平台风控约束。

## 4. 任务二：价格治理

### 4.1 任务目标

持续监测授权商品、品牌词、SKU/型号在各平台的展示价与实际可得价，识别低于品牌策略或授权边界的疑似异常，生成可复核证据并跟踪恢复结果。

“控价”在系统内使用更准确的名称 **价格治理**，避免把合法市场竞争、促销补贴与未经核实的违规行为混为一谈。

### 4.2 价格口径

- 标价、券后价、满减后价、会员价、直播间价、百亿补贴/平台补贴价分开记录。
- 每条观察包含商品标识、店铺、平台、地区、时间、活动、价格组成、页面链接和证据 hash。
- 阈值由客户 InstanceOverlay 配置，例如 MAP/建议零售价/渠道协议价；AOS 不内置某品牌价格。
- 同款匹配需要 SKU、规格、包装、赠品和运费校验，禁止仅凭标题相似直接判定。

### 4.3 任务 DAG

```text
P1 定义品牌词、SKU、授权店铺、价格口径和阈值
 → P2 多平台观察与截图/响应取证
 → P3 商品同一性匹配和价格归一
 → P4 异常检测、平台补贴识别和风险分级
 → P5 人工复核
 → P6 生成通知/申诉/平台举报草稿
 → P7 人工批准并通过合规渠道处置
 → P8 定时复查价格是否恢复
 → P9 关闭、升级或转法务，并生成复盘
```

### 4.4 多智能体协作

- 数据参谋：监测 owner、同款归一、异常检测、证据完整性和趋势看板。
- 活动策划师：识别平台活动、优惠叠加和价格策略冲突。
- 客服专员：只生成合规沟通草稿，不自动威胁或高频骚扰商家。
- 人工品牌运营/法务：确认授权关系、批准通知/申诉/举报和升级策略。

### 4.5 核心 Artifact

- `PriceGovernancePolicyRevision`
- `PriceObservationEvidence`
- `ProductIdentityMatch`
- `PriceViolationCandidate`
- `PriceEnforcementDraft`
- `PriceRestorationCheck`
- `PriceGovernanceReview`

### 4.6 安全边界

- 允许：官方 API、授权数据、合法公开页面观察、人工上传截图、合规通知/申诉/举报草稿。
- 需要批准：对外通知、平台申诉/举报、法务升级、任何账号写操作。
- 禁止：虚假购买、恶意退款、刷单、骚扰、绕验证码、规避限流、未经授权抓取个人信息、自动认定违法。

会议提到的“购买后立即退货迫使下架”不进入产品能力，也不作为建议策略。

## 5. 平台优先级与能力差异

| 平台 | 达人增长 | 价格治理 | 首期策略 |
|---|---|---|---|
| 微信小店 | P0，围绕优选联盟/合作管理 | P1，店内与公开渠道观察 | 新建 `platform.ecommerce.wechat-shop`；先完成 capability probe |
| 抖音电商 | P0，复用精选联盟 Creator/Commission 模型 | P1 | 补齐发现、邀约、合作漏斗，不重做佣金模型 |
| 快手电商 | P0，达人撮合/磁力聚星/小店场景 | P1 | 核验当前开放能力；旧批量任务接口不可直接假定可用 |
| 拼多多 | P2 | P0，重点低价观察 | 先只读取证和人工处置，不做对抗性动作 |
| 淘宝/京东 | P2 | P1 | 复用平台 Connector 与统一价格口径 |

平台 capability snapshot 必须区分：`official_api`、`partner_api`、`manual_import`、`approved_browser_assist`、`unavailable`。没有官方权限时不得以 UI 自动化伪装成 API 能力。

## 6. 数据参谋工作台

首页增加两个任务域，不按平台复制三套页面：

### 6.1 达人增长驾驶舱

- 跨平台候选漏斗与平台/层级筛选。
- 今日唯一候选、待复核、待批准、已邀约、已合作、已挂品、已开播。
- KOC/腰部/头部成本和绩效分层。
- 数据新鲜度、API 权限、限流、失败和人工接管状态。

### 6.2 价格治理驾驶舱

- SKU × 平台价格矩阵、异常趋势和区域/店铺分布。
- 待复核、待处置、复查中、已恢复、升级法务。
- 每个异常可回看价格构成、同款证据、截图 hash 和处理时间线。

### 6.3 大屏

大屏展示各平台订单、达人 GMV/佣金/ROI、达人漏斗和价格异常，但所有指标必须带口径、时间窗口、数据新鲜度和 unavailable 状态，不用假数据填 0。

## 7. 与现有 G0～G6 的映射

| 波次 | 新需求映射 |
|---|---|
| G0 | 增加两类 `EcommerceAgentTaskPayload`、Artifact 引用、风险与批准策略；仍不执行 |
| G1 | 数据参谋发现、监控、任务拆解、驾驶舱和只读/草稿闭环 |
| G2 | 内容官生成达人 brief/邀约草稿；客服沿用既有能力 |
| G3 | 活动策划师管理合作批次、预算、档期和跨平台分析 |
| G4 | 从真实合作/控价结果形成经验候选，不保存原始敏感联系方式为共享记忆 |
| G5 | 微信小店/抖音/快手 Connector capability 与只读数据接入 |
| G6 | 经 C0.2、平台权限和人工批准后开放邀约、佣金、挂品、举报等写操作 |

## 8. MVP 与分期

### P0：可信数据与人工协作

- 微信小店 capability probe、人工导入和平台内标识。
- 三平台候选统一、去重、评分、短名单与批准。
- 价格观察、同款复核、截图证据和人工处置清单。
- 任务/Artifact/看板真实回读，不自动外联、不自动举报。

### P1：受控平台协作

- 在官方 API/服务商权限支持的平台同步合作状态、佣金和效果。
- 邀约/通知草稿与人工一键确认。
- 定时复查和 EffectReview。

### P2：受控自动化

- 仅在 G6 与平台权限完成后，对低风险、可撤销动作开放批准后执行。
- 预算、频控、kill switch、回执、补偿和人工接管齐全。

## 9. 验收标准

1. 微信小店、抖音、快手候选进入统一任务和统一去重，不重复联系。
2. 同一达人跨平台身份不强行合并；有证据的 identity link 才合并。
3. 筛选条件可配置，支持 KOC/腰部/头部分层和统计窗口。
4. 每个短名单达人都有来源、时间、评分原因和风险；敏感联系方式受控。
5. 每个价格异常都有同款证据、价格构成、时间、截图/hash 和人工结论。
6. API 不可用、权限不足、数据过期时显示 unavailable，不伪造自动化成功。
7. 未批准时不能发送邀约、修改佣金/挂品、通知商家或提交举报。
8. 禁止动作在方案、UI、执行器和 Evals 四层均不可达。

## 10. 当前结论

“达人增长”和“价格治理”应上升为新电商解决方案的 P0 任务域；微信小店应新增为独立 PlatformAdapterPack。下一步先评审本产品基线和微信小店 capability probe，再回写 G0/G1/G3/G5 的编码实施检查表；当前不授权提前编码或执行平台动作。
