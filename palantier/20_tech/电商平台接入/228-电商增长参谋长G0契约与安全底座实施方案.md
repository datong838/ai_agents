## 0. 使用的 Rules

| Rule | G0 约束 |
|---|---|
| 先契约后执行 | G0 只建设可信契约、持久化、审批和安全门，不执行增长任务或生产 Action |
| 服务端真源 | PostgreSQL + 不可变 revision 是唯一真源；内存单例、localStorage 和页面状态不得参与批准判断 |
| 租户先行 | 所有主键、外键、查询、幂等和审计均包含 org/project |
| 批准绑定版本 | 人工批准只绑定精确 plan revision/hash；修改后必须重新批准 |
| 职责分离 | 方案创建人不能批准自己的方案；角色、marking 和审批策略由服务端强制 |
| 外部内容不可信 | 网络内容只作证据，必须引用、限量、过期、防提示词注入，不得携带执行指令 |
| 记忆不自动生效 | G0 只冻结 MemoryCandidate/MemoryItem 契约，不允许经验直接成为长期记忆 |
| C0.2 边界 | GrowthPlan 批准不是生产写回授权；Draft/Action/Automation 继续禁用 |
| 失败关闭 | 存储、权限、适配器、证据或版本异常时返回明确失败，不生成假记录或假成功 |

## 1. 目标、非目标与完成定义

### 1.1 目标

G0 为后续 G1～G6 建立唯一、可信、可持久化的公共底座：

1. 冻结 `IntelligenceEvidence`、`GrowthPlan`、`GrowthPlanRevision`、`GrowthApprovalEvent`、`AgentTask`、`TaskDependency`、`AgentHandoff`、`ExecutionArtifact`、`EffectReview`、`MemoryCandidate` 和 `MemoryItem` 契约。
2. 实现 GrowthPlan 的租户隔离持久化、不可变 revision、提交、批准、驳回、撤回和审计事件。
3. 实现内部/外部证据的不可变元数据、引用、时效、可信度和安全标记。
4. 实现任务 DAG 与 Handoff 的严格验证，但不执行任务。
5. 建立角色、职责分离、marking、持久幂等、CAS 和跨租户 404 门禁。
6. 清除会影响 G0 OpenAPI 确定性的重复 Draft 路由；旧审批能力不得静默接管新方案。
7. 建立外部研究 Tool 的安全 Protocol 和空注册表；没有批准适配器时可信失败。
8. 为 G1 工作台提供只读 GrowthPlan/任务/证据 API 和真实空态。

### 1.2 非目标

G0 不做：

- 不调用真实网络搜索、社交平台或 LLM；只冻结适配器和证据契约。
- 不自动生成晨报、增长方案或任务清单。
- 不运行任何 AgentTask、AIP Logic 或定时调度。
- 不发布内容、不触达客户、不改价、不发优惠、不操作商城。
- 不批准 Draft、不写 Ontology、不启用 Automation。
- 不实现 CustomerLite、六数字同事 37 条 Logic 或长期记忆检索。
- 不修改栖月汇线上 MariaDB。

### 1.3 G0 完成定义

只有同时满足以下条件，G0 才能标记完成：

1. 两个租户可以使用相同 plan/evidence/task/handoff ID 且互不可见。
2. GrowthPlan revision 不可变，批准绑定精确 revision/hash，修改后旧批准自动失效。
3. 无批准角色、创建人自批、跨租户、过期证据、DAG 环和越权字段均被服务端阻断。
4. API 重启后计划、证据、批准、任务和审计仍可回读。
5. 相同幂等键/相同请求返回相同结果；相同键/不同请求返回 409。
6. OpenAPI 无 Growth 路由碰撞且不再报告 Draft 重复 operationId。
7. 外部研究适配器为空时返回结构化不可用错误，不生成伪证据。
8. 所有生产写回正向尝试仍失败，响应明确 `production_written=false` 或无写路径。
9. 后端专项、API 全量、前端类型/测试/构建、浏览器负向主流程全部通过。

### 2.3 OpenAPI 实测

在 `m1@bc9711a` 生成 OpenAPI 的结果：

- `/v1/aip/drafts`、`/{draft_id}`、`/{draft_id}/reject` 存在重复 operationId 警告，来源为 PostgreSQL `routers/drafts.py` 与内存 `phase3_aip_drafts.py` 同时挂载。
- `/api/aip/long-memory` 暴露 GET/POST，但路由无 `require_principal`。
- `/v1/aip/logic/graphs` 和 `/{graph_id}/dry-run` 已存在可信入口。
- `growth-plan`、`agent-task`、`effect-review`、`memory-candidate` 当前均无路由。

因此，G0 不是对旧 Task/Memory/Draft“补几个字段”，而是建立新的 canonical 增长域，并关闭旧实现的静默路由优先级。

### 2.4 当前安全基线

[AIP 生产写回 C0.2 方案](../228-AIP生产写回C0租户与审批安全闭环方案.md) 尚未关闭退出门。G0 只能批准“经营方案”，不能批准任何生产对象修改。所有 AgentTask 的 `execution_status` 固定为 `not_enabled`，后续 G1 也只允许只读/草稿能力。

## 4. Canonical 数据契约

### 4.1 通用字段规范

所有持久对象必须包含：

- `org_id`、`project_id`：来自服务端 Principal，不接受 body 覆盖。
- 业务 ID：1～160 字符，受限字符集，禁止路径、控制字符和空白混淆。
- `created_by/updated_by`：来自 Principal subject。
- `created_at/updated_at`：服务端 UTC。
- `revision`：从 1 单调递增。
- `payload_hash`：对 canonical JSON 计算 SHA-256。
- `marking`：`public/internal/restricted/highly_restricted` 中的受控值。
- `schema_version`：首版固定 `1`，后续显式升级。

所有 Pydantic 模型：`extra="forbid"`、strict、字符串/列表/JSON 字节上限、递归深度上限；未知枚举和未知字段返回 422。

### 4.2 `IntelligenceEvidence`

分为两类：

1. `internal`：绑定 Dataset/OT/Metric 的精确 revision/hash、查询窗口和脱敏摘要。
2. `external`：绑定 HTTPS URL、domain、发布时间、获取时间、内容 hash、摘要、claim、可信度、过期时间和安全扫描结果。

关键字段：

```yaml
evidence_id: ev-...
kind: internal|external
title: ...
claim: ...
summary: ...
source_ref: ...
source_url: null
source_domain: null
published_at: null
retrieved_at: ...
expires_at: ...
confidence: 0.0-1.0
content_hash: sha256:...
prompt_injection_status: clean|suspected|blocked|not_checked
verification_status: unverified|system_verified|human_verified|revoked
marking: internal
```

G0 不保存网页全文；只保存必要摘要、claim、hash 和引用。原始抓取物如果未来需要保存，必须进入受控 Media/Blob 域并遵守版权、PII 与留存策略。

### 4.3 `GrowthPlan` 与 revision

`growth_plan` 保存当前指针和状态；`growth_plan_revision` 保存不可变业务快照。

快照至少包含：

- 业务问题、周期、基线、目标、护栏、假设。
- 内外 evidence refs。
- 任务草案、预算、风险、审批策略、效果窗口、停止条件。
- `payload_hash`、创建 actor 和时间。

状态全集：

```text
DRAFT → PENDING_APPROVAL → APPROVED → RUNNING → OBSERVING → REVIEWED → CLOSED
   └──────────────→ REJECTED / CANCELED
APPROVED/RUNNING/OBSERVING → PAUSED / CANCELED
```

G0 只启用 `DRAFT/PENDING_APPROVAL/APPROVED/REJECTED/CANCELED`；其余状态在 G1 开启。服务端拒绝 G0 未启用转换。

### 4.4 `GrowthApprovalEvent`

事件只追加，不更新/删除：

- `submitted`、`approved`、`rejected`、`canceled`。
- 精确绑定 `plan_id/revision/payload_hash`。
- actor、actor roles、comment、request hash、时间。
- 批准策略快照和职责分离判断结果。

批准后修改方案生成新 revision，并把 plan 当前状态重置为 DRAFT；旧 approval event 永久保留，但不能授权新 revision。

### 4.5 `AgentTask` 与依赖

G0 冻结并持久化任务，但禁止执行：

```yaml
task_id: task-...
plan_id: gp-...
plan_revision: 3
owner_agent: content_officer
collaborator_agents: [data_strategist]
title: ...
objective: ...
input_refs: []
allowed_tools: []
forbidden_actions: []
risk_level: low|medium|high|critical
approval_policy: ...
acceptance_criteria: []
effect_window: ...
status: PLANNED
execution_status: not_enabled
```

`owner_agent` 只允许六个 canonical ID：

- `data_strategist`
- `content_officer`
- `shopping_guide`
- `customer_service`
- `private_domain_keeper`
- `campaign_planner`

依赖表存 `upstream_task_id/downstream_task_id`；创建或替换任务集合时做全图拓扑校验，禁止环、自依赖、跨 plan/revision、跨租户和不存在引用。

### 4.6 `AgentHandoff`

G0 只允许创建 Handoff Draft 并验证：

- from/to agent 不同且均为 canonical ID。
- 来源任务、目标任务、plan revision 和租户一致。
- `purpose`、最小 `summary`、input refs、allowed/forbidden fields、有效期。
- 不允许内嵌手机号、地址、凭据、完整对话和无限 JSON。
- 目标任务未批准或已取消时不可激活。

G0 中 `status` 只能是 `draft/validated/rejected/expired`，不能 delivered。

### 4.7 `EffectReview`

G0 只冻结模型，不开放“自动判有效”接口。字段包括：

- plan/revision、baseline、target、actual、guardrails。
- 执行确认、观察窗口、归因方法、干扰因素、置信度。
- `EFFECTIVE/INEFFECTIVE/HARMFUL/INCONCLUSIVE/NOT_EXECUTED`。
- 继续/扩大/调整/停止建议和 evidence refs。

实际复盘引擎在 G1 实现。

### 4.8 `MemoryCandidate` / `MemoryItem`

G0 冻结：

- `MemoryCandidate` 必须引用 EffectReview、plan、task、条件、结果和证据。
- memory scope：agent-private/shared；layer：working/episodic/semantic/procedural。
- 置信度、适用范围、有效期、PII 扫描、冲突、Evals 和审批状态。
- `MemoryItem` 只能由 G4 的治理发布流程生成，G0 不提供 create API。

旧 `/api/aip/long-memory` 不得映射或迁移为新 MemoryItem；其任意 config 不具备可信来源。

## 5. PostgreSQL 模型

### 5.1 表清单

| 表 | 作用 | 可变性 |
|---|---|---|
| `growth_plan` | 当前 revision、状态和指针 | CAS 更新 |
| `growth_plan_revision` | 不可变方案快照 | insert-only |
| `growth_approval_event` | 提交/批准/驳回/取消 | append-only |
| `growth_intelligence_evidence` | 内外证据元数据 | insert-only；可追加 revoke event |
| `growth_evidence_event` | 验证、撤销和过期审计 | append-only |
| `growth_agent_task` | 指定 plan revision 的任务 | G0 仅 PLANNED/CANCELED |
| `growth_task_dependency` | DAG 边 | 与任务集合事务写入 |
| `growth_agent_handoff` | Handoff Draft/验证 | 状态机更新 |
| `growth_effect_review` | 复盘模型占位 | G1 前不可创建 final |
| `growth_memory_candidate` | 经验候选占位 | G4 前不可发布 |
| `growth_idempotency` | 持久幂等响应和 request hash | 受 TTL 清理 |
| `growth_audit_event` | 安全与业务审计 | append-only |

### 5.2 主键与外键

- 所有表主键以 `(org_id, project_id, business_id...)` 开头。
- revision 外键必须包含 `(org_id, project_id, plan_id, revision)`。
- task、dependency、handoff、review、memory candidate 的 plan 外键绑定精确 revision。
- 不使用只含全局业务 ID 的外键。
- 跨租户资源统一返回 404，不暴露是否存在。

### 5.3 不可变保护

`growth_plan_revision`、approval/evidence/audit event 使用数据库 trigger 拒绝 UPDATE/DELETE，沿用 publication 不可变实现模式。修正使用新 revision/event，不原地改历史。

### 5.4 并发与事务

- plan replace：`expected_revision` CAS，冲突 409。
- submit/approve/reject/cancel：锁定 current plan 或等价 CAS。
- approve 同事务写 approval event 和 plan status；并发只能一个成功。
- task 集合与 dependency 全图一次事务写入；任一边失败全部回滚。
- idempotency 行与业务结果同事务提交，避免已写业务但未写幂等记录。

### 5.5 downgrade

- upgrade/downgrade 必须在临时 schema 验证。
- 有数据时 downgrade 默认拒绝，除非明确导出/清理 G0 表；不能静默丢弃审计和批准证据。
- 迁移保持 Alembic 单 head，生成检查和生产启动模式测试通过。

## 6. API 契约

### 6.1 路径

```text
POST   /v1/aip/growth/plans
GET    /v1/aip/growth/plans
GET    /v1/aip/growth/plans/{plan_id}
PUT    /v1/aip/growth/plans/{plan_id}
GET    /v1/aip/growth/plans/{plan_id}/revisions
GET    /v1/aip/growth/plans/{plan_id}/revisions/{revision}
POST   /v1/aip/growth/plans/{plan_id}/submit
POST   /v1/aip/growth/plans/{plan_id}/approve
POST   /v1/aip/growth/plans/{plan_id}/reject
POST   /v1/aip/growth/plans/{plan_id}/cancel

POST   /v1/aip/growth/evidence
GET    /v1/aip/growth/evidence
GET    /v1/aip/growth/evidence/{evidence_id}
POST   /v1/aip/growth/evidence/{evidence_id}/verify
POST   /v1/aip/growth/evidence/{evidence_id}/revoke

GET    /v1/aip/growth/plans/{plan_id}/tasks
GET    /v1/aip/growth/tasks/{task_id}
GET    /v1/aip/growth/plans/{plan_id}/dag
POST   /v1/aip/growth/plans/{plan_id}/tasks/validate

POST   /v1/aip/growth/handoffs/validate
GET    /v1/aip/growth/preflight
```

G0 不开放 task execute、handoff deliver、effect review finalize、memory publish 和任何 production action 路径。

### 6.2 写请求公共字段

- `Idempotency-Key`：create/submit/approve/reject/cancel/verify/revoke 必填，1～160 字符。
- body 含 `expected_revision` 和需要时的 `expected_payload_hash`。
- org/project/actor 不接受 body；由 Principal 注入。
- comment 有长度上限并做日志脱敏。

### 6.3 响应与回读

- POST/PUT 成功后返回服务端 snapshot；前端必须 GET 回读 revision/hash/status 一致后显示成功。
- 所有响应包含 `production_written: false`（或 G0 统一顶层 capability 声明），避免批准方案被误解为执行动作。
- 列表使用稳定游标 `(updated_at, plan_id)`，有 limit 上限，不提供无限全量。
- 外部证据不返回网页全文、请求凭据或内部安全检测细节。

### 6.4 错误语义

| 状态 | code | 场景 |
|---:|---|---|
| 401 | `AUTH_REQUIRED` | 无合法 Principal |
| 403 | `GROWTH_ROLE_REQUIRED` | 无规划/审批/审计角色 |
| 403 | `GROWTH_SELF_APPROVAL_DENIED` | 创建人批准自己方案 |
| 404 | `GROWTH_PLAN_NOT_FOUND` | 不存在或跨租户 |
| 409 | `GROWTH_REVISION_CONFLICT` | expected revision/hash 过期 |
| 409 | `GROWTH_IDEMPOTENCY_CONFLICT` | 同键不同 request hash |
| 409 | `GROWTH_STATE_CONFLICT` | 非法状态迁移或并发终态 |
| 422 | `GROWTH_PLAN_INVALID` | 契约、目标、护栏、证据或任务错误 |
| 422 | `GROWTH_DAG_INVALID` | 环、自依赖或跨 revision |
| 422 | `GROWTH_EVIDENCE_UNSAFE` | 过期、blocked、引用无效或安全扫描未过 |
| 503 | `GROWTH_STORE_UNAVAILABLE` | 持久化不可用；不得降级内存 |
| 503 | `GROWTH_RESEARCH_ADAPTER_UNAVAILABLE` | 未注册受控研究适配器 |

错误不得回显网页原文、SQL、Token、PII、完整 prompt 或内部堆栈。

## 7. 角色、marking 与批准策略

### 7.1 角色

G0 增加增长域角色映射，不修改 token 自身：

| 角色 | 权限 |
|---|---|
| `growth_viewer` | 读取授权 marking 的方案、任务和证据 |
| `growth_planner` | 创建/修改/提交方案，创建证据草案 |
| `growth_approver` | 批准/驳回非本人方案 |
| `growth_auditor` | 读取不可变历史和安全事件，不执行 |
| `growth_evidence_verifier` | 验证/撤销外部证据 |
| `memory_curator` | G4 使用；G0 无发布权限 |

现有 `admin/developer` 在 dev 环境的映射需显式配置；生产 OIDC 不默认把 `developer` 当批准者。

### 7.2 职责分离

- `created_by == approver.subject` 固定拒绝。
- 提交者可以是创建者，但不能批准。
- high/critical 方案预留双批准策略；G0 首版 high/critical 直接不允许批准，等待 G1/G6。
- 审批时冻结 actor roles/markings 快照，后续角色变化不改历史。

### 7.3 marking

- evidence、plan、task、handoff 的 marking 取自身与所有输入引用的最高敏感级别。
- Principal 缺少相应 marking 时统一 404 或按资源读取策略 403，不返回部分敏感字段拼装结果。
- Handoff 不得降级 marking。

## 8. 外部研究安全底座

### 8.1 Protocol

新增 `ResearchAdapterRegistry` 或在 canonical RuntimeAdapter 安全语义上建立专用 Protocol，注册项必须声明：

- adapter name/version。
- `read_only=true`、`dry_run_safe=true`。
- 允许的 source types 和 domain policy。
- 超时、并发、最大结果数、最大字节数。
- 是否返回来源 URL、published/retrieved time 和 content hash。
- prompt-injection scanning 能力版本。

生产默认空注册表。G0 的 preflight 必须显示 `external_research=blocked`，而不是提供演示搜索结果。

### 8.2 URL 与网络安全

未来适配器必须：

- 只接受 `https`（明确允许的官方本地开发例外除外）。
- 禁止回环、RFC1918、链路本地、云元数据和 DNS rebinding。
- 限制重定向次数，重定向后重新校验目标。
- 不携带用户凭据访问任意 URL。
- 不执行网页脚本、下载可执行文件或自动提交表单。

### 8.3 内容安全

- 外部正文与系统/开发者/用户指令分区，永不解释为高优先级指令。
- 检测“忽略此前规则、泄露密钥、调用工具、访问内部地址”等提示词注入信号。
- `suspected/blocked/not_checked` 证据不得支撑自动批准。
- 保存摘要与 claim，不将整页内容无界送入 LLM。
- 外部信息与内部本体冲突时标记冲突并请求人工确认，不自动覆盖内部事实。

## 12. 测试计划

### 12.1 契约与模型

- extra field、宽松类型、超长字符串、超大 JSON、深度、NaN/Infinity 全部拒绝。
- canonical JSON/hash 对 key 顺序稳定，对实际内容变化敏感。
- 状态机所有合法/非法转换表驱动测试。
- 六 canonical agent ID、风险级别、marking 和 memory layer 严格枚举。

### 12.2 租户和权限

- 两个租户使用相同 plan/evidence/task/handoff ID，list/get/update/submit/approve 全隔离。
- token claim 与 header 不一致 403。
- 跨租户资源 404，不泄露存在性。
- viewer/planner/approver/auditor/verifier 权限正反例。
- 创建人自批、角色不足、marking 不足、高风险单批准全部失败。

### 12.3 revision、并发和幂等

- replace expected revision 成功/409。
- submit 与 replace 并发，只有合法顺序成功。
- 两个 approver 并发只有一次批准事件和一个终态。
- 相同 idempotency key 相同请求重放；不同请求 409。
- API 重启后 idempotent replay 仍成立。
- 事务注入失败：revision、event、current pointer 和 idempotency 全部回滚。

### 12.4 证据安全

- 非 HTTPS、内部 IP、非法 domain、过期、无 hash、无 retrieved_at 拒绝。
- suspected/blocked/not_checked 提示词注入状态不能用于提交方案。
- revoked 证据使未批准方案无法提交；已批准历史保留但 preflight 告警。
- 外部摘要中 PII/凭据模式阻断或遮罩。
- 不返回网页全文和内部扫描规则。

### 12.5 DAG / Handoff

- 正常 DAG、环、自环、重复边、孤儿、跨 revision、跨租户。
- Handoff from=to、过期、字段越界、敏感字段、目标未批准。
- G0 execute/deliver 路径不存在或固定受控拒绝。

### 12.6 OpenAPI 与路由

- `scripts/generate_domain_aggregates.py --check`。
- OpenAPI 导出两次字节一致。
- operationId 唯一，Growth path/method 唯一。
- `/v1/aip/drafts` 不再由 Phase3 内存路由重复注册。
- `/api/aip/long-memory` 生产写入口不可达。

### 12.7 累计回归

- Growth 专项测试。
- Logic Graph/DryRun/Evals/Publication 累计测试。
- auth/tenant/marking/Draft/OpenAPI/route manifest 累计测试。
- API 全量 pytest。
- Web unit/typecheck/build。
- 敏感信息扫描与迁移单 head/upgrade/downgrade。

### 12.8 浏览器主流程

1. 无适配器时 Preflight 显示网络研究阻断。
2. 创建内部证据和 GrowthPlan Draft，刷新/API 重启后仍存在。
3. 编辑产生 revision 2，revision 1 不变。
4. 创建人提交后尝试自批，被服务端拒绝。
5. 合法 approver 批准 revision 2，GET 回读 hash/status 一致。
6. 再次编辑产生 revision 3，旧批准不授权 revision 3。
7. 查看任务 DAG 预览，执行按钮不存在。
8. 切换第二租户，同 ID 资源不可见。

## 13. 可观测性、灰度与回滚

### 13.1 日志与指标

日志只记录 ID、actor、tenant、revision、状态、错误码和耗时，不记录 plan 全文、网页摘要、客户数据或凭据。

指标：

- plan create/replace/submit/approve/reject 数量与失败码。
- revision conflict、自批阻断、跨租户 404。
- evidence unsafe/expired/revoked。
- idempotent replay/conflict。
- store latency/error、adapter unavailable。
- route/openapi preflight 状态。

### 13.2 Feature Flag

- `AOS_GROWTH_CONTROL_PLANE_ENABLED=0` 默认关闭新 UI/写 API。
- 开启后仍只有方案控制面，无执行面。
- 外部研究、任务执行、Handoff delivery、Memory publication 分别独立 flag，G0 固定关闭。
- flag 不能绕过服务端角色、状态机和 C0.2。

### 13.3 灰度

1. migration/preflight only。
2. 指定 dev org 的只读列表/详情。
3. 指定 org 开放 Draft 创建/编辑。
4. 开放提交/批准，仍不执行。
5. 观察稳定后作为 G1 前置。

### 13.4 回滚

- 关闭 feature flag 停止新增写入，保留只读审计。
- Router 回滚不能重新启用 Phase3 内存 Draft/Memory。
- 数据迁移不自动删除；使用向前修复或经批准的导出/清理流程。
- 已批准 plan 只代表历史决策，不产生任何未回滚外部副作用。
