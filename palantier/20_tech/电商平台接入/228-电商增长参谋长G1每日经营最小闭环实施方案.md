## 0. 使用的 Rules

- 只在 G0 canonical 契约和持久层上开发，不复用旧 TAOR 内存 Task。
- 数据参谋 D01～D06 必须形成真实闭环，不能只生成一段建议文本。
- 内部数据只走租户化 MetricQuery；外部搜索只走批准的只读 Research Adapter。
- 人工批准精确 GrowthPlan revision 后才 materialize 任务。
- G1 任务只允许只读分析、草稿产物和 Handoff Draft，不执行外部写回。
- 自动复盘必须区分有效、无效、有害、无结论和未执行。
- 每次生成均保存证据、prompt/template version、run、产物和错误，不保存 CoT。
- D01～D06、DailyBrief 和 Growth Review 属于 `solution.ecommerce.growth`；通用 Metric/Research adapter 与调度外壳属于平台内核。

## 1. 目标与完成定义

G1 完成数据参谋的每日最小经营循环：

```text
数据就绪检查
  → 内部指标巡检
  → 受控网络研究
  → 晨报与机会排序
  → GrowthPlan Draft
  → 人工批准精确 revision
  → AgentTask DAG materialize
  → 只读/草稿任务交付确认
  → 指标观察
  → 初步/最终 EffectReview
```

真实完成必须满足：

1. 晨报中的每个数字绑定内部 metric revision，每个外部判断绑定 Evidence URL/时间。
2. 数据未就绪、搜索不可用或证据不足时明确降级/阻断。
3. GrowthPlan 不是自由文本，而是 G0 严格模型。
4. 创建人不能批准；批准后才能创建任务 DAG。
5. 任务状态、产物、Handoff、观察和复盘在 API 重启后可回读。
6. G1 不存在发布、触达、Action、Automation 或生产对象写路径。

## 2. 当前能力与缺口

可复用：

- canonical Logic Graph、DryRun、运行历史、Evals 和不可变 publication。
- `RuntimeAdapterRegistry` 的空注册、只读/安全声明、超时和并发模式。
- Principal、租户、marking、G0 GrowthPlan/Task/Evidence 持久层。

阻断：

- 当前无批准的外部网络搜索 adapter；`AgentImportPage` 中的 `search_web` 只是映射文字，不是运行能力。
- `tool_runtime.query.objects` 未完整按 org/project 查询，不能作为数据参谋内部查询。
- 当前无 canonical MetricQuery、DailyBrief、ExecutionObservation、EffectReview 服务。
- 旧 `aip_logic_engine` 会自动构造 approved plan，禁止进入 G1。
- 当前无 Growth Command Center 页面。

## 4. 内部 MetricQuery

数据参谋不能生成任意 SQL。G1 冻结白名单查询契约：

```yaml
metric_id: paid_order_count
dimensions: [day, channel]
filters:
  shop_id: shop-...
window:
  start_at: ...
  end_at: ...
comparison: previous_period
```

要求：

- `metric_id/dimension/filter` 均来自服务端注册表。
- 服务端从 Principal 注入 org/project，拒绝 body scope。
- 结果保存 metric definition version、Dataset/OT revision、时间窗口、行数、hash 和脱敏摘要。
- 查询有时间、扫描行、返回行、字节和并发上限。
- CustomerLite 之前不得查询客户 PII；聚合结果小样本需抑制。
- 数据缺失返回 `NOT_READY`，不补零、不使用演示数据。

首批通用指标：数据新鲜度、商品/SKU 数、可售/缺货、订单数、成交额、订单状态、履约超时、退款/投诉占位指标。平台缺少某指标时标记 unavailable。

## 5. 外部 Research Adapter

### 5.1 Provider-neutral 契约

G1 可接一个经过批准的搜索 provider，但业务契约不绑定供应商：

```yaml
query: ...
purpose: trend|competitor|platform_rule|customer_question|other
domains_allow: []
domains_deny: []
language: zh-CN
freshness_days: 7
max_results: 10
```

返回必须包含 URL、title、snippet/summary、published_at（可空但显式）、retrieved_at、domain 和 content hash。没有 URL 的结果不能成为 `external` Evidence。

### 5.2 安全与真实性

- provider 凭据使用 secret_ref，不进入 request body、日志或数据库。
- 查询与结果按 G0 SSRF、重定向、字节、超时和提示词注入策略处理。
- 平台规则类查询优先官方域名；没有官方证据时标记未确认。
- 不复制整篇文章，不自动登录账号，不抓取私密页面。
- 适配器不可用时 D02 失败或生成“外部研究缺失”的受限晨报，不能伪造趋势。

## 6. 数据参谋 D01～D06

### D01 数据与经营健康巡检

```text
input → use_tool(metric_readiness) → use_tool(query_metrics)
      → transform(health_rules) → branch(ready/degraded/blocked) → handoff
```

输出 `DailyDataReadiness`：每个数据域的新鲜度、最新 revision、缺口、阻断原因和允许继续的能力。

### D02 内外机会研究

```text
input → use_tool(query_internal_opportunities)
      → use_tool(web_research)
      → transform(evidence_alignment)
      → branch(supported/conflicted/insufficient) → handoff
```

只输出带 evidence refs 的机会；内部/外部冲突进入人工核验队列。

新电商平台增加两个 P0 research profile：

- `creator_growth`：在微信小店、抖音、快手的授权 capability 中发现达人候选，按平台、达人层级、粉丝区间、开播活跃、受众画像可用性、品类、成本和风险形成带证据候选；跨 run 去重，平台字段不可用时标记 unavailable。
- `price_governance`：观察授权 SKU 与公开渠道价格，拆分标价、券、满减、会员/直播/平台补贴，完成同款核验后才生成价格异常候选。

两者在 G1 只做只读研究、Artifact 和人工核验，不发送邀约、不修改佣金/挂品、不通知商家、不提交平台举报。

### D03 增长方案生成

```text
input → get_property(goals) → use_tool(load_constraints)
      → use_llm(growth_planner_model)
      → transform(validate_plan_schema)
      → branch(valid/invalid) → handoff(draft_inbox)
```

LLM adapter 必须显式注册批准模型，输出严格 JSON；随后服务端重新验证目标、护栏、预算、证据和任务，不相信模型自报合法。

### D04 审批后任务拆解

只接受 `GrowthPlan.APPROVED` 的精确 revision/hash：

```text
load_approved_plan → deterministic_decompose → validate_dag
                   → materialize_tasks → GET 回读
```

任务拆解优先确定性模板；需要 LLM 补充时其输出仍须严格 DAG 校验。G1 任务 owner 可为六数字同事，但非数据参谋任务只能进入 `ASSIGNED/DELIVERED` 的草稿交付模式，不调用尚未实现的 G2 Logic。

首批新增确定性任务模板：

- `CREATOR_DISCOVERY_AND_COLLABORATION`：数据参谋 owner；活动策划师、内容官和导购顾问为 collaborator；输出候选、评分、短名单、邀约草稿和合作跟踪 Artifact。
- `CROSS_PLATFORM_PRICE_GOVERNANCE`：数据参谋 owner；活动策划师和客服专员为 collaborator；输出价格观察、同款证据、异常候选、处置草稿和恢复复查 Artifact。

不新增第七个 canonical Agent。联系方式、受众画像和截图证据继承输入的最高 marking；对外动作仍为 forbidden action。

### D05 执行监控与调整建议

读取任务、产物、阻塞和 metric observation；护栏触发时生成 pause/cancel 建议。G1 不自动取消外部动作，因为没有外部动作。

### D06 效果归因与复盘

```text
collect_artifacts → confirm_executed → collect_metrics
                  → compare_baseline → classify_result
                  → generate_review → memory_candidate_draft
```

G1 只生成 `MemoryCandidate.DRAFT`；G4 前不能晋升长期记忆。

## 7. Working Memory 与运行证据

G1 的 Working Memory 是任务级、持久化、限量上下文，不复用长期记忆引擎：

- 绑定 plan revision、task、Logic run 和 actor。
- 保存输入/输出引用、摘要、变量和待解决问题；不保存 CoT。
- PII/凭据禁止；JSON 大小和 TTL 有上限。
- 任务关闭/取消后按策略过期，审计引用保留 hash。
- 同一 Agent 只能读取当前授权任务上下文。

新增 `growth_working_context`、`growth_execution_artifact`、`growth_execution_observation` 和 `growth_daily_brief` 表；均使用复合租户键。

迁移 `228growth1_daily_operations.py` 只建新表、约束和索引，不回填演示晨报或伪造历史运行。upgrade 后先保持功能旗标关闭并验证双租户、重启回读和数据新鲜度；downgrade 只在没有 G1 revision/run 被后续对象引用时允许，否则停用功能并保留只读证据表。

## 9. 每日调度

第一小波只允许人工触发 D01～D06，以便验证证据和审批。第二小波才增加租户化调度绑定：

- 绑定 immutable Logic publication + template version。
- 配置店铺时区、数据就绪窗口、最大运行时长和错过策略。
- 同一 org/project/day 幂等。
- 数据未就绪按策略延迟或产生 degraded brief，不重试风暴。
- 调度只能创建 Draft/只读 run，不能自动批准 GrowthPlan。

不得复用当前内存 L4 Automation 作为生产调度真源。

## 10. 增长参谋长工作台

首版页面：

- 数据就绪与能力 Preflight。
- 今日经营健康、问题和机会。
- 内外 Evidence 及引用时间。
- GrowthPlan Draft、revision diff 和人工批准。
- 任务 DAG、状态、产物和阻塞。
- 指标观察、护栏和初步/最终复盘。

禁止状态：

- 网络研究未注册：显示阻断和人工证据导入入口。
- 数据缺失：指标显示 unavailable，不显示 0。
- 计划未批准：materialize 禁用。
- G2 Agent 未实现：任务显示“待专业 Logic 接入”，允许人工上传草稿产物但不得假执行。
- C0.2 未完成：发布、触达、写回按钮不存在。

## 11. 分波与并行边界

| 小波 | 内容 | 退出门 |
|---|---|---|
| G1-A | MetricQuery、Research Adapter、readiness/research run | 内外证据可信、无 adapter 失败关闭 |
| G1-B | D01-D03、DailyBrief、Plan compiler | 晨报/计划全部可追溯且严格 Schema |
| G1-C | D04-D06、Task materialize、Observation/Review | 批准后 DAG、观察和复盘闭环 |
| G1-D | 工作台、人工触发浏览器主流程 | 刷新/重启可恢复，真实空态 |
| G1-E | 受控每日调度 | 不自动批准、不重复运行、不写生产 |

四 Worker 可分别负责 Metric/Research、Logic/Compiler、Task/Review、前端；共享迁移、router manifest 和 OpenAPI 由总控集成。

## 12. 测试与退出门

- Metric whitelist、租户、small-cell 抑制、数据缺失和查询预算。
- 搜索超时、无 URL、过期、非官方规则、提示词注入、SSRF 和结果过大。
- D01～D06 canonical Graph、节点配置、适配器未注册和失败历史。
- LLM 返回非法 JSON、越权任务、无护栏计划、伪造 evidence refs 全部拒绝。
- 未批准/旧 revision/旧 hash 不能 materialize；DAG 并发幂等。
- NOT_EXECUTED/INCONCLUSIVE/HARMFUL 等复盘正反例。
- Working Memory TTL、PII、跨 Agent/租户、取消清理。
- 手工触发和调度同日幂等、API 重启恢复、错过窗口。
- 浏览器完成 readiness → research → brief → plan → 自批阻断 → 合法批准 → tasks → artifact → observation → review。
- API/Web 全量、G0 累计、OpenAPI、迁移、敏感信息扫描全部通过。

功能旗标：`growth_daily_operations_enabled`、`growth_research_enabled`、`growth_daily_scheduler_enabled`。回滚时先停调度和新 run，再等待/终止在途只读任务，最后关闭页面入口；已产生的 Evidence、Plan、Task、Observation 和 Review 保持只读，不伪装删除。主要剩余风险为错误指标口径、外部内容投毒、调度重复和过早把相关性解释为因果，必须由证据、Evals、幂等和人工批准控制。

G1 结束时，系统能够真实完成“研究—规划—批准—分派—观察—复盘”，但仍不能代表内容官、导购顾问和客服专员已经具备专业执行能力；这些由 G2 实现。
