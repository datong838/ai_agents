## 0. 使用的 Rules

- 私域运营必须先有 purpose-specific consent、联系频控、退订和人工批准；没有同意不能生成可执行触达。
- G3 只规划、分析和生成 Draft，不调用社交平台发布、私信、优惠券、改价或库存写回。
- 活动目标必须同时受预算、毛利、库存、履约、品牌和客户权益约束，不能只优化成交额。
- 归因明确区分事实、估计和未知，不把最后一次接触武断视为唯一贡献。
- 实验必须预先冻结假设、分组、指标、窗口、停止条件和污染规则，结果出来后不改口径。
- 私域管家、活动策划师和数据参谋通过 canonical Task/Handoff 协作，不共享完整客户明细。
- 所有分群和触达建议都可解释、可撤回、可审计、可复盘。
- 私域、活动和电商归因属于 `solution.ecommerce.growth`；渠道数据读取由 PlatformAdapterPack 提供，实例预算/频控进入 InstanceOverlay。

## 1. 业务目标与完成定义

G3 扩展两位数字同事：私域管家和活动策划师，并增强数据参谋的跨渠道/跨周期分析。

```text
数据参谋识别机会与约束
  → 私域管家生成合规分群/关系维护 Draft
  → 活动策划师形成活动/实验计划
  → 人工批准精确 revision
  → 生成渠道无关的触点/素材/任务 Draft
  → 人工或外部专项执行
  → 聚合渠道与经营结果
  → 归因、实验评估和自动复盘
```

真实完成必须满足：

1. 每个可触达客户都能解释 consent purpose、来源、有效期、频控和退订状态。
2. 活动方案包含预算、毛利、库存、履约容量、停止条件和风险负责人。
3. 人工批准前不 materialize 可执行触点；G3 仍不能外部发送。
4. 跨渠道分析保存数据 revision、口径、窗口、归因模型和置信区间/不确定性。
5. 复盘能回答“是否增长、成本如何、是否伤害客户/毛利、结论能否推广”。
6. G0～G3 累计回归和生产写回负向门全部通过。

## 2. 当前能力与阻断项

可复用 G0～G2 的 GrowthPlan、Task、Evidence、Handoff、CustomerLite、MetricQuery、Outcome、Review、Logic Runtime 和工作台框架。

当前阻断：

- 无 canonical CustomerSegment、ContactPolicy、Campaign、Experiment、Attribution 契约和持久层。
- 无批准的外部渠道 Connector，不能把“发送草稿”显示为“已触达”。
- 当前 L4 Automation 的部分单例路径没有完整消费 Principal，不可作为活动自动执行器。
- 平台数据口径与身份键不齐时只能做渠道内聚合，不得强行跨平台客户归并。
- CustomerLite 不包含真实联系方式；实际触达必须由未来 Connector 在平台边界内解析 token。

## 3. 核心对象与边界

| 对象 | 关键字段 | 不变量 |
|---|---|---|
| `CustomerSegmentRevision` | filter AST、purpose、snapshot/data revision、size、suppression | 不保存客户明细快照；revision 不可变 |
| `ContactPolicy` | channel、purpose、quiet hours、frequency cap、cooldown、opt-out | deny/withdrawn 优先于任何计划 |
| `TouchPlanRevision` | segment ref、channel intent、content ref、schedule window | `draft` 不等于已发送 |
| `CampaignRevision` | goal、budget、margin floor、inventory guard、capacity、tasks | 批准精确 hash 后不可变 |
| `CampaignVariant` | audience、offer/content、channel、allocation | 变体差异显式记录 |
| `ExperimentRevision` | hypothesis、unit、assignment、metrics、window、stop rule | 开始后不可改口径 |
| `AttributionTouch` | pseudonymous token、channel、campaign、event time、source revision | 不携带 PII |
| `AttributionReport` | model、window、eligible set、result、uncertainty | 估计不能伪装事实 |

分群过滤只允许注册字段和运算符；不得按民族、宗教、疾病等敏感属性分群。小样本低于阈值时抑制明细和细分指标。

## 4. 私域管家 Logic：P01～P05

| Logic | 输入 | 处理 | 输出/门禁 |
|---|---|---|---|
| P01 关系健康巡检 | CustomerLite 聚合、互动/服务结果 | recency/frequency/value band、投诉/退订 | RelationshipHealth；小样本抑制 |
| P02 合规分群 | 目标、consent、ContactPolicy | allowlisted filter → snapshot → suppression | SegmentRevision；无同意者排除 |
| P03 培育路径 | segment、生命周期、内容资产 | touch sequence → cooldown → channel intent | TouchPlan Draft |
| P04 流失/召回建议 | inactive/risk、服务反馈 | reason cluster → value/risk check | Winback Draft；高投诉者不促销 |
| P05 私域复盘 | touch outcome、conversion/service outcome | incremental/guardrail analysis | PrivateDomainReview |

私域管家“管关系”，不持有联系方式，不直接发送消息，不绕过退订，不把高频骚扰当活跃。

## 5. 活动策划师 Logic：A01～A06

```text
A01 目标与约束冻结
  → A02 受众/商品/渠道组合
  → A03 活动机制与预算测算
  → A04 素材/任务 DAG 编排
  → A05 实验与停止规则
  → A06 效果复盘与节奏建议
```

硬门：

- 活动预计毛利低于 floor、库存覆盖不足、履约容量不足或预算超限时不能提交批准。
- 优惠、价格、券、赠品仅形成建议；必须引用平台真实规则和商品 revision。
- 不使用诱导分享、虚假倒计时、虚假原价、虚假销量或不可兑现承诺。
- 活动节奏与内容/私域/导购/客服任务必须给出依赖和并发上限。
- 活动批准者不能兼任预算/价格实际执行者；G6 再定义 Action approval。

## 6. 数据参谋跨渠道与跨周期增强

首批分析能力：

- 渠道漏斗：曝光 → 互动 → 咨询 → 推荐采用 → 支付 → 服务/退款。
- 商品/内容/渠道/活动 cohort，支持日、周、活动窗口及前后对照。
- 增量实验优先；无实验时可提供规则归因或相关性，但必须标明限制。
- 同渠道 first/last/linear/time-decay 可配置；跨渠道身份不可靠时只做聚合比较。
- 同时报告成交额、毛利估计、获客成本、转化、退款/投诉、履约和触达负担。
- 避免幸存者偏差、选择偏差、数据延迟和重复事件；数据未闭合时标记 preliminary。

归因报告必须保存 metric definitions、query hashes、eligible population、model version、data cutoff、excluded reasons 和 uncertainty。

## 7. consent、频控与退订

服务端决策顺序：

```text
tenant/actor authorized
  → purpose consent granted
  → channel eligible
  → not opted out / not suppressed
  → quiet hours allowed
  → frequency cap/cooldown allowed
  → campaign/segment revision current
  → return ELIGIBLE or explicit denial reason
```

拒绝码至少包含 `CONSENT_REQUIRED`、`CONSENT_WITHDRAWN`、`CHANNEL_NOT_ALLOWED`、`QUIET_HOURS`、`FREQUENCY_CAP`、`SUPPRESSED`、`STALE_SEGMENT`。禁止前端自行判断后绕过服务端。

### 9.1 数据表与迁移策略

迁移新增 segment/item revision、contact policy、eligibility decision、touch plan、campaign/variant、experiment/assignment、attribution touch/report 等表。业务唯一键必须包含 org/project；冻结对象只追加 revision；大规模 assignment/attribution 表按时间与租户建立索引/分区策略。

upgrade 不生成真实分群或活动，不从 CustomerLite 反向推断 consent；功能旗标默认关闭。downgrade 只在没有冻结实验、活动和下游 report 引用时删除新表；一旦存在经营证据，只关闭能力并保留只读审计。异步归因任务必须先停发、排空或标记 cancelled 后才能迁移回滚。

## 10. 工作台与人工批准

- 私域页默认显示聚合关系健康、合规分群和不可触达原因，不显示客户 PII。
- 分群编辑器显示预估规模、抑制数量、数据时间与 filters diff；冻结后创建新 revision 才能修改。
- 活动页同时展示目标与护栏，预算/毛利/库存/履约任一失败时批准按钮禁用。
- 实验页在 freeze 后锁定假设和口径；提前停止必须记录 actor、理由与证据。
- 归因页把 observed、estimated、unknown 分栏显示，禁止只有一个“归因成交额”。
- 所有页面明确“草稿/已批准/已人工执行/已观测”，不以颜色或 toast 混淆状态。

| G3.5 | 跨智能体节奏与累计回归 | DAG/Handoff、失败恢复、G0～G3 API/Web/Evals |

测试另需覆盖 OpenAPI 确定性、幂等、CAS、异步重试、注入内容、PII 扫描、错误码和生产写入为 0。

功能旗标：`growth_private_domain_enabled`、`growth_campaign_planner_enabled`、`growth_experiment_enabled`、`growth_attribution_enabled`。回滚关闭功能并停止新异步任务，已冻结 revision 与审计保持只读。

G3 退出门：P01～P05、A01～A06 和跨渠道分析全部可追踪；consent/频控硬门不可绕过；实验/归因口径可复现；G0～G3 累计回归通过；无外部发送和业务写回。
