## 0. 使用的 Rules

- “越工作越聪明”必须通过可审查、可评测、可撤回的记忆晋升实现，不允许模型自动修改代码、Logic 或系统提示词。
- Working、Episodic、Semantic、Procedural 四层分开；个人记忆和共享记忆分开。
- 只有真实任务、产物、结果和 EffectReview 能产生 MemoryCandidate；对话猜测不能直接成为长期事实。
- 每条记忆绑定租户、agent、purpose、证据、适用范围、版本、TTL、风险和来源。
- 召回前重新做权限、marking、有效期、冲突和最小披露检查；被撤回内容不能继续进入上下文。
- 旧进程内 LongMemory 仅作原型证据，不迁移成生产真源。
- 不保存 CoT；只保存受控摘要、决策、依据、结果和可复现实验信息。

## 1. 目标与完成定义

G4 为数据参谋及五位数字同事建立受治理的经验系统：

```text
任务与结果
  → EffectReview
  → MemoryCandidate
  → 脱敏/冲突/过期/投毒检查
  → Evals 与人工审查
  → immutable MemoryItem revision
  → 按 agent/purpose/权限检索
  → 新任务引用并记录 retrieval
  → 新结果反证、修订、降权或撤回
```

真实完成必须满足：

1. 六个智能体均能形成个人经验，但不能读取别人的私有记忆。
2. 共享经验必须单独批准，并能指出来源、适用对象和反例。
3. 记忆在进程重启后仍可回读，双租户同 ID 不泄漏。
4. 任一召回可解释“为什么命中、用了哪个 revision、是否影响产物”。
5. 错误、过期、冲突或含 PII 的候选不能晋升；已晋升内容可撤回并阻断新召回。
6. Evals 证明使用记忆后质量改善且安全性不下降；否则不扩大灰度。

非目标：自主训练基础模型、自动改 prompt、自动发布 Logic、跨商家共享客户/经营数据、保存完整聊天或模型思维链。

## 2. 当前代码审计结论

`aip_long_memory.py` 及其 router 当前无 Principal/租户边界，使用进程内最多 200 条记录，可接收任意 config，重启即丢失。它不能承载生产记忆，也不能直接迁移数据。

可复用：

- G0 的 `MemoryCandidate` 公共契约边界、Evidence、Approval、Artifact、Review。
- canonical Logic run/history、publication 和 Evals。
- Principal、roles、markings 和平台审计框架。

阻断：当前无持久化 MemoryItem、candidate review、检索策略、冲突/撤回、记忆 Evals 和管理工作台。

## 3. 四层记忆模型

| 层 | 内容 | 生命周期 | 例子 | 是否长期召回 |
|---|---|---|---|---|
| Working | 当前 Task 的输入、步骤、临时结果 | task 完成/过期即清理 | 当前晨报证据、草稿上下文 | 否，仅任务内 |
| Episodic | 一次任务/活动的受控经历摘要 | 有 TTL，可撤回 | 某次活动在某类条件下失败 | 是，带场景约束 |
| Semantic | 经多次证据支持的业务知识 | 定期重验证 | 特定品类常见咨询意图 | 是，不能冒充永恒事实 |
| Procedural | 经 Evals 验证的工作方法 | 版本化、严格批准 | 推荐前先查库存与替代项 | 是，只影响流程建议 |

Working Memory 在 G1 的 Task scope 中实现，不走长期检索；G4 负责另外三层及其治理。

## 4. 个人与共享边界

记忆 scope：

```yaml
scope_type: agent_private|team_shared|role_shared
owner_agent_id: data_strategist|content_officer|shopping_guide|customer_service|private_domain_manager|campaign_planner
allowed_roles: []
purpose_allow: []
org_id: ...
project_id: ...
markings: []
```

- `agent_private` 默认，仅 owner agent 在匹配 purpose 时可检索。
- `team_shared` 需额外审批，必须脱敏、泛化并带适用/不适用条件。
- `role_shared` 只用于同一职责的通用方法，不跨租户。
- CustomerLite 个体偏好不是团队知识；只能通过受控 CustomerLite 查询在单次任务中使用。
- 六智能体的个人经验互不自动复制；Handoff 只传当前任务必要结论。

## 5. Candidate → Item 状态机

```text
candidate_draft
  → submitted
  → sanitizing
  → evaluating
  → pending_review
  → approved
  → active
  → superseded|revoked|expired

任一阶段 → rejected|quarantined
```

晋升硬门：

1. 有 EffectReview、Task、Artifact、Outcome 和 Evidence 引用。
2. 内容不含 PII、Secret、整段版权内容、提示词注入或不可验证绝对结论。
3. 声明适用条件、反例、数据时间、confidence 和 TTL。
4. 至少通过事实性、安全性、相关性、非退化 Evals。
5. `team_shared/procedural` 必须由不同于候选创建人的审查者批准。

## 6. 数据模型

| 表/对象 | 关键字段 |
|---|---|
| `growth_memory_candidate` | source refs、proposed layer/scope、summary、applicability、risk、status |
| `growth_memory_candidate_eval` | suite/version、baseline、candidate score、failures、evidence refs |
| `growth_memory_item` | stable id、layer、scope、owner、active revision、status |
| `growth_memory_item_revision` | content、evidence、applicability、counterexamples、confidence、TTL、hash |
| `growth_memory_access_policy` | purpose、role、marking、deny/allow、version |
| `growth_memory_retrieval_event` | query hash、filters、returned ids/revisions、score、consumer run |
| `growth_memory_feedback` | helpful/harmful/irrelevant/contradicted、outcome refs |
| `growth_memory_revocation` | reason、actor、affected revisions、effective_at |

记忆正文使用结构化段落：`claim`、`when_to_use`、`when_not_to_use`、`steps`、`evidence_refs`、`counterexamples`，不能只存自由文本 embedding。

## 7. 检索与上下文装配

检索顺序：

```text
Principal + agent + purpose
  → tenant/project/marking policy
  → active + unexpired revisions
  → layer/scope/applicability filter
  → lexical/vector candidate retrieval
  → evidence freshness/conflict rerank
  → token/minimum disclosure budget
  → return snippets + ids + reasons
```

要求：

- 向量索引只是检索副本，canonical 内容仍在事务数据库。
- 每个命中携带 stable id、revision、layer、scope、score components 和 evidence freshness。
- 超过 token budget 时按任务相关性截断，不拼接完整历史。
- 被撤回/过期 revision 必须从过滤层立即不可见，索引异步清理不能成为漏洞。
- 记忆内容被视为不可信数据，不允许其中指令覆盖系统/Logic/Tool 权限。
- 产物保存 `memory_refs_used`；未使用也记录空列表。

---

## 8. 冲突、过期与投毒治理

- 同一 claim 出现冲突时创建 `conflict_set`，默认降权或阻断，交由审查者处理。
- 数据/平台规则超过 TTL 或源 revision 失效后进入 `stale`，不能继续作为硬事实。
- 用户文本、网页内容和外部评论只作为 evidence candidate，不直接成为 procedural memory。
- 异常高频候选、单一来源自证、循环引用、指标异常跃升进入 quarantine。
- 负面结果能触发反证候选；撤回不抹除审计，但从新 run 的召回中隔离。
- 发现 PII/Secret 后立即禁用 revision，记录安全事件并启动派生索引清理。

### 10.1 数据库迁移与索引重建

迁移只创建 Candidate、Item/Revision、Eval、Policy、Retrieval、Feedback、Revocation 与 Conflict 表，不把旧进程内 LongMemory 自动导入。canonical 表先落库并验证租户/marking，再异步建立检索索引；索引记录 canonical revision/hash 和 build version，可随时丢弃重建。

upgrade 期间检索旗标保持关闭，完成全量 hash 对账后再灰度。downgrade 不删除已批准记忆或审计；先关闭检索、停止晋升、删除可重建索引副本，canonical 表保持只读。只有空库且无下游 run 引用时才允许物理降级。

## 11. 工作台与可观测性

- 候选队列显示来源任务、证据、建议层/范围、风险、Evals 和 diff。
- Item 详情显示完整 revision 链、适用条件、反例、命中历史、反馈和撤回状态。
- 冲突队列允许“保留 A/保留 B/合并新 revision/全部撤回”，全部需说明理由。
- run 详情显示检索请求、过滤原因、实际使用记忆和对最终产物的引用。
- 指标包括候选通过率、撤回率、过期率、错误命中率、helpful/harmful 反馈、质量 uplift 和安全门失败。
- 不展示隐藏 CoT，不在日志记录原始敏感文本或完整检索上下文。

## 12. 分小波与测试

| 小波 | 内容 | 退出门 |
|---|---|---|
| G4.1 | Candidate/Item 持久层、状态机、租户/marking | 双租户、CAS、重启回读、PII/Secret 负向通过 |
| G4.2 | sanitizer、Evals、审批、撤回/过期 | 职责分离、冲突、撤回即时生效通过 |
| G4.3 | 检索、索引副本、上下文预算 | policy、过期、投毒、索引延迟、相关性通过 |
| G4.4 | 六智能体集成与 run trace | 私有/共享边界、memory_refs_used、失败降级通过 |
| G4.5 | 治理工作台和累计回归 | 浏览器、OpenAPI、G0～G4 API/Web/Evals 通过 |

Evals 必须做 baseline vs memory A/B：任务质量、事实性、完成率、延迟、token 成本、错误复用和安全性。只有质量显著提升且安全不退化才允许扩大召回比例。

## 13. 风险、回滚与退出门

主要风险：记忆投毒、旧规则污染、跨租户泄漏、个人信息泛化、错误经验自我强化、召回导致 token/延迟膨胀。通过 Candidate 门、权限过滤、TTL/撤回、Evals、灰度和 kill switch 控制。

功能旗标：`growth_memory_candidate_enabled`、`growth_memory_retrieval_enabled`、`growth_memory_shared_enabled`。回滚首先关闭检索，Logic 在无长期记忆条件下仍须正确运行；canonical 记忆保留只读，不直接删除。

G4 退出门：四层边界清楚；六智能体私有记忆隔离；共享晋升受审批；撤回即时阻断；run 可解释实际使用 revision；baseline 对照证明有益；G0～G4 累计回归全部通过。
