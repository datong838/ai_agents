# 228-AIP 通用能力与六数字同事统一实施总方案

> 状态：**评审通过 · v1.0 方案基线（仍不授权编码）**
> 版本：v1.0 · 2026-08-10
> 适用租户：`org-org / dev-project`（栖月汇商贸有限公司 / 默认工作区）
> 定位：AIP、通用工作台、FDE、行业 Wiki、六数字同事与电商增长任务的统一实施总纲；完成本方案包后，才进入微商城工作台专项细分。

## 0. 使用的 Rules

1. 先方案、后评审、再编码；本文及子方案均不构成编码授权。
2. 以当前 `aos-platform/m1`、真实 API 回读和浏览器行为为准，不以旧文档、测试名、静态卡片或按钮可点击推断“已完成”。
3. 只认 `org-org / dev-project` 为栖月汇真实范围；`dev-org` 只可作为负向隔离 canary。
4. 复用已封板 O1 的 Object/Link/Action/OKF/Wiki 契约，不扩写第二套本体、Action、Draft、Task 或知识模型。
5. 对外发布、客户触达、价格/库存/支付/退款等写操作继续 Draft-only；C0.2 与 G6 退出门关闭前生产写回不可达。
6. 通用能力先于平台专项；平台差异进入 AdapterPack，客户差异进入 InstanceOverlay。
7. 每波必须同时通过：契约、迁移、权限、租户、并发/幂等、负向、累计回归、真实 API 回读和浏览器主流程。

## 1. 统一结论

当前 AIP 不是“完全未做”，也不是“已经可支撑六数字同事”。它处于三个层级并存的状态：

| 层级 | 当前事实 | 判断 |
|---|---|---|
| 平台骨架 | Logic Graph revision/hash、安全试跑、发布证据、Evals API、Draft 页面、模型供应/路由/容量已有较多真实实现 | 可复用，不重做 |
| 过渡实现 | TAOR、Task、Agent、Lineage、Long Memory 等仍有进程内单例或旧模型；部分新旧路由并存 | 必须收敛到 canonical 契约 |
| 展示/样例 | AIP 分析师使用内存表；智能体目录/列表大量静态数据；可观测趋势和 Token 为推演/估算；部分导入向导预填扫描结果 | 不能作为业务完成证据 |

因此本项目的下一阶段不是继续补单页按钮，而是先形成一条通用、可审计的运行主链：

```text
经营目标 / 用户请求 / 定时任务
  -> Task + PlanRevision
  -> Agent / Skill / Capability 解析
  -> TAOR / Logic Graph 精确 revision 执行
  -> Object/Link/OKF/Wiki 只读上下文
  -> ActionProposal -> Draft -> Approval -> Receipt
  -> EvalReport + DecisionLineage + Observability
  -> EffectReview -> MemoryCandidate -> 治理后晋升
```

## 2. 权威文档与冲突裁决

发生冲突时按以下顺序裁决：

1. 平台安全、租户隔离、C0.2、O1 已封板公共契约。
2. `228-电商增长参谋长与六数字同事协同进化实施方案.md`。
3. 本方案包。
4. G0～G6 最新 228 实施方案及达人/控价任务契约。
5. 11/12/13/14 目录中的旧目标设计。
6. `电商领域数字同事初探`、开源支持篇与内容官专项中的探索性建议。

旧文档中以下口径一律废止：

- 默认走 Mock 仍可算 Harness 完成。
- 用 Redis/进程内单例作为未审查的生产真源。
- FDE “已完成”表示代码已完成；其多数仅代表方案已编写。
- 通过静态 Agent 卡片、固定 trace、样例查询证明智能体可运行。
- 六数字同事各自定义一套 Customer/Content/Creator/Task 模型。

## 3. 目标架构边界

### 3.1 平台通用层

- Canonical Task/Plan/Run/Checkpoint/Artifact/Evidence。
- AgentDefinition、SkillDefinition、CapabilityBinding、HandoffEnvelope。
- Logic Graph revision/hash、DryRun、Publication。
- ActionType/ActionProposal、Draft、Approval、Receipt。
- EvalSuite/EvalRun/EvalReport/ReleaseGate。
- DecisionLineage、Trace、Metric、Alert、Budget。
- MemoryCandidate/MemoryItem、Wiki Source/Freshness/Revision。
- Model Provider/Route/Catalog/Capacity。

### 3.2 电商通用 SolutionPack

- 增长参谋长、六数字同事角色定义与 37 条 Logic 能力地图。
- GrowthPlan、AgentTask、IntelligenceEvidence、EffectReview。
- `CustomerLite` 仅作为 canonical Customer 的字段受限读投影/兼容别名，不创建独立 identity、对象表或第二套生命周期；其他电商对象也只能通过已批准 O1 对象契约进入。
- 达人增长、控价/比价、每日经营闭环等 TaskTemplate 与 EvalPack。

### 3.3 平台与租户差异

- 微信小店、抖音、快手、微商城差异进入 AdapterPack。
- 栖月汇商品、渠道、策略、权限、工作台布局进入 InstanceOverlay。
- 本轮不开发微商城专项页面，不接具体平台生产 Action。

## 6. 波次治理

每阶段进入编码前必须另建当波开发清单，冻结：文件所有权、数据库迁移、OpenAPI diff、回滚、测试矩阵、浏览器步骤与证据目录。未经评审不得把本总方案直接拆成开发任务。

每波完成后必须：

1. 回读服务端真实状态并与 UI 对账。
2. 更新 `AOS项目开发上下文`。
3. 更新本总方案的“实施状态”，但不得把“文档已写”改成“代码 GREEN”。
4. 给出下一波建议；若到具体微商城 Adapter/工作台专项准入门，停止并请求决策。

## 7. 阶段依赖与并行边界

```text
AIP-0
  -> AIP-1 -> AIP-2 -> AIP-3 -> AIP-4
                                      |-> AIP-5 -|
                                      |-> AIP-6 -+-> AIP-8 -> AIP-9 -> AIP-10
                                      |-> AIP-7 -|
```

- AIP-0～AIP-4 是唯一强串行主链；数据库迁移、公共 DTO、错误码和事件 envelope 未冻结前不得并行实现上层页面。
- AIP-5、AIP-6、AIP-7 可在 AIP-4 退出后并行，但 Handoff、Memory 引用、Eval 和 Lineage envelope 由一个公共契约负责人维护。
- AIP-8 必须等待 AIP-5/AIP-6/AIP-7 共同退出；页面不得提前复制未稳定的服务端状态机。
- AIP-9 只实现内容生产与发布草稿；AIP-10 只验收通用场景，不顺带接入任何具体平台账号。
- O1 Waves 1～10 及其 D4/D5 已独立封板；AIP-10 只消费其公共契约，不重跑、不改写、不借用 O1 GREEN 作为 AIP GREEN。

## 8. 全局数据、安全与变更军规

1. `org_id/project_id` 从认证上下文解析，禁止相信客户端提交的同名字段；所有 canonical 表启用双租户 RLS、组合唯一键和负向 canary。
2. PostgreSQL/不可变 Receipt 是权威真源；Redis 只能做可重建缓存、租约或队列，不承载唯一业务状态。
3. 迁移采用 expand -> backfill -> dual-read-compare -> cutover -> contract；回填需隔离区、run_id、逐行证据和可逆脚本。
4. 删除是租户实例或绑定的生命周期变化，不能删除平台模板、历史 Receipt、Lineage 引用或其他组织资源。
5. 前端不得用 localStorage、静态数组或 fallback 数据掩盖 API 空态/错误态；所有异步操作必须显示 queued/running/succeeded/failed/unknown。
6. 所有外部副作用执行前必须重验租户、权限、revision、预算和批准；超时后进入 unknown/reconcile，不得盲重试。

## 9. 评审结论

以下架构决策已通过本轮评审并冻结为 v1.0 基线：

1. 以 PostgreSQL canonical store 收敛遗留单例，不引入新的 Redis 真源。
2. AIP-0～AIP-5 是六数字同事共同前置；不得从单个同事页面绕过公共执行和安全链。
3. Agent/Skill 采用“平台模板 + 组织实例 + 工作区运行绑定”，禁止复制六套代码或模板源文件。
4. AIP 分析师首期只读消费 O1/OKF/Wiki canonical read model；无数据返回真实空态。
5. 内容官重能力只通过 C1 Job/C2 Session Adapter 接入，禁止塞入 Function 沙箱。
6. 本方案通过仅表示“可据此生成 AIP-0 开发清单”；没有当波清单再次评审，不授权修改代码。
