# 228-AIP 模型供应、路由、容量与成本治理实施方案

> 状态：**待评审 · 不授权编码**
> 对应阶段：AIP-7（模型侧）。

## 1. 现状

供应商插件、默认网关、路由规则、凭据引用、容量页面已有较完整骨架；当前租户模型目录为空，容量使用为 0。需要完成从 provider 到 AgentRun 的真实版本和成本闭环，而不是重做页面。

## 2. 主链

```text
ProviderPlugin version
 -> Credential secretRef
 -> ProviderInstance(org)
 -> Health/egress policy
 -> ModelCatalogItem
 -> RegisteredModel
 -> ModelRouteRevision
 -> Agent/Skill binding
 -> UsageReceipt + cost attribution
```

图像模型不得自动作为文本任务 fallback；模型能力、上下文、数据出境、PII、成本和延迟必须参与路由校验。

## 3. 治理要求

- 凭据只存 secretRef，页面/日志/证据不回显密钥。
- Route 保存使用 CAS/version；试聊与生产共用同一解析器。
- 容量按 org/project/agent/task/skill/model 归因。
- 实时任务保留容量、批处理预算、熔断、降级和 kill switch 明确。
- Token/成本以 provider usage receipt 为真源；缺失显示 unknown。
- 供应商安装就绪不等于运行态，不自动改默认网关。

## 5. 验收

- Provider 未健康、模型未注册、能力不匹配、出境不允许时路由失败关闭。
- 试聊、TAOR、Logic DryRun、Eval 和生产发布解析到相同 route revision。
- 容量超限能区分排队、拒绝、fallback，且谱系可见。
- 删除/轮换凭据不泄漏旧值；旧运行仍只保留 key id/version。
- 双租户 provider、route、quota、usage 隔离。
