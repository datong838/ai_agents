# 228-AIP 六数字同事电商通用场景验收方案

> 状态：**待评审 · 不授权编码**
> 对应阶段：AIP-10（上层通用场景）。

## 1. 验收目的

用真实但只读/草稿化的电商通用任务验证 AIP，而不是用孤立按钮或 synthetic Agent 卡片验收。平台专项只提供 Adapter；场景契约保持通用。

## 2. 场景一：每日经营闭环

```text
数据健康/经营事实
 -> 数据参谋晨报
 -> GrowthPlanDraft
 -> 人工批准
 -> AgentTask DAG
 -> 五同事并行草稿
 -> 结果/阻断
 -> EffectReview
 -> MemoryCandidate
```

验收：计划 revision、任务依赖、Handoff 最小披露、证据新鲜度、失败关闭、复盘与记忆治理全链可见。

## 3. 场景二：达人邀约（只读候选 + 草稿）

- 数据参谋形成达人候选与证据；导购核验产品匹配；内容官生成个性化邀约草稿；活动策划师形成佣金/库存/毛利边界；客服协助回复分类；私域管家只维护已建立关系。
- 首期允许每天形成 100 个候选/草稿，但不自动批量发送。
- 接活、商务 revision、签约、挂链、带货效果和长期维护必须有独立状态与回执。

验收：拒绝/退订/频控、PII 最小化、重复达人、过期联系方式、无授权渠道、发送未批准均被阻断。

## 4. 场景三：控价与竞品比价（只读）

- 核心同款可配置每小时观察；重点竞品每 4 小时；类目大盘每日。能力/限流/预算不足时必须降频并显示 stale。
- 同款治理与同类目比价分流；补贴、券、会员、直播、运费、赠品和单位价单列。
- 模型只能输出异常候选，不能自动认定违法倾销、售假或恶意竞争。
- 通知/申诉/举报/调价在 G6 前不可达。

验收：两次确认、来源/hash/地区/时间、治理依据、误报、恢复新证据、调度抖动/退避/kill switch。

## 5. 统一真实数据原则

- 正向范围只用 `org-org/dev-project` 的真实上架商品、真实有效订单和授权公开数据。
- `dev-org` 只跑负向隔离 canary，不作为业务完成证据。
- PII 采用 tokenized reference；截图/导出脱敏。
- 没有真实数据时显示“无数据/待接入”，禁止自动注入 Mock。

## 6. 封板证据

每个场景输出：plan/task/run ids、精确 revisions/hashes、API 请求摘要、Artifact/Evidence refs、Eval report、Draft/Approval（如有）、Lineage、浏览器截图、跨租户 canary、风险与剩余不可达动作。

## 7. 平台专项准入门

只有当 AIP-0～AIP-10 全部退出门关闭，且三场景只读/草稿链稳定后，才进入：

1. 微商城 Adapter/工作台细分评审；
2. 微信小店/抖音/快手 capability probe；
3. 单个平台、单动作、单租户灰度。
