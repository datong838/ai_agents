## 2. 开源资产裁决

| 资产 | 可吸收 | 不可直接做的事 |
|---|---|---|
| Avernet/Deer Flow/LangGraph/Prime Agent | 编排、研究、长任务模式 | 不取代 AOS canonical Task/Run/tenant store |
| PenguinHarness/Skill Recorder | 经验/技能生成方法 | 不能自动改生产 Prompt、权限、代码 |
| HugAgentOS | 零 LLM 门控、知识治理模式 | 不复制第二本体/第二 Action 引擎 |
| Milvus/Qdrant | 向量检索实现候选 | 不成为授权、revision、source 真源 |
| Promptfoo | Eval runner 候选 | 不取代 AOS EvalReport/ReleaseGate |
| Outline/Wiki.js | UI 参考 | AGPL 不进入客户交付包 |

## 3. 状态词规范

| 状态 | 必要证据 |
|---|---|
| 已编写 | 文档存在 |
| 待评审 | 内容完整但未批准 |
| 评审通过 | 明确评审结论和版本 |
| 开发中 | 有批准清单和代码提交 |
| 验证通过 | 当前波专项测试/API/浏览器证据通过 |
| GREEN | 累计回归、跨租户、证据封板且无阻断风险 |

禁止用“页面有数据”“单测通过”“方案标完成”“静态卡片存在”替代 GREEN。

## 5. 冲突处理程序

1. 先标记冲突对象、字段、版本、来源和影响阶段，不在代码中静默选边。
2. 安全、租户、O1 authority、Action/Draft/Receipt 和 M1～M5 安装主链优先于产品探索稿。
3. 同级文档以更新且有明确评审结论、代码/API/浏览器证据者优先；只有日期而无证据不提升权威。
4. 裁决写入本表或 ADR，并同步统领方案、专项方案和 AOS 项目开发上下文。
5. 旧文件不强行改写历史，但必须标注 superseded/仅供参考，避免两个“当前方案”。

## 6. 本轮裁决结论

- 六数字同事共用 canonical Task/Agent/Skill/Action/Memory，不各自复制数据模型。
- `CustomerLite` 被裁决为 canonical Customer 的受控读投影/兼容别名，不是独立对象类型或持久化真源。
- 行业 Wiki 统一消费 O1 Wiki/KnowledgeSubject；向量库只是索引。
- FDE 复用 M1～M5 安装与证据主链、AIP Task/Checkpoint，不建设第二控制面。
- 内容官的 Function/Job/Session 类型与 Content-0～5 实施子波分名，消除 C0/C1/C2 命名冲突。
- 历史 D4/D5 仅指已封板 O1/微商城证据；AIP 使用 AIP-FDE EvidencePack 和 AIP 通用场景证据，不复用阶段名称。
- 本方案包通过后仍需单独评审 AIP-0 开发清单，不能从“评审通过”直接推导“开发中”。
