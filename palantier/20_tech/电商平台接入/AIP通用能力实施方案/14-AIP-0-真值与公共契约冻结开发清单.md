## 0. 本清单使用的 Rules

1. 本清单只冻结 AIP-0 的真值、公共契约和兼容边界；不实现 AIP-1 Task 持久化，不修改 O1 已封板能力，不接微商城或任何外部平台。
2. 以 `m1` 源码、递归路由清单、提交内 OpenAPI、迁移 head、真实 API 回读和浏览器行为共同判定真值；任一来源不一致必须先标记漂移，禁止直接重生成快照掩盖。
3. `org_id/project_id` 只取认证上下文；`org-org/dev-project` 是唯一真实正向范围，`dev-org` 只用于负向隔离 canary。
4. PostgreSQL 与不可变 Receipt/Lineage 是权威真源；进程内字典、单例、session/localStorage、静态数组和 fallback 只能标为 legacy/demo，不得晋升为 canonical。
5. 先消除并行公共路由和并行 DTO，再开放后续 AIP-1 编码；同一资源、状态或动作只允许一个公共 authority。
6. 只做最小收敛：保留仍被消费的兼容读接口；未实现能力必须失败关闭或禁用，禁止用占位成功响应维持“可用”假象。
7. 每项变更必须同时给出 owner、文件边界、兼容策略、测试、回滚和证据；清单评审通过仍不等于代码 GREEN，需用户再次明确开工。
8. 2026-08-11 用户已授权本清单及后续全量清单编码；执行仍逐波通过质量门，不把全量授权解释为绕过租户、安全、证据或外部副作用边界。
9. 后续开发仅在 `m1` 单分支、由单执行者串行完成；本文件第 8 节旧 worker 建议已被全量清单 v1.1 裁决取代。

## 1. AIP-0 目标与非目标

### 1.1 目标

- 建立可机器校验的 AIP 路由、DTO、错误码、状态机和引用契约清单。
- 将 AIP 公共 API 的 9 组重复 `method + path` 收敛为 0。
- 解释并消除源码、运行服务与已提交 OpenAPI 之间的漂移。
- 冻结 AIP-1～AIP-10 共同依赖的资源引用、异步状态、错误 envelope 和分页 envelope。
- 建立前端专用 AIP SDK 契约层，禁止页面继续直接猜测响应或用 Mock/fallback 掩盖失败。
- 给出可复验的租户、兼容、浏览器和证据退出门。

### 1.2 非目标

- 不在 AIP-0 新建 Task/Plan/Run 业务表；这些属于 AIP-1。
- 不把 TAOR、Agent、Memory、Lineage 的进程内实现直接改成生产实现；只标记 authority、禁用边界和后续归属。
- 不重做 Logic Graph、O1 Object/Link/Action、OKF 或 Wiki。
- 不改 AIP 页面信息架构和视觉布局；只处理“真实/估算/样例/不可用”的表现诚实性。
- 不产生外部副作用，不进行具体电商平台调用，不写真实业务数据。

## 4. Canonical 公共契约冻结

### 4.1 通用 envelope

所有 AIP 新公共接口统一使用：

- `ResourceRef {resourceType, resourceId, revision?, authority}`
- `TenantContext {orgId, projectId}`：仅响应/证据可返回；请求体中的同名字段不参与授权。
- `PageInfo {limit, nextCursor, hasMore}`：游标分页，不以总数作为一致性承诺。
- `ErrorBody {code, message, details, traceId}`：沿用现有 `errors.py` 形态。
- `EvidenceRef {evidenceId, evidenceType, contentHash, createdAt}`
- `ArtifactRef {artifactId, artifactType, revision?, contentHash?}`
- `ActorRef {actorType, actorId}`：不得暴露跨租户主体信息。

字段命名原则：OpenAPI/JSON 使用现有服务统一的 camelCase 输出策略；数据库保持 snake_case；Pydantic alias 负责转换，前端不得双猜字段。

### 4.2 AIP-1 前置资源 DTO

AIP-0 只冻结 schema，不发布伪实现路由：

| 资源 | 最小字段 | 冻结约束 |
|---|---|---|
| `Task` | id、type、title、status、priority、createdBy、createdAt、currentPlanRevisionId、version | `version` 用于 CAS；租户不由请求指定 |
| `PlanRevision` | id、taskId、revision、contentHash、steps、createdAt | 已运行 revision 不可变 |
| `TaskRun` | id、taskId、planRevisionId、status、startedAt、finishedAt、lastCheckpointId | 只能绑定精确 revision/hash |
| `StepRun` | id、runId、stepKey、attempt、status、inputRefs、outputRefs、error? | attempt 与幂等键可审计 |
| `Checkpoint` | id、runId、sequence、stateHash、artifactRefs、createdAt | 追加写，不覆盖历史 |
| `Artifact` | id、type、uri/ref、contentHash、metadata、createdAt | 只存引用或受控内容，不混业务对象 |
| `Evidence` | id、type、subjectRef、contentHash、source、freshnessAt、createdAt | 来源和新鲜度必填 |

### 4.3 状态机

- `TaskStatus` 直接复用并冻结 `public_contracts.py` 现有 canonical 枚举：`pending -> planning -> awaiting_approval -> approved -> executing -> paused -> completed|failed|cancelled`，`completed -> rolled_back` 只表达受控补偿后的平台状态，不删除历史事实。
- `TaskRunStatus`: `queued -> running -> succeeded|failed|cancelled|unknown`。
- `StepRunStatus`: `queued -> running -> succeeded|failed|skipped|unknown`。
- 不允许从终态回到运行态；重跑创建新 Run/attempt，不改写旧终态。
- 外部副作用超时必须进入 `unknown` 并 reconcile；AIP-0 仅冻结语义，AIP-3 实现执行闭环。
- 现有 legacy 枚举若名称不同，必须在兼容映射表中一一映射；无法无损映射的接口失败关闭。

### 4.4 引用而非复制

- Agent/Skill/Capability 使用 `ResourceRef`，详细生命周期在 AIP-6。
- ActionProposal/Draft/Approval/Receipt 使用 O1/M3 公共引用，详细状态在 AIP-3。
- Eval/Lineage/Usage 使用引用，详细模型在 AIP-4/AIP-7。
- Object/Link/OKF/Wiki 只保存 authority ID/revision/hash，不复制业务字段为 AIP 真源。

### 4.5 错误码冻结

| HTTP | code | 语义 |
|---|---|---|
| 400 | `AIP_INVALID_ARGUMENT` | schema 合法但业务参数无效 |
| 401 | `AUTH_REQUIRED` | 无有效认证上下文 |
| 403 | `AIP_SCOPE_FORBIDDEN` | 无当前组织/工作区或能力权限 |
| 404 | `AIP_RESOURCE_NOT_FOUND` | 当前 scope 内不可见；跨租户也返回该语义 |
| 409 | `AIP_VERSION_CONFLICT` | CAS/revision 冲突 |
| 409 | `AIP_IDEMPOTENCY_CONFLICT` | 同 key 不同 payload |
| 422 | `AIP_INVALID_TRANSITION` | 状态迁移非法 |
| 429 | `AIP_BUDGET_EXCEEDED` | 容量、速率或预算门拒绝 |
| 503 | `AIP_DEPENDENCY_UNAVAILABLE` | 权威依赖不可用，禁止 Mock 回退 |
| 501 | `AIP_CAPABILITY_NOT_ACTIVE` | 契约已知但当前阶段未启用 |
| 504 | `AIP_OUTCOME_UNKNOWN` | 外部结果未知，需 reconcile |

3. 9 组 AIP 重复键降为 0；全局其他历史重复另建风险账，不借 AIP-0 扩大范围。

5. `operationId`、响应 schema、错误 schema 和分页方式一经 AIP-0 封板，AIP-1～10 只能向后兼容扩展。
6. 不发布返回静态成功或 `501` 的假路由来凑 OpenAPI；未实现的 AIP-1 资源只作为 contract artifact，待实现时再进入运行 OpenAPI。

## 7. 数据库、迁移与回滚

### 7.1 本波数据库决策

AIP-0 **不新增业务表、不回填业务数据、不修改真实业务记录**。迁移输出仅包含：

- 当前 AIP 相关表/索引/RLS/constraint inventory。
- AIP-1～AIP-4 迁移依赖图和命名预留。
- 进程内 store 到 PostgreSQL 的数据分类：可丢 demo、需导出配置、禁止迁移伪业务数据。

若实现过程中发现“不加表就无法完成 AIP-0”，必须停止并重新评审清单，不得把 AIP-1 表混入本波。

### 7.2 回滚

- 回滚单位：路由 manifest、生成聚合、contract artifacts、前端 SDK/诚实性标记和 OpenAPI snapshot。
- 回滚不得恢复重复公共 authority；若兼容方必须临时恢复，只能恢复为显式 legacy 内部路径。
- 因本波无 schema/data migration，不存在业务数据反向迁移。
- 所有证据追加保存；回滚不删除失败证据。
