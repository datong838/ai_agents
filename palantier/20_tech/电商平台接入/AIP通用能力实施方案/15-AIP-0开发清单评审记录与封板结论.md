## 0. 使用的 Rules

1. 以当前源码和可执行入口复核清单，不以方案中的理想路径替代真实文件。
2. 同一公共资源只有一个 authority；不新增第二 Task 状态机、第二 Draft 写链或第二 O1 模型。
3. 评审必须覆盖路由/OpenAPI、DTO/状态、租户、迁移/回滚、前端真值、测试/证据六个门。
4. 发现问题先修清单再复审；“清单通过”不等于代码已实现或测试 GREEN。
5. 真实正向范围仅 `org-org/dev-project`；`dev-org` 只用于负向 canary。

## 4. 交叉一致性复审

1. 与 AIP v1.0 总方案一致：AIP-0 只做真值与契约冻结，AIP-1 才做 Task/Plan/Run 持久化。
2. 与 O1 封板边界一致：只引用 Object/Link/Action/OKF/Wiki，不改 schema、不重跑 D4/D5。
3. 与现有 Draft 链一致：查询/创建/拒绝归 `drafts.py`，批准写入归 `runtime_write.py`，旧 transition 不得绕权。
4. 与真实数据原则一致：不写栖月汇业务数据、不用 Mock 证明完成；页面无数据必须是真空态。
5. 与分支规则一致：清单提供四个低冲突 owner，但是否建 worker 要在开工时根据最新 worktree 再决定。
