## 2. 三个关键产品定位

### 2.1 任务协作助手不是总导航

任务协作助手的产品职责是：围绕一个真实 `Task / TaskRun / AgentRun` 建立持续对话和协作上下文，让用户能查看任务目标、计划、参与智能体、事件时间线、产物、证据、审批、取消和恢复，并通过 Receipt/Lineage 审计全过程。

当前页面在选择真实任务后仍不能建立对话线程，输入、发送、取消不可用，主体内容主要是跳转到智能体列表、业务逻辑编排、目录和可观测性。因此当前事实是“运行上下文缺口导航页”，不是已完成的协作助手。

### 2.2 AIP 分析师不是原始对象浏览器

AIP 分析师的产品职责是：让业务分析人员以中文问题选择经营对象与指标，执行受控只读语义查询，得到可理解的指标、表格、图表、结论摘要、筛选口径、来源、新鲜度、证据、归因路径、关键假设和不确定性，并可把结果保存、复用或交给任务协作链。

当前真实查询能返回 50 行栖月汇对象，但主视图仍以 `Product/niushop:1:1`、`niushop:1:1`、`deterministic_canonical_read` 和大量重复来源记录为主体；缺少商品名、订单号、客户、金额、渠道、时间、经营摘要和可理解证据。因此当前事实是“canonical 对象调试浏览器”，不是业务分析师工作台。

### 2.3 六数字同事不是状态卡片集合

六数字同事必须落实为：原子 Skill → 业务 Logic → 数字同事实例绑定 → Task/Run 执行 → 工作台贡献 → Evidence/Eval/Receipt。页面显示“已安装/已启用”但 `0/6 可派发`、工具为 0、绑定证据过期或所有操作永久禁用，只能说明目录和定义存在，不能说明数字同事可工作。

## 4. 统一缺陷分类

1. **产品职责缺失**：页面只有目录、状态或导航，没有完成一个真实工作任务。
2. **业务语义缺失**：原始对象名、ID、枚举和技术证据抢占主阅读层。
3. **交互闭环缺失**：按钮永久禁用、静默无反馈、只能跳转，不能完成创建、保存、试跑、审批、取消或回读。
4. **前后端合同缺失**：前端显示的选择、摘要或状态无法与服务端精确回包、Receipt、Lineage 对账。
5. **数字同事运行链缺失**：Agent/Skill/Capability/Logic/Tool/Model/Eval/Binding/Run 没有形成可派发组合。
6. **证据与治理缺失**：结果、来源、新鲜度、评测、谱系、可观测、记忆和成本相互割裂。
7. **导航与布局缺失**：全侧栏、分组、折叠、滚动、深链、焦点和窄屏行为不统一。
8. **状态表达失真**：内部开发缺口被当成长期产品状态，历史代码 GREEN 被外推为产品完成。

## 7. 每页完成定义

一个页面只有同时满足以下条件才可完成：

1. 用户能说清楚它服务谁、解决什么工作、输入什么、产出什么。
2. 页面至少能完成一条真实主流程，不是状态看板或总导航壳。
3. 主流程按钮均有可观察结果；没有静默 no-op、永久禁用或客户端假成功。
4. 主阅读层可被业务用户理解；技术标识不抢占业务内容。
5. 前端请求、服务端合同、数据权威、Receipt/Lineage 能精确对账。
6. 当前租户数据、可信空、安全条件和内部缺口被严格区分。
7. 视觉、滚动、折叠、深链、键盘和三视口通过内置浏览器验收。
8. 专项与累计测试通过，方案、代码和证据一致。
