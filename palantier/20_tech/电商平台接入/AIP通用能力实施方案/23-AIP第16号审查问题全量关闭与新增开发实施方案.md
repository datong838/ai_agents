## 0. 使用的 Rules

1. 本方案关闭第 16 号报告的全部 P0/P1 和完成定义，不把“已写入旧清单”视为完成。
2. 已 GREEN 的 Task/Action/Eval/Memory/Agent/W2-A 不重做；新增开发必须通过 additive authority、typed projection 或现有 owner 集成完成。
3. 所有新增波次遵循方案→代码→测试→浏览器→真实回读→上下文→提交；每一步可从 `01/06 + git log/status` 恢复。
4. `org-org/dev-project` 只使用真实数据和真实空态；`dev-org/dev-project` 只做隔离负向证据。
5. 外部知识、Provider、平台账号、数字人、TTS/视频、平台写操作和公开直播仍受独立许可/凭据/预算/安全门；代码授权不自动解除。
6. 六数字同事、10 capability、37 Logic、八公共生产对象和八工作台只保留一套 canonical identity/authority；前端、BFF、Bundle、YAML、localStorage 不建第二真源。
7. 功能完成必须证明 loading/empty/blocked/failed/stale/unknown/ready 语义；按钮存在、页面渲染或目录 published 不等于业务可运行。

## 1. 为什么需要新增本方案

第 16 号报告既是审计，也是后续开发增量来源。现有 00～15 清单主要覆盖 2026-08-11 的 38 份历史方案；17～22 已补了部分增量，但仍缺少一份统一闭环：

- W2-B～D 六个公共生产对象族尚未开发；
- AIP-7 exact 模型运行门刚完成 A7-0；
- E7 六同事个人记忆/共享投影未做；
- AIP-8 通用助手/分析师尚未接 exact Brief/Evidence/Eval/Route；
- AIP-9 仍需从固定 Agent 团队改为 ResponsibilityPlan + capability 自适应生产；
- AIP-10/FDE 与八工作台没有在同一真实生产契约上完成反向验收；
- P1 术语、Artifact/Issue/Impact、覆盖矩阵状态与 AIP-8 边界仍需代码/文档共同关闭。

本方案把这些问题变成线性增量路线，并保留外部门。

## 5. 各波次实施规格

### G0 · 审查与术语防漂移门

- 为 16/17/18/21/22/23 建立统一覆盖索引；
- canonical：AgentTemplate、SkillTemplate、CapabilityRevision、HandoffEnvelope、ResponsibilitySlot；
- 旧名只作输入 alias，不出现在新 OpenAPI output；
- 增加静态测试，禁止正式 DTO/路由再次引入 `HandoffContext` 或 Definition authority。

### W2-B · EvalContract + ResponsibilityPlan

- `w2_002_eval_responsibility` additive migration；
- EvalContract exact 绑定 AIP-4 Suite/Publication/Gate，不复制 EvalRun；
- ResponsibilityPlan slot/assignee/coverage/merge decision 使用 A6F exact instance/binding refs；
- Skill/Capability 未绑定时允许 draft，但 freeze/readiness 必须 blocked；
- SDK/UI 展示六实例候选、未覆盖 slot、独立审核冲突和机器原因码。

### E7 · 六同事个人记忆与共享投影

- memory subject 只接受 exact AgentInstanceRef；
- personal/shared 是受控投影，不复制 MemoryItem payload；
- Handoff、purpose、marking、consent、TTL、revoke、最小披露；
- content coordinator、数据参谋和其他角色只能看到任务所需投影；
- 跨租户、实例撤销、角色字符串、未授权共享全部拒绝。

### W2-C · Stage/Artifact/Review

- `w2_003_stage_artifact_review`；
- StageTemplate 签名 compiler 输出现有 PlanRevision/PlanStep，不建 StageRun；
- ArtifactRelation append-only，无环、同租户、exact hash；
- ReviewIssue aggregate + ReturnDecision event；return 产生新 Step attempt/new Artifact lineage；
- 页面支持阶段、产物族、问题定位、退回原因和恢复，不用前端状态推进真值。

### W2-D · ImpactPreview + start gate

- `w2_004_impact_start`；
- immutable preview exact 绑定 ActionProposal/Approval/Lease；依赖漂移失效；
- `production-runs/start` 组合校验 frozen Brief/Bundle/Eval/Responsibility/Stage/Route/Policy/Binding；
- 未具备 AIP-7 时稳定 blocked 且不创建半运行；
- 已具备时复用 TaskRun/AgentRun，不另建 ProductionRun 真源。

### A7-1～A7-6 · exact 模型运行

严格按 22 号方案：authority → resolver → API/旧写关闭 → AgentRun/adapter → capacity/usage → SDK/UI。任何 secret/provider/eval/price unknown 不得 ready。

### BIND-1 · 六实例与共享 capability 运行绑定

- 从 A6E 37 Skill/10 capability 的 exact refs 创建按需 Binding，不固定创建 10 个 Agent；
- Binding 只引用 secretRef、Provider/Route/Policy/Eval exact refs；
- readiness 聚合 required data/tool/license/provider/eval/route/budget；
- 没有真实 Provider 的 capability 保持 blocked；
- 第一条 runnable 只能由真实配置、Eval 与浏览器证据产生。

### P8 · AIP 助手、分析师与通用工作台

- 通用助手：TaskBrief → Plan → Knowledge/Metric query → EvidenceBundle → Draft/ActionProposal；
- 分析师：真实 OT/Metric/SavedExploration，输出决策摘要、证据链、归因路径、关键假设和不确定性；
- 只用 AIP/O1 canonical authority，不执行任意 SQL，不使用 Northampton/Mock fallback；
- 八领域 Module 只通过 SolutionPack slot 注册，AIP-8 不复制其页面与业务状态。

### P9 · 自适应内容与多媒体生产

- 内容官 Coordinator 生成 ResponsibilityPlan，不直接吞并专业 slot；
- LITE/STANDARD/FULL 都保留事实、审核、许可、预算和 Receipt；
- 10 capability 按 readiness 动态解析 Agent/Human/Tool/Provider；
- TaskBrief/Evidence/Eval/Stage/Artifact/Issue/Impact 同一 lineage；
- 文案可先在真实模型门满足后 operational；短视频/数字人按 Provider 和平台专项门分级；
- 未授权平台动作只到 Draft/预览，不发布、不推流。

### P10 · FDE/Checkpoint/rollback 集成

- 六技能链消费同一 TaskBrief/Plan/Responsibility/Route/Policy；
- 26 Reflection 使用类型化规则，禁止 Python eval/任意表达式；
- Checkpoint/rollback 复用 TAOR；
- DeerFlow 等 Harness 只能拿 scoped binding，回传真实 model/tool/usage/artifact receipts；
- 未登记 fallback、下载、子任务或费用时交付 blocked/unknown。

### W4 · 八工作台反向验收

逐一验收：日常任务总控、内容与活动、统一运营、达人邀约与签约、多媒体全过程、经营参谋、价格治理、客户关系。

每个 Module 必须具备：

- 真实 TaskBrief/Evidence/Eval/Responsibility/Stage/Artifact/Issue/Impact 投影；
- 六同事/共享能力 readiness 与 disabled reason；
- Action Draft/Approval/Receipt/unknown/reconcile；
- Memory/Candidate 最小披露；
- loading/empty/blocked/stale/failed/unknown/ready；
- 刷新恢复、浏览器点击、console 0 error、跨租户 canary；
- 无 Mock、静态在线、无效按钮、第二真源。

1. P0/P1 逐项有代码/浏览器/Receipt 证据，不再是文档裁决；

4. 10 capability readiness 逐项可解释，未具备者诚实 blocked；
5. 八工作台不建第二真源并完成真实浏览器反向验收；
6. 外部门未过的能力保持 blocked/degraded/unknown；
7. 第 16 号状态经最终复审达到 `FULLY_SUPPORTS_WORKSHOP_V3`，或明确列出仍由外部条件阻断的剩余项，不虚报完成。
