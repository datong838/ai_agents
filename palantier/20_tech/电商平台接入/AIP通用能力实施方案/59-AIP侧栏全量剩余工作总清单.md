## 0.3 本轮目标与图像/视频验收口径（用户冻结 · 2026-08-19）

### 本轮要什么

| 目标 | 含义 |
|---|---|
| **功能完善** | 侧栏各页可操作功能点可用、诚实空态/门禁可读、关键链路可走通（见 §2 / §7） |
| **视觉与页面完善** | **§1.4 二十二页专表**全覆盖；对标 foundry；轨道 G/H/I；禁方案口号主文案 |

### 图像 / 视频 · 责任边界

| 判定 | 口径 |
|---|---|
| **系统逻辑** | Binding / Route / Receipt / 幂等 / 租户隔离 / 失败关闭文案 —— 属 AIP 责任；错了才算本系统逻辑债 |
| **大模型 API** | 图像/视频生成或 Provider Health **耗时长、偶发超时、供应商侧慢/5xx** —— **归外部模型 API**，**不**默认记为本系统逻辑缺陷 |
| **禁止** | 为「赶绿」盲目抬全局 timeout、连打三探、或把供应商慢伪装成平台全绿 |

### 测试验收门（可拉长 · 可多试）

| 项 | 口径 |
|---|---|
| 文本类 | 维持既有较短验收窗（现网运维习惯即可） |
| **图像 / 视频** | **允许拉长验收等待**；**允许同一链路多试几次**（Health 三探间隔、单次调用墙钟、稳定观察窗、失败后间隔重试均可按供应商 SLA 放宽）。目标是**功能链路齐全**，不是赶时间假绿 |
| 通过条件 | 在拉长窗 + 有限次重试内：调用/健康检查能拿到**真实成功证据**（或诚实失败原因可读）；控制面投影与 Receipt 一致 |
| 不通过条件 | 平台自身逻辑错误（错绑、错租户、假绿、无 Receipt、门禁绕过）——与 API 慢/偶发无关 |

> **2026-08-19 用户再确认**：保功能全有；图片与视频 **时长可多等、可多试几次**。与 **D10/D19** 一致——慢不挡主线封板，但 **W-C\*** 仍要尽量拿到真实证据，禁止因等不起而砍功能。

### 对轨道 C 的影响

- **W-C1 / W-C2 / W-C3** 仍要做：确认链路与投影正确；但 **不得**因「供应商慢」单独把本轮功能/视觉封板卡住。  
- 供应商持续不可达时：页面诚实 `blocked` /「部分就绪」可接受；功能+视觉主线按 §7 其它轨道继续。  
- 证据里须写明：**慢 = API**，并记录实际墙钟，便于与逻辑缺陷区分。
