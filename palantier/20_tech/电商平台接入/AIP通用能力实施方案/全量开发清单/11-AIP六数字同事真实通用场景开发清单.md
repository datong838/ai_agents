## 1. 本清单边界

- 本阶段验证六数字同事如何共同完成真实电商任务，不接入新的具体电商平台。
- 六数字同事是业务角色模板，不复制 Task、Action、Memory、Wiki、Eval、Model Router 等底座。
- 电商对象、37 Logic 和 G0～G6 实现进入 `solution.ecommerce.growth`，不得把领域词汇写进 AOS 通用内核。
- 所有外部发送、改价、下架、投放、退款等动作仍须经过 Draft、审批、Lease、Receipt。
- 不以 Mock、静态演示数据或 `dev-org` 结果作为 GREEN 证据。

| 子波 | 强制前置 | 解锁结果 |

| G1 | G0、07、09；真实 OT/OKF/Wiki 水位可读 | 数据参谋每日经营与 GrowthPlan Draft |
| G2 | G1、03、06、08 通用能力 | CustomerLite 与内容/导购/客服 20 Logic |
| G3 | G2；consent/ContactPolicy/实验契约冻结 | 私域/活动 11 Logic 与跨渠道归因 |
| G4 | G3、06 治理链 | 个人/共享记忆投影和协同进化 |
| G5 | G3/G4、08、10；官方能力/测试账号专项核验 | 通用 Connector 与数字人沙箱；平台写仍受限 |
| G6 | G5、04/05、C0.2 生产写回安全门 | 受控生产 Action；严重风险仍需专项评审 |

### G0 契约、证据和安全底座

- 复用平台 `EvidenceRef/PlanEnvelope/TaskGraph/HandoffEnvelope/ReviewEnvelope`，在领域包实现 `GrowthPlanSpec/GrowthEffectReview`。
- 实现不可变 revision、CAS、幂等、RLS、职责分离、marking、DAG/Handoff 验证和只读真实空态。
- G0 不运行 Logic、不调用网络/LLM、不写生产数据；外部研究 registry 为空时可信失败。

退出门：相同 ID 双租户隔离、修改使旧批准失效、创建人不能自批、重启可回读、路由无碰撞、生产写路径不可达。

### G1 每日经营最小闭环

- 实现 D01～D06、MetricQuery、Observation、GrowthPlan Draft、AgentTask DAG、ExecutionObservation 和 EffectReview。
- 消费 12 OT 真实水位、OKF、Wiki 和有引用的外部 ResearchJob；数据不足允许“无动作/INCONCLUSIVE”。
- 建经营参谋工作台：健康、证据、计划、审批、任务、阻塞、效果和回放。

### G2 CustomerLite 与三个核心同事

- CustomerLite 仅是 canonical Customer 的字段受限读投影/兼容别名，默认不含姓名、手机号、地址、OpenID、支付凭据和聊天原文。
- 实现 `ContentBrief/ContentAsset/ContentVariant/LeadSignal/ConsultationSession/Recommendation/ServiceCase`。
- 交付 C01～C08、G01～G06、S01～S06 共 20 条 Logic；所有外发、承诺、优惠、退款和订单写回保持 Draft-only。

退出门：撤回 consent、删除、CAS、PII 扫描、库存/价格过期、医疗/功效越界、承诺和人工升级负向门通过。

### G3 私域、活动和跨渠道分析

- 交付 P01～P05、A01～A06；增强 D05/D06 的跨渠道、实验和归因能力。
- 实现 ContactPolicy、consent、退订、允许用途/渠道、频控、静默时段、小样本抑制。
- 实现 Campaign/Experiment、assignment 冻结、污染检测、预算/毛利/库存/履约护栏和归因口径版本。

### G4 多智能体记忆与协同进化

- 任务经历形成 MemoryCandidate，经过 06 的去敏、去重、冲突、适用范围、Evals 和批准后发布 MemoryItem。
- 六角色分别定义个人记忆策略；共享区只保存受治理投影，不共享工作记忆或敏感会话。
- Working/Episodic/Semantic 为运行记忆；Procedural 作为 Skill/Logic/Policy/Playbook 版本资产。
- “越用越聪明”必须由事实准确率、护栏违规率、人工修改率、首次通过率和业务效果 Eval 证明。

### G5 Connector、渠道能力和数字人直播

- 建通用 Connector/OAuth/Webhook/签名/重放/限流/回执和 CapabilitySnapshot；不宣称任何平台当前具备具体写能力。
- 对视频号、朋友圈、抖音、小红书、今日头条、闲鱼六个渠道分别登记官方证据、账号权限、读写能力、版本和复核时间。
- 消费 08 的 ContentVariant、14 Harness Skill 和直播 L0～L3；L4/L5 真实平台能力保持 deferred。
- 所有渠道发布、评论、私信、投流和开播默认 Draft/manual，只有 G6 明确批准才可能执行。

### G6 受控生产 Action 与经营自动化

- 基于 04 实现领域 ActionProposal、risk、maker-checker、预算/频控、ExecutionLease、Receipt、kill、补偿和 reconcile。
- 超时或平台结果不明进入 `unknown/reconcile`，禁止盲重试；补偿也是新的受控 Action。
- 支付、退款、库存扣减、账户权限等严重风险动作默认禁止自动执行，需专项安全评审。

G0～G6 必须顺序封板；某子波方案/实现 GREEN 不自动授权下一子波。

## 6. SC06 日常运营巡检详细链路

1. 读取 12 个 OT 的新鲜度、水位、失败 Receipt 和权威口径。
2. 数据参谋生成“机会/异常/无动作”三类结论，禁止强行产生建议。
3. 私域管家、导购顾问、内容官、客服专员按建议并行生成只读分析或 Draft。
4. 活动策划师仅在达到活动条件时介入，负责节奏、依赖和 Checkpoint。
5. 汇总任务完成度、业务指标、未决风险和人工待办。
6. 将经过反馈的结论写为 MemoryCandidate，不直接提升为长期知识。

验收：一条经营任务能从触发、计划、交接、执行、审批、证据、复盘完整回放。

## 8. SC08 全网同款控价与同类目比价详细链路

1. 分离“同款控价”和“同类目竞品比价”两种任务，不混用结论。
2. 规范商品匹配：条码、规格、单位、净含量、SKU、店铺、渠道和相似度。
3. 归一化到单位价格，并显式拆分券、补贴、运费、赠品、会员价和直播价。
4. 每次异常至少保留两次独立观测、页面证据、采集时间和来源链接。
5. 数据参谋识别价格异常；导购顾问解释竞争差异；活动策划师安排复查节奏。
6. 客服专员/私域管家仅生成沟通 Draft；禁止自动投诉、恶意下单退货或自动改价。
7. 开发阶段采用节制的定时策略，避免高频拉取外部平台；频率由平台规则和真实业务需要评审后确定。

## 9. 调度、限流与失败处理

- 每个场景必须配置最大候选数、并发数、预算、超时、重试和停止条件。
- 数据过期、来源不可用、模型降级、审批超时分别进入明确状态，禁止伪装成功。
- 外部副作用超时统一进入 `unknown/reconcile`，由对账任务确认最终事实。
- 定时任务保存 Schedule、Run、Receipt、checkpoint 和水位，不靠前端内存计时。

## 10. 页面与交互任务

- 六数字同事总览：角色、当前任务、阻塞、能力绑定和最近效果。
- 协作任务图：Task DAG、Handoff、Checkpoint、审批与 Receipt。
- 达人任务台：候选、去重、筛选、草稿、回复、签约、效果、长期维护。
- 控价比价任务台：同款/同类目切换、价格构成、证据时间线、复查计划。
- 日常经营大屏：数据新鲜度、机会、异常、待审批和业务结果。
- 增长参谋长工作台：Evidence、GrowthPlan revision、审批、37 Logic readiness、Task DAG、Observation、EffectReview。
- CustomerLite/内容/导购/客服/私域/活动工作台：按组织实例、权限、用途和最小披露显示。
- Logic Catalog：37 条 Logic 的状态、版本、Eval、Tool/知识依赖和 blocked 原因。
- 所有按钮必须有真实后端契约、权限、成功/失败反馈；无契约按钮不得展示为可用。

## 11. 测试与浏览器验收

- 单元测试：派发规则、去重、价格归一、频控、风险分级、结果回写。

- 浏览器：逐页操作正常、空态/失败态/恢复态完整，真实租户数据与 API 一致。
- 真实验收覆盖 SC01～SC09；外部副作用未授权的场景以真实输入+Draft/blocked/沙箱完成，不能伪造平台成功回执。
- 37 Logic 做 37/37 contract/Eval/readiness 盘点；分波未发布 Logic 必须显示 blocked/deferred，而不是静态成功。
- G0～G6 各自独立 EvidencePack、租户 canary、浏览器流程和回滚/停止演练。
