## 使用说明

天猫品牌旗舰店的 AOS 对接**已在淘宝天猫合并方案中完整覆盖**。

### 为什么合并？

| 维度 | 淘宝 C 店 | 天猫品牌店 | 结论 |
|------|----------|-----------|------|
| 开放平台 | 淘宝开放平台（TOP） | 同一个 TOP | ✅ 统一接入 |
| 认证 | app_key + access_token | 同一个 OAuth | ✅ 统一认证 |
| 订单/物流/会员 API | taobao.trades.* / taobao.logistics.* / taobao.crm.* | **完全相同** | ✅ 统一 API |
| 商品发布 API | taobao.item.add（JSON） | tmall.item.schema.add（XML Schema） | ⚠️ 唯一差异 |

### 天猫独有内容覆盖点

在主方案中已专门覆盖的天猫独有内容：

| 差异点 | 覆盖位置 | 说明 |
|--------|---------|------|
| Schema XML 商品发布 | 主方案 §3.1 + 02-天猫Schema体系分析.md | 7 种 Field Type / 18 种 Rule / Depend-Group / 增量更新 |
| 品牌旗舰店认证 | 主方案 §3.6 | shop_type = "tmall" |
| 天猫会员等级 | 主方案 §3.3 | T1-T6 天猫会员 + 淘宝会员（双轨） |
| 天猫评分体系 | 主方案 §3.6 | DSR 三项 + 综合评分 + 品牌力 |
| 天猫营销活动 | 主方案 §3.7 | 聚划算/百亿补贴/超级品牌日 |
| 天猫国际 | 未覆盖 | 保税仓/跨境清关（待跨境方案补充） |

### 需要这份文档的场景

仅当以下条件成立时才需要独立天猫方案：
- 天猫和淘宝的 Ontology Object Type 需要**完全独立建模**（而非共用）
- 天猫有专属的数据治理/合规要求（隐私脱敏、数据出境等）
- 天猫国际（跨境）业务有独立需求

**当前阶段：直接使用淘宝天猫合并方案即可。**
