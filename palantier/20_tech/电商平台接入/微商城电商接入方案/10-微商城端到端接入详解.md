## Stage 1 · 数据接入（Data Connection）

### 1.1 连接器配置

| 项 | 配置 |
|----|------|
| 连接器类型 | **JDBC · MySQL**（AOS 内置 JDBC Connector） |
| 连接方式 | **Agent 代理**（SSH 隧道 `127.0.0.1:13306` → 线上库） |
| 认证方式 | 用户名/密码（只读账号） |
| 数据库 | `niushop_b2c_v5`（~302 张 `ns_*` 表） |
| 租户隔离 | `site_id=1`（单租户），多小程序 `weapp_id`（11/10/9） |

## Stage 2 · 数据同步（Sync）

### 2.1 同步策略

| 域 | 事务类型 | 增量列 | 调度周期 | 说明 |
|----|----------|--------|----------|------|
| T0 租户/端 | SNAPSHOT | — | 每日 02:00 | 配置类，量小变更少 |
| T1 会员 | APPEND | `update_time` | 每 30 分钟 | PII 标记 |
| T2 商品 | SNAPSHOT | — | 每 1 小时 | 多子表分 Sync 或库侧 VIEW |
| **T3 订单** | **APPEND** | **`create_time`** | **每 5 分钟** | **态势感知核心**，短周期保新鲜 |
| T4 履约 | APPEND | `update_time` | 每 15 分钟 | |
| T5 特色 | APPEND | `create_time` | 每 1 小时 | |
| T6 内容 | SNAPSHOT | — | 每日 03:00 | |

### 2.2 SQL 查询示例（订单增量同步）

```sql
-- 增量拉取新订单
SELECT order_id, order_no, order_money, member_id, create_time, pay_time,
       delivery_status, order_status, weapp_id, site_id, refund_status,
       coupon_money, point_money, real_money, -- ... 130+ 列
FROM ns_order
WHERE create_time > ?
ORDER BY create_time ASC
```

### 2.3 落盘 Dataset

- 路径：`/Foundry/Niushop/{domain}/{table}`
- 格式：Parquet + Iceberg
- 特殊：`ns_order` 全量 ~12,847 行，130 列

## Stage 3 · 管道清洗（Pipeline Builder）

### 3.1 订单关系网 Join 链

```
ns_order（130列）
  ├── Join Inner  → ns_member（补全：客户名称、会员等级、手机号）
  ├── Join Left   → ns_order_goods（补全：SKU 列表、数量、单价）
  │    └── Join Left → ns_goods_sku → ns_goods（补全：品牌、类目、图片）
  ├── Join Left   → ns_express_delivery_package（补全：运单号、签收状态）
  ├── Map         → ns_order / ns_order_goods 的退款状态（不存在 ns_order_refund 表）
  └── Join Left   → ns_member_shop_share_experience（补全：分享体验码、分润标记）
```

### 3.2 类型转换（Cast 组件）

| 列 | 源类型 | 目标类型 | 说明 |
|----|--------|----------|------|
| `order_money` | VARCHAR | DECIMAL(12,2) | 金额字符串转数值 |
| `create_time` | INT（时间戳） | DATETIME | Unix 时间戳转日期 |
| `pay_time` | INT | DATETIME | |
| `is_paid` | TINYINT | BOOLEAN | 0/1 → false/true |
| `delivery_status` | INT | ENUM | 状态值必须从真实分布与 Niushop 字典冻结，不凭经验硬编码 |

### 3.3 Niushop 特色处理

- **多小程序隔离**：`weapp_id` 作为属性保留，不物理分割数据
- **分润流水**：`ns_member_shop_commission_log` 独立 Join，计算店主分润
- **商品多子表**：PB 无多表 Join 时用库侧 VIEW `v_aos_goods_sku_flat`

## Stage 4 · OKF 映射（Funnel）

### 4.1 OT 映射表

| 源表 | 统一 OT | 主键 | 关键映射 |
|------|---------|------|----------|
| `ns_order` | **Order** | `order_id` | order_no→order_no, order_money→amount, delivery_status→delivery_status |
| `ns_member` | **Customer（D2 延后）** | `member_id` | 先完成 PII 最小化、访问控制与统一 OT 契约 |
| `ns_goods` | **Product** | `goods_id` | goods_name→title, price→price, category_id→category |
| `ns_goods_sku` | **ProductSku** | `sku_id` | sku_name→sku_name, price→price |
| `ns_order_goods` | **OrderLine** | `order_goods_id` | goods_id→product_id, sku_id→variant_id, real_money→line_total |
| `ns_pay` | **Payment（D2 延后）** | `id` | 先完成支付安全与统一 OT 契约 |
| `ns_express_delivery_package` | **Shipment** | `id` | express_no→tracking_no, express_code→carrier |
| `ns_store` | **Store** | `store_id` | store_name→name, address→location |
| `ns_member_shop_share_experience` | **ShareExperience** | `id` | 体验码、分享人、核销状态 |
| `ns_member_shop_commission_log` | **CommissionLog** | `id` | 金额、比例、结算状态 |

### 4.2 Funnel 状态机

```
created → unpaid → paid → delivering → completed
                 ↘ refunding → closed
```

## Stage 6 · 上层消费

### 6.1 COP 态势指标

| 指标 | 数据源 | 刷新 |
|------|--------|------|
| 今日新单数 | Order OT | 5 min |
| 待发货数 | Order.status=paid | 5 min |
| 三 weapp 单量切片 | Order.weapp_id | 5 min |
| 低库存 SKU | ProductSku.stock | 1 h |
| 分润异常 | CommissionLog | 1 h |

### 6.2 平台缺口（微商城暴露）

| 缺口 ID | 描述 | 优先级 |
|---------|------|--------|
| G-PB-01 | Pipeline 无多表 Join（需 VIEW 或分表） | P0 |
| G-JDBC-01 | JDBC 单表/弱多 query | P0 |
| G-RT-01 | 无 CDC/真推送（态势非秒级） | P1 |
| G-COP-01 | COP 指标难绑自定义 OT | P0 |
| G-OKF-01 | OKF Bundle 一键导入 | P2 |
