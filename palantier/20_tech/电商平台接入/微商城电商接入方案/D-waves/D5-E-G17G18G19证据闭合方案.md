## 4. G17 派生指标全量重算

### 4.1 验收标准与上位规格同步门（v2.7）

D4 §7 D1 只明确冻结了三项阈值：
- `quality_score` ≥ 90%（Product 有评价就有分）
- `stock_health` ≥ 85%
- `pay_duration_min` 在已支付订单上 100%

其余 5 项的 eligible denominator 与建议阈值尚未写入 D4。D5 只能提出诊断建议，不能作为下位文档反向修改上位验收标准。因此新增前置门：

> **G17-SPEC**：D4 §7 D1 必须正式补齐 8 项指标各自的 eligible denominator、阈值、null 语义和空集合判定，并记录 D4 文档版本/hash。G17-SPEC 未通过时，D5 可以输出诊断结果，但 G17 不得判最终 GREEN。

> **D4-SPEC-SYNC**：D4 还必须把 Link 总数修正为“枚举项一致的 14 条”，冻结各 OT 的 Canonical ID 规则，并把固定 `org-other/proj-other` 改为“运行级唯一临时 scope”的语义。本文不越权修改 D4；同步完成前可实施 O1 的安全底座，但不得宣告总体 D4 GREEN。

以下表中，D4 已冻结的三项标记为“权威”；其余五项标记为“建议，待 D4 接纳”：

| 派生指标 | OT | 阈值 | eligible denominator（冻结） | null 语义 | 空集合保护 |

```python
    "CHECKPOINT_REGRESSION": "VALIDATION_ERROR",
}

# source_error_code 只允许以下稳定规范码；禁止直接保存任意异常类名。
SOURCE_ERROR_CODES: frozenset[str] = frozenset({
    *_ECOM_ERROR_CODE_MAP.keys(),
    "CONNECTION_ERROR", "TIMEOUT", "OS_ERROR", "SQL_INTEGRITY_ERROR",
    "VALUE_ERROR", "KEY_ERROR", "TYPE_ERROR", "UNCLASSIFIED_EXCEPTION",
})

def classify_pipeline_error(exc: Exception) -> ErrorClassification:
    """返回规范分类码 + 可检索的领域原码。

    只用于 handle_failure 路径（有异常对象的场景）。
    POST /v1/dlq 路径不经过此函数（见 §5.3）。
    """
    # 1. EcomConsistencyError：读取领域错误的 code
    if isinstance(exc, EcomConsistencyError):
        source_code = (
            exc.code if exc.code in _ECOM_ERROR_CODE_MAP
            else "UNCLASSIFIED_EXCEPTION"
        )
        return ErrorClassification(
            error_code=_ECOM_ERROR_CODE_MAP.get(exc.code, "VALIDATION_ERROR"),
            source_error_code=source_code,
        )

    # 2. 网络/连接异常
    if isinstance(exc, TimeoutError):
        return ErrorClassification("SOURCE_CONNECTION_ERROR", "TIMEOUT")
    if isinstance(exc, ConnectionError):
        return ErrorClassification("SOURCE_CONNECTION_ERROR", "CONNECTION_ERROR")
    if isinstance(exc, OSError):
        return ErrorClassification("SOURCE_CONNECTION_ERROR", "OS_ERROR")

    # 3. SQLAlchemy IntegrityError（理论不应绕过 EcomConsistencyError，但防御性映射）
    if exc.__class__.__name__ == "IntegrityError":
        return ErrorClassification("STORE_CONFLICT", "SQL_INTEGRITY_ERROR")

    # 4. 数据校验异常
    if isinstance(exc, ValueError):
        return ErrorClassification("VALIDATION_ERROR", "VALUE_ERROR")
    if isinstance(exc, KeyError):
        return ErrorClassification("VALIDATION_ERROR", "KEY_ERROR")
    if isinstance(exc, TypeError):
        return ErrorClassification("VALIDATION_ERROR", "TYPE_ERROR")

    # 5. fallback：规范分类仍 fail-closed；不保存原始类名
    return ErrorClassification("VALIDATION_ERROR", "UNCLASSIFIED_EXCEPTION")
```

**关键约束**：
- 不再把所有异常包装成 `RuntimeError`
- `handle_failure` 调用时传入**原始异常**
- `EcomConsistencyError` 的 code 是权威冲突的真实来源（代码核查确认 store 使用 `EcomConsistencyError("IDEMPOTENCY_CONFLICT")` 等）

### 5.3 POST /v1/dlq 独立请求契约

POST /v1/dlq 没有 Exception 对象，不能共用 `classify_pipeline_error`。

**冻结**：POST /v1/dlq 要求 body 中显式传 `error_code`，不自动推断；同时必须通过 `Idempotency-Key` 请求头提交幂等键。`org_id/workspace_id/dlq_id/status/retry_count` 均由服务端生成或维护，客户端不得提交。

```python
# POST /v1/dlq 请求契约（v2.6 冻结）
# Header: Idempotency-Key: <1..160 chars>
{
    "error_code": "SOURCE_CONNECTION_ERROR|STORE_CONFLICT|VALIDATION_ERROR",
    "source_error_code": "可选；如 DANGLING_LINK/IDEMPOTENCY_CONFLICT",
    "pipeline_id": "P01-shop-qyh",
    "reason": "可选的人类可读原因",
    "metadata": { ... }  # 可选的附加上下文
}

# 服务端处理：
# 1. 验证 error_code 在三类规范码白名单内
# 2. source_error_code 只接受 SOURCE_ERROR_CODES，不允许自由文本或任意异常类名
# 3. 递归脱敏 reason 和 metadata
# 4. 对脱敏后的规范 payload 计算 request_hash/payload_hash
# 5. 同一 scope + Idempotency-Key：同 hash 原样返回既有 dlq_id；异 hash 返回 409
# 6. 首次写入 ecom_dlq，状态固定为 open、retry_count=0
```

`handle_failure()` 不依赖客户端请求头：幂等键由服务端按
`sha256(run_id, pipeline_id, stage_id, attempt_no, canonical_error_code)` 生成；其中 `run_id/attempt_no`
必须来自持久化 Pipeline Run，不得使用进程随机 UUID 伪造可重放身份。返回兼容字段 `id`
等于规范 `dlq_id` 的字符串形式，保持现有 `/v1/dlq/{dlq_id}/retry` 路径可用。

### 5.4 G18 PII 策略冻结（v2.6）

**冻结策略**：**敏感键可以保留，但其值必须为 `[REDACTED]`**。"键名零泄漏"修正为"敏感键的**原始值**零泄漏"。

```python
# 脱敏器：保留键，值替换
PII_FIELD_DENYLIST: frozenset[str] = frozenset({
    "mobile", "telephone", "phone", "address", "full_address",
    "wx_openid", "openid", "nickname", "avatar", "reg_address",
    "last_login_ip", "password", "pay_password",
    "invoice_full_address", "invoice_email",
    "refund_address", "refund_address_id",
})

def _sanitize_pii_recursive(obj, key_name: str = ""):
    """递归脱敏：敏感键保留，值替换为 [REDACTED]。

    匹配规则：k.lower().startswith(denylisted)
    （覆盖 nickname_test, mobile_backup 等变体）
    """
    if isinstance(obj, str):
        return _sanitize_pii(obj)  # 原有 regex 脱敏（值层面）
    elif isinstance(obj, dict):
        result = {}
        for k, v in obj.items():
            if isinstance(k, str) and _is_pii_key(k):
                result[k] = "[REDACTED]"  # 键保留，值替换
            else:
                result[k] = _sanitize_pii_recursive(v, k)
        return result
    elif isinstance(obj, list):
        return [_sanitize_pii_recursive(v, key_name) for v in obj]
    return obj

def _is_pii_key(k: str) -> bool:
    """检查键名是否是 PII 字段（前缀匹配，不精确匹配）。"""
    kl = k.lower()
    return any(kl.startswith(d) for d in PII_FIELD_DENYLIST)
```

**验证器与脱敏器的一致性**（v2.6）：

```python
def _assert_no_pii(entry: dict):
    """递归检查：denylist 键值已替换，任何字符串都不命中生产 PII 正则。

    v2.4 统一：
    - 敏感键可以保留（不报错）
    - 但敏感键的值必须是 [REDACTED]（否则报 value_not_redacted）
    - 每个字符串复用生产 `_find_pii_matches()`，不能只检查固定测试 needle
    """
    leaked = []
    def _scan(obj, path=""):
        if isinstance(obj, dict):
            for k, v in obj.items():
                if isinstance(k, str) and _is_pii_key(k):
                    # 键是 PII → 值必须被替换为 [REDACTED]
                    if v != "[REDACTED]":
                        leaked.append({"path": f"{path}.{k}", "type": "value_not_redacted", "key": k})
                if isinstance(v, str):
                    for pii_type, match in _find_pii_matches(v):
                        leaked.append({
                            "path": f"{path}.{k}", "type": "value_pattern",
                            "pii_type": pii_type, "match_hash": deterministic_hash(match),
                        })
                _scan(v, f"{path}.{k}")
        elif isinstance(obj, list):
            for i, v in enumerate(obj):
                _scan(v, f"{path}[{i}]")
    _scan(entry)
    assert not leaked, f"PII leaked: {leaked}"
```

测试数据必须覆盖已知样本、嵌套 dict/list、大小写键、Unicode、带分隔符号码，以及由固定 seed
生成的随机号码/邮箱变体。失败报告只输出路径、PII 类型和匹配值 hash，不回显原始敏感值。

#### 5.6.1 三种真实失败路径 + 独立 errorCode

## 6. G19 租户隔离 100%

### 6.1 五组验证矩阵（v2.6）

| 组 | 场景 | 租户 A | 租户 B | 验证 | 判定标准（严格） |
|----|------|--------|--------|------|----------------|
| 1 | 不同 org + 不同 ws | 临时 org-A/ws-A | 临时 org-B/ws-B | 双向查不到对方 canary | **双向 count == 0** |
| 2 | 相同 org + 不同 ws | 临时 org-A/ws-A1 | 临时 org-A/ws-A2 | 双向查不到对方 canary | **双向 count == 0** |
| 3 | 不同 org + 相同 ws 名 | 临时 org-A/shared-ws | 临时 org-B/shared-ws | 双向查不到对方 canary | **双向 count == 0** |
| 4 | **缺失组织** | 不发 X-Org-Id | — | **必须明确拒绝** | **HTTP 401** |
| 5 | **缺失工作区** | 发 X-Org-Id 但不发 X-Project-Id | — | **必须明确拒绝** | **HTTP 401** |

**补充验证**（不单独编号但必须执行）：
- **未知组织**：已认证请求的 X-Org-Id=不存在的 org → 403
- **未知工作区**：已认证请求的 X-Project-Id=不存在的 project → 403
- **Claim 与 Header 冲突**：JWT claim org=X，Header org=Y → 403
- **A 看不到 B、B 也看不到 A**：双向验证
- **真实租户只读**：从 `org-org/dev-project` 只读抽取一个既有真实对象 identity；临时 scope 查询该 identity 必须为 0。不得在真实 scope 创建 canary、DLQ、Receipt 或临时安装
- **真实租户越权写零落库**：在显式事务中绑定 `org-org/dev-project`，尝试写入其他 scope 的租户键，必须由 RLS 拒绝并整体回滚；前后动态基线完全一致

```python
# 绑定后由 tenant_directory_service.require_workspace(org, project)
# 验证 twa_workspace 存在；未知 scope 明确拒绝，不能构造 Principal。
```

**统一入口覆盖要求**：`resolve_principal()` 的 OIDC、Header fallback、`token == DEV_TOKEN`、middleware request.state 四条路径不得各自实现默认租户；它们必须复用同一绑定器及目录校验服务。任何路径出现字面默认值 `dev-org/dev-project` 都视为 G19 失败。

**v2.6 冻结约束**：

| 环境 | 无 header / 未知 org 行为 | 预期 |

### 6.5 RLS FORCE（v2.6）

**代码核查确认**：
- ecom_object/ecom_link 已在迁移中设置 `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY`
- 事务变量是 `aos.org_id` 和 `aos.project_id`（不是 `app.current_org`）
- `aos_runtime` 是运行角色，表 owner 通常也是 `aos_runtime`

**v2.6 冻结断言**：

| 测试对象 | 测试方法 | 断言 |
|---------|---------|------|
| `aos_runtime` 运行角色 | 显式事务内 `SET LOCAL ROLE` + `set_config(..., true)` | 只能看到当前 scope，事务结束后角色/GUC 自动恢复 |
| 表 owner 在 FORCE RLS 下 | 用 owner 身份查询，设置不同 GUC | FORCE RLS 让 owner 也受约束 |
| 超级用户 | **不作为 RLS 隔离断言对象**（超级用户和 BYPASSRLS 角色可以绕过 RLS） | 只用于审计和清理 |
