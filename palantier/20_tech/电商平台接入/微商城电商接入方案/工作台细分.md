## 一、定位：从"后台管理"到"数字同事"

### 1.1 重要前提：后台已有，不重复造

微商城基于 **Niushop B2C v5**，后台管理系统已具备完整的电商管理能力：商品上下架、订单发货、会员管理、分润配置、体验码补发、营销活动配置、内容发布等。**这些不是本文档的重点。**

本文档的重点是：**6 个数字同事如何对接微商城真实数据（302 表 + 315 API）落地**，让运营在 AOS 工作台获得"会思考、会执行"的数字同事，而非又一个静态后台。

### 1.3 与公域平台差异（数字同事视角）

| 维度 | 微商城（私域）数字同事 | 公域平台数字同事 |
|------|---------------------|----------------|
| **客户定义** | Member + 店主资格(`has_shop_qualified`) + 端绑定(`member_weapp`) | 买家/粉丝 + 关注关系 |
| **触达渠道** | 企微/短信/公众号/小程序消息 | 站内信/客服/评论/直播 |
| **订单流程** | 创单三板斧 + `share_member` + `X-Weapp-Id` | 各平台订单流程 |
| **特色业务** | 店主分润 + 分享体验码 + 超级卡 + 三端横切 | 直通车/巨量算数/直播带货 |
| **数据源** | Niushop 302 表（JDBC + Schedule） | 各平台开放 API |
| **端隔离** | 三小程序横切(`weapp_id`) | 无横切或单端 |

### 2.3 三小程序横切处理：weapp_id 作为 OT 属性贯穿

| 域 | 横切字段 | 影响 |
|----|---------|------|
| 会员 | `member_weapp.weapp_id` | 同一会员可绑定多端；按端筛选客户 |
| 订单 | `order.weapp_id` | 订单按端隔离；三端 GMV 独立统计 |
| 支付 | `pay.weapp_id` | 支付单按端隔离 |

### 3.2 技能1 客户沉淀：店主 + 消费老客导入

```
查询 ns_member（has_shop_qualified=1 店主 + order_money>0 消费老客）
  + ns_member_weapp（端绑定：栖月汇11/源仓集10/聚味台9）
  + ns_member_shop_commission_log（分润客户识别）
        │
        ▼
按 LTV 排序 → 分批（每日≤10，防封频控）
        │
        ▼
LLM 生成个性化企微好友申请话术（基于消费历史）
        │
        ▼
action_writeback: AddToWeCom（需审批）
        │
        ▼
记录到 Episodic Memory
```

**数据对接**：
- 表：`ns_member`（`has_shop_qualified`、`order_money`、`order_num`、`member_level`）+ `ns_member_weapp`（端绑定）
- API：`GET /api/membershop/customerList?page={p}&page_size={n}`（店主客户列表，需 token）
- 输出：导入方案（批次/话术/频控）

### 3.5 技能4 跟进排期：体验码 + 分润异常驱动

| 触发条件 | 数据源 | 跟进动作 |
|---------|--------|---------|
| 体验码 `status=pending` 超过 3 天未领取 | `member_shop_share_experience` | 提醒店主领取 |
| 体验码 `status=claimed` 超过 7 天未发货 | `member_shop_share_experience` | 提醒发货 |
| 分润 `commission_log.status` 异常 | `member_shop_commission_log` | 通知店主 + 转客服 |
| 老客 R 远（30 天未下单） | `member` + `order` | 复购提醒触达 |

### 3.6 技能5 主动提醒：定时巡检

```
定时巡检（每日 09:00 / 14:00 / 20:00）
  ├─ ns_order.pay_status=0（未支付订单 → 提醒支付）
  ├─ ns_order.order_status=1 & delivery_status=0（待发货 → 提醒发货）
  ├─ ns_order.refund_status>0（异常退款 → 转客服）
  ├─ ns_member_shop_share_experience.status=pending 过期（体验码过期）
  ├─ ns_member_shop_commission_log 异常（分润未结算/金额异常）
```

> 通用技能链来源：`../11-AIP决策引擎升级方案/08-数据参谋技能编排.md`（6 技能）
> 数据参谋管"为什么"：异常检测 → 归因分析 → 趋势预测 → 用户画像 → 决策建议 → 自动报告

### 8.1 技能 × 微商城数据对接总表

| 技能 | 微商城数据源（表） | 关键字段 | 对接路径 | 输出 |
|------|------------------|---------|---------|------|
| 1.异常检测 | `order` · `pay` · `member_shop_commission_log` · `member_shop_share_experience` | 订单状态分布异常 + 支付异常 + 分润异常 + 体验码核销异常 | AOS JDBC 查询（非 Niushop API） | 异常告警 + 初判原因 |

### 8.2 数据参谋的特殊性：走 AOS 而非 Niushop API

> **重要**：数据参谋是唯一**不走 Niushop API**的数字同事。它直接消费 AOS Ontology（JDBC 同步的 302 表），因为：
> - Niushop API 面向 C 端交易，不适合全量分析查询
> - AOS OT 已通过 JDBC Sync 保持态势新鲜度（订单 1~5 min）
> - 数据参谋需要跨表聚合、全量扫描，API 无法支撑

```
ns_* 302 表（JDBC 只读）
  │
  ▼
AOS Dataset（按域 T0~T10 分级）
  │
  ▼
Ontology OT（Member/Order/Goods/...）
  │
  ▼
数据参谋 ontology_query（跨表聚合、全量扫描）
  │
  ▼
异常检测 / 归因 / 趋势 / 画像 / 建议 / 报告
```
