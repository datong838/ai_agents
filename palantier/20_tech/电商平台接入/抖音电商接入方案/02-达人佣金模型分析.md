## 1. 四角模型概述

抖音电商与其他平台最大的差异在于 **达人带货体系**。每一笔通过达人推广成交的订单，涉及四方利益分配：

```text
                    ┌─────────────┐
                    │   消费者     │  下单购买
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │   订单       │  GMV（交易额）
                    └──┬───┬───┬──┘
                       │   │   │
          ┌────────────┘   │   └────────────┐
          ▼                ▼                ▼
   ┌──────────────┐  ┌──────────┐   ┌──────────────┐
   │  达人/主播     │  │  商家     │   │  抖音平台     │
   │ author_amount │  │shop_amount│   │platform_amount│
   │  (佣金)       │  │ (实收)    │   │  (抽佣)       │
   └──────────────┘  └──────────┘   └──────────────┘
          │
          ▼
   ┌──────────────┐
   │  MCN 机构     │  从达人佣金中抽成（可选）
   │ agency_amount │
   └──────────────┘
```

| 角色 | 金额字段 | 含义 |
|------|---------|------|
| **消费者** | `pay_amount` | 实付金额（GMV） |
| **达人/主播** | `author_amount` | 达人佣金（推广报酬） |
| **商家** | `shop_amount` | 商家实收（GMV - 佣金 - 平台扣点） |
| **平台** | `platform_amount` | 平台扣佣（技术服务费） |
| **MCN 机构** | `agency_amount` | 从达人佣金中抽成（仅签约达人有） |

> **核心公式：** `pay_amount = author_amount + shop_amount + platform_amount`  
> 其中 MCN 从 `author_amount` 中再分配。

## 2. 佣金设置机制

### 2.1 精选联盟佣金

商家在精选联盟后台为商品设置推广佣金比例：

```
商品 GMV 100 元
├── 佣金比例 20% → 达人佣金池 = 20 元
│   ├── 达人实得 author_amount = 20 × (1 - 平台服务费率)
│   ├── 平台从佣金中扣除技术服务费
│   └── MCN 从达人佣金中抽成（如有）
├── 商家实收 shop_amount = 100 - 20 - 平台扣点
└── 平台扣点 platform_amount = GMV × 平台费率（通常 1%-5%）
```

### 2.2 佣金类型

| 类型 | 说明 | 设置方 |
|------|------|--------|
| **通用佣金** | 对所有达人统一设置的佣金比例 | 商家 |
| **专属佣金** | 对特定达人设置的更高佣金 | 商家 |
| **招商团长佣金** | 通过招商团长活动设置的佣金 | 团长/商家 |
| **抖客专属佣金** | 抖客 CPS 渠道专用 | 商家 |
| **活动佣金** | 大促期间限时佣金加码 | 平台/商家 |

### 2.3 推广位 PID

```text
PID (Promotion ID) 格式：dy_xxxxxxxx_xxxxxxxx_xxxx
                     └─────┘ └─────┘ └───┘
                     用户ID   渠道ID  场景ID

用途：
- 渠道追踪：不同 PID 对应不同推广渠道
- 佣金归因：订单 → PID → 达人 → 佣金计算
- 效果分析：按 PID 统计 ROI
```

## 3. Ontology 建模

### 3.1 Object Type

#### Creator（达人）

```yaml
Object Type: Creator
  primaryKey: authorId (string)
  props:
    nickName: string          # 达人昵称
    fanCount: int             # 粉丝数
    avgGmv: decimal           # 平均带货GMV
    categoryMatch: string[]   # 品类匹配度
    mcnId: string             # 所属MCN（可选）
    pid: string               # 推广位PID
```

#### Commission（佣金单）

```yaml
Object Type: Commission
  primaryKey: commissionId (string)  # orderId + authorId 组合
  props:
    orderId: string           # 关联订单
    authorId: string          # 达人ID
    productId: string         # 推广商品
    pid: string               # 推广位
    gmvAmount: decimal        # 订单GMV
    authorAmount: decimal     # 达人佣金
    shopAmount: decimal       # 商家实收
    platformAmount: decimal   # 平台扣佣
    agencyAmount: decimal     # MCN抽成（可选）
    commissionRate: decimal   # 佣金比例(%)
    commissionType: enum      # 通用/专属/团长/抖客/活动
    settleStatus: enum        # 待结算/已结算/已取消
    settleTime: timestamp     # 结算时间
```

#### Agency（MCN 机构）— 后置

```yaml
Object Type: Agency
  primaryKey: mcnId (string)
  props:
    name: string
    authorCount: int          # 签约达人数
    totalGmv: decimal         # 机构总GMV
```

### 3.2 Link Type

| Link | from → to | 说明 |
|------|-----------|------|
| `Order.hasCommission` | Order → Commission | 订单关联佣金单 |
| `Commission.forCreator` | Commission → Creator | 佣金归属达人 |
| `Commission.forProduct` | Commission → Product | 推广的商品 |
| `Creator.employedBy` | Creator → Agency | 达人签约MCN（可选） |
| `Creator.promotes` | Creator → Product | 达人推广商品 |
| `Creator.hosts` | Creator → LiveSession | 达人主持直播（后置） |

## 4. 佣金结算流程

```text
订单完成
    │
    ▼
T+0  精选联盟生成佣金记录（settleStatus = 待结算）
    │
    ▼
T+15 售后期结束（15天无售后）
    │
    ├─ 无售后 → 佣金确认（settleStatus = 已结算）
    │   ├── 达人收到 author_amount
    │   ├── 商家收到 shop_amount
    │   └── 平台扣除 platform_amount
    │
    └─ 有售后 → 佣金回退（settleStatus = 已取消）
        └── 佣金记录标记取消，不结算
```

> **关键注意：** 佣金结算延迟 15 天（售后期），AOS 需要同步跟踪 `settleStatus` 状态变更。

## 5. 数据接入策略

### 5.1 精选联盟订单同步

| 路径 | 接口 | 频率 | 说明 |
|------|------|------|------|
| 增量同步 | `/alliance/order/list` | 30 min | 按 update_time 增量拉取 CPS 归因订单 |
| RDS 推送 | 数据推送（免费） | 实时 | 佣金变更直接推送（免计费） |
| 结算回写 | `/alliance/order/list` | 1 h | 检查 settleStatus 状态变更 |

### 5.2 达人数据同步

| 数据 | 接口 | 频率 | 说明 |
|------|------|------|------|
| 达人列表 | `/buyin/author/list` | 1 day | 可合作的达人列表 |
| 精英达人 | `/alliance/elite/list` | 1 day | 高带货能力达人 |
| 达人商品配置 | `/alliance/product/detail` | 6 h | 达人推广的商品+佣金 |

## 7. 与其他平台 CPS 体系对比

| 维度 | 淘宝客 | 多多进宝 | **抖音精选联盟** | Amazon Associates |
|------|--------|---------|----------------|-------------------|
| 分佣角色 | 商家→淘客 | 商家→推客 | 商家→达人→(MCN) | Amazon→Associate |
| 四角模型 | 否（三角） | 否（三角） | **是（四角+MCN）** | 否（三角） |
| 佣金设置 | 商家设定 | 商家设定 | **多种类型** | 平台统一 |
| 结算周期 | T+15 | T+15 | **T+15** | T+60 |
| PID | 淘客PID | 推广位PID | **PID** | Associate Tag |
| 达人数据 | 弱 | 弱 | **强（粉丝/品类匹配）** | 弱 |

## 8. 风险与注意

| # | 风险 | 说明 | 缓解 |
|----|------|------|------|
| R1 | 佣金结算延迟 | T+15 天结算，期间可能因售后回退 | OT 跟踪 settleStatus 状态 |
| R2 | 退货导致佣金回退 | 消费者退货后佣金取消 | Commission 状态机含「已取消」 |
| R3 | MCN 抽成数据 | MCN 从达人佣金中抽成，比例不透明 | agencyAmount 为可选字段，需达人/MCN 授权 |
| R4 | 佣金类型多 | 5 种佣金类型（通用/专属/团长/抖客/活动） | OT 的 commissionType 枚举需完整 |
| R5 | 自播 vs 达人播 | 商家自播不产生佣金，需区分 | orderDetail 中 `author_amount = 0` 表示自播 |
