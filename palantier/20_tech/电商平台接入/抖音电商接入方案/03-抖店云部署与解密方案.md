## 1. 为什么需要抖店云

抖店云是抖音电商提供的云端部署环境。部署在抖店云内的应用享受两大优势：

| 优势 | 说明 | 量化收益 |
|------|------|---------|
| **API 费用降低 90%** | 云外 0.18 元/百次 → 云内 0.018 元/百次 | 月均万级调用量可节省数千元 |
| **解密能力** | 订单地址/手机号加密数据，**仅允许云内解密** | 没有云内环境 → 无法获取明文地址 |

> **核心结论：** 抖音接入**必须**部署在抖店云内，否则无法获取订单收货地址。

## 2. 敏感数据加密体系

### 2.1 加密范围

抖音对消费者隐私数据实行**全加密**策略：

| 加密字段 | 原始字段 | 加密格式 | 影响 |
|---------|---------|---------|------|
| 收件人姓名 | `post_addr.name` | `***` 或 base64 密文 | 无法直接使用 |
| 收件人手机 | `post_addr.mobile` | 加密串 | 无法直接使用 |
| 收件人地址 | `post_addr.province`/`city`/`district`/`detail` | 加密串 | 无法直接使用 |
| 买家昵称 | `buyer_words` | 加密匿名 | 无法关联真实身份 |

### 2.2 解密接口

```
接口：/order/batchDecrypt
计费：免费
约束：仅限抖店云内调用（云外调用被拒绝）
```

**调用流程：**

```text
1. 通过 /order/searchList 获取订单列表（地址为密文）
2. 提取 addr_anonymous 密文字段
3. 调用 /order/batchDecrypt：
   POST {
     "order_id": "4730xxxxxxxx",
     "addr_anonymous": "加密串",
     "type": "address"   // address / mobile / name
   }
4. 返回明文：{
     "name": "张三",
     "mobile": "138****8888",  // 部分脱敏
     "address": "广东省深圳市南山区xxx"
   }
```

### 2.3 解密约束

| 约束 | 说明 |
|------|------|
| **仅限云内** | 必须从抖店云 IP 段发起请求 |
| **不可缓存** | 解密结果不可持久化存储（合规要求） |
| **不可导出** | 明文数据不可导出抖店云外 |
| **限频** | 单次最多 50 条，QPS 有限制 |
| **时效** | 密文有时效性，超时需重新获取 |

> **⚠️ 合规红线：** 解密后的明文数据**不可写入 AOS Dataset**。AOS Ontology 中存储的地址 Prop 需使用**脱敏格式**（如 `138****8888`），完整明文仅在抖店云内临时用于发货操作。

## 3. 抖店云部署架构

### 3.1 整体架构

```text
┌─────────────────────────────────────────────────────┐
│                   抖店云（内网环境）                    │
│                                                      │
│  ┌──────────────────────────────────────────────┐   │
│  │          AOS Connector (Cloud Agent)          │   │
│  │                                                │   │
│  │  ┌─────────┐  ┌──────────┐  ┌──────────────┐ │   │
│  │  │ Sync    │  │ Decrypt  │  │ RDS Receiver │ │   │
│  │  │ Service │  │ Service  │  │ (免费推送)    │ │   │
│  │  └────┬────┘  └────┬─────┘  └──────┬───────┘ │   │
│  │       │            │                │         │   │
│  │       ▼            ▼                ▼         │   │
│  │  ┌──────────────────────────────────────┐    │   │
│  │  │        数据缓冲层 (临时存储)           │    │   │
│  │  │  订单JSON → 解密 → 脱敏 → 压缩传输    │    │   │
│  │  └──────────────────┬───────────────────┘    │   │
│  │                     │                         │   │
│  └─────────────────────┼─────────────────────────┘   │
│                        │                              │
└────────────────────────┼──────────────────────────────┘
                         │ HTTPS 加密隧道
                         │ (压缩 + 脱敏数据)
                         ▼
┌─────────────────────────────────────────────────────┐
│                AOS 主集群（自有环境）                   │
│                                                      │
│  ┌──────────┐  →  ┌──────────┐  →  ┌──────────┐    │
│  │ Ingestion │     │ Pipeline │     │ Dataset  │    │
│  │ Endpoint  │     │ (Build)  │     │ (脱敏)   │    │
│  └──────────┘     └──────────┘     └────┬─────┘    │
│                                        │            │
│                                  ┌─────▼─────┐      │
│                                  │ OKF → OT  │      │
│                                  │ (地址脱敏) │      │
│                                  └───────────┘      │
└─────────────────────────────────────────────────────┘
```

### 3.2 数据流转策略

| 阶段 | 位置 | 数据状态 | 说明 |
|------|------|---------|------|
| 1. API 调用 | 抖店云内 | 密文 | 从抖店 API 获取订单 |
| 2. 解密 | 抖店云内 | 明文 | 调用 batchDecrypt 获取明文 |
| 3. 脱敏处理 | 抖店云内 | **脱敏** | 手机号 `138****8888`、地址保留省市+模糊详情 |
| 4. 压缩传输 | 云内→主集群 | 脱敏 | HTTPS 加密隧道 |
| 5. 落库 | AOS 主集群 | 脱敏 | Dataset 中存储脱敏地址 |
| 6. 发货操作 | 抖店云内 | 临时明文 | 发货时实时解密（不落库） |

### 3.3 RDS 数据推送（免费）

```text
抖店平台
  │
  ├── 订单创建 → RDS 推送（免费）
  │     直接写入开发者数据库
  │     {
  │       "order_id": "4730xxx",
  │       "event_type": "order_create",
  │       "data": { ...订单密文JSON... }
  │     }
  │
  └── 售后变更 → RDS 推送（免费）
        {
  │       "order_id": "4730xxx",
  │       "event_type": "afterSale_update",
  │       "data": { ...售后密文JSON... }
        }
```

> **RDS 推送优势：**
> - 完全免费（不计入 API 调用量）
> - 实时推送（无需轮询）
> - 订单/售后变更即时感知
> - 数据仍然是密文（需在云内解密）

## 4. 成本对比

### 4.1 月度 API 费用估算

假设：日均 1000 笔订单，每订单需 3 次 API 调用（列表+详情+物流）

| 部署方式 | 日调用量 | 日费用 | 月费用（30天） |
|---------|---------|--------|--------------|
| **云外部署** | 3,000 次 | 5.4 元 | **162 元** |
| **云内部署** | 3,000 次 | 0.54 元 | **16.2 元** |
| **云内 + RDS推送** | ~500 次（仅配置+异常） | 0.09 元 | **2.7 元** |

> 结论：云内 + RDS 推送比云外**节省 98%** 的 API 费用。

### 4.2 额外基础设施成本

| 项目 | 说明 | 成本 |
|------|------|------|
| 抖店云实例 | 云服务器 | 按需付费（抖店云定价） |
| RDS 数据库 | 推送落库用 | 按需 |
| HTTPS 隧道 | 云内→主集群安全通道 | 标准网络费用 |

## 6. 合规要求

| 要求 | 说明 | AOS 应对 |
|------|------|---------|
| **明文不落库** | 解密后明文数据不可持久化 | Dataset 只存脱敏地址 |
| **明文不导出** | 明文不可离开抖店云 | 传输前必须脱敏 |
| **访问审计** | 谁在何时解密了什么 | Cloud Agent 记录解密日志 |
| **数据最小化** | 只解密必要字段 | 按需解密（发货时才解密地址） |
| **定期清理** | 云内临时明文需定期清理 | 每日清理临时缓冲 |

## 7. 风险与注意

| # | 风险 | 说明 | 缓解 |
|----|------|------|------|
| R1 | **没有抖店云就无法接入** | 地址加密→无法发货→无法履约 | **必须**部署 Cloud Agent |
| R2 | 解密 QPS 限制 | 单次 max 50 条 | 批量解密 + 队列控制 |
| R3 | 脱敏地址精度损失 | 脱敏后地址精度降低（仅省市） | 发货时实时解密获取完整地址 |
| R4 | 云内外网络延迟 | 云内→主集群的数据传输延迟 | 异步传输 + 本地缓冲 |
| R5 | 合规审计 | 抖音可能审计数据使用情况 | Cloud Agent 完整日志 |
| R6 | RDS 推送可靠性 | 推送可能丢消息 | 定期全量对账补偿 |
