## Stage 1 · 数据接入（Data Connection）

### 1.1 连接器配置

| 项 | 配置 |
|----|------|
| 连接器类型 | **REST API Connector**（AOS 新增类型） |
| 网关地址 | `https://open-api.pinduoduo.com/` |
| 认证方式 | **OAuth 2.0**（`authorization_code`）→ `access_token`（有效期 ~24h） |
| 签名算法 | **MD5**（参数首字母升序 + 前后追加 `client_secret` → 大写 32 位） |
| 数据格式 | JSON（`data_type=JSON`） |
| 速率限制 | 单接口 500 QPS（需报备），默认较低 |
| 分页方式 | `page` + `page_size`（默认 10/100） |
| 时间戳要求 | 与服务器时间差值 ≤ 5 分钟 |

### 1.2 PDD 签名流程（与 TOP 的关键差异）

```
1. 收集所有业务参数（不含 sign）
2. 参数名首字母升序排列（注意：PDD 按 ASCII 排序，不是拼音）
3. 拼接：key1value1key2value2...
4. 前后追加 client_secret：client_secret + 拼接串 + client_secret
5. MD5 → 大写 32 位 → sign 参数

⚠️ 与淘宝的差异：
  - 淘宝：secret + params + secret → MD5（相同结构）
  - 拼多多：client_secret + params + client_secret → MD5（结构相同，参数名不同）
  - 核心差异在参数体系：type/data_type/sign_method 不同
```

### 1.3 Source 创建

```
Step 1 · 选择类型：REST API（自定义连接器 → 拼多多模板）
Step 2 · 连接方式：直连（API 网关）
Step 3 · 命名：prod-rest-pinduoduo
Step 4 · 配置：
  Client ID: ****
  Client Secret: ****
  Access Token: ****（OAuth 授权码，24h 过期需轮换）
  网关: https://open-api.pinduoduo.com/
  数据格式: JSON
```

### 1.4 Token 轮换机制

```
access_token 有效期 ~24h → refresh_token 刷新（有效期 30 天）
AOS OAuth Token Manager（G2）负责自动轮换：
  1. 记录 token 获取时间
  2. 提前 1h 调用 /api/oauth/token（grant_type=refresh_token）
  3. 更新 Source 配置中的 access_token
  4. 失败重试 3 次 + 告警
```

## Stage 2 · 数据同步（Sync）

### 2.1 同步策略

| 数据域 | API | 事务类型 | 增量方式 | 调度 |
|--------|-----|----------|----------|------|
| **订单** | `pdd.order.number.list.increment.get` | APPEND | **增量接口**（15min/30min/1h/4h 粒度） | **每 15 分钟** |
| 商品 | `pdd.goods.list.get` | SNAPSHOT | 全量覆盖 | 每 6 小时 |
| 售后 | `pdd.refund.list.get` | APPEND | `start_updated_at` | 每 30 分钟 |
| 物流 | 按订单号查询 | APPEND | 关联订单 | 每 30 分钟 |
| 分销 | `pdd.ddk.*` | APPEND | 分页全量 | 每 1 小时 |

### 2.2 PDD 增量接口优势

```
✅ 原生增量接口（淘宝没有）：
  pdd.order.number.list.increment.get
  参数:
    start_updated_at: 2026-07-23 14:00:00
    end_updated_at:   2026-07-23 14:15:00
    order_status: 1   -- 待发货
    page: 1
    page_size: 100
  返回: order_sn 列表 → 再逐个调 pdd.order.information.get 获取详情
```

### 2.3 拼团状态机特殊处理

拼多多特有**拼团状态**（淘宝/天猫没有）：

```
拼团状态:
  0 → 待成团（未达到成团人数）
  1 → 已成团（达到人数，待发货）
  2 → 成团失败（超时未成团 → 自动退款）

订单状态:
  1 → 待发货
  2 → 已发货
  3 → 已签收
```

## Stage 3 · 管道清洗（Pipeline Builder）

### 3.1 PDD 订单字段映射

| PDD 字段 | Dataset 列 | Cast | 说明 |
|----------|-----------|------|------|
| `order_sn` | `order_id` | STRING | 订单号 |
| `pay_amount` | `amount` | DECIMAL(12,2) | 实付金额（**单位：分**） |
| `order_status` | `status` | INTEGER→ENUM | 1/2/3 数字编码 |
| `group_status` | `group_status` | INTEGER→ENUM | 拼团状态（0/1/2） |
| `created_time` | `created_at` | INT→DATETIME | Unix 时间戳（秒） |
| `pay_time` | `paid_at` | INT→DATETIME | |
| `receiver_phone` | `phone` | STRING | PII 标记 |
| `item_list[].goods_count` | `item_count` | INTEGER | |

### 3.2 金额单位转换（Cast + Expression）

```sql
-- PDD 金额单位是"分"，需要转换
Cast: pay_amount  INTEGER → DECIMAL(12,2) / 100
  '19900' → 199.00（元）

Expression:
  CASE WHEN refund_status = 'SUCCESS' THEN pay_amount ELSE 0 END AS refund_amount
```

### 3.3 拼团状态展开（Explode 组件）

```sql
-- 拼团订单可能包含多个子单（团员各一单）
Explode: group_members ARRAY
  一个拼团主单展开为 N 个团员子单
  每个子单独立追踪发货/签收状态
```

## Stage 4 · OKF 映射（Funnel）

### 4.1 OT 映射表

| PDD 对象 | 统一 OT | 主键 | 关键映射 |
|----------|---------|------|----------|
| `Order` | **Order** | `order_sn` | pay_amount(分)→amount(元), order_status→status_enum |
| `Order.Item` | **OrderLine** | `order_sn+goods_id` | goods_count→quantity, goods_price→unit_price |
| `Goods` | **Product** | `goods_id` | goods_name→title, image_url→image |
| `GoodsSku` | **ProductVariant** | `sku_id` | spec→variant_name |
| `Refund` | **AfterSales** | `after_sales_id` | refund_amount→amount, refund_reason→reason |
| `Mall` | **Shop** | `mall_id` | mall_name→name |

### 4.2 Funnel 状态机（含拼团）

```
待成团(group=0) → 已成团(group=1) → 待发货(status=1) → 已发货(status=2) → 已签收(status=3)
      ↘ 成团失败(group=2) → 自动退款
                                                    ↘ 售后退款
```
