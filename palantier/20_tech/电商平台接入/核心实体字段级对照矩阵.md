## 6. 字段对齐策略

### 6.1 枚举值统一

| 概念 | 微商城 | 淘宝 | 拼多多 | 京东 | 抖音 | 统一枚举 |
|------|--------|------|--------|------|------|---------|
| 订单状态 | 0-5 | WAIT/SEND/SUCCESS | 1-5 | WAIT/PAID/SHIPPED | status int | `PENDING` / `PAID` / `SHIPPED` / `COMPLETED` / `CANCELLED` / `REFUNDED` |
| 商品状态 | 0/1 | ONSALE/INSTOCK | 0/1 | state int | status int | `ACTIVE` / `INACTIVE` / `DRAFT` |
| 售后类型 | — | refund_phase | after_sales_type | type | aftersales_type | `REFUND_ONLY` / `RETURN_REFUND` / `EXCHANGE` / `REPAIR` |

### 6.2 金额处理策略

| 策略 | 说明 |
|------|------|
| **统一精度** | 所有金额字段以 `Decimal(minor_unit=2)` 存储，即"分" |
| **多币种** | Shopify/Amazon 需保留 `currency` 字段；国内平台默认 CNY |
| **Shopify MoneyBag** | Shopify 的 `price_set` 返回多种货币组合，统一取 `presentment_money` |
| **Amazon 金额** | SP-API 金额含 `CurrencyAmount` 对象，统一取 `amount` 字段 |

### 6.3 时间处理策略

| 策略 | 说明 |
|------|------|
| **时区** | 国内平台统一 `Asia/Shanghai`；Amazon 按 marketplace 时区（NA=Pacific, EU=UTC, FE=Tokyo）；统一存储 UTC |
| **格式** | 输入：平台原生格式；存储：ISO 8601 with timezone |
| **增量同步** | 以平台 `updated_time` 为增量游标，非 `create_time` |

### 6.4 加密数据策略

| 平台 | 加密范围 | 解密方案 |
|------|---------|---------|
| **抖音** | 收货人姓名、手机、地址（全加密） | G8 解密插件 → 抖店云 Cloud Agent 代理解密 |
| 淘宝 | 部分（buyerId 脱敏） | 无需解密（平台不提供原始数据） |
| 其他 | 无加密 | — |
