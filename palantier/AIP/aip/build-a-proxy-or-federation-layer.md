# [](https://www.palantir.com#build-a-proxy-or-federation-layer-with-aip)Build a proxy or federation layer with AIP

A proxy or federation layer sits between AIP and one or more external model providers. Your compute module receives inference requests from AIP, applies custom logic, and forwards them to external providers. This allows you to control exactly what data leaves your environment and how requests are routed.

## [](https://www.palantir.com#use-cases)Use cases

- **PII redaction:** Strip or mask sensitive data from prompts before they reach an external provider.

- **Prompt injection:** Prepend system prompts, append instructions, or transform request content before forwarding.

- **API format remapping:** Translate between the provider API format that AIP expects and a provider that uses a different format.

- **Multi-provider federation:** Route requests across multiple providers behind a single registered model, based on cost, latency, or model availability.

## [](https://www.palantir.com#additional-prerequisites)Additional prerequisites

In addition to the general [prerequisites](https://www.palantir.com/docs/foundry/aip/compute-module-backed-models/#prerequisites) for models backed by compute modules, using a compute module as a proxy or federation layer requires:

- **Network egress:** Your compute module must be able to reach external model providers. Configure egress through a [source](https://www.palantir.com/docs/foundry/compute-modules/sources/) in Data Connection with the appropriate network policies.

- **Secrets:** API keys or other credentials for external providers must be attached to the source. Your container accesses these credentials at runtime through the `SOURCE_CREDENTIALS` environment variable. Review [sources](https://www.palantir.com/docs/foundry/compute-modules/sources/) for details on configuring and reading secrets.

## [](https://www.palantir.com#how-to-build-a-proxy-or-federation-layer-with-aip)How to build a proxy or federation layer with AIP

- Build a container that implements a [supported provider API format](https://www.palantir.com/docs/foundry/aip/llm-provider-compatible-apis/). The container should receive requests from AIP, apply your custom logic (such as redaction, routing, or prompt injection), and forward them to one or more external providers.

- Create a [source](https://www.palantir.com/docs/foundry/compute-modules/sources/) in Data Connection with network policies that allow egress to your external providers. Attach API keys or other credentials as secrets.

- Set the `application.port` label in your Dockerfile and publish the image to Artifacts. For general container guidance, review the [compute module containers](https://www.palantir.com/docs/foundry/compute-modules/containers/) documentation.

- Create a [compute module](https://www.palantir.com/docs/foundry/compute-modules/overview/) with the published image and attach the source you created. Set minimum replicas to at least one.

- [Register the model](https://www.palantir.com/docs/foundry/aip/compute-module-backed-models/#register-and-use-the-model) in Control Panel and configure capabilities.

- Select the model in any [supported AIP application](https://www.palantir.com/docs/foundry/aip/bring-your-own-model/#supported-applications-and-features).
