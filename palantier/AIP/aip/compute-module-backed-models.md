# [](https://www.palantir.com#models-backed-by-compute-modules)Models backed by compute modules

Compute-module-backed models allow you to host a large language model server in a [compute module](https://www.palantir.com/docs/foundry/compute-modules/overview/) and register it as a first-class model in AIP. The registered model appears in the model selector across all [supported applications](https://www.palantir.com/docs/foundry/aip/bring-your-own-model/#supported-applications-and-features), just like a Palantir-provided model or a REST API registered model.

This approach is suited for two primary scenarios:

- **[Self-hosting models on your own compute](https://www.palantir.com/docs/foundry/aip/self-host-models/):** You can use models backed by compute modules to run open-source or custom models on your own GPUs for data sovereignty, on-premise or air-gapped deployments, cost control, or early access to newly released models.

- **[Building a custom proxy or federation layer](https://www.palantir.com/docs/foundry/aip/build-a-proxy-or-federation-layer/):** You can use models backed by compute modules to remap API formats, inject prompts, redact data before it reaches an external provider, or federate requests across multiple providers behind a single registered model.

## [](https://www.palantir.com#prerequisites)Prerequisites

Your compute module application must meet the following requirements before you register it as a model source:

- 

**Serve a supported provider API format:** Your container must expose an API that conforms to one of the [supported provider API formats](https://www.palantir.com/docs/foundry/aip/llm-provider-compatible-apis/). Inference servers such as vLLM and Ollama expose a compatible API by default.

- 

**Set the application port:** You must add an `application.port` label in your Dockerfile pointing to the port your model server listens on. For example `LABEL application.port=&#x27;8000&#x27;`. For general container guidance, review the [compute modules containers documentation](https://www.palantir.com/docs/foundry/compute-modules/containers/).

![](images/compute-module-backed-models_cm-dockerfile-label.png)

- 

**Set minimum replicas to at least one:** Configure your compute module with a minimum of one replica. Review the documentation on [minimum replicas](https://www.palantir.com/docs/foundry/compute-modules/scaling/#minimum-replicas) for details.

![](images/compute-module-backed-models_cm-replica-configuration.png)

## [](https://www.palantir.com#register-and-use-the-model)Register and use the model

You must be an **Enrollment administrator** to register a model.

After your compute module is running, register it as a model in Control Panel:

- 

Navigate to the **AIP settings** extension and select the **Registered models** tab.

![](images/compute-module-backed-models_registered-models-homepage.png)

- 

Select **Register a model**.

- 

Choose your compute module as the source.

![](images/compute-module-backed-models_cm-registration-source-selection.png)

- 

Configure the **Model ID**. Set this to the identifier your model server expects, such as the model name used by your inference server.

- 

Define the model&#x27;s capabilities. Enabling **Reasoning**, **Structured outputs**, and **Tool calling** ensures [AI FDE](https://www.palantir.com/docs/foundry/ai-fde/overview/) and [AIP Analyst](https://www.palantir.com/docs/foundry/aip-analyst/overview/) can use the model.

- 

Define rate limits for the model. Review [Features supported for registered models](https://www.palantir.com/docs/foundry/aip/bring-your-own-model/#features-supported-for-registered-models) for details on enrollment and user rate limits.

- 

Enable registered model access for your enrollment or for specific user groups.

Your registered model will now appear in the model selector across all [supported applications](https://www.palantir.com/docs/foundry/aip/bring-your-own-model/#supported-applications-and-features).

![](images/compute-module-backed-models_model-selector-with-description.png)
