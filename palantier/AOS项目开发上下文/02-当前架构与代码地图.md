# 当前架构与代码地图

## 1. 冻结架构

```text
Signed Bundle / Manifest
          ↓
PostgreSQL Registry + Release Evidence
          ↓
Registry Snapshot + Deterministic Resolver
          ↓
Immutable Composition Lock + Permission/Migration/Contribution Diff
          ↓
Installation State Machine
          ↓
Receipt-first Idempotency + ETag/CAS + Maker-checker
          ↓
Immutable Revision / Decision / Event + Server Evidence
          ↓
Canonical HTTP API
          ↓
M3 TypeScript SDK Adapter + FDE Installation UI
          ↓
M4 Integration Projector + Service + PostgreSQL Reader + Canonical Case API
```

M3/M4 位于最下游展示、调用与证据投影层。它们不得复制 Resolver、重算 hash、推导权限真相或在浏览器中维护第二套安装/阶段状态机。

## 4. Canonical API 能力

- Registry：`/v1/asset-bundles` 及 bundle/version 生命周期端点。
- Composition：resolve 与指定 revision lock 读取。
- Installation：create/list/get 与 submit、approve、reject、apply、verify、rollback。
- create/detail/action 的 HTTP ETag 与 body `etagVersion` 一致；M3 可直接由 body 构造 `If-Match: "<etagVersion>"`。
- list 支持 `state/limit/offset`，marking 在 SQL 计数和分页前过滤。
- Integration Case 提供 create、list、detail、snapshot 与 timeline；公共 HTTP 不提供 Evidence 写入或撤销。
- current list 在返回前重投影本租户到期 Case，失败关闭；reference 与 current 严格隔离。
