# 当前架构与代码地图

## 1. 冻结架构

```text
Signed Bundle / Manifest
          ↓
PostgreSQL Registry + Release Evidence
          ↓
Registry Snapshot + Deterministic Resolver
          ↓
Immutable Composition Lock + Permission/Migration/Contribution Diff
          ↓
Installation State Machine
          ↓
Receipt-first Idempotency + ETag/CAS + Maker-checker
          ↓
Immutable Revision / Decision / Event + Server Evidence
          ↓
Canonical HTTP API
          ↓
M3 TypeScript SDK Adapter + FDE Installation UI
```

M3 位于最下游展示与调用层。它不得复制 Resolver、重算 hash、推导权限真相或在浏览器中维护第二套安装状态机。

## 2. 后端代码地图

| 能力 | 代码位置 | M3 使用方式 |
|---|---|---|
| Registry API | `services/aos-api/aos_api/routers/asset_bundles.py` | 资产列表、详情、版本与发布事实 |
| Registry Service/Store | `asset_registry/registry_service.py`、`registry_store.py` | 只经 API 使用，不由 UI 直连 |
| Snapshot/Resolver/Diff | `registry_snapshot.py`、`resolver.py`、`diff_service.py` | 通过 resolve 得到服务端 lock/diff |
| Composition 契约 | `composition_contracts.py` | SDK 类型与运行时响应校验的权威字段来源 |
| Composition 控制面 | `composition_service.py`、`composition_store.py` | resolve/get lock |
| Installation 控制面 | `installation_service.py`、`installation_store.py` | create/list/get 与六个 action |
| Revalidation/Evidence | `installation_revalidation.py`、`installation_evidence.py` | UI 只展示服务端结果，不接收客户端伪造 evidence |
| 权限/协议/装配 | `control_policy.py`、`control_protocols.py`、`control_wiring.py` | 保持失败关闭与依赖边界 |
| HTTP Router | `routers/bundle_compositions.py`、`bundle_installations.py` | M3 SDK 的 11 个 operation 映射目标 |
| Header 约束 | `routers/asset_control_headers.py` | SDK 生成 Idempotency-Key、按 body `etagVersion` 发送强 If-Match |
| OpenAPI 真源 | `packages/contracts/openapi/v1.generated.json`、`v1.inventory.json` | 契约漂移检查，不手写另一份后端规范 |

## 3. Web 现状与 M3 接入点

| 位置 | 当前事实 | M3 最小改动方向 |
|---|---|---|
| `apps/web/src/pages/s2/AssetBundlesPage.tsx` | 请求不存在的 `/v1/assets`，空/失败时使用 `MOCK_ASSET_BUNDLES` | 切换 `/v1/asset-bundles`，移除隐式 Mock，增加真实状态与安装视图 |
| `apps/web/src/pages/s2/routes.tsx` | `/apollo/assets` 已路由到该页 | 保留现有入口；只有需要详情深链时才追加子路由 |
| `apps/web/src/api/client.ts` | 通用 client 只返回 body，服务 1000+ 调用 | 不改变返回形状；M3 新增资产控制专用 adapter |
| `apps/web/src/pages/s2/shared.tsx` | 提供通用 `useJsonGet` | 简单 Registry 读取可复用；安装 mutation/ETag 应使用专用 SDK |
| `packages/ontology-sdk` | Ontology 专用包 | 不混入资产安装 SDK，避免领域边界污染 |

## 4. Canonical API 能力

- Registry：`/v1/asset-bundles` 及 bundle/version 生命周期端点。
- Composition：resolve 与指定 revision lock 读取。
- Installation：create/list/get 与 submit、approve、reject、apply、verify、rollback。
- create/detail/action 的 HTTP ETag 与 body `etagVersion` 一致；M3 可直接由 body 构造 `If-Match: "<etagVersion>"`。
- list 支持 `state/limit/offset`，marking 在 SQL 计数和分页前过滤。

## 5. 不得在 M3 复制的逻辑

- 版本选择、依赖图求解、capability/conflict 检测。
- lock/diff/evidence hash 计算和真实性判定。
- maker-checker、role/marking/tenant 决策。
- 状态迁移合法性、active/previous pointer 更新。
- 幂等 receipt、CAS 冲突裁决和服务端证据生成。
