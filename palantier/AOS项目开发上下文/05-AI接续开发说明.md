# AI 接续开发说明

## 1. 开始前必读

按顺序阅读本目录、M0 总方案、M2 公共契约、M2-B 方案、M2-B 最终证据和当前阶段方案。不要仅凭聊天摘要或文件名推断实现。

## 2. 每次接续检查

1. 核验 `aos-platform` 与 `docs` 的分支、HEAD、工作树和 worktree 映射。
2. 识别并保护用户未提交改动；禁止 reset、checkout 覆盖或宽泛暂存。
3. 将方案中的 API、DTO、状态机、权限、错误码映射到真实代码。
4. 若当前基线已前移，先检查新增提交是否改变本目录快照，再更新上下文。
5. 修改代码前先完善当前阶段方案，明确文件所有权、退出门和回滚。

## 3. M3 接续指令

- 起点：`aos-platform m1@d85992b`，或经人工确认的后续 m1。
- 方案：`228-M3-安装管理UI与SDK实施方案.md`。
- 不改生产后端架构；优先新增 Web 专用 asset-control adapter、类型、hooks 和页面组件。
- 保留 `/apollo/assets` 入口，切换真实 `/v1/asset-bundles`，禁止空/错时回退 Mock。
- 所有 mutation 显式传 Idempotency-Key；action 显式传强 If-Match。
- 先做 SDK 契约测试，再做页面状态/交互测试，再做浏览器真实 API 与累计回归。

## 4. 证据要求

每波记录：基线提交、修改文件、专项测试、前序累计测试、Web typecheck/build、浏览器场景、风险与未解决项。阶段 GREEN 后更新本目录状态和分支映射。

## 5. 禁止事项

- 不提前开发 M4/M5 或 G0～G6。
- 不伪造发布、验证、审批、evidence 或 active 状态。
- 不在前端复刻服务端状态机、Resolver 或 hash 算法。
- 不以本地 Mock、localStorage 或离线缓存完成安全敏感 mutation。
- 不将真实客户数据、Secret、生产凭据或商城写回引入测试夹具。
