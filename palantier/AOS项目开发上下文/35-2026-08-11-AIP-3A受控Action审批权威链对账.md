# AIP-3A 受控 Action 审批权威链对账

> 日期：2026-08-11
> 状态：`IMPLEMENTED_GREEN`
> 代码：`aos-platform/m1@60344d5`
> 正向租户：`org-org / dev-project`

## 1. 本波目标

在不调用外部 Adapter、不写真实业务对象的前提下，建立 ActionProposal → Draft → maker-checker Approval 的 PostgreSQL 权威链，并冻结 AIP-3 公共 DTO、风险下限、状态与审计边界。

## 2. 已实现

- 新增 `aip3_001`，建立 Proposal、Draft、ApprovalEvent、ExecutionLease、Receipt、Event 六张表；复合租户主键/外键、FORCE RLS、append-only 权限已落地。
- 复用 O1 `meta_action_type`，不建立第二 Action 定义；保存精确 revision hash 与 policy snapshot。
- Proposal hash 绑定 TenantScope、发起人、task/run/object、purpose、payload、diff、evidence 和 expiry。
- 服务端执行 R0～R4 风险下限；客户端 risk hint 只能抬高风险。
- Proposal 创建同时生成不可外发 Draft；Approval 绑定精确 proposal version/hash。
- maker 不得自批；只有 `admin/approver/aip_approver` 可决策；R3/R4 至少两名 checker，R4 默认不可执行。
- PostgreSQL advisory transaction lock 封闭并发幂等窗口；同请求重放返回同一事实，不同语义重用 key 返回 409。
- 新增 canonical create/list/get/decision/timeline API，并进入唯一 Router Manifest 与 OpenAPI 契约。

## 5. 风险与边界

- AIP-3A 只证明提案和审批权威链；批准不等于执行，更不等于业务效果已应用。
- ExecutionLease/Receipt 表已扩展，但执行 API、预算/频控、kill switch、Adapter、unknown/reconcile 尚未发布。
- 旧 `runtime_write.py` 的 `autoApprove` 和旧 Draft 直接写生产旁路仍必须在 AIP-3B 失败关闭；在关闭前不得宣称 Action 安全链整体 GREEN。
- 权限撤回、审批 expiry 和执行人职责分离必须在获取 lease 前重新验证，不能复用审批时快照冒充当前权限。
