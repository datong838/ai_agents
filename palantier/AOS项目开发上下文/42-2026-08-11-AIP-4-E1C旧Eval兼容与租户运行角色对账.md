## 本波结果

- 保留旧 `/v1/evals/*` 为 compatibility surface；旧内存 `EvalsEngine` 只承担纯评测计算，不恢复为生产 Suite/Report 真源。
- 根因不是生产 Store 或 FORCE RLS 缺陷，而是旧 API 测试的临时隔离 schema 未向请求期运行角色 `aos_runtime` 授权。请求进入真实租户作用域后角色切换生效，表因此不可见并返回 503。
- 测试夹具仅新增隔离 schema 的 `USAGE` 与表级最小 DML 权限，并设置 transaction-local `aos.org_id` / `aos.project_id`；没有放松生产 RLS，没有修改真实业务数据。
- 跨租户伪造 header 在 Store 前由认证层以 `403 AUTH_TENANT_UNKNOWN` fail-closed，替换过期的 404 期望。
