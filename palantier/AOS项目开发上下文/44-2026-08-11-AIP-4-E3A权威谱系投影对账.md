# AIP-4 E3A 权威谱系投影对账

## 当前结论

AIP-4 E3A 已 `IMPLEMENTED_GREEN`，代码基线为 `aos-platform/m1@16aed87`。本波没有包装旧固定六段 Trace，而是建立了从 PostgreSQL 权威运行事实到 canonical append-only `LineageEvent` 的唯一投影链。

## 实施对应

- `aip4_004_lineage_source_authority.py`：为谱系事件增加 `source_kind/source_id/source_hash` 完整元组、租户内同源唯一索引和 root timeline 索引；保留 RLS/FORCE RLS、append-only 与 truncate guard。
- `aip_lineage_service.py`：从 TaskRun/Step/Checkpoint/Artifact/Evidence、ActionEvent/Receipt、EvalRun/Event/Report、PublicationEvent 读取权威事实，确定性生成事件 ID、sequence 与 source hash。
- `routers/aip_lineage_authority.py`：查询接口不写事实；对账接口只允许 admin/executor/aip_executor 选择 root 触发，DTO 不接受 event type、quality、payload 或 GREEN。
- `aip_eval_contracts.py` 与 authority store：非 legacy 谱系强制完整 source tuple；历史 legacy lineage 仍可只读兼容。
- OpenAPI/路由固定清单同步更新；没有出现新增 AIP 重复路由。

## 风险与下一门

- 源权威行若绕过自身版本/CAS 发生原地漂移，重复投影会以 source hash 冲突失败关闭，不会静默改写旧谱系。
- `ResearchJob` root 明确留到 E3D；E3A 请求该 root 返回 unsupported，不伪造外部执行事实。
- 下一波进入 E3B：tenant-scoped persistent spans、provider UsageReceipt/Adjustment、producer/observed 时间与 unknown quantity 语义；随后 E3C 做成本归因与 Capability Receipt。
