# ADR-005：M4 证据不可变与服务端阶段投影

> 状态：Accepted
> 日期：2026-08-03
> 决策基线：`aos-platform m1@c10d5ee`
> 实现进度：M4-2 已在 `aos-platform m1@483dd0f` 完成 PostgreSQL 真源、Projector、Service、Reader、Marking Resolver、Canonical API 与真实 HTTP 闭环

## 背景

接入案例阶段、统计和生产状态不能由页面常量、平台文档或客户端提交值决定。Evidence 还会过期、被撤销或出现新的负向 revision，因此只存一个可变 current 状态无法保留历史，也会在到期后继续显示假生产。

## 决策

1. Integration Evidence 使用 strict typed claims 和 append-only revision；禁止自由 metadata 决定阶段。
2. 公共 HTTP 不开放“上传 valid Evidence”接口；可信平台能力通过内部 `EvidenceWriter` 协议写入 canonical Evidence。
3. Snapshot 固定数据库 cutoff、Evidence 精确 revision/full canonical envelope、Policy 版本与 hash，不只保存可变引用。
4. Stage 只由服务端 Policy 计算最高连续通过门；客户端不得提交 stage、cutoff、metrics 或 effective status。
5. latest negative、expiry 和 revoke 触发新 Snapshot；阶段变化时原子写 append-only Stage Event。
6. current/reference 严格隔离；reference 是单独脱敏副本，不含租户 owner、Installation、Overlay 或 Lock 绑定，也不计入 current 统计。
7. 无有效测量返回 `null`，明确测得零返回 `0`；授权过滤先于 total、分页和聚合。

## 影响

- M4-1 必须建立不可变 Evidence/Snapshot/Stage Event、Projection、Command receipt 与一致性 trigger。
- M4-2 Router 只能触发服务端快照，不能接受 EvidenceRefs 或 Stage。
- M4-3 页面只展示服务端事实，不能根据静态步骤或文档名称推断“生产运行”。
- 到期重投影失败时读取失败关闭，不能继续返回旧的高阶段。

## 不采用的方案

- 扩宽 Registry Evidence 或 Installation Event Evidence：它们的作用域、生命周期和披露边界不同。
- 客户端上传 Evidence 并声明 valid：会形成 Stage 自证通道。
- 只在 Python 校验 Snapshot/Stage：不能防止直接 SQL 伪造。
- reference 与 tenant Case 共用原行：会产生隐私泄漏和统计污染。
