# ADR-010：AIP 与 Workshop 双开发线及共享文档单写边界

> 状态：Accepted
> 日期：2026-08-13
> 适用范围：`aos-platform` 代码开发、AIP/Workshop 方案文档与 AOS 项目上下文

## 背景

AIP 通用能力与八工作台后续均进入大规模全栈实施阶段。两类工作会持续触碰不同代码域，但共同依赖同一平台内核、同一 docs 仓库和同一项目状态投影。继续在单一代码工作树交错开发，会放大误暂存、未验收能力进入稳定线、文档并发覆盖和断流恢复误判风险。

## 决策

1. `/Users/ddt/work/projects/ai_agent/aos-platform` 的 `m1` 是唯一稳定集成线，不直接承载未封板开发。
2. 从 `m1@d205427` 建立两条长期开发线：
   - `/Users/ddt/work/projects/ai_agent/aos-platform-w1-aip` / `w1-aip`：只承载 AIP 通用能力及其直接依赖代码；
   - `/Users/ddt/work/projects/ai_agent/aos-platform-w2-workshop` / `w2-workshop`：只承载工作台产品实现代码。
3. 两条开发线不得相互直接合并。每个已评审、已测试、证据完整的波次先合入 `m1`；另一条开发线只在自己的安全检查点同步最新 `m1`。
4. 禁止使用 reset、rebase、force-push 伪造齐平。冲突必须在集成前审查其方案归属和权威边界。
5. docs 仓库继续共享一个 `m1` 工作树，但采用目录单写：
   - `20_tech/电商平台接入/AIP通用能力实施方案/`：AIP 开发线单写；
   - `20_tech/电商平台接入/12-工作台层方案/`：Workshop 开发线单写；
   - `20_tech/电商平台接入/12-工作台层技术方案/`：Workshop 开发线单写；
   - `palantier/AOS项目开发上下文/`：双方共享，但必须 CAS 串行写。
6. 上下文 CAS 协议：写入前记录 docs HEAD；提交前再次核对 HEAD。若 HEAD 已变化，停止提交、读取新提交并重放语义；禁止覆盖他方检查点。每次只精确暂存本波文件。
7. `01-当前项目状态.md` 与 `06-当前执行检查点.md` 每个可验证子步骤更新；检查点必须写明代码工作树、分支、最后安全提交、已完成、未完成和下一步。
8. AIP 与 Workshop 的方案授权互不继承。工作台技术基线冻结不等于获准编码；AIP 波次 GREEN 也不允许夹带工作台实现。

## 集成门

一个开发线提交进入 `m1` 前必须同时满足：方案授权有效、定向与累计测试 GREEN、需要页面时完成内置浏览器验收、租户/权限/真值边界复核、代码工作树干净、上下文与证据同步。合入后推送 `origin/m1`，再由仍在安全检查点的另一开发线同步；不得强迫存在未提交工作的开发线立即合流。

## 当前起跑线

2026-08-13 三条线均为 `d205427777f58e636a1b614f51aafdd19fc45d8a`，工作树干净且对应远端 ahead/behind 均为 `0/0`：`m1`、`w1-aip`、`w2-workshop`。

## 回退

若长期双开发线导致持续交叉冲突，可在双方工作树均干净、所有提交已进入 `m1` 后删除开发 worktree/分支，回到 `m1` 串行开发；不得丢弃尚未集成的提交。
