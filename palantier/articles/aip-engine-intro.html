架构全景
五层架构，全链路闭环

AIP 决策引擎基于 Foundry AIP 官方架构设计，分为用户界面层、编排构建层、质量保障层、可观测性层与模型基础设施层。数据从文档智能进入，经 Logic 编排、Evals 质检，最终通过 Chatbot / Analyst 服务用户，全程由 Observability 监控。

用户界面层

AIP Assist 平台助手、Chatbot Studio 对话机器人、AIP Analyst 分析助手 —— 三类入口覆盖不同业务场景。

编排构建层

AIP Logic 无代码 LLM 函数构建器。Input → Variable → Use LLM → Transform → Apply Action，可视化编排复杂逻辑。

质量保障层

AIP Evals 评测门控。评测集管理、跨模型对比、门控上线 —— 未达标禁止发布为生产 Function。

可观测性层

AIP Observability 全程监控。链路追踪、指标仪表盘、日志管理、阈值告警，全链路透明。

模型基础设施层

Model Catalog 模型目录 + Capacity Management 容量管理。模型登记、评估、生命周期与配额控制。

数据处理层

Document Intelligence 文档智能。PDF/Word/图片解析、信息提取、语义理解、多模态索引。

核心组件关系
造人 · 健脑 · 配枪 —— 三位一体的智能体生产流水线

AIP 决策引擎的三大核心模块不是孤立的功能点，而是一条完整的"智能体生产流水线"。在线制作智能体负责"造人"，AIP 逻辑画布负责"健脑"，智能体工具面板负责"配枪"。三者闭环协作，才能把一个业务需求转化为可上岗的智能体。

① 在线制作智能体

作用：定义"谁"在干活

给智能体起名字、写系统 Prompt、选择底层模型、配置本体上下文、设定安全等级（L0-L4）。产出一份《智能体出生证明》——包含身份、性格、能力边界和权限红线。

② AIP 逻辑画布

作用：定义"怎么干"

用 8 种 Block 把 LLM 调用、变量处理、条件判断、工具执行编排成可运行的 Pipeline。让智能体拿到任务后先做什么、再做什么、什么条件下走分支。

③ 智能体工具面板

作用：定义"用什么干"

为智能体配备工具箱：对象查询（读数据）、动作（写数据）、函数（计算）、请求澄清（反问用户）。设定每个工具的安全策略——谁审批、什么条件下自动执行。让智能体从"只会聊天"变成"能查能写能调系统"。

核心能力 02
AIP 逻辑画布

AIP Logic 是决策引擎的"发动机"。10 种 Block 是构建智能体运行逻辑的"乐高积木"。每一个 Block 都代表一个原子操作，开发者通过拖拽、连接这些 Block，将零散的能力点拼装成一个自动化的工作流（Pipeline）。三栏 UI 设计：左侧块链编排、中间可视化画布、右侧运行与调试面板，支持实时调试与版本管理。

Block 组件库
📥
输入 Input
输入 (Input)
作用：
定义推理入口变量，指定 Pipeline 接收什么类型的业务对象作为输入，如 ObjectType / ObjectId。
场景：
差评触发时，Pipeline 第一步就是通过 Input 接收差评记录的 ID 和对象类型，后续所有步骤都围绕这条数据展开。
📐
创建变量 Create Variable
创建变量 (Create Variable)
作用：
在逻辑执行过程中定义并初始化一个临时变量，将中间计算结果暂存以便复用。
场景：
将订单的"风险等级"计算结果存入 var_risk_level，供后续的"分支判断"和"应用动作"步骤直接读取，避免重复计算。
🔗
获取属性 Get Property
获取属性 (Get Property)
作用：
从一个已注册的业务对象（Object）或其他数据源中读取特定的字段值，是数据读取的入口。
场景：
智能体接收到"订单ID"后，先用"获取属性"Block 查询订单对象，拿到订单的"金额"、"客户等级"、"商品类型"等具体信息作为后续决策的依据。
🤖
使用 LLM Use LLM
使用 LLM (Use LLM)
作用：
调用大语言模型进行推理、对话、总结或结构化信息提取，是智能体的"大脑"。
场景：
读取用户差评文本后，通过 LLM 分析评论的情感倾向（愤怒/失望/中立）、提取关键词（过敏/物流慢/客服问题），并输出结构化标签供后续判断。
🔧
使用工具 Use Tool
使用工具 (Use Tool)
作用：
调用已在工具面板中注册的 Capability 工具，如对象查询、外部 API、计算函数等。
场景：
差评处理流程中，需要查询"客户历史退款记录"，通过 Use Tool 调用"客户行为查询工具"，获取该客户过去6个月的交易和退款频次，作为风险评估的补充依据。
🔄
数据变换 Transform
数据变换 (Transform)
作用：
对读取的数据或变量进行格式转换、清洗或简单运算，将数据转换为 LLM 易于理解的格式。
场景：
将订单金额从"分"转换为"元"以便展示；或把"客户姓名 + 购买的商品名称"拼接为一段自然语言描述，再喂给 LLM 进行分析。
✏️
应用动作 Apply Action
应用动作 (Apply Action)
作用：
触发一个写操作改变系统状态，通常对应一个预定义的 API 调用；调试模式下 dryRun 不落库。
场景：
当判定一个差评为高优先级时，触发"创建工单"Action，自动在客服系统中生成一张待处理工单，并自动分配给对应品类的售后团队。
🚀
执行 Execute
执行 (Execute)
作用：
运行一个外部函数（Function）或已发布的 AIP 逻辑单元，实现逻辑复用；也可用于提交执行结果或触发外部通知。
场景：
如果有一个已封装好的"计算客户价值"函数，可直接通过 Execute 调用它；或将最终处理结果以 Webhook 形式推送给企业微信通知相关处理人。
🔀
分支 Branch
分支 (Branch)
作用：
根据一个条件（通常是变量或属性的值），将流程引导到不同的执行路径上，实现逻辑的多样性。
场景：
根据"差评的风险等级"走两条路径：高风险走"主管介入 + 优惠券补偿"路径；低风险走"标准话术回复 + 自动跟进"路径，实现差异化的智能处理。
🔗
汇聚 Handoff
汇聚 (Handoff)
作用：
汇聚多路分支的上下文，输出统一的决策摘要+产物清单+待确认项，传递给下一个智能体或人工审批。
场景：
高风险分支与低风险分支处理完毕后，通过 Handoff 汇总决策结论、生成的补偿方案、需要主管确认的开放问题，一并交付给"风控审批智能体"继续处理。
