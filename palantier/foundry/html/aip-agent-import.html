如何选用 Adapter 类型？ 点击收起/展开
HTTP API 最轻量
什么时候选：Agent 已经部署成 Web 服务，有现成的 REST/GraphQL 端点可以调用
典型场景：接入第三方 SaaS API（如 Stripe 风控 API）、企业内部已有的微服务
通信方式：HTTP 请求 → JSON 响应 · 无需部署代码
Process Wrapper 最常用
什么时候选：Agent 是 Python/Node 脚本，有 main() 入口，可以在沙箱里 fork 子进程跑起来
典型场景：awesome-llm-apps 的 Streamlit/Flask 单文件 Agent、内部快速原型
通信方式：stdin/stdout JSON-RPC · AOS 沙箱内执行 · 自动隔离
MCP Bridge 标准化协议
什么时候选：Agent 已经按 MCP（Model Context Protocol）标准实现了 Server
典型场景：awesome-llm-apps 的 MCP AI Agents 分支、标准化的工具服务
通信方式：MCP JSON-RPC over stdio/SSE · 自动发现工具列表
Docker Container 重量级
什么时候选：Agent 需要特殊系统依赖（如 GPU 驱动、C++ 库），或者已经有 Dockerfile
典型场景：需 GPU 推理的 Agent、含复杂数据处理 pipeline 的 Agent
通信方式：K8s Pod 拉起 + HTTP/Grpc · 冷启动 10-30s
Session Gateway 实时会话
什么时候选：Agent 涉及语音对话、视频通话、数字人/虚拟形象等实时流式交互
典型场景：Voice AI Agent、直播数字人、视频客服 Bot
通信方式：WebSocket 长连接 + 流式 Audio/Video · 需要 TURN 服务器
⚡ 快速决策路径：
① Agent 已有 HTTP 接口？→ HTTP API
② 是 Python/Node 脚本？→ Process Wrapper（默认推荐）
③ 实现了 MCP 协议？→ MCP Bridge
④ 需要 Docker 环境？→ Docker Container
⑤ 有音视频流？→ Session Gateway
推荐理由：检测到 Streamlit 框架 + Python 单进程运行，适合 Process Wrapper（沙箱内 fork 子进程 + stdin/stdout JSON-RPC 通信）。
