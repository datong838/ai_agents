## 第 2 页 · 数据的黑盒时代

**【画面】** 企业正在被数据淹没，而不是被数据赋能

**【讲稿】**

先看一个普遍现象。几乎所有企业今天都不缺数据——

工艺卡片、实验记录、商品详情、客服对话、专利文献、内部培训材料……数据量在涨，系统也在增多。

但有一个残酷的事实：**绝大多数数据从未被真正用于决策。**

Gartner 一类调研常给出类似结论——七成以上的企业数据躺在那里「只存不用」。  
更麻烦的是，数据质量差带来的隐性损失，往往比缺数据更大。

所以问题从来不是「有没有数据」，而是——  
**企业缺的是把数据转化为行动的能力。**

知识在专家脑子里、在 PDF 里、在 LIMS 的一条记录里，但组织层面**看不见、连不起来、更用不了**。

这就是我们今天要解决的起点。

## 第 3 页 · 传统方案的困局

**【画面】** CRM / ERP / BI / 数据湖 · 数据孤岛 · AI 停在 Chat 阶段

**【讲稿】**

过去二十年，企业信息化靠堆系统：CRM 管客户、ERP 管流程、BI 看报表、数据湖存一切。

每个系统都是一个**孤岛**。  
N 个系统之间，理论上需要 N×(N-1)/2 种连接——每多上一个系统，集成复杂度指数级上升。

更深层的问题在于：**SaaS 卖的是 Feature，不是决策。**

用户在十个工具之间切换，永远形不成统一的业务视图。  
到了 AI 时代，这个问题被放大了——

大模型很强，但它读不到你的真实业务对象，触达不了你的流程，更**触发不了任何业务动作**。  
于是 AI 停在了「聊天」阶段：能写摘要、能答通识，但**不是决策引擎**。

这就是我们看到的结构性困局：**数据有了，语义没有；模型有了，本体没有；对话有了，行动没有。**

## 第 4 页 · 我们的方向

**【画面】** 从数据混沌到清晰行动 · 智能体系统的崛起

**【讲稿】**

我们的回答，不是再做一个工具，而是构建一套**智能体操作系统**。

核心命题再次强调——  
**基于生物-数字双模态知识网与神经扩散机制的智能体系统研发及应用。**

拆开来说有三层含义：

1. **生物-数字双模态**：把生物神经系统的结构隐喻，映射到数字知识图谱——节点像神经元，边像突触，查询像动作电位，反馈像突触可塑性。
2. **知识网**：不是扁平向量库，而是 document / section / concept / media 多层异构图，文本与谱图、商品与段落、概念与案例之间有**有向、有权、可解释**的联结。
3. **神经扩散机制**：查询进来，先在向量空间激活种子，再沿 meta-path 做 PPR 有向扩散——经验从相关节点「传导」到答案，而不是黑盒检索。

**算法渊源（30 秒，建议口述）**  
我们最早的研究起点，是**异构图神经网络（Heterogeneous GNN）+ 知识图谱**——在异质信息网络（HIN）上做 Message Passing、meta-path 语义传导。  
工程落地时，考虑到冷启动数据量与部署成本（2GB 机、无 GPU 训练窗口），**先落地为 BGE 种子 + PPR 有向扩散 + meta-path 白名单**——这等价于**「无需训练参数的 Message Passing」**：可解释、可审计、当天可部署。  
L3 可塑层预留 **R-GCN / HAN** 等可学习扩散（边>10 万且有标注时再议）——与 PPR 共用 `activate → propagate → package` 接口，**Skill 层不感知**底层换引擎。

我们已经在这条路上工程化落地：**谛听客户端 + 营销智能体服务端**，从私域需求挖掘、知识库图谱、到客服话术智能体，共用同一套知识网底座。

## 第 5 页 · 核心理念：增强人类，而非替代

**【画面】** 知识网本体 · 人机协同 · 数据→决策→行动

**【讲稿】**

三个核心理念，贯穿所有产品设计。

**第一，知识网本体思维。**  
类似 Palantir 的 Ontology，但我们用生物隐喻来定义：  
用 document、section、concept、media 映射真实世界的文档、段落、概念与媒体——  
**不是数据库表，是活的业务语义模型。**

**第二，Human-in-the-Loop，人机协同。**  
AI 负责分析、检索、扩散、推荐；人类负责判断、审批、实验、担责。  
不是自动驾驶，是**战斗机的 HUD**——把该看的态势叠在你眼前，但方向盘还在你手里。

**第三，Data → Decision → Action。**  
不止「我看到了洞察」，而是**从「我知道了」到「我做了」**。  
智能体的输出必须能落到具体动作：推荐一段话术、挂接一个商品、生成一份方案、给出带来源的排查清单。

## 第 7 页 · 三大能力层

**【画面】** 知识网层 · 传导引擎层 · 智能体层

**【讲稿】**

系统分三大能力层，可以类比 Palantir 的 Foundry + AIP，但我们的内核是生物隐喻。

**知识网层（Knowledge Network）**  
负责「学」：把关系型数据、文档、图片、商品、对话记录结构化入库，建成异构知识图谱。  
文本走 BGE-M3 向量，图片走 VLM 描述，边表存 contains / mentions / appears_in / references 等关系。

**传导引擎层（Neural Diffusion）**  
负责「想」：完整链路见下一页（7+）——  
`Query → Embedding → ANN 种子 → Meta-path 约束下的 PPR 扩散 → 子图聚合 → Skills`。  
这是**向量相似 + 图结构传导**的双引擎，冷启动可用，可解释、可配置、可审计。

**智能体层（Domain Agents）**  
负责「做」：需求雷达、智能客服、内容写作、认知推演……  
每个 Skill 是知识网上的一种**输出模式**，统一走 `activate → propagate → package → llm → skill_output` 契约。

三层共享底座：异构图存储、向量库、LLM 网关、私有化部署与数据安全治理。

## 第 7+ 页 · 神经扩散检索链路（技术核心 · 建议必讲）

**【画面】** 左：工程链路流程图 · 右：仿生大脑对照表

**【讲稿 · 先用一句话】**

如果只用一句话讲清楚我们智能体怎么「想」——

> 用户提问 → 向量感知定位起点 → 图上沿业务语义路径扩散 → 聚成子图 → 交给 Skill 做决策或生成。

下面我分「工程步骤」和「生物隐喻」两层讲，**两层说的是同一件事**。

---

**【工程链路 · 六步】**

```text
用户 Query
    ↓ Embedding（BGE-M3 等）
ANN 召回 Top-K 种子节点
    ↓ 种子激活
按 Meta-path 白名单约束，做 PPR 语义扩散
    ↓ 沿 mentions / contains / references / appears_in 等边游走
聚合相关子图（节点 + 边 + 来源片段）
    ↓ package 打包为 prompt 上下文
返回给智能体 Skills → 决策 / 生成 / 推荐
```

逐步解释：

1. **Query → Embedding**：把自然语言问题编码成向量，进入同一语义空间。
2. **ANN 召回种子**：在 Chroma 等向量库里做近似最近邻检索，秒级找回 Top-K 最相关的文档段、概念、商品段——这些是 PPR 的**起点**，不是最终答案。
3. **Meta-path 约束**：不是所有边都允许走。系统按业务语义注册路径模板（如 MP1/MP2/MP5），避免图上游走「跑偏」。
4. **PPR 扩散**：以种子为个性化向量，在知识图上做带阻尼的随机游走，给每个节点算「与种子的结构关联强度」。
5. **边聚合子图**：高分节点 + 连接它们的 mentions、contains、references 等边，形成**可解释、带来源**的子图。
6. **Skills 消费**：客服话术、需求分析、报告生成等 Skill 只读这份子图，不再各自拼检索——**一只网，多只手**。

---

**【仿生对照 · 一张表讲清】**


| 工程步骤                                | 算法/对象          | 生物隐喻            | 一句话                    |
| ----------------------------------- | -------------- | --------------- | ---------------------- |
| Query → Embedding                   | 向量编码           | **感知**（感官输入）    | 把外界信号变成神经系统能处理的编码      |
| ANN Top-K 召回                        | 近似最近邻          | **动作电位 · 种子激活** | 少数神经元首先被强烈激活           |
| 种子节点集合                              | Seed Nodes     | **起始放电位点**      | 扩散从这儿开始，不是全图均匀启动       |
| PPR 随机游走                            | 个性化 PageRank   | **神经传导**        | 激活沿突触向邻居传递，可衰减、可重启     |
| mentions / contains / references 等边 | 异构图边           | **突触**          | 连接类型决定「什么信息传向哪里」       |
| Meta-path 白名单                       | 路径模板           | **皮层功能区**       | 不同路径对应不同语义任务，避免乱传导     |
| 子图 → Skills                         | prompt_context | **运动输出**        | 激活场收敛为可执行的行为（话术/方案/决策） |


**【讲稿 · 收尾句】**

所以当我们说「神经扩散机制」，不是比喻装饰——  
**ANN 负责广撒网感知，PPR 负责沿网深化，Meta-path 负责语义分区，边类型负责传导规则。**  
四者合起来，才是「仿生大脑」在算法层的落地。

**【算法演进 · 一句话】**  
研究起点是**异构图神经网络 + 知识图谱**的 Message Passing；  
今日生产默认是 **PPR（静态 Message Passing）**；  
明日 L3 可平滑升级为 **R-GCN / HAN（可学习 Message Passing）**——同一套 Skill 契约，不换应用。

## 第 8 页 · 系统架构：三层引擎

**【画面】** 应用层 / 本体层 / 数据层

**【讲稿】**

从工程架构看，同样是三层。

**应用层**：Electron 客户端「谛听」——需求雷达、知识库、知识图谱 Tab、认知推演、智能体对话；服务端「营销智能体」——Analyze、Ingestion、Graph API、Skill 编排。

**本体层**：知识网的核心——  
节点是业务对象（文档、段落、概念、媒体、商品……），  
边是语义关系（包含、提及、跨文档共现、挂接……），  
技能是可触发动作（检索、推荐、生成、诊断……）。  
**这一层是灵魂，所有应用共享同一真相来源。**

**数据层**：Ingestion Pipeline——分段入库、HTML/图片解析、OCR/VLM、Niushop 同步、用户上传、主动学习产物……  
实时与批量兼顾，带来源、有版本、可回溯。

## 第 9 页 · 知识网本体：系统的灵魂

**【画面】** 传统数据模型 ✕ vs 谛听知识网 ✓

**【讲稿】**

这一页是整个方案的「题眼」。

传统数据模型：数据在表里，关系靠 JOIN 临时拼，业务语义散落在 SQL 和代码里，**每个应用看到不同的「真相」**。

谛听知识网本体：

- **节点**：document → section → concept → media，层级清晰  
- **边**：持久化、有权重、有类型，不是临时 JOIN  
- **跨模态**：实验报告原文 → 段落 → 关键概念 → 色谱图/商品图  
- **统一视图**：所有智能体、所有 Skill、所有 Analyze **读同一张网**

这也是 AI 能否落地的分水岭——  
**没有本体，LLM 只是通用助手；有了本体，LLM 才是领域专家。**

## 第 10 页 · 飞轮效应

**【画面】** 数据融合 → 语义成网 → 智能体赋能 → 反馈强化

**【讲稿】**

知识网建好后，会自然形成飞轮。

**第一步，数据融合。** 多源异构数据经 Pipeline 清洗、抽取、标准化，进入统一入口。

**第二步，语义成网。** 实体挂节点、关系写边表、meta-path 模板注册——网开始「通电」。

**第三步，智能体赋能。** 上层应用不再从零拼上下文，而是从网中**扩散**出子图，驱动各类 Skill。

**第四步，反馈强化。** 用户采纳、点赞、修正，乃至业务结果回流——边权更新，成功路径强化，失败路径弱化。

**用得越多，网越密，推荐越准，越离不开。**  
这就是知识网相对「一次性 ETL 项目」的结构性优势。

## 第 11 页 · 三大构件：名词 · 关系 · 动词

**【画面】** 节点 Nodes · 边 Links · 技能 Skills

**【讲稿】**

把知识网本体拆成三个构件，Palantir 叫 Objects / Links / Actions，我们叫**节点 / 边 / 技能**。

**节点 = 名词**  
文档、段落、概念、媒体、商品、评价……每个节点有属性，有向量，有类型。

**边 = 关系**  
contains、references、mentions、appears_in、related_product……  
不是临时查询，是**第一公民**——持久、可遍历、有权、可解释。

其中 **mentions（提及边）** 尤其关键：表示某段文字或某张图**提到了**某个概念/实体——  
例如：`Section「纯化梯度描述」--mentions--> Concept「乙腈浓度」`。  
它连接**非结构化载体**（document / section / media）与**结构化概念**（concept / parameter），  
是 NER + LLM 抽取后写入图谱的语义挂接，也是 PPR **从一段文字追到概念、再扩散到其他文档**的主通道。

产品 UI 里我们给边起了生物别名：胞体-胞突、短程突触、长程髓鞘突触、**语义树突簇（mentions）**——帮助业务人员理解「为什么这条边会传导经验」。

**技能 = 动词**  
检索、推荐、话术生成、内容写作、挂接商品……  
每个 Skill 内置：输入校验、来源追溯、权限控制、Human-in-the-Loop 审批。

传统系统最大的撕裂是：**名词在数据库，关系在代码，动词在应用层。**  
知识网把三者**统一在一个语义层**，一次定义，处处可用。

## 第 12 页 · 为什么 AI 必须有知识网

**【画面】** 没有知识网的 AI ✕ vs 有知识网的 AI ✓

**【讲稿】**

这一页专门回答技术决策者最常问的问题：「我已有大模型，为什么还要知识网？」

**没有知识网：**

- 只能读公开文献、写通识摘要  
- 不知道你的「商品 A」和「概念·补水」之间什么关系  
- 无权控、无来源、无审计  
- 答完就结束，**触发不了任何业务动作**  
- 幻觉无法被业务上下文约束

**有知识网：**

- LLM 理解「这款套装和敏感肌场景」的完整语义  
- Agent 沿 meta-path 检索真实商品段、评价、配图  
- 基于 License / 类目 / 角色做精确权限控制  
- 输出带 node_id、chunk 来源、mini_path，**可复核、可点击、可行动**  
- 本体约束显著降低幻觉

我们的工程契约已经标准化（与第 7+ 页链路一一对应）：

```text
activate(query) → seeds[]                    # Embedding + ANN → 动作电位 / 种子激活
propagate(seeds, meta_paths) → subgraph      # PPR + 边聚合 → 神经传导 / 突触网络
package(subgraph) → prompt_context           # 子图打包 → 皮层读出
llm.infer(context) → skill_output            # Skills → 行为输出
```

**为什么这比裸 LLM 或纯向量 RAG 更强？**

- **纯 LLM**：闭卷考试，容易幻觉。  
- **纯向量 RAG**：只找回语义相似的 chunk，**看不见**「这篇报告的失败实验」和「当前异常」之间的结构关联。  
- **ANN + PPR + Meta-path**：先感知相似起点，再沿 mentions / contains 等边多跳传导——  
向量负责「像不像」，图负责「连没连、该不该连、连到哪」。

底层实现体可以是 `ppr_expand()`，未来可换 GNN——**Skill 层不感知**，这是架构的可演进性。

## 第 13 页 · 不可复制的护城河

**【画面】** 网络效应 · 零边际成本 · 组织知识固化 · AI 倍增器

**【讲稿】**

知识网一旦在客户侧跑起来，会形成四类护城河。

**数据网络效应。** 每多接入一种数据源，已有节点的关系都更丰富——不是线性增值，是**指数增值**。

**AI 能力倍增器。** 裸 LLM 是通识；LLM + 专属知识网 = 领域专家。  
迁移到别家平台，意味着 AI 从零重新理解你的业务。

竞争格局里，有人有数据湖，有人有 CRM，有人有工作流——  
但很少有人把**数据 + 关系 + 操作 + 安全 + AI** 统一在一个语义层。这是我们的定位。

## 第 17 页 · 模型选型：RAG 优先，小模型专精

**【画面】** 检索增强 + Skill 调度 + 混合推理 · RAG = 我们的检索端 + 生成端

**【讲稿】**

模型策略上，我们坚持**不重复造轮子，但坚持本体优先**。

先澄清一个常被误用的词——**RAG（Retrieval-Augmented Generation，检索增强生成）**。

**专业定义**：不再单纯依赖模型参数里固化的知识，而是在用户提问时，**先从外部知识库检索相关片段**，再把「检索结果 + 原问题」一起交给 LLM 生成答案。

**在我们体系里，RAG 被拆成两段，且检索端比常规定义更强：**


| 环节      | 常规定义           | 谛听实现                                            |
| ------- | -------------- | ----------------------------------------------- |
| **检索端** | 向量 Top-K chunk | **ANN 向量召回 + PPR 图扩散 + Meta-path 约束** → 结构化知识子图 |
| **生成端** | LLM 读 chunk 作答 | 智能体读「生物-数字知识网片段」→ 话术 / 建议 / 选型 / 报告             |
| **价值**  | 降低幻觉           | **开卷考试**：基于企业私有沉淀推理，来源与边权可查                     |


因此，当我们说「优先 RAG」，指的是：**优先把私有知识网喂给模型**，而不是让大模型闭卷瞎编。

**其余组件分工：**

**对话与推理**：DeepSeek 等 LLM，必须被知识网上下文约束，禁止裸奔生成。  
**向量检索**：BGE-M3 + Chroma，负责 ANN 种子激活。  
**图扩散**：PPR + meta_paths 白名单，负责结构传导。  
**视觉理解**：VLM 填 media 节点描述，图谱可跨文档反查。  
**结构化预测**：XGBoost / LightGBM 等小模型，与符号规则 + 图扩散**混合推理**，保证可解释。  
**外部重模型**：专业工具作为 **Skill 调度**，不自研全部底层。

原则只有一句：**优先 RAG（ANN+PPR 增强型）+ 小模型专精 + Skill 调度；数据不够不盲目微调；本体不够不上生产。**

## 第 18 页 · 范式跃迁：三代进化

## 第 20 页 · 干湿闭环：从地图到自动驾驶仪

**【画面】** 感知 → 理解 → 推理 → 行动 → 学习

**【讲稿】**

五级闭环，对应我们 L1/L2/L3 传导架构的产品化表达。

**感知**：Pipeline 接入文档、对话、商品、图片，多模态入库。  
**理解**：实体抽取，节点挂接，**「这款商品适合敏感肌」而非「表格第 5 行」**。  
**推理**：Agent 在知识网上扩散，检测缺口、推荐关联、模拟「如果换这个概念会怎样」。  
**行动**：输出话术、方案、挂链——经人审后可执行。  
**学习**：采纳/拒绝/修正回流，边权更新，**突触可塑性**——L3 层。

这就是**生物-数字双模态**的完整含义：  
生物侧是可塑性、传导、反馈；数字侧是图、向量、Agent、Pipeline。  
**两侧同构，才能闭环。**

## 第 21 页 · 突触可塑性：会学习的知识网

**【画面】** 强化 · 退化 · 髓鞘增厚 · staleness 治理

工程上落在 `props_json`：weight、traversal_count、staleness、pruned……  
与运营侧「图谱 Tab 红色半透明边」联动——**可治理、可回滚**。

这让系统从「人教 AI」逐步走向「AI 建议、人审批、系统记住」。

## 第 23 页 · 三件事（从行业最佳实践到我们的实践）

## 附录 A · 高频 Q&A 参考回答

**Q：和 Palantir / 传统知识图谱公司有什么不同？**  
A：Palantir 卖 Ontology 操作系统；我们用**生物隐喻**定义异构知识网，PPR 神经扩散是已落地的传导机制，且从私域运营场景验证了端到端闭环。更轻、可私有化、Skill 可插拔。

**Q：为什么用生物隐喻，不是噱头吗？**  
A：不是装饰。document/section/concept/media 对应神经元形态；边类型对应突触；PPR 对应动作电位传播；边权反馈对应可塑性——**每一层隐喻都映射了工程对象**，见入库方案 §十四。早期算法起点是**异构图神经网络 + 知识图谱**的 Message Passing，PPR 是其可部署、可解释版本。

**Q：ANN 和 PPR 为什么不能只用一个？**  
A：**ANN 解决「从海量高维里秒级找起点」**——广撒网的语义感知；**PPR 解决「从起点沿结构深化」**——多跳传导、跨文档联动。只做 ANN 会漏掉「向量不相似但结构关键」的节点（如旧报告里的失败案例）；只做 PPR 没有好种子，扩散无从谈起。二者耦合才是「感知 + 神经传导」。

**Q：Meta-path 是什么，为什么需要？**  
A：在异构图里，不同类型节点和边组成的**类型化路径模板**。例如 `Concept → Section ← Document` 表示「某概念在哪些文档哪些段落被讨论」。智能体按任务选 path：问功效走 MP1，配图反查走 MP2，同图跨品走 MP5——**避免全图乱游走，保证推理符合业务逻辑**。

**Q：一定要上大模型微调吗？**  
A：不一定。默认 **RAG + 知识网约束**；数据量足够且边界清晰时才考虑领域微调。本体质量 > 模型规模。

**Q：GNN 做了吗？和 PPR 什么关系？**  
A：**研究渊源**在异构图神经网络 + 知识图谱 Message Passing；**生产默认**是 BGE + PPR + meta-path（静态、可解释）；**L3 远期**可上 R-GCN/HAN，共用 propagate 接口，Skill 层无感。不是没做 GNN，是**分阶段**：先可部署，再可学习。

**Q：智能客服实现 HAN 了吗？**  
A：**没有**。今日生产是 `ann_then_ppr`（BGE 种子 + meta-path 白名单 PPR），见 `ppr.py`、`knowledge_search.py`、`dialogue_compose.py`。HAN/R-GCN 是 L3 远期选项，与 Skill 层解耦。

**Q：四类智能体分别什么状态？**  
A：**电商售前导购**（M6-1/2）已 POC；**文案写手**（M6-3）已落地；**短视频创作**（M7-1 导演+Skill 链）进行中；**数字人直播**技能集已预留、远期。四者共用 L2 子图与 Skill 契约，换 L1 策略不换网。

**Q：部署和数据安全？**  
A：客户端 + 服务端分离；支持私有化；按 category 隔离；License 鉴权；敏感数据不出域可配置。

### B.2 RAG（Retrieval-Augmented Generation）

**定义**：将信息检索与大语言模型生成结合的技术架构。不单纯依赖模型训练时固化在参数里的知识，而是在用户提问时，先从外部知识库（向量库 / 图谱）检索相关片段，再把「检索结果 + 原问题」交给 LLM 生成答案。

**在谛听体系里**：

- **检索端**：ANN 向量检索 + PPR 图扩散 + Meta-path 约束 → 拿到与问题最相关的**结构化知识子图**（非扁平 chunk 列表）。  
- **生成端**：智能体基于检索到的「生物-数字知识网片段」生成建议、报告或决策，**降低幻觉，保证可追溯**（node_id、边、来源可查）。  
- **价值**：基于企业**私有沉淀**（工艺卡片、实验记录、商品库、监测报告等）做推理，是**开卷考试**，不是闭卷瞎编。

---

### B.3 PPR（Personalized PageRank）

**定义**：PageRank 的变种。传统 PageRank 衡量全图节点的**全局**重要性；PPR 从指定的**种子节点（Seed Nodes）出发，通过随机游走计算其他节点与种子的局部**关联强度。种子节点初始概率为 1，其余为 0；游走中以阻尼系数 α 向邻居扩散，并可「重启」回种子。

**公式直觉**（宣讲可口述，不必写板）：

```text
π = α · P · π + (1 − α) · v
```

- `v`：个性化向量（只在种子节点非零）  
- `P`：转移矩阵（沿边游走）  
- `α`：扩散程度 / 阻尼（越大越扩散，越小越贴种子）

**在谛听体系里**：

- 种子来自 **ANN 召回**或智能体当前关注的概念节点（如「敏感肌」「某杂质谱」）。  
- PPR 在知识网上扩散：不直接相连的远距节点，若通过多跳 mentions / contains 路径语义相关，也会获得较高分。  
- 模拟**神经传导 / 激活扩散**：从一个知识点触发，沿突触（边）逐步激活相关知识。

---

### B.4 Meta-path（元路径）

**定义**：在异质信息网络（HIN）中，描述从一类节点到另一类节点、经过**类型化关系序列**的路径模板。形式化：

```text
A₁ ─R₁─→ A₂ ─R₂─→ … ─Rₗ─→ Aₗ₊₁
```

**示例**：

- `Document --contains--> Section --mentions--> Concept`  
- `Concept --←mentions-- Section --contains-- Document`（反向：某概念在哪些文档哪些段被讨论）  
- `Section --references--> Media --appears_in--> Document`（配图反查）

**语义意义**：不同 meta-path 承载不同业务语义——


| 模板      | 路径（工程）                       | 业务语义             |
| ------- | ---------------------------- | ---------------- |
| **MP1** | concept → section ← document | 问某概念/功效，命中多文档多段落 |
| **MP2** | section → media → document   | 从配图反查商品/报告       |
| **MP5** | media → … → document         | 同一张图关联多个文档/商品    |


**在谛听体系里**：PPR 扩散**仅沿 meta_paths 白名单**游走。智能体规划时按任务选 path——做概念解析走 MP1，做配图推荐走 MP2——**避免无意义游走，保证推理符合业务逻辑**（如参数因果链、跨文档经验迁移）。

---

### B.5 ANN + PPR 语义扩散（双引擎耦合）

**定义**：向量相似性与图结构传导的联合检索机制——谛听「神经扩散机制」的算法内核。

**ANN（Approximate Nearest Neighbor）**：

- 在 BGE 等 Embedding 空间快速找回与 Query 语义相似的 Top-K 节点。  
- 解决「从海量高维数据里秒级定位少量相关起点」。  
- 生物映射：**感知 / 感官编码**。

**PPR 语义扩散**：

- 以 ANN 召回节点为种子，在知识图谱上做随机游走。  
- 不仅看向量相似，还看拓扑：多跳 contains / references / mentions 会把相关性传给**间接但结构关键**的节点。  
- 生物映射：**神经传导 / 激活场形成**。

**联合效果**：


| 引擎        | 负责        | 生物隐喻        |
| --------- | --------- | ----------- |
| ANN       | 广撒网定位起点   | 感官激活少数神经元   |
| PPR       | 沿网深化、多跳推理 | 突触网络扩散形成语义场 |
| Meta-path | 约束可走的路径类型 | 皮层功能区划分     |
| 边类型       | 传导规则与权重   | 突触类型与强度     |


> 先由感官（向量）激活少数节点，再通过突触网络（图边）扩散——实现多跳、跨文档的复杂推理。这正是「神经扩散机制」的算法映射。

---

### B.6 Mentions（提及关系边）

**定义**：知识图谱中的一种语义边，表示某个**文本单元 / 媒体单元**提到了某个**实体 / 概念 / 对象**。

**示例**：

- `Document「工艺报告 2023」--mentions--> Concept「某修饰基团」`  
- `Section「纯化梯度描述」--mentions--> Parameter「流动相比例」`

**在知识网中的定位**：

- 核心边类型之一，连接**非结构化载体**（document / section / media）与**结构化概念**（concept / parameter / entity）。  
- 与 contains（包含）、references（引用）、appears_in（出现在）并列；**mentions 侧重语义标注**，多由 NER + LLM 抽取写入。  
- 产品图例生物别名：**语义树突簇**。

**作用**：

- 让原始文件（实验记录、监测报告、商品详情）挂接到知识网语义概念上。  
- 支持 PPR 沿 `Section --mentions--> Concept` 正向 / 反向扩散——**从一段文字追到概念，再扩散到讨论同一概念的其他文档**。  
- 是跨文件知识联动、失败案例追溯、参数链推理的关键边。

### B.8 算法演进：异构 GNN 研究 → PPR 工程 → L3 可学习扩散

**研究起点 · 异构图神经网络 + 知识图谱**

- 在**异质信息网络（HIN）**上建模：不同类型节点（document / section / concept / media）与类型化边（contains / mentions …）**不拍平**为同质 `related`。  
- 核心思想与 GNN 的 **Message Passing** 一致：节点沿边聚合邻居信息、多跳传播、meta-path 定义高阶语义路径（与 HAN 等经典工作同脉络）。  
- 生物-数字双模态隐喻，即在此算法框架上发展而来——不是后期贴标签。

**工程现状 · 为何先上 PPR 而非端到端 GNN**

| 考量 | 说明 |
|------|------|
| 部署 | 2GB CVM、无 GPU 训练窗口 → 默认**不训** GNN |
| 冷启动 | 边规模与标注不足时，黑盒 GNN 难解释、难审计 |
| PPR 定位 | **BGE 种子 + 加权 PPR** = 无需训练的 Message Passing（入库方案 §14.3.2 结论） |
| 可解释 | 扩散路径、边类型、meta-path 均可可视化 → 图谱 Tab / 认知推演 |

**演进路线 · 三层算法栈**

```text
L1 建网     异构图 / HIN 属性图（node_type + rel_type）          ✅ 已有
L2 传导     ANN 种子 + PPR + meta-path（静态 Message Passing）  ✅ 基本盘
L3 可塑     R-GCN / HAN + 边权学习（可训练 Message Passing）     🔜 远期可选
```

**统一接口（Skill 不感知底层换引擎）**

```text
activate(query) → seeds[]
propagate(seeds, meta_paths) → subgraph    # 今日 ppr_expand() · 明日 gnn_forward()
package(subgraph) → prompt_context
llm.infer(context) → skill_output
```

**宣讲口径**：有算法纵深，但不夸大——**今日交付 PPR，明日预留 GNN，研究与应用一条线。**
